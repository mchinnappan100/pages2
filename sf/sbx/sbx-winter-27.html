Get early access with your Winter '27 sandbox preview

Every major release opens a six-week preview window before go-live. Decide now whether each sandbox rides ahead on Winter '27 or stays put on Summer '26 — and don't miss the cutoff.

How sandbox preview works

Sandboxes live on either a preview instance or a non-preview instance. All sandboxes on a preview instance upgrade together, six weeks ahead of everyone else — your first real chance to test configurations on the new release. The only way to change which group a sandbox belongs to is to refresh it onto a different instance, and that has to happen before the cutoff.

Preview instance

Upgrades to Winter '27 on Aug 28–29, 2026. Default for new sandboxes unless you opt out.

Non-preview instance

Stays on Summer '26 until Oct 9–10, 2026, the general release upgrade.

What are my options?

Pick the scenario that matches what you're trying to do.

🆕 Creating a new sandbox

Want Winter '27 preview

Submit the request well ahead of the Aug 27 cutoff so the copy finishes before the release. Cut it too close and the sandbox lands on a non-preview instance instead.

Want to stay on Summer '26

Select Request Non-Preview before the cutoff (needs an org permission from Salesforce Support) — or simply wait and submit the request after Aug 29, 2026.

🗂️ I already have a sandbox
Release type Want Winter '27 Want to stay on Summer '26
Preview No action needed — it upgrades automatically on Aug 28. Only refresh if you must, and do it well before the cutoff. Select Request Non-Preview before the cutoff, or wait to refresh until after Aug 27, 6 PM PT.
Non-Preview Refresh it before the Aug 27 cutoff to move it onto a preview instance. No action needed — it stays on Summer '26 until the Oct 9–10 general upgrade.
⚠

Refreshing deletes the sandbox and rebuilds it from production — save anything sandbox-specific first.

🧬 Cloning a sandbox

Before the preview window

Clone requests default to a preview instance. Select Request Non-Preview before the cutoff to route it elsewhere.

During the preview window

From Aug 27, 6 PM PT through Oct 10, clones are built on the same release version as the sandbox they came from.

AgentExchange packages

Where uploads and installs are allowed during the transition.

Before preview starts · until Aug 28

Upload and install from your Summer '26 production or sandbox org, to any Summer '26 production or sandbox org.

During preview · Aug 28 – Oct 9

Summer '26 orgs continue as before. Winter '27 sandboxes can upload and install to other Winter '27 orgs, and can still install packages built on Summer '26.

Should I refresh my sandbox?

Why do requests slow down near the cutoff?

The preview program is popular, so create and refresh requests back up close to the deadline — and a full sandbox copy simply takes time. Request at least a week out to improve your odds of landing on the right instance before Aug 28.

What happens to incomplete requests?

Any sandbox still incomplete when preview starts on Aug 28 is reset to a non-preview instance, regardless of what you originally requested.

How do I check which instance a sandbox is on?

In production, go to Setup → Sandbox and check the Release Type column. You can also enter your instance name into the Sandbox Preview Guide to confirm preview vs non-preview status.
