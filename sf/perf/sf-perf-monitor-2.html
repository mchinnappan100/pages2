Why SF Perf Monitor?

Raw EventLogFile CSVs tell you nothing. SF Perf Monitor tells you everything.

Feature What it gives you
📊 Five event types, one dashboard ApexExecution · ApexRestApi · RestApi · ApexCallout · ApexTrigger — together, not siloed
🔍 P95 and slow % in every view Percentile breakdowns (P50 · P75 · P90 · P95 · P99 · Max) so outliers don't hide in the mean
⚡ Source code + static analysis Click any slow entry point → Apex source via Tooling API → 8 anti-pattern rules fire instantly
🕸️ SF Graphy — Apex Knowledge Graph Whole-org dependency graph: god classes, cycles, BFS impact, shortest path, heatmap, mini-map
🤖 AI Sidekick + graph context Runtime P95, anti-pattern findings, and graph topology injected into every AI conversation

04 / 28

Data Flow

sf CLI query → REST download → Parse + index → WebSocket broadcast → Live Dashboard
Step What happens
01 sf CLI query EventLogFile SOQL via sf data query — execFileAsync, no shell strings
02 REST download CSV fetched with org access token · cached to data/<org>_<Type>.csv
03 Parse + index In-memory state.logs — header + rows per event type
04 WebSocket broadcast Typed messages: logs, summary, status
05 Live Dashboard Chart.js · DataTable · percentile widgets · heatmap — all updated in-place

No SDK dependency. Uses the sf CLI you're already authenticated with.

Apex Anti-Pattern Engine

8 regex rules run synchronously in the browser — no build step, no external service.

Severity Rule Why it matters
🔴 Critical SOQL inside loop Governor limit: max 100 SOQL queries per transaction
🔴 Critical DML inside loop Governor limit: max 150 DML statements per transaction
🔴 Critical HTTP callout in trigger Callouts are prohibited in DML triggers
🟡 Warning Non-bulkified trigger (Trigger.new[0]) Only processes first record; bulk ops silently drop data
🟡 Warning SOQL without LIMIT Unbounded queries cause timeouts on large orgs
🟡 Warning Hardcoded Salesforce Id Ids change between environments; breaks deployments
🔵 Info System.debug spam Fills debug logs, degrades production performance
🔵 Info Large inline collection Memory pressure in bulk operations

Snap to Slack & Snap to Email

Capture a full-height PNG of the entire dashboard and deliver it in one click.

1. html2canvas  →  expands #view-dashboard to full scrollHeight, captures all charts
2. canvas.toDataURL('image/png')  →  base64 PNG

Slack path:
  POST /api/slack/upload-image
  → slack.js: Files API 3-step
      Step 1: GET files.getUploadURLExternal  { filename, length }  → { upload_url, file_id }
      Step 2: PUT pngBuffer to upload_url  (Content-Type: image/png)
      Step 3: POST files.completeUploadExternal  { files: [{id, title}], channel_id }

Email path:
  POST /api/email/send-image
  → nodemailer: inline cid: attachment  (renders inside the email body)

Requirements
Slack: Bot Token (xoxb-...) with files:write scope + Channel ID
Email: SMTP config in ~/.sfperfmon/smtp.json

SF Graphy — Apex Knowledge Graph

An interactive dependency graph explorer that maps your entire Salesforce codebase in one view.

sf data query (ApexClass) → stripApexNoise() → regex parse
  → nodes (Classes, Triggers, Interfaces)
  → edges (CALLS · EXTENDS · IMPLEMENTS · QUERIES · USES · DML)
      → D3 v7 force-directed graph
Capability Detail
🕸️ Whole-org view All Apex classes simultaneously — tested on orgs with 738 – 1,431 classes
🔍 Edge types CALLS · EXTENDS · IMPLEMENTS · QUERIES · USES · DML
🏛️ Architecture analysis God classes · orphans · cycles · BFS impact count
📡 SFDX offline Parses local .cls files — no org connection required
🚀 SSE streaming /api/graphy/org/stream pushes progress frames (data: <JSON>\n\n) — UI builds graph live as classes arrive

Launch: node server.js -o <alias> then open /graphy.html

12 / 28

SF Graphy — Graph Edge Types

Six relationship categories rendered as colour-coded directed edges.

Edge Colour What it captures
CALLS Blue Method invocations between classes
EXTENDS Green Inheritance chains (extends)
IMPLEMENTS Teal Interface implementation
QUERIES Amber SOQL targets ([SELECT ... FROM SObject])
USES Grey Variable/field type references
DML Red insert · update · delete · upsert · merge operations

Before any regex runs, source is stripped of:

  • // line comments
  • /* */ block comments
  • Single-quoted string literals

Prevents comment text and string values from producing phantom class names or fake SOQL targets.

SF Graphy — Architectural Analysis

Find systemic problems that only become visible across the whole codebase.

Analysis How it works What it reveals
🔴 God classes Nodes with ≥ 35% of max degree Over-coupled classes — single largest refactoring risk
👻 Orphans Nodes with zero in + out edges Dead code — safe to delete, or missing wiring
🔄 Cycles Mutual A→B→A detection Circular deps — test isolation and deployment risk
🌊 BFS Impact Breadth-first from selected node "What breaks if I change this?" — transitive dependent count
🛤️ Shortest Path BFS from node A to node B Exact call chain between any two classes in N hops

SF Graphy — Interactive Controls

Progressive filtering and focus — render only the subgraph you care about.

Control What it does
🔢 Top-N slider Limit rendered nodes to top-N by degree (default 80) — keeps large orgs navigable
🎯 BFS focus-hops Render only N hops from the selected node — isolate one service cluster
🔘 Node-type filter Show/hide Classes · Triggers · Interfaces independently
🔗 Edge-type filter Show/hide any of the 6 edge kinds
🔍 Search Highlight matching nodes by name
📌 Pin nodes Double-click any node to pin it in place (orange dashed ring = pinned); double-click again to release
🗺️ Mini-map Top-left 160×110 px navigator — click to pan; viewport rect tracks main zoom
🔥 Complexity heatmap Toggle: colours all nodes green→amber→red by method count — instantly shows complex classes

All controls call computeSubgraph() → renderGraph() — every filter updates the live graph.

SF Graphy — Complexity Heatmap

Colour every class by method count — spot complexity at a glance.

Low method count  →  🟢  rgb(58, 125, 82)
Mid method count  →  🟡  rgb(245, 200, 66)
High method count →  🔴  rgb(200, 75, 47)
  1. Collect methodCount for every visible node
  2. Normalize 0 → 1 across the visible set
  3. Interpolate through the 3-stop green → amber → red gradient
  4. Apply as fill on each node circle

The heatmap re-applies after every filter change — applyView() calls applyHeatmap() at the end so colours survive node/edge type toggles and Top-N changes.

Toggle off → node colours revert to KIND_COLOR (class / trigger / interface defaults).

SF Graphy — Shortest Path Finder

Find the exact call chain between any two classes in the codebase.

Click "Shortest Path" in the Analysis sidebar
  → Enter FROM class  (e.g. AccountController)
  → Enter TO class    (e.g. AccountRepository)
  → Click "Find Path"
      → BFS on adjacency list built from graphData.edges
          → Reconstruct path via prev[] map
              → Highlight path nodes + edges
              → Dim all other nodes and edges
              → Display chain: A → B → C → D

Shortest path (3 hops):
AccountController → AccountService → AccountRepository

Click "Clear" to restore the full graph.

Useful for impact planning: "How does a UI action reach the database layer?"

SF Graphy — Export

All export formats capture a fully-settled layout — simulation runs to convergence before capture.

runToConvergenceAndExport(cb):
  simulation.stop()
  while alpha > alphaMin && ticks < 500: simulation.tick()
  flush final x/y to every .link and .node DOM element
  cb()   ← exportSVG() or exportPNG() runs here
Format Button Use case
⬇️ SVG ⬇ SVG Scalable vector — embed in docs, Confluence, Notion
⬇️ PNG ⬇ PNG Raster at 2× device pixel ratio — presentations, emails
⬇️ JSON ⬇ JSON { nodes, edges } — import into Gephi or Cytoscape
⬇️ GraphML ⬇ GraphML XML graph format — Gephi, yEd, draw.io compatible

All exports include only the current subgraph (respects Top-N, BFS focus, search, and node/edge type filters).

Never call buildExportSVG() directly — always go through runToConvergenceAndExport() or the export shows a bunched, partially-settled layout.

Scheduled Notifications & Auto-Fetch

Two independent cron controls — standard 5-field syntax.

Expression Meaning
*/15 * * * * Every 15 minutes
0 * * * * Every hour on the hour
0 8 * * * Every day at 08:00
0 8 * * 1-5 Weekdays at 08:00
0 8,17 * * 1-5 Weekdays at 08:00 and 17:00
*/30 9-17 * * 1-5 Every 30 min, business hours
0 0 * * 0 Weekly Sunday midnight

Auto-Fetch: Settings → Auto-Fetch. Single-job guarantee — changing the expression cancels and recreates.
Notifications: Settings → Scheduled Notifications. Check Slack, Teams, Email. Leave cron blank to notify after every fetch.

Security Model

Rule How
🔒 No shell interpolation sf called via execFileAsync([...args]) — never a template-literal shell string
🔒 DOM safety All dynamic content via textContent / DOM methods — never innerHTML with external data
🔒 Event-type allowlist KNOWN_EVENTS array validated on all per-event API routes; unknown types → 400
🔒 Path traversal guard File download endpoint uses path.basename() to strip traversal sequences
🔒 Config file permissions All ~/.sfperfmon/*.json written with mode 0600 (owner-readable only)
🔒 AI keys in localStorage API keys never written to disk or proxied through the Node server
🔒 No backend database CSV cache + in-memory state are intentional — zero persistent attack surface
🔒 Tooling API auth Uses the org's existing bearer token from sf org display — no separate credential storage

CLI Quick Reference

sf-perf-monitor [options]

Options:
  -o, --org <alias>          Salesforce org username or alias
  -e, --events <list>        Comma-separated event types (default: all 5)
  -p, --port <number>        HTTP port (default: 3000)
  -t, --threshold <ms>       Slow threshold in ms (default: 3000)
  --enable-ai                Enable AI Sidekick panel
  --debug-logs               Fetch ApexLog debug logs alongside EventLogFile data
  --debug-log-limit <n>      Max ApexLog rows to fetch (0 = unlimited, max 50 000)

Examples:
  sf-perf-monitor -o my-org
  sf-perf-monitor -o my-org -t 5000 --enable-ai
  sf-perf-monitor -o my-org -e ApexExecution,ApexCallout -p 4000
  sf-perf-monitor -o my-org --debug-logs --debug-log-limit 2000

Get Started

# 1. Install
npm install -g sf-perf-monitor

# 2. Authenticate your Salesforce org
sf org login web -a my-org

# 3. Launch
sf-perf-monitor -o my-org --enable-ai

Open http://localhost:3000 in your browser.

http://localhost:3000 Performance dashboard — charts, drill-down, heatmap
http://localhost:3000/graphy.html SF Graphy — Apex Knowledge Graph explorer
