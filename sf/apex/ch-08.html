Agentforce & Apex — The Big Picture

Agentforce is Salesforce's AI agent platform. Apex is the primary way to extend what agents can do — writing custom actions, tools, and integrations that agents invoke autonomously.

Agentforce Agent → decides action → Apex Action / Tool
Apex Action → queries / mutates → Salesforce Data or calls → External API
Apex Action → returns structured result → Agent uses result

How Agents Use Apex

An Agentforce agent (powered by an LLM) decides which action to call based on the user's intent and the action's description. The agent passes input parameters, Apex executes, and returns a structured result the agent incorporates into its response.

  • @InvocableMethod — the primary mechanism. Apex methods annotated this way become callable from Flow, Agentforce, and Process Builder.
  • Custom Agent Actions — actions defined in the Agent Builder, backed by an @InvocableMethod or Flow.
  • Prompt Templates — structured prompts that can call Apex via merge fields or Flow actions for dynamic context.
  • Einstein AI APIs — Apex can call Salesforce's Einstein platform APIs for predictions, completions, and embeddings.

@InvocableMethod — The Agent Action Interface

Any Apex class method annotated with @InvocableMethod can be surfaced as an action in Agentforce, Flow, and Process Builder. The label and description are what the AI reads to decide when to call it — they must be precise.

🤖

Basic @InvocableMethod

A simple agent action that looks up an Account and returns a summary.

  • Must be static
  • Must accept a List parameter
  • Must return a List or void
  • label shown in Flow/Agent Builder
  • description guides AI invocation
  • Input class uses @InvocableVariable
public with sharing class AccountLookupAction {

    // Input wrapper — @InvocableVariable defines each field
    public class Input {
        @InvocableVariable(
            label='Account Name'
            description='The name of the Account to look up'
            required=true)
        public String accountName;
    }

    // Output wrapper
    public class Output {
        @InvocableVariable(label='Account Id')
        public String accountId;

        @InvocableVariable(label='Account Summary')
        public String summary;

        @InvocableVariable(label='Found')
        public Boolean found;
    }

    // The action method
    @InvocableMethod(
        label='Look Up Account'
        description='Searches for an Account by name and returns its Id, industry, and annual revenue summary. Use this when the user asks about a specific company.')
    public static List<Output> lookupAccount(List<Input> inputs) {
        List<Output> results = new List<Output>();

        for (Input inp : inputs) {
            Output out = new Output();
            String searchName = '%' + inp.accountName + '%';

            List<Account> matches =
                [SELECT Id, Name, Industry, AnnualRevenue
                 FROM Account
                 WHERE Name LIKE :searchName
                 WITH SECURITY_ENFORCED
                 LIMIT 1];

            if (!matches.isEmpty()) {
                Account acc = matches[0];
                out.found     = true;
                out.accountId = acc.Id;
                out.summary   = acc.Name
                    + ' (' + (acc.Industry ?? 'Unknown industry') + ')'
                    + ' — Revenue: $'
                    + (acc.AnnualRevenue != null
                        ? acc.AnnualRevenue.format() : 'N/A');
            } else {
                out.found   = false;
                out.summary = 'No account found matching: ' + inp.accountName;
            }

            results.add(out);
        }
        return results;
    }
}

Creating Records via Agent Action

Allow an agent to create a Case on behalf of a user — with full validation.

  • Agents can trigger write operations via Apex
  • Always use with sharing — respect user permissions
  • Return meaningful output for agent to confirm
  • Include error details in output for graceful handling
  • required=true on mandatory inputs
  • Describe parameters precisely — AI reads them
public with sharing class CreateCaseAction {

    public class Input {
        @InvocableVariable(label='Subject' required=true
            description='Brief description of the issue')
        public String subject;

        @InvocableVariable(label='Description'
            description='Detailed description of the problem')
        public String description;

        @InvocableVariable(label='Priority'
            description='Case priority: Low, Medium, or High')
        public String priority;

        @InvocableVariable(label='Contact Id'
            description='Salesforce Id of the contact raising the case')
        public String contactId;
    }

    public class Output {
        @InvocableVariable(label='Case Number')
        public String caseNumber;

        @InvocableVariable(label='Case Id')
        public String caseId;

        @InvocableVariable(label='Success')
        public Boolean success;

        @InvocableVariable(label='Error Message')
        public String errorMessage;
    }

    @InvocableMethod(
        label='Create Support Case'
        description='Creates a new support case in Salesforce for the customer. Use when the user reports a problem and wants to open a support ticket.')
    public static List<Output> createCase(List<Input> inputs) {
        List<Output> results = new List<Output>();

        for (Input inp : inputs) {
            Output out = new Output();
            try {
                Case c = new Case(
                    Subject     = inp.subject,
                    Description = inp.description,
                    Priority    = inp.priority ?? 'Medium',
                    Status      = 'New',
                    Origin      = 'Chat',
                    ContactId   = inp.contactId
                );
                insert c;

                // Re-query to get the auto-generated CaseNumber
                c = [SELECT CaseNumber FROM Case WHERE Id = :c.Id];
                out.success    = true;
                out.caseId     = c.Id;
                out.caseNumber = c.CaseNumber;
            } catch (DmlException e) {
                out.success      = false;
                out.errorMessage = e.getDmlMessage(0);
            }
            results.add(out);
        }
        return results;
    }
}

Search Action — Semantic Lookup

A multi-object search action that surfaces the most relevant records for a natural language query.

  • Combine SOSL for full-text search
  • Return ranked / summarised results
  • Limit to a handful of top results
  • Include object type in output for agent context
  • Always security-enforce results
  • Use callout=true if calling Einstein Search API
public with sharing class KnowledgeSearchAction {

    public class Input {
        @InvocableVariable(label='Search Query' required=true
            description='Natural language search query from the user')
        public String query;

        @InvocableVariable(label='Max Results'
            description='Maximum number of results to return (default 5)')
        public Integer maxResults;
    }

    public class SearchResult {
        @InvocableVariable(label='Title')
        public String title;

        @InvocableVariable(label='Summary')
        public String summary;

        @InvocableVariable(label='Record Id')
        public String recordId;

        @InvocableVariable(label='Object Type')
        public String objectType;
    }

    public class Output {
        @InvocableVariable(label='Results')
        public List<SearchResult> results;

        @InvocableVariable(label='Total Found')
        public Integer totalFound;
    }

    @InvocableMethod(
        label='Search Knowledge Base'
        description='Searches Salesforce Knowledge articles and FAQ records for information relevant to the user\'s question. Use when the user asks a question that may be answered in our documentation.')
    public static List<Output> search(List<Input> inputs) {
        List<Output> outputs = new List<Output>();

        for (Input inp : inputs) {
            Integer limit = inp.maxResults ?? 5;
            Output out = new Output();
            out.results = new List<SearchResult>();

            // SOSL full-text search across Knowledge
            String searchTerm = inp.query;
            List<List<SObject>> sosl = [
                FIND :searchTerm
                IN ALL FIELDS
                RETURNING
                    Knowledge__kav(Id, Title, Summary
                        WHERE PublishStatus = 'Online'
                        LIMIT :limit)
                LIMIT :limit
            ];

            List<Knowledge__kav> articles =
                (List<Knowledge__kav>) sosl[0];

            for (Knowledge__kav art : articles) {
                SearchResult r = new SearchResult();
                r.title      = art.Title;
                r.summary    = art.Summary;
                r.recordId   = art.Id;
                r.objectType = 'Knowledge Article';
                out.results.add(r);
            }

            out.totalFound = out.results.size();
            outputs.add(out);
        }
        return outputs;
    }
}

Analytics Action — Data Summaries

Give agents access to aggregated business data without exposing raw records.

  • Use aggregate SOQL to summarise at query level
  • Return human-readable formatted strings
  • Agents embed the summary in natural language responses
  • Keep results concise — agents have token limits
  • Include comparison context (vs. last month)
  • Always apply with sharing
public with sharing class SalesSummaryAction {

    public class Input {
        @InvocableVariable(label='Period'
            description='Time period: THIS_QUARTER, THIS_YEAR, THIS_MONTH')
        public String period;

        @InvocableVariable(label='Owner Id'
            description='Filter by a specific sales rep (optional)')
        public String ownerId;
    }

    public class Output {
        @InvocableVariable(label='Summary Text')
        public String summaryText;

        @InvocableVariable(label='Total Revenue')
        public Decimal totalRevenue;

        @InvocableVariable(label='Deal Count')
        public Integer dealCount;

        @InvocableVariable(label='Win Rate')
        public Decimal winRate;
    }

    @InvocableMethod(
        label='Get Sales Summary'
        description='Returns a sales performance summary including total revenue, number of deals closed, and win rate for a given time period. Use when the user asks about sales performance, pipeline, or revenue.')
    public static List<Output> getSalesSummary(List<Input> inputs) {
        List<Output> results = new List<Output>();

        for (Input inp : inputs) {
            String period = inp.period ?? 'THIS_QUARTER';
            Output out = new Output();

            // Closed won
            String wonQuery =
                'SELECT COUNT(Id) cnt, SUM(Amount) total ' +
                'FROM Opportunity ' +
                'WHERE StageName = \'Closed Won\' ' +
                'AND CloseDate = ' + period;

            if (!String.isBlank(inp.ownerId)) {
                wonQuery += ' AND OwnerId = \'' +
                    String.escapeSingleQuotes(inp.ownerId) + '\'';
            }

            AggregateResult wonAR =
                Database.query(wonQuery)[0];
            out.dealCount    = (Integer) wonAR.get('cnt');
            out.totalRevenue = (Decimal) wonAR.get('total') ?? 0;

            // Total pipeline (won + lost)
            Integer totalDeals = [
                SELECT COUNT() FROM Opportunity
                WHERE IsClosed = true
                AND CloseDate = THIS_QUARTER
            ];
            out.winRate = totalDeals > 0
                ? (out.dealCount * 100.0 / totalDeals).setScale(1)
                : 0;

            out.summaryText =
                period + ' Sales: ' + out.dealCount +
                ' deals closed, $' + out.totalRevenue.format() +
                ' revenue, ' + out.winRate + '% win rate.';

            results.add(out);
        }
        return results;
    }
}

@InvocableVariable — AI-Readable Parameters

The description on each @InvocableVariable is not just documentation — the LLM reads it to understand what value to pass. Write descriptions as if instructing a smart human assistant.

Best Practices for @InvocableVariable descriptions

// ❌ BAD — vague descriptions the AI cannot act on
public class Input {
    @InvocableVariable(label='Id' description='The Id')
    public String id;

    @InvocableVariable(label='Date' description='A date')
    public Date startDate;
}

// ✅ GOOD — precise, instructional descriptions
public class Input {
    @InvocableVariable(
        label='Account Id'
        description='The 18-character Salesforce Id of the Account record. Use the Account Id from a previous lookup action or from the conversation context.'
        required=true)
    public String accountId;

    @InvocableVariable(
        label='Report Start Date'
        description='The start date for the report period in YYYY-MM-DD format. Defaults to the first day of the current month if not specified.'
        required=false)
    public Date startDate;

    @InvocableVariable(
        label='Include Inactive'
        description='Set to true to include inactive records in the results. Default is false (active records only).'
        required=false)
    public Boolean includeInactive;
}
AI reads your descriptions: The Agentforce LLM uses label, description, and the method-level description to decide when and how to call your action. Treat them as a contract between your code and the AI, not just comments.

Custom Agent Tools & Action Topics

In Agentforce, actions are grouped into Topics. A Topic is a domain (e.g., "Customer Support") that groups related actions an agent can use. Apex actions are surfaced through the Agent Builder UI.

Wiring Apex to an Agentforce Topic

  1. Write an Apex class with one or more @InvocableMethod methods
  2. In Setup → Agents → Agent Actions, create a new action backed by your Apex method
  3. In Agent Builder, add the action to a Topic
  4. Configure the action's instructions — what the agent should do when it calls this action
  5. Test in the Agent Builder preview pane
  6. Deploy the agent to your org

Calling Einstein AI from Apex

Apex can call the Einstein AI Platform API for completions, classification, and embeddings directly.

  • Use ConnectApi.EinsteinAI classes
  • Or call the /einstein/ai REST API via Named Credential
  • Generate text with LLMs from Apex
  • Classify records using Einstein intent models
  • Generate embeddings for semantic search
  • Always mock in tests — real AI calls are expensive
// Calling Einstein Platform API for text generation
@future(callout=true)
public static void generateCaseSummary(Id caseId) {
    Case c = [SELECT Id, Subject, Description, Status
              FROM Case WHERE Id = :caseId];

    // Build the prompt
    String prompt = 'Summarise the following support case in 2 sentences '
        + 'for a manager dashboard:\n\n'
        + 'Subject: ' + c.Subject + '\n'
        + 'Description: ' + c.Description;

    // Call Einstein AI Platform REST API
    HttpRequest req = new HttpRequest();
    req.setEndpoint('callout:EinsteinAI/v1.0/generations');
    req.setMethod('POST');
    req.setHeader('Content-Type', 'application/json');

    Map<String, Object> body = new Map<String, Object>{
        'prompt' => prompt,
        'maxTokens' => 150,
        'model' => 'sfdc_ai__DefaultGPT4Omni'
    };
    req.setBody(JSON.serialize(body));

    Http http = new Http();
    HttpResponse res = http.send(req);

    if (res.getStatusCode() == 200) {
        Map<String, Object> resp =
            (Map<String, Object>) JSON.deserializeUntyped(res.getBody());
        List<Object> generations = (List<Object>) resp.get('generations');
        Map<String, Object> gen = (Map<String, Object>) generations[0];
        String summary = (String) gen.get('text');

        // Store summary back on the case
        c.AI_Summary__c = summary.trim();
        update c;
    }
}

Prompt Templates + Apex Merge Fields

Prompt Templates can include Apex data via merge fields, injecting live CRM context into AI prompts.

  • Prompt Templates defined in Setup → Einstein → Prompts
  • Apex data exposed via @InvocableMethod actions
  • Or accessed through SOQL merge fields

Testing Apex Agent Actions

Apex agent actions are just @InvocableMethod methods — they are unit-testable with the same patterns as any other Apex. The LLM orchestration layer is outside Apex and tested in the Agent Builder.

Unit-Testing an @InvocableMethod

@IsTest
private class AccountLookupActionTest {

    @TestSetup
    static void makeData() {
        insert new Account(
            Name     = 'ACME Corp',
            Industry = 'Technology',
            AnnualRevenue = 5000000
        );
    }

    @IsTest
    static void testLookup_found() {
        AccountLookupAction.Input inp = new AccountLookupAction.Input();
        inp.accountName = 'ACME';

        Test.startTest();
        List<AccountLookupAction.Output> results =
            AccountLookupAction.lookupAccount(
                new List<AccountLookupAction.Input>{inp});
        Test.stopTest();

        System.assertEquals(1, results.size(),
            'Should return one output');
        System.assertEquals(true, results[0].found,
            'Account should be found');
        System.assert(results[0].summary.contains('ACME'),
            'Summary should mention account name');
        System.assertNotEquals(null, results[0].accountId,
            'Account Id should be populated');
    }

    @IsTest
    static void testLookup_notFound() {
        AccountLookupAction.Input inp = new AccountLookupAction.Input();
        inp.accountName = 'NonExistentCompany12345';

        Test.startTest();
        List<AccountLookupAction.Output> results =
            AccountLookupAction.lookupAccount(
                new List<AccountLookupAction.Input>{inp});
        Test.stopTest();

        System.assertEquals(false, results[0].found,
            'Account should not be found');
        System.assert(results[0].summary.contains('No account found'),
            'Summary should indicate not found');
    }
}

Best Practices for Apex + Agentforce

Write Descriptions for the AI, Not Humans

The LLM reads your @InvocableMethod and @InvocableVariable descriptions to decide when and how to call your action. Be precise and instructional.

❌ description='The account' // AI cannot act on this
✅ description='The exact name of the Account to look up. Case-insensitive partial match is supported.'

Always Use with sharing in Agent Actions

Agents act on behalf of users. Using without sharing would let an agent access records the user is not permitted to see.

❌ public class LookupAction { } // unknown sharing
✅ public with sharing class LookupAction { }

Return Structured, Concise Output

Agents incorporate your output into their responses. Return the minimum information needed — tokens are expensive and agents can hallucinate when given too much data.

❌ return full Account sObject with 50 fields
✅ return summary string + Id + 2-3 key fields only

Include Error Information in Output

Agents cannot catch exceptions. Return a success Boolean and errorMessage String so the agent can gracefully tell the user what went wrong.

❌ Unhandled exception → agent crashes with generic error
✅ out.success = false; out.errorMessage = e.getMessage();

Test All Input Combinations

Agents can call your action with unexpected inputs. Test null required fields, edge-case strings, empty lists, and very long inputs.

❌ Test only the golden path with valid data
✅ Also test: null input, blank string, very long string, wrong format

Apply WITH SECURITY_ENFORCED

Agent actions are invoked with the context of the running user. Enforce FLS to prevent data leakage to agents acting on behalf of lower-privileged users.

❌ [SELECT SSN__c FROM Contact] // FLS bypassed
✅ [SELECT SSN__c FROM Contact WITH SECURITY_ENFORCED]
