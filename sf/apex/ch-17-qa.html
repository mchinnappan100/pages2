Which fields are automatically indexed by Salesforce? (Select the best answer)
✓ Correct: B

Salesforce auto-indexes: Id, Name, CreatedDate, LastModifiedDate, OwnerId, RecordTypeId (system fields), External ID fields (custom fields marked as External ID), and Unique fields. Regular custom text fields are NOT indexed unless you mark them External ID/Unique or request a custom index via Support.

2
A query has a Query Plan cost of 0.98. What does this indicate?
✓ Correct: C

Cost >= 1 means Salesforce will perform a full TABLE_SCAN — scanning every row in the object. This is slow on large objects (100k+ rows) and will degrade as data grows. Rewrite to use indexed fields in WHERE, or use SOSL for text searches.

3
Why does WHERE Status != 'Active' always cause a TABLE_SCAN even if Status is indexed?
✓ Correct: B

Negation operators (!=, NOT IN, NOT LIKE, EXCLUDES) always force a TABLE_SCAN regardless of indexing, because the index structure cannot efficiently answer 'give me everything except X'. Rewrite as positive conditions where possible: WHERE Status IN ('Inactive', 'Pending').

4
What is the Salesforce selectivity threshold for standard objects — below what percentage of rows must a query return to use an index?
✓ Correct: C

For standard objects, Salesforce uses an index if the query returns fewer than approximately 30% of table rows. For custom objects the threshold is ~10%. Even indexed fields can trigger TABLE_SCAN if too many rows match — this is 'low selectivity'. Combine conditions with AND to reduce the matched row count.

5
You need to paginate through 500,000 Accounts efficiently. Which approach is correct?
✓ Correct: B

Keyset pagination using WHERE Id > :lastSeenId ORDER BY Id LIMIT 200 is O(1) per page — it uses the indexed Id field to find the next page instantly. OFFSET scans all prior rows (up to OFFSET 2,000 max). For 500,000 records use keyset or Batch Apex with a QueryLocator.

6
What is the primary advantage of Batch Apex's QueryLocator over a List query in start()?
✓ Correct: B

Database.getQueryLocator() returns a cursor — no rows loaded into heap. Salesforce delivers them to execute() in chunks. It supports up to 50 million rows. A List query in start() is limited to 50,000 rows (the standard SOQL row limit) and loads them all into heap.

7
A SOQL for-loop for (Account a : [SELECT Id FROM Account]) processes records in how many rows per batch?
✓ Correct: C

The SOQL for-loop delivers records in chunks of 200 rows per internal batch. Each batch is processed and the previous batch is eligible for garbage collection before the next arrives — keeping heap usage constant regardless of the total result size.

8
Which type of WHERE condition on an indexed field still causes a TABLE_SCAN due to selectivity?
✓ Correct: C

Even with an indexed field, if the query matches too many rows (>30% for standard objects), Salesforce determines that a table scan is cheaper than using the index and switches to TABLE_SCAN. 80,000/200,000 = 40% — above the threshold. Combine with more selective conditions to reduce the matched count.

9
What is the maximum OFFSET value allowed in SOQL?
✓ Correct: C

The maximum OFFSET is 2,000. Attempting a higher value causes a compile-time error. Even within this limit, each page requires scanning all prior rows — page 10 of 200 scans 2,000 rows just to skip them. Use keyset pagination for production paginated data.

10
Which SOQL query most efficiently counts all active Accounts without loading them into heap?
✓ Correct: B

SELECT COUNT() FROM Account WHERE ... counts at the database level and returns a plain Integer — zero records loaded into heap. Option A loads up to 50,000 Ids just to call .size(). Option D works but returns AggregateResult[] which is more verbose than needed.
