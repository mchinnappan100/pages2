Which keyword combination must a class use to allow it to be subclassed in Apex?
✓ Correct: C

By default, Apex classes are sealed — they cannot be extended. To allow inheritance, the base class must be declared virtual (can be instantiated, methods optionally overridable) or abstract (cannot be instantiated, may have abstract methods that subclasses must implement). This is unlike Java, where all classes are extendable unless marked final.

2
What is the key difference between an abstract class and an interface in Apex?
✓ Correct: B

An abstract class can contain concrete method implementations, instance variables, and constructor logic alongside abstract method declarations. An interface contains only method signatures (no bodies, no instance variables). A class can extend only one abstract class (single inheritance) but implement multiple interfaces. Abstract classes are best for "is-a" relationships with shared code; interfaces are best for "can-do" contracts.

3
A subclass constructor must call super(args). Where must this call appear?
✓ Correct: B

super(args) must be the first statement in the subclass constructor. This ensures the parent class is fully initialised before any subclass code runs. If the parent has a no-arg constructor, the call is optional (Apex inserts it implicitly), but if the parent only has parameterised constructors, the subclass must call super(args) explicitly.

4
Which access modifier makes a method or variable accessible to subclasses but NOT to external code?
✓ Correct: B — protected

protected members are accessible within the class itself AND within any subclass, but not from unrelated classes. It is specifically for the inheritance hierarchy. private is restricted to the declaring class only; public is accessible anywhere in the same namespace; global is accessible across namespaces.

5
A class implements Comparable. What method must it implement, and what values must it return?
✓ Correct: B

The Comparable interface requires implementing compareTo(Object other). The convention: return negative if this < other, 0 if equal, positive if this > other. Once implemented, call list.sort() and Apex invokes compareTo internally to sort the elements.

6
How many classes can an Apex class extend simultaneously?
✓ Correct: A

Apex supports single inheritance — a class can extend only one parent class. However, a class can implement multiple interfaces. This design avoids the diamond inheritance problem. The solution when you need multiple behaviours is to combine one parent class (via extends) with multiple interface contracts (via implements).

7
What is the primary reason to use a wrapper class as the return type of an @AuraEnabled method instead of a raw sObject?
✓ Correct: C

Wrapper classes let you augment sObject data with computed fields (e.g., isHighValue, statusLabel, formattedDate) that don't exist on the object itself. The LWC receives a flat, JSON-serialisable object. Raw sObjects can technically be returned, but you lose the ability to add derived data or hide sensitive fields.

8
Static variables in Apex persist for how long?
✓ Correct: C

Static variables persist for the lifetime of the current execution context (transaction). They are reset at the start of every new transaction. This is widely used for the recursion-prevention pattern: if (MyTriggerHelper.hasRun) return; — the static flag is set once per transaction and prevents the trigger from firing again. They are NOT persistent across transactions (use Custom Settings or Platform Cache for that).

9
Which Salesforce system interface must a class implement to enable Batch Apex?
✓ Correct: C

Database.Batchable<SObject> is the interface for Batch Apex. It requires implementing three methods: start() (returns a QueryLocator), execute() (processes each chunk), and finish() (called once after all chunks). Database.Stateful is an additional marker interface that preserves instance variables between execute() calls.

10
Why is coding to an interface (e.g., IEmailSender sender) preferred over coding to a concrete class (e.g., SalesforceEmailSender sender)?
✓ Correct: B

When a class depends on an interface type, any class that implements that interface can be injected — including test mocks. This is the core of dependency injection and makes unit tests possible for code that sends emails, makes callouts, or performs complex DML. Without interfaces, you'd have to use Test.isRunningTest() branching everywhere — a much worse pattern.
