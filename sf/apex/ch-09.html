What Is the Apex ANTLR Grammar?

The Apex ANTLR4 grammar (apex.g4) is a formal specification of the Apex language. It derives from the Java 1.7 grammar and extends it with Salesforce-specific constructs.

Why the Grammar Matters

ANTLR (ANother Tool for Language Recognition) generates parsers from grammar files. The Apex grammar is used by:

  • IDEs and extensions — VS Code, IntelliJ, and Illuminated Cloud parse Apex using this grammar for syntax highlighting and error detection
  • Static analysis tools — PMD Apex plugin, Checkmarx, and Salesforce Code Analyzer use it to build Abstract Syntax Trees (ASTs) for rule-based analysis
  • Code migration tooling — platforms that upgrade Apex (e.g., API version migrations) traverse the AST to detect and transform patterns
  • Custom linters — developers write ANTLR visitors/listeners to enforce org-specific coding standards
  • Language servers — the Apex Language Server (used in SFDX CLI) parses code in real-time using the grammar

Grammar File Header

grammar apex;

// Entry point — every Apex compilation unit starts here
compilationUnit
    : typeDeclaration* EOF
    ;

// A type declaration is a class, interface, or enum
typeDeclaration
    : classOrInterfaceModifier*
      ( classDeclaration
      | enumDeclaration
      | interfaceDeclaration
      | annotationTypeDeclaration
      )
    | SEMI  // empty statement
    ;

Key Parser Rules

Parser rules (lowercase) define the hierarchical structure of Apex code — how tokens combine into meaningful language constructs.

🏛️

Class & Type Declarations

Rules that define how Apex classes, interfaces, and enums are structured in the grammar.

  • classDeclaration
  • classBody
  • classBodyDeclaration
  • memberDeclaration
  • interfaceDeclaration
  • enumDeclaration
// Class declaration — Apex-specific modifiers included
classDeclaration
    : CLASS Identifier
      ( EXTENDS type )?
      ( IMPLEMENTS typeList )?
      classBody
    ;

// Apex-specific modifiers on top of standard Java modifiers
classOrInterfaceModifier
    : annotation
    | PUBLIC
    | PROTECTED
    | PRIVATE
    | STATIC
    | ABSTRACT
    | FINAL
    | GLOBAL        // Apex: accessible across namespaces
    | WEBSERVICE    // Apex: exposes as web service
    | APEX_WITH_SHARING     // with sharing
    | APEX_WITHOUT_SHARING  // without sharing
    | VIRTUAL       // Apex: can be extended
    | OVERRIDE      // Apex: overrides parent method
    | TESTMETHOD    // Apex: marks as test method
    ;

// Class body — members wrapped in braces
classBody
    : LBRACE classBodyDeclaration* RBRACE
    ;

// Example Apex class this grammar accepts:
// public with sharing class AccountService extends BaseService
//     implements IService {
//     ...
// }

Method & Field Declarations

How methods, constructors, and fields are parsed — including Apex property syntax.

  • methodDeclaration
  • constructorDeclaration
  • fieldDeclaration
  • propertyDeclaration
  • getter / setter
  • formalParameters
// Method declaration
methodDeclaration
    : ( type | VOID ) Identifier formalParameters
      ( LBRACKET RBRACKET )*
      ( THROWS qualifiedNameList )?
      (  methodBody | SEMI )
    ;

// Formal parameter list
formalParameters
    : LPAREN formalParameterList? RPAREN
    ;

formalParameterList
    : formalParameter ( COMMA formalParameter )*
      ( COMMA lastFormalParameter )?
    | lastFormalParameter
    ;

formalParameter
    : variableModifier* type variableDeclaratorId
    ;

// Apex property with get/set accessors
propertyDeclaration
    : type variableDeclarators
      LBRACE getter? setter? RBRACE
    ;

getter
    : classOrInterfaceModifier? GET ( SEMI | block )
    ;

setter
    : classOrInterfaceModifier? SET ( SEMI | block )
    ;

// Constructor
constructorDeclaration
    : Identifier formalParameters
      ( THROWS qualifiedNameList )?
      constructorBody
    ;

Statements & Blocks

All statement forms — including Apex-specific DML and RUNAS statements.

  • statement
  • apexDbExpression
  • runAsStatement
  • forStatement
  • enhancedForControl
  • tryStatement
// Statement — all forms
statement
    : block
    | ASSERT expression ( COLON expression )? SEMI
    | IF parExpression statement ( ELSE statement )?
    | FOR LPAREN forControl RPAREN statement
    | WHILE parExpression statement
    | DO statement WHILE parExpression SEMI
    | TRY block
      ( catches finallyBlock? | finallyBlock )
    | SWITCH parExpression LBRACE switchBlockStatementGroups RBRACE
    | RETURN expression? SEMI
    | THROW expression SEMI
    | BREAK Identifier? SEMI
    | CONTINUE Identifier? SEMI
    | SEMI
    | statementExpression SEMI
    | apexDbExpression SEMI       // Apex DML
    | runAsStatement              // System.runAs()
    ;

// Apex DML — insert, update, delete, etc.
apexDbExpression
    : ( DB_INSERT | DB_UPDATE | DB_UPSERT
      | DB_DELETE | DB_UNDELETE )
      expression
    ;

// System.runAs — test-only statement
runAsStatement
    : RUNAS LPAREN expression RPAREN block
    ;

// Enhanced for (for-each)
enhancedForControl
    : variableModifier* type variableDeclaratorId
      COLON expression
    ;

Expressions

Left-recursive expression rules — how operators, method calls, casts, and SOQL literals are parsed.

  • expression
  • primary
  • SoqlLiteral
  • creator
  • arguments
  • mapCreator
// Expression — left-recursive in ANTLR4
expression
    : primary                                           // literal, identifier
    | expression DOT Identifier                         // field access
    | expression DOT Identifier arguments               // method call
    | expression LBRACKET expression RBRACKET           // array index
    | expression ( INC | DEC )                         // post increment/decrement
    | ( ADD | SUB | INC | DEC ) expression              // unary
    | ( TILDE | BANG ) expression                      // bitwise NOT, logical NOT
    | expression ( MUL | DIV | MOD ) expression        // multiplicative
    | expression ( ADD | SUB ) expression              // additive
    | expression ( LSHIFT | RSHIFT | URSHIFT ) expression // shift
    | expression
      ( LT LT | GT GT GT | GT GT
      | LE | GE | INSTANCEOF ) expression              // relational
    | expression ( EQUAL | NOTEQUAL | LTGT ) expression // equality; LTGT = <>
    | expression BITAND expression
    | expression CARET expression
    | expression BITOR expression
    | expression AND expression                         // &&
    | expression OR expression                          // ||
    | expression QUESTION expression COLON expression  // ternary
    | expression
      ( ASSIGN | ADD_ASSIGN | SUB_ASSIGN | MUL_ASSIGN
      | DIV_ASSIGN | AND_ASSIGN | OR_ASSIGN | XOR_ASSIGN
      | RSHIFT_ASSIGN | URSHIFT_ASSIGN | LSHIFT_ASSIGN
      | MOD_ASSIGN ) expression                        // assignment
    | LPAREN type RPAREN expression                    // cast
    | NEW creator                                       // object creation
    | SoqlLiteral                                       // [SELECT ...] inline query
    ;

// SOQL literal — the inline query syntax
SoqlLiteral
    : LBRACKET WS* SELECT ( ~[[\]]+ )* RBRACKET
    ;

// Primary atoms
primary
    : LPAREN expression RPAREN
    | THIS
    | SUPER
    | literal
    | Identifier
    | type DOT CLASS
    | VOID DOT CLASS
    | nonWildcardTypeArguments ( explicitGenericInvocationSuffix | THIS arguments )
    ;

SOQL & DML in the Grammar

Apex-specific grammar extensions that make SOQL queries and DML first-class language constructs.

  • SOQL wrapped in [ ] as SoqlLiteral
  • DML keywords: DB_INSERT, DB_UPDATE
  • DB_UPSERT, DB_DELETE, DB_UNDELETE
  • DML part of apexDbExpression
  • Separated from Java — Java has no DML
  • Enables static analysis of data operations
// SOQL literal — scanned as a single token
// Everything between [ ] starting with SELECT is a SOQL query
SoqlLiteral
    : LBRACKET WS*
      [sS][eE][lL][eE][cC][tT]
      ( ~[\[\]] )*  // any characters except brackets
      RBRACKET
    ;
// This means [SELECT Id FROM Account WHERE Name = :name]
// is ONE token in the grammar, not parsed character by character.
// The SOQL itself has its own sub-grammar not covered here.

// DML statement tokens — case-insensitive
DB_INSERT   : [iI][nN][sS][eE][rR][tT] ;
DB_UPDATE   : [uU][pP][dD][aA][tT][eE] ;
DB_DELETE   : [dD][eE][lL][eE][tT][eE] ;
DB_UNDELETE : [uU][nN][dD][eE][lL][eE][tT][eE] ;
DB_UPSERT   : [uU][pP][sS][eE][rR][tT] ;

// apexDbExpression — appears as a statement
apexDbExpression
    : ( DB_INSERT | DB_UPDATE | DB_UPSERT
      | DB_DELETE | DB_UNDELETE )
      expression   // the record or list of records
    ;

// Example Apex parsed by this rule:
// insert new Account(Name = 'ACME');
// delete [SELECT Id FROM Contact WHERE Email = :email];
// upsert accounts ExternalId__c;

Collection & Map Literals

Grammar rules for creating Lists, Sets, Maps, and the Apex-specific => map entry syntax.

  • creator
  • createdName
  • arrayCreatorRest
  • classCreatorRest
  • mapCreator
  • LAMBDA_LIKE (=>)
// Object/array creator
creator
    : nonWildcardTypeArguments createdName classCreatorRest
    | createdName
      ( arrayCreatorRest
      | classCreatorRest
      | mapCreatorRest       // Apex-specific: new Map{k1 => v1}
      | setCreatorRest       // Apex-specific: new Set{v1, v2}
      )
    ;

// Array/list initialiser
arrayCreatorRest
    : LBRACKET
      ( RBRACKET ( LBRACKET RBRACKET )* arrayInitializer
      | expression RBRACKET ( LBRACKET expression RBRACKET )*
                             ( LBRACKET RBRACKET )* )
    ;

// Map literal: new Map{'a' => 1, 'b' => 2}
mapCreatorRest
    : LBRACE
        ( mapCreatorRestPair ( COMMA mapCreatorRestPair )* )?
      RBRACE
    ;

mapCreatorRestPair
    : expression LAMBDA_LIKE expression   // key => value
    ;

// LAMBDA_LIKE token: the => operator (map entry, not lambda)
LAMBDA_LIKE : '=>' ;

// Set literal: new Set{'a', 'b', 'c'}
setCreatorRest
    : LBRACE ( expression ( COMMA expression )* )? RBRACE
    ;

// List literal: new List{1, 2, 3}
// uses standard arrayInitializer
arrayInitializer
    : LBRACE
        ( variableInitializer ( COMMA variableInitializer )* COMMA? )?
      RBRACE
    ;
03

Key Lexer Rules

Lexer rules (UPPERCASE) define how raw characters are turned into tokens. Apex's grammar is fully case-insensitive — a unique characteristic implemented through fragment rules.

Case-Insensitive Keywords
Every keyword is defined using fragment characters [aA], [bB] etc. to allow mixed case.
PUBLIC : [pP][uU][bB][lL][iI][cC];
APEX_WITH_SHARING
Two-word keyword matching with sharing (space-sensitive).
WITH ' '+ SHARING → APEX_WITH_SHARING
RUNAS
Matches System.runAs as a single token in the grammar.
SYSTEM '.' RUNAS → RUNAS token
StringLiteral
Single-quoted strings. The QUOTE token is skipped; strings use a synthetic token.
'\'' ~['\r\n]* '\''
Identifier
Standard Java identifier rules — letters, digits, underscore. Unicode supported.
JavaLetter JavaLetterOrDigit*
IntegerLiteral
Decimal, hex (0x), octal (0 prefix), binary (0b) forms.
DecimalIntegerLiteral | HexLiteral
WS (Whitespace)
Space, tab, newline — all skipped. Apex code can use any indentation.
[ \t\r\n ]+ -> skip
LINE_COMMENT
Single-line // comments — skipped by the lexer.
'//' ~[\r\n]* -> skip
BLOCK_COMMENT
Multi-line /* ... */ comments — skipped. Includes ApexDoc /** ... */.
'/*' .*? '*/' -> skip

Using the Grammar — Tooling

With the apex.g4 grammar you can generate a parser in Java, Python, JavaScript, or any ANTLR4-supported language.

Getting Started with ANTLR4 + apex.g4

# 1. Download ANTLR4 tool
curl -O https://www.antlr.org/download/antlr-4.13.1-complete.jar

# 2. Download apex.g4
curl -O https://raw.githubusercontent.com/mohan-chinnappan-n/grammars-v4/\
  cc5970e082e9ea07e11b1cd951be3268e279bf24/apex/apex.g4

# 3. Generate Java parser from grammar
java -jar antlr-4.13.1-complete.jar -Dlanguage=Java apex.g4

# Generated files:
#   apexLexer.java
#   apexParser.java
#   apexListener.java  (walker pattern)
#   apexVisitor.java   (visitor pattern)

# 4. Compile generated code
javac -cp antlr-4.13.1-complete.jar *.java

# 5. Test with a .cls file using grun (ANTLR TestRig)
java -cp .:antlr-4.13.1-complete.jar org.antlr.v4.gui.TestRig \
  apex compilationUnit -tree MyClass.cls

# 6. Generate Python3 parser instead
java -jar antlr-4.13.1-complete.jar -Dlanguage=Python3 apex.g4

Writing a Visitor to Analyse Apex

// Custom ANTLR visitor that counts DML statements in an Apex file
import org.antlr.v4.runtime.*;
import org.antlr.v4.runtime.tree.*;

public class DmlCounter extends apexBaseVisitor<Integer> {

    @Override
    public Integer visitApexDbExpression(
            apexParser.ApexDbExpressionContext ctx) {
        // Called every time a DML statement is encountered in the AST
        String dmlType = ctx.getStart().getText().toUpperCase();
        System.out.println("Found DML: " + dmlType
            + " at line " + ctx.getStart().getLine());
        return visitChildren(ctx);
    }

    @Override
    protected Integer aggregateResult(Integer aggregate, Integer nextResult) {
        return (aggregate == null ? 0 : aggregate)
             + (nextResult  == null ? 0 : nextResult);
    }
}

// Driver — parse a .cls file and count DML
public class ApexAnalyser {
    public static void main(String[] args) throws Exception {
        CharStream input = CharStreams.fromFileName(args[0]);
        apexLexer  lexer  = new apexLexer(input);
        CommonTokenStream tokens = new CommonTokenStream(lexer);
        apexParser parser = new apexParser(tokens);

        ParseTree tree = parser.compilationUnit();

        DmlCounter counter = new DmlCounter();
        counter.visit(tree);
    }
}

Real-World Use Cases

Static Code Analysis

PMD's Apex plugin uses the grammar to build an AST. Custom PMD rules traverse the AST to detect SOQL in loops, hardcoded Ids, and missing sharing keywords.

✅ pmd check --dir force-app --rulesets apex-bestpractices.xml

IDE Syntax Highlighting

VS Code Apex extensions and IntelliJ plugins use the grammar to tokenise source files, enabling syntax highlighting, autocomplete, and real-time error detection.

✅ apexLexer tokenises .cls files → tokens fed to syntax highlighter

Code Migration & Refactoring

Parse old Apex, traverse the AST, apply transformations (e.g., replace deprecated API patterns), then regenerate source from the modified tree.

✅ parse → find deprecated.method() → replace → emit updated code

Custom Linters

Write ANTLR listeners to enforce org-specific standards: max method length, required sharing keyword, prohibited DML in constructors, mandatory System.assert in tests.

✅ implements apexListener → override enterMethodDeclaration → check length

Dependency Analysis

Parse all Apex classes, extract all new ClassName() and method call expressions, and build a dependency graph to understand impact of changes.

✅ visitCreator() + visitMethodCall() → build class dependency graph

Test Coverage Gap Detection

Parse production classes to enumerate all branches (if, try/catch) and cross-reference with test class method calls to identify untested paths.

✅ visitStatement() → map branches → compare vs test assertions
