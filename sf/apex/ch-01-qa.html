What is the primary reason governor limits exist in Salesforce Apex?
✓ Correct: B

Governor limits exist because Salesforce runs multiple customer orgs on shared hardware. Without limits, a single runaway transaction could degrade performance for thousands of other customers. Every org shares CPU, memory, and database I/O, so Salesforce enforces per-transaction caps to ensure fair resource usage across the platform.

2
How many SOQL queries can be issued in a single synchronous Apex transaction?
✓ Correct: B — 100

The synchronous SOQL query limit is 100 per transaction. Asynchronous contexts (Batch, Queueable, Future) allow 200. The most common way to hit this limit is placing SOQL queries inside for-loops. The fix is to query once outside the loop and use a Map for lookups.

// Anti-pattern — can hit 101 limit with 101 records
for (Opportunity o : Trigger.new) {
    Account a = [SELECT Id FROM Account WHERE Id = :o.AccountId]; // ❌
}

// Correct pattern — 1 SOQL regardless of record count
Map<Id, Account> accts = new Map<Id, Account>([SELECT Id FROM Account WHERE Id IN :acctIds]); // ✅

Which access modifier should you always use by default when declaring an Apex class, unless you have an explicit reason not to?
✓ Correct: C

with sharing enforces the running user's record-level sharing rules — organization-wide defaults, role hierarchy, sharing rules, and manual shares. Omitting it (or using without sharing) is a security risk because it can inadvertently expose records the user doesn't have permission to see. global is reserved for managed package code that must be accessible from outside the package namespace.

What does this code print to the debug log?

Integer qty = 5;
Decimal price = 19.99;
System.debug(qty * price);
✓ Correct: C — 99.95

Apex automatically widens the Integer to Decimal during arithmetic. The result is 99.95. Decimal preserves all significant digits, making it the right choice for financial calculations. Using Double could introduce floating-point rounding errors (e.g., 99.94999...).

5
Which collection type should you use to eliminate duplicate Salesforce record Ids before using them in a SOQL WHERE Id IN :collection clause?
✓ Correct: B

A Set<Id> automatically de-duplicates values by definition — it never stores the same element twice. This is the standard pattern for collecting Ids from trigger records before a single bulk SOQL query:

Set<Id> acctIds = new Set<Id>();
for (Contact c : Trigger.new) {
    acctIds.add(c.AccountId); // duplicates silently ignored
}
List<Account> accts = [SELECT Id FROM Account WHERE Id IN :acctIds];

You need to process 2 million records with Apex. A standard synchronous transaction will hit governor limits. Which Apex feature is designed specifically for this use case?
✓ Correct: C

Batch Apex implements the Database.Batchable<SObject> interface and processes records in chunks (default 200, max 2,000). Each chunk executes in its own transaction with a fresh set of governor limits. This allows processing millions of records that would otherwise exceed the 50,000-row SOQL return limit or 10,000 DML row limit of a single transaction.

global class MassAccountUpdate
    implements Database.Batchable<SObject> {

    global Database.QueryLocator start(Database.BatchableContext bc) {
        return Database.getQueryLocator('SELECT Id FROM Account');
    }
    global void execute(Database.BatchableContext bc, List<Account> scope) {
        // scope = up to 200 records per execution
        for (Account a : scope) { a.Description = 'Processed'; }
        update scope;
    }
    global void finish(Database.BatchableContext bc) { }
}
7
What happens when a LimitException is thrown (e.g., "Too many SOQL queries: 101")?
✓ Correct: B

LimitException is uncatchable. It propagates immediately to the top of the execution stack, rolling back the entire transaction. This is intentional — Salesforce uses it as a hard safety valve. The only correct approach is writing bulkified code that never exceeds limits in the first place. You can monitor usage proactively with the Limits class.

8
What is the correct Apex syntax to expose a static method to a Lightning Web Component?
✓ Correct: B

The @AuraEnabled annotation exposes an Apex method to both Aura and Lightning Web Components. Setting cacheable=true enables client-side caching and allows the method to be called via the @wire decorator in LWC. Methods that perform DML must omit cacheable=true. @RemoteAction is for Visualforce; @InvocableMethod exposes methods to Flow.

9
Which of the following is a key difference between Apex and Java?
✓ Correct: C

Unlike Java, Apex is case-insensitive and ships with built-in DML keywords (insert, update, delete, etc.) and inline SOQL/SOSL syntax. Java uses JDBC and is case-sensitive. Apex has no file system access, no multi-threading (use async patterns instead), and uses sObject types that map directly to Salesforce database tables.

A developer needs to insert 500 records and wants successful rows to commit even if some rows fail, while collecting errors for the failed rows. Which approach should they use?
✓ Correct: C

The Database.insert(records, false) method performs a partial-success DML operation. Passing false as the allOrNone parameter means rows that can be saved will be committed while rows that fail are captured in the Database.SaveResult[] array. Option B (insert one at a time) is an anti-pattern that wastes DML statements and won't scale.

Database.SaveResult[] results = Database.insert(records, false);
for (Database.SaveResult sr : results) {
    if (!sr.isSuccess()) {
        for (Database.Error err : sr.getErrors()) {
            System.debug('Failed: ' + err.getMessage());
        }
    }
}
