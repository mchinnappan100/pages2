Primitive Data Types

Apex's type system is strongly typed and includes several primitives not found in Java. Every variable must be declared with a type; Apex is not dynamically typed.

Integer
32-bit signed integer. Range: −2,147,483,648 to 2,147,483,647.
Integer x = 42;
Long
64-bit signed integer. Use when Integer overflows.
Long big = 10000000000L;
Double
64-bit floating-point. Avoid for money — use Decimal.
Double d = 3.14159;
Decimal
Arbitrary-precision. Required for all financial calculations.
Decimal price = 19.99;
String
Unicode text. Null and empty string are different values.
String s = 'Hello';
Boolean
Three values: true, false, null. Null ≠ false.
Boolean active = true;
Date
Calendar date (no time component).
Date d = Date.today();
Datetime
Date + time, stored as UTC.
Datetime dt = Datetime.now();
Time
Time of day without a date.
Time t = Time.newInstance(9,0,0,0);
Id
Salesforce record ID (15 or 18 chars). Validates format at assignment.
Id recId = acc.Id;
Blob
Binary data. Used for files, attachments, crypto operations.
Blob b = Blob.valueOf('data');
Null awareness: All Apex primitives can hold null. A Boolean that is null is neither true nor false — it is null. Always guard with != null or String.isBlank() before use.
💰

Decimal vs. Double for Money

This is one of the most common bugs in Apex code. Double introduces binary floating-point errors; Decimal does not.

  • Double stores values in base-2 — 0.1 cannot be represented exactly
  • Decimal is base-10 arbitrary precision — safe for all currency
  • Use .setScale(2, RoundingMode.HALF_UP) for display
  • Salesforce Currency fields map to Decimal in Apex
Double d = 0.1 + 0.2;
System.debug(d); // 0.30000000000000004 ❌

Decimal dec = 0.1 + 0.2;
System.debug(dec); // 0.3 ✅

// Financial rounding
Decimal tax = (149.99 * 0.085).setScale(2, RoundingMode.HALF_UP);
System.debug(tax); // 12.75
🆔

The Id Type

Apex's Id type is a validated, case-insensitive wrapper around Salesforce record identifiers.

  • 15-char (case-sensitive) and 18-char (case-insensitive) are equivalent
  • Apex automatically pads 15-char Ids to 18-char when stored as Id type
  • Invalid format causes a runtime exception at assignment
  • Prefix identifies the object type (e.g., 001 = Account)
// Safe: Apex validates the format
Id accId = '0010000000AbCdEAAA'; // valid

// 15-char auto-padded to 18-char
Id shortId = '0010000000AbCdE';

// Determine object type from prefix
String prefix = String.valueOf(accId).substring(0, 3);
Schema.SObjectType objType =
    Schema.getGlobalDescribe().get(
        [SELECT QualifiedApiName FROM EntityDefinition
         WHERE KeyPrefix = :prefix LIMIT 1].QualifiedApiName
    );
📅

Date & Datetime Operations

Apex provides rich factory methods and arithmetic for temporal types.

  • Date.today(), Datetime.now() — current values
  • .addDays(n), .addMonths(n), .addYears(n)
  • .daysBetween(other) — integer day difference
  • Datetime is stored and queried as UTC; format for display with .format()
Date today = Date.today();
Date closeDate = today.addDays(30);
Integer daysLeft = today.daysBetween(closeDate); // 30

// Create specific date
Date q1End = Date.newInstance(2025, 3, 31);
Boolean isPast = q1End < today;

// Datetime formatting
Datetime now = Datetime.now();
String display = now.format('MMM d, yyyy h:mm a');
System.debug(display); // e.g., "Aug 10, 2026 2:30 PM"
📝

String Methods

String is immutable in Apex. The String class provides dozens of utility methods.

  • String.isBlank(s) — null or whitespace-only
  • String.isEmpty(s) — null or empty (not whitespace)
  • .contains(), .startsWith(), .endsWith()
  • .trim(), .toLowerCase(), .substring()
  • .format() — sprintf-style formatting
  • String.valueOf(obj) — safe toString for any type
String email = '  User@Example.COM  ';
String clean = email.trim().toLowerCase();
// 'user@example.com'

Boolean hasAt = clean.contains('@'); // true

// Null-safe blank check (use this, not == null)
String s = null;
System.debug(String.isBlank(s)); // true

// Format
String msg = String.format(
    'Welcome, {0}! You have {1} unread messages.',
    new List<Object>{ 'Alice', 5 }
);
// 'Welcome, Alice! You have 5 unread messages.'
02

Collections: List, Set & Map

Collections are the backbone of bulkified Apex. Mastering when to use each type — and how to combine them — is essential for writing governor-safe code.

📋

List<T>

Ordered, index-accessible, allows duplicates. The most commonly used collection in Apex.

  • 0-indexed: list[0]
  • .add(item), .size(), .isEmpty(), .remove(index)
  • Can be initialized from SOQL inline: new Map<Id,Account>([SOQL])
  • DML accepts List directly — always bulk DML
  • Equivalent to Java's ArrayList
// List literal initialization
List<String> colors = new List<String>{
    'red', 'green', 'blue'
};
colors.add('yellow');
System.debug(colors.size()); // 4
System.debug(colors[0]);     // 'red'

// List of sObjects for bulk DML
List<Contact> toUpdate = new List<Contact>();
for (Contact c : [SELECT Id, Title FROM Contact]) {
    if (c.Title == null) {
        c.Title = 'Associate';
        toUpdate.add(c);
    }
}
if (!toUpdate.isEmpty()) update toUpdate;
🔵

Set<T>

Unordered, no duplicates, O(1) membership testing. The go-to for deduplicating Ids before SOQL queries.

  • .add(item) — silently ignores duplicates
  • .contains(item) — O(1) membership test
  • .remove(item), .size()
  • No index access — iterate with for-each
  • Use in SOQL WHERE Id IN :mySet
Set<Id> accountIds = new Set<Id>();
for (Opportunity opp : Trigger.new) {
    if (opp.AccountId != null) {
        accountIds.add(opp.AccountId);
    }
}
// Query once — no duplicates in the Set
List<Account> accounts =
    [SELECT Id, Name FROM Account WHERE Id IN :accountIds];

// Membership test
Set<String> premium = new Set<String>{'Gold','Platinum','Diamond'};
if (premium.contains(account.SLA__c)) {
    // fast-track support
}
🗺️

Map<K,V>

Key-value pairs with O(1) lookup. The most powerful pattern for avoiding SOQL in loops.

  • .put(key, value), .get(key), .containsKey(key)
  • .keySet() returns a Set of all keys
  • .values() returns a List of all values
  • Initialise from SOQL: new Map<Id, Account>([SOQL])
  • .get() returns null for missing keys — always null-check
// Classic bulkify pattern: one SOQL, Map for instant lookup
Map<Id, Account> accountMap = new Map<Id, Account>(
    [SELECT Id, Name, Rating FROM Account
     WHERE Id IN :accountIds]
);

for (Opportunity opp : Trigger.new) {
    Account acc = accountMap.get(opp.AccountId);
    if (acc != null && acc.Rating == 'Hot') {
        opp.Priority__c = 'High';
    }
}

// Map of Map — grouping opps by stage
Map<String, List<Opportunity>> byStage =
    new Map<String, List<Opportunity>>();
for (Opportunity o : [SELECT Id, StageName FROM Opportunity]) {
    if (!byStage.containsKey(o.StageName)) {
        byStage.put(o.StageName, new List<Opportunity>());
    }
    byStage.get(o.StageName).add(o);
}
🔄

Collection Iteration Patterns

Choosing the right iteration pattern impacts both readability and governor-limit safety.

  • For-each over List/Set — clean, readable, no index needed
  • For-each over Map.entrySet() — iterate key+value together
  • SOQL for-loop — avoids heap overflow on large data sets
  • Traditional for-loop when index access is required
// For-each over List
for (Account a : accountList) {
    System.debug(a.Name);
}

// Iterating Map entries
for (Id key : accountMap.keySet()) {
    Account val = accountMap.get(key);
    System.debug(key + ' → ' + val.Name);
}

// SOQL for-loop (processes 200 records per batch chunk)
// Prevents heap overflow when querying millions of records
for (Lead lead : [SELECT Id, Email FROM Lead
                   WHERE IsConverted = false]) {
    // governor limits measured per 200-record batch
}

// Index-based loop
List<String> items = new List<String>{'a','b','c'};
for (Integer i = 0; i < items.size(); i++) {
    System.debug(i + ': ' + items[i]);
}

Operators & Expressions

Apex operators behave like Java with a few key additions. Understanding null propagation through expressions prevents subtle NullPointerExceptions.

Arithmetic & Assignment

  • + - * / Math.mod(a,b) — standard arithmetic
  • ++ -- — increment/decrement
  • += -= *= /= — compound assignment
  • + on strings is concatenation
  • Integer ÷ Integer = Integer (truncates, not rounds)

Comparison & Logical

  • == != < > <= >= — comparison
  • && || ! — logical AND / OR / NOT
  • == on String is value equality (not reference)
  • Ternary: cond ? a : b
  • Null-coalescing pattern: x != null ? x : default

Type Casting & instanceof

Apex supports explicit casting and safe type testing with instanceof.

// Numeric widening (safe — no cast needed)
Integer i = 10;
Decimal d = i; // auto-widened

// Narrowing cast (explicit — may lose precision)
Double pi = 3.14159;
Integer truncated = (Integer) pi; // 3

// instanceof for safe downcasting
Object obj = 'hello world';
if (obj instanceof String) {
    String s = (String) obj;
    System.debug(s.toUpperCase());
}

// sObject casting
SObject rec = [SELECT Id, Name FROM Account LIMIT 1];
Account acc = (Account) rec;
System.debug(acc.Name);
04

Control Flow

Apex control flow is nearly identical to Java. The one Apex-specific addition is the SOQL for-loop, which is critical for large data volume scenarios.

🔀

if / else if / else

Standard conditional branching. Always use braces, even for single-statement bodies.

  • Conditions must evaluate to Boolean (not truthy/falsy like JS)
  • Null Boolean in condition throws NullPointerException
  • Short-circuit evaluation: && stops on first false
Integer score = 87;
String grade;
if (score >= 90) {
    grade = 'A';
} else if (score >= 80) {
    grade = 'B';
} else if (score >= 70) {
    grade = 'C';
} else {
    grade = 'F';
}

// Null-safe Boolean check
Boolean isActive = acc.IsActive__c;
if (isActive != null && isActive) {
    // safely checked
}
🔁

for Loops — All Three Forms

Apex has three distinct for-loop syntaxes, each serving a different purpose.

  • Traditional: index-based, full control
  • Enhanced for-each: iterate any Iterable/List/Set
  • SOQL for-loop: processes records in heap-safe 200-record chunks
// 1. Traditional for-loop
for (Integer i = 0; i < 10; i++) {
    System.debug('Index: ' + i);
}

// 2. Enhanced for-each
List<String> names = new List<String>{'Alice', 'Bob'};
for (String name : names) {
    System.debug(name);
}

// 3. SOQL for-loop — heap safe for large data
for (Account acc : [SELECT Id, Name FROM Account
                     WHERE Type = 'Customer']) {
    // Salesforce processes in 200-record chunks
    acc.Description = 'Verified';
    update acc; // Note: still counts against DML limit
}
🔂

while & do-while

Use while/do-while when iteration count is unknown at compile time.

  • while: condition checked before each iteration
  • do-while: body executes at least once
  • Both support break and continue
  • Infinite loops are possible — always ensure an exit condition
// while — process queue until empty
List<String> queue = new List<String>{'task1','task2','task3'};
while (!queue.isEmpty()) {
    String task = queue.remove(0);
    System.debug('Processing: ' + task);
}

// do-while — execute at least once
Integer attempts = 0;
do {
    attempts++;
    System.debug('Attempt: ' + attempts);
} while (attempts < 3);
// prints: Attempt: 1, Attempt: 2, Attempt: 3
🔛

break, continue & return

Loop control keywords work the same as Java.

  • break — exit the innermost loop immediately
  • continue — skip remainder of current iteration
  • return value — exit method and return a value
  • No labeled break/continue (unlike Java)
// break — stop at first match
Account found = null;
for (Account acc : accounts) {
    if (acc.Name.startsWith('ACME')) {
        found = acc;
        break; // no need to continue
    }
}

// continue — skip invalid records
for (Contact c : contacts) {
    if (String.isBlank(c.Email)) continue; // skip
    sendEmail(c.Email, 'Newsletter');
}

Enums

Enums provide a type-safe way to represent a fixed set of named constants. Use them instead of magic strings.

Defining & Using Enums

// Define at top-level or inside a class
public enum Season { SPRING, SUMMER, FALL, WINTER }

public enum Priority { LOW, MEDIUM, HIGH, CRITICAL }

// Usage
Priority p = Priority.HIGH;
System.debug(p);           // HIGH
System.debug(p.name());    // 'HIGH' (String)
System.debug(p.ordinal()); // 2 (0-based index)

// Switch-like behavior with if/else
if (p == Priority.CRITICAL) {
    sendPagerAlert();
} else if (p == Priority.HIGH) {
    createTask();
}

// Enums in switch statements (Apex does not have switch — use if/else or a Map)
Map<Priority, String> slaMap = new Map<Priority, String>{
    Priority.LOW      => '5 days',
    Priority.MEDIUM   => '2 days',
    Priority.HIGH     => '4 hours',
    Priority.CRITICAL => '1 hour'
};
String sla = slaMap.get(p); // '4 hours'

Exception Handling in Depth

Robust exception handling separates production-quality code from fragile scripts. Know which exceptions are catchable, which are not, and when to create your own.

🚧

Built-in Exception Types

Salesforce provides a rich hierarchy of built-in exceptions, each with specific utility methods.

  • DmlException — DML failure; use .getDmlMessage(0)
  • QueryException — SOQL returns wrong row count
  • NullPointerException — null dereference
  • TypeException — illegal cast
  • MathException — divide by zero
  • LimitException — governor limit exceeded (uncatchable!)
  • CalloutException — HTTP callout failure
try {
    // QueryException: might return 0 or >1 rows
    Account a = [SELECT Id FROM Account WHERE Name = 'ACME' LIMIT 1];
    a.Description = 'Updated';
    update a;
} catch (QueryException qe) {
    System.debug('No record found: ' + qe.getMessage());
} catch (DmlException de) {
    // DmlException has extra detail per row
    for (Integer i = 0; i < de.getNumDml(); i++) {
        System.debug('Row ' + i + ': ' + de.getDmlMessage(i));
    }
} catch (Exception e) {
    // Generic catch-all — use sparingly
    System.debug('Unexpected: ' + e.getMessage() + '\n' + e.getStackTraceString());
} finally {
    System.debug('Cleanup always runs');
}
🎯

Custom Exception Classes

Domain-specific exceptions make error handling much cleaner and more informative.

  • Must extend Exception (directly or indirectly)
  • Get four free constructors: message, cause, message+cause, none
  • Naming convention: MyDomainException
  • Can add custom fields/methods for extra context
// Custom exception with extra context
public class InsufficientInventoryException extends Exception {
    public Integer requested;
    public Integer available;

    public InsufficientInventoryException(
            Integer req, Integer avail) {
        this('Cannot fulfil order: need ' + req +
             ', only ' + avail + ' available.');
        this.requested  = req;
        this.available  = avail;
    }
}

// Throwing and catching
try {
    Integer stock = getStock(productId);
    if (qty > stock) {
        throw new InsufficientInventoryException(qty, stock);
    }
} catch (InsufficientInventoryException e) {
    System.debug('Short by: ' + (e.requested - e.available));
}

Best Practices

Always Check for Null Before Dereferencing

Any variable can be null. Dereferencing null causes a NullPointerException that rolls back the entire transaction.

❌ String s = acc.BillingCity.toUpperCase();
✅ if (acc.BillingCity != null) s = acc.BillingCity.toUpperCase();

Use Decimal, Not Double, for Money

Double uses base-2 representation which introduces floating-point errors that compound over many calculations.

❌ Double total = qty * 19.99; // may be 199.89999...
✅ Decimal total = qty * 19.99; // exactly 199.90

Use String.isBlank() Not == null

A string can be null, empty, or all whitespace. String.isBlank() handles all three cases in one call.

❌ if (s == null || s == '') { }
✅ if (String.isBlank(s)) { }

Prefer Enums Over Magic Strings

Magic strings are typo-prone and not refactoring-safe. Enums provide compile-time safety and make intent clear.

❌ if (status == 'HIGH') { }
✅ if (priority == Priority.HIGH) { }

Catch Specific Exceptions First

A generic catch (Exception e) block swallows all errors. Always catch the most specific type first, generic last.

❌ catch (Exception e) { // hides DmlException details }
✅ catch (DmlException de) { } catch (Exception e) { }

Use Map for Lookups, Not Nested SOQL

Building a Map from one query is always faster than issuing a query per iteration, and keeps you under the 100-query governor limit.

❌ Account a = [SELECT Id FROM Account WHERE Id = :id]; // inside loop
✅ Account a = accountMap.get(id); // O(1), no query consumed
