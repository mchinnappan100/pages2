02

Use SOSL When…

SOSL
🔍

User-typed search box

A user types free text and you want to find matching records across the org.

  • Global search across objects
  • Relevance-ranked results
  • Stemming handles word forms
  • Spell correction for typos
// Classic search box implementation
public with sharing class GlobalSearchController {
    @AuraEnabled(cacheable=true)
    public static Map<String, List<SObject>> search(
            String userQuery) {
        if (String.isBlank(userQuery) ||
                userQuery.length() < 2) {
            return new Map<String, List<SObject>>();
        }
        String term = userQuery.trim() + '*';
        List<List<SObject>> results =
            [FIND :term
             IN ALL FIELDS
             RETURNING
                 Account(Id, Name, Industry LIMIT 5),
                 Contact(Id, FirstName, LastName, Email LIMIT 5),
                 Opportunity(Id, Name, StageName LIMIT 5),
                 Case(Id, Subject, Status LIMIT 5)
             WITH SPELL_CORRECTION = true
            ];
        return new Map<String, List<SObject>>{
            'accounts'     => results[0],
            'contacts'     => results[1],
            'opportunities'=> results[2],
            'cases'        => results[3]
        };
    }
}
SOSL
💬

Autocomplete / type-ahead

Show suggestions as the user types — no table scan, fast prefix matching.

  • 3+ chars before searching
  • Trailing wildcard: term*
  • IN NAME FIELDS (fastest)
  • LIMIT 5-10 per object
@AuraEnabled(cacheable=true)
public static List<Account> autocomplete(String typed) {
    if (String.isBlank(typed) || typed.length() < 2) {
        return new List<Account>();
    }
    String term = typed.trim() + '*';
    List<List<SObject>> results =
        [FIND :term
         IN NAME FIELDS
         RETURNING Account(Id, Name, Industry
             ORDER BY Name
             LIMIT 8)
        ];
    return (List<Account>) results[0];
}
SOSL
📚

Knowledge base / help search

Full-text search across article content — SOQL would TABLE_SCAN Long Text fields.

  • Searches article body content
  • Relevance-ranked results
  • WITH SNIPPET for excerpts
  • WITH DATA CATEGORY filters
SOSL
🔗

Duplicate detection

Find potential duplicates by searching name and email across multiple object types.

  • Search name across Account + Contact + Lead
  • Search email across Contact + Lead
  • Search phone across all objects
  • One query, multiple object types
03

Use SOQL When…

SOQL
🎯

Exact field value lookup

You know the exact field value — use SOQL for guaranteed accuracy and index efficiency.

  • WHERE Id = :recordId
  • WHERE Email = :email
  • WHERE ExternalId__c = :extId
  • WHERE Name = 'Exact Corp'
SOQL
📅

Date & numeric filters

SOSL cannot filter on dates or numbers — these fields aren't in the search index.

  • WHERE CloseDate = THIS_QUARTER
  • WHERE Amount > 50000
  • WHERE CreatedDate = LAST_N_DAYS:7
  • WHERE Probability >= 80
SOQL
📊

Aggregation & reporting

SOSL has no aggregate functions. All COUNT, SUM, GROUP BY, HAVING work only in SOQL.

  • SELECT COUNT(Id) FROM Lead
  • GROUP BY StageName
  • SUM(Amount) / AVG(Amount)
  • HAVING COUNT(Id) > 5
SOQL
🏭

Bulk / batch processing

Processing thousands or millions of records requires SOQL + Batch Apex. SOSL max is 2,000 per object.

  • Batch Apex + QueryLocator
  • Up to 50M rows via Batch
  • SOSL max: 2,000 per object
  • Data migration, cleanup jobs
SOQL
⚡

Immediate post-insert lookup

After inserting a record, SOQL retrieves it immediately. SOSL may not find it due to index lag.

  • insert record; then query by Id
  • No index lag — reads from DB
  • Trigger after insert patterns
  • Transactional correctness
SOQL
🔗

Relationship queries

SOQL can traverse parent-child relationships in a single query. SOSL RETURNING can do limited parent traversal but not sub-selects.

  • Parent-to-child sub-selects
  • Child-to-parent dot notation
  • 5 levels of parent traversal
  • Up to 20 sub-selects

Hybrid Patterns — SOSL + SOQL Together

The most powerful search architectures combine SOSL for discovery and SOQL for enrichment. Use SOSL to find which records match, then SOQL to retrieve the full data you need.

Pattern 1: SOSL for Discovery → SOQL for Enrichment

// Step 1: SOSL to find matching record IDs (fast, multi-object)
String searchTerm = 'healthcare innovation';
List<List<SObject>> soslResults =
    [FIND :searchTerm IN ALL FIELDS
     RETURNING
         Account(Id LIMIT 20),
         Opportunity(Id LIMIT 20)
    ];

Set<Id> accountIds    = new Set<Id>();
Set<Id> opportunityIds = new Set<Id>();

for (SObject acc : soslResults[0]) accountIds.add(acc.Id);
for (SObject opp : soslResults[1]) opportunityIds.add(opp.Id);

// Step 2: SOQL to get full data with relationships, computed fields
// SOSL RETURNING can't do sub-selects or complex joins
List<Account> richAccounts =
    [SELECT Id, Name, Industry, AnnualRevenue,
            (SELECT Id, Name, Amount FROM Opportunities
             WHERE StageName != 'Closed Lost'
             ORDER BY Amount DESC LIMIT 3)
     FROM Account
     WHERE Id IN :accountIds
       AND AnnualRevenue > 1000000
     WITH SECURITY_ENFORCED
     ORDER BY AnnualRevenue DESC];

List<Opportunity> richOpps =
    [SELECT Id, Name, Amount, StageName, Account.Name
     FROM Opportunity
     WHERE Id IN :opportunityIds
       AND Amount > 50000
     WITH SECURITY_ENFORCED];

Pattern 2: SOSL for Cross-Object Dedup → SOQL for Merge Candidates

// Find potential duplicates by name across Lead + Contact + Account
String name = 'John Smith';
List<List<SObject>> dupes =
    [FIND :name IN NAME FIELDS
     RETURNING
         Lead(Id, FirstName, LastName, Email, Company
             WHERE IsConverted = false LIMIT 10),
         Contact(Id, FirstName, LastName, Email, AccountId LIMIT 10)
    ];

List<Lead>    leadMatches    = (List<Lead>)    dupes[0];
List<Contact> contactMatches = (List<Contact>) dupes[1];

// Use SOQL to get more detail on the matches
if (!contactMatches.isEmpty()) {
    Set<Id> ids = new Set<Id>();
    for (Contact c : contactMatches) ids.add(c.Id);

    List<Contact> detailedContacts =
        [SELECT Id, Name, Email, Phone,
                Account.Name, LastActivityDate
         FROM Contact
         WHERE Id IN :ids
         WITH SECURITY_ENFORCED];
    // Present to user for merge decision
}
The golden rule: SOSL finds which records match. SOQL retrieves what you need from those records. One governor query for discovery (SOSL), one for enrichment (SOQL) — clean, efficient, and scalable.
