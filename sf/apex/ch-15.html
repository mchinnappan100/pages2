01

SELECT Clause Fundamentals

Every SOQL query starts with SELECT. Unlike SQL, you must explicitly name every field — there is no SELECT * in SOQL.

Complete SOQL Syntax Reference

// Full SOQL syntax:
// SELECT fieldList
// FROM objectType
// [WHERE conditionExpression]
// [WITH [SECURITY_ENFORCED | DATA CATEGORY filteringExpression]]
// [GROUP BY {fieldGroupByList}]
// [HAVING conditionExpression]
// [ORDER BY {fieldOrderByList} [ASC|DESC] [NULLS FIRST|LAST]]
// [LIMIT numberOfRows]
// [OFFSET numberOfRowsToSkip]
// [ALL ROWS]

// Basic query — always include Id
List<Account> accs = [
    SELECT Id, Name, Industry, AnnualRevenue, Type
    FROM Account
    WHERE Type = 'Customer'
      AND AnnualRevenue > 1000000
    ORDER BY AnnualRevenue DESC NULLS LAST
    LIMIT 50
];

// Single record — use LIMIT 1 and handle QueryException
Account big;
try {
    big = [SELECT Id, Name FROM Account
           WHERE Name = 'ACME Corp' LIMIT 1];
} catch (QueryException e) {
    big = null; // no record found
}

// Count only — returns Integer, no heap for records
Integer total = [SELECT COUNT() FROM Account
                  WHERE Type = 'Customer'];

// Distinct values via GROUP BY (no DISTINCT keyword in SOQL)
AggregateResult[] industries =
    [SELECT Industry FROM Account GROUP BY Industry];
for (AggregateResult ar : industries) {
    System.debug(ar.get('Industry'));
}

WHERE Clause & Operators

⚖️

Comparison Operators

All standard comparison operators plus Salesforce-specific ones.

  • = exact match
  • != not equal
  • < > <= >= numeric
  • LIKE wildcard text
  • IN set membership
  • NOT IN exclusion
  • INCLUDES/EXCLUDES multi-picklist
  • AND OR NOT boolean
// = and !=
[SELECT Id FROM Account WHERE Type = 'Customer']
[SELECT Id FROM Account WHERE Type != 'Prospect']

// Numeric comparisons
[SELECT Id FROM Opportunity WHERE Amount >= 50000]
[SELECT Id FROM Opportunity WHERE Amount > 0 AND Amount < 100000]

// LIKE — % = any chars, _ = single char
[SELECT Id FROM Account WHERE Name LIKE 'ACME%']     // starts with
[SELECT Id FROM Account WHERE Name LIKE '%Corp']     // ends with
[SELECT Id FROM Account WHERE Name LIKE '%cloud%']   // contains
[SELECT Id FROM Account WHERE Name LIKE '_BMC']      // one char prefix

// IN — multiple values (much more efficient than OR)
Set<String> industries = new Set<String>{'Technology','Finance'};
[SELECT Id FROM Account WHERE Industry IN :industries]
[SELECT Id FROM Account WHERE Type IN ('Customer','Partner')]

// NOT IN
[SELECT Id FROM Account WHERE Industry NOT IN ('Unknown','')]

// INCLUDES / EXCLUDES for multi-select picklist
[SELECT Id FROM Case WHERE Category__c INCLUDES ('Billing','Technical')]
[SELECT Id FROM Case WHERE Category__c EXCLUDES ('Spam')]

// Boolean
[SELECT Id FROM Lead WHERE IsConverted = false AND Status != 'Dead']

// NULL checks
[SELECT Id FROM Contact WHERE Email = null]     // IS NULL
[SELECT Id FROM Contact WHERE Email != null]    // IS NOT NULL
🔗

AND / OR / NOT

Combine conditions with logical operators. Use parentheses to control precedence.

  • AND has higher precedence than OR
  • Use () to group conditions
  • NOT negates a condition
  • Short-circuit: AND stops on first false
  • Filter selectivity matters for performance
  • Most selective condition first
// AND — both conditions must be true
[SELECT Id FROM Account
 WHERE Industry = 'Technology'
   AND AnnualRevenue >= 1000000]

// OR — at least one condition true
[SELECT Id FROM Opportunity
 WHERE StageName = 'Closed Won'
    OR StageName = 'Closed Lost']

// Grouping with parentheses — critical for complex conditions
[SELECT Id FROM Lead
 WHERE (Status = 'New' OR Status = 'Working')
   AND (LeadSource = 'Web' OR LeadSource = 'Email')]

// NOT
[SELECT Id FROM Account
 WHERE NOT (Type = 'Prospect' OR Type = 'Other')]

// Complex example
[SELECT Id, Name, Amount FROM Opportunity
 WHERE (StageName = 'Prospecting' AND Amount > 10000)
    OR (StageName = 'Qualification' AND Amount > 5000)
 ORDER BY Amount DESC
 LIMIT 20]

Date & DateTime Comparisons

SOQL uses ISO date formats and provides rich date literals for common ranges.

  • Date format: YYYY-MM-DD
  • DateTime format: YYYY-MM-DDThh:mm:ssZ
  • Date literals: TODAY, THIS_WEEK
  • Parameterised: LAST_N_DAYS:7
  • Bind variables work for dates too
  • DateTime is always stored as UTC
// Specific date literal
[SELECT Id FROM Opportunity
 WHERE CloseDate = 2025-01-01]

// Date range with bind variables
Date startDate = Date.newInstance(2025, 1, 1);
Date endDate   = Date.today();
[SELECT Id FROM Opportunity
 WHERE CloseDate >= :startDate
   AND CloseDate <= :endDate]

// DateTime comparison (UTC)
DateTime cutoff = DateTime.newInstance(2025, 6, 1, 0, 0, 0);
[SELECT Id FROM Case WHERE CreatedDate >= :cutoff]

// Date literals (see full list in ch-04)
[SELECT Id FROM Case WHERE CreatedDate = TODAY]
[SELECT Id FROM Case WHERE CreatedDate = THIS_WEEK]
[SELECT Id FROM Case WHERE CreatedDate = LAST_N_DAYS:30]
[SELECT Id FROM Opportunity WHERE CloseDate = NEXT_QUARTER]
[SELECT Id FROM Lead WHERE CreatedDate = LAST_YEAR]

// Fiscal period literals (requires custom fiscal year)
[SELECT Id FROM Opportunity WHERE CloseDate = THIS_FISCAL_QUARTER]
🔒

Bind Variables

Bind variables inject Apex values into SOQL safely, preventing injection and improving readability.

  • Use : prefix in SOQL
  • Works for primitives, Lists, Sets, Maps.keySet()
  • Automatically escaped — no injection risk
  • Evaluated at query time
  • Cannot bind field names or object names
  • Use dynamic SOQL for that (with validation)
// Primitive bind variable
String targetIndustry = 'Technology';
[SELECT Id FROM Account WHERE Industry = :targetIndustry]

// List / Set bind variable — for IN clause
List<String> stages = new List<String>{
    'Closed Won', 'Closed Lost'};
[SELECT Id FROM Opportunity WHERE StageName IN :stages]

Set<Id> accountIds = new Set<Id>{'001..', '001..'};
[SELECT Id, Name FROM Account WHERE Id IN :accountIds]

// Map.keySet() bind variable
Map<Id, String> accountMap = new Map<Id, String>();
// ... populate map ...
[SELECT Id FROM Contact WHERE AccountId IN :accountMap.keySet()]

// Numeric bind variable
Decimal minAmount = 50000;
[SELECT Id FROM Opportunity WHERE Amount >= :minAmount]

// Date bind variable
Date closingBefore = Date.today().addDays(30);
[SELECT Id FROM Opportunity WHERE CloseDate < :closingBefore]

// WRONG: cannot bind field names
// String fieldName = 'Name';
// [SELECT :fieldName FROM Account] — compile error
// Use Database.query() for dynamic field names
03

ORDER BY, LIMIT & OFFSET

Sorting and Pagination

// ORDER BY — single field
[SELECT Id, Name, AnnualRevenue FROM Account
 ORDER BY AnnualRevenue DESC NULLS LAST
 LIMIT 10]

// ORDER BY — multiple fields
[SELECT Id, LastName, FirstName, Department FROM Contact
 ORDER BY Department ASC NULLS FIRST,
          LastName ASC,
          FirstName ASC]

// LIMIT — cap result count (max 50,000)
[SELECT Id FROM Lead LIMIT 200]

// OFFSET — skip rows (max 2,000 for OFFSET value)
// Use for page 2 of 50 results
Integer pageSize = 50;
Integer pageNum  = 2; // 0-indexed
[SELECT Id, Name FROM Account
 ORDER BY Name
 LIMIT :pageSize
 OFFSET :(pageNum * pageSize)]

// WARNING: OFFSET is slow for large offsets
// Better: keyset pagination
Id lastSeenId; // stored from previous page
[SELECT Id, Name FROM Account
 WHERE Id > :lastSeenId   // uses index
 ORDER BY Id
 LIMIT 50]

// COUNT() — returns Integer directly (no AggregateResult)
Integer total = [SELECT COUNT() FROM Account
                  WHERE Type = 'Customer'];

Semi-joins & Anti-joins

SOQL supports subqueries in WHERE clauses for filtering based on related records — without loading those records into memory.

Semi-join (IN subquery) & Anti-join (NOT IN subquery)

// Semi-join — Accounts that HAVE at least one Opportunity
// (equivalent to SQL: WHERE EXISTS (...))
List<Account> accountsWithOpps =
    [SELECT Id, Name FROM Account
     WHERE Id IN (SELECT AccountId FROM Opportunity
                   WHERE StageName = 'Closed Won')];

// Anti-join — Accounts with NO closed won opportunities
List<Account> accountsNoWins =
    [SELECT Id, Name FROM Account
     WHERE Id NOT IN (SELECT AccountId FROM Opportunity
                       WHERE StageName = 'Closed Won'
                         AND AccountId != null)];

// Contacts on high-value accounts
List<Contact> vipContacts =
    [SELECT Id, FirstName, LastName FROM Contact
     WHERE AccountId IN (SELECT Id FROM Account
                          WHERE AnnualRevenue > 1000000
                            AND Type = 'Customer')];

// Cases without any closed Opportunities on the account
List<Case> orphanCases =
    [SELECT Id, Subject FROM Case
     WHERE AccountId NOT IN
         (SELECT AccountId FROM Opportunity
           WHERE IsClosed = true
             AND AccountId != null)];

// Important: The subquery field must match the outer field type
// Outer: WHERE Id IN (subquery returns Id field)
// The subquery SELECT must return a single field that
// matches the outer WHERE field type
Performance: Semi-joins and anti-joins are evaluated at the database level — far more efficient than loading both result sets into Apex and comparing in code. They also count as a single SOQL query against the 100-query governor.
06

Best Practices

Always Include Id in SELECT

Omitting Id from SELECT means you can't update, delete, or relate records later. Always include it as a matter of habit.

❌ [SELECT Name FROM Account] // can't update later
✅ [SELECT Id, Name FROM Account]

Use Bind Variables, Not String Concat

Binding a variable is auto-escaped. Concatenating user input into SOQL is a SOQL injection vulnerability.

❌ 'WHERE Name = \'' + userInput + '\''
✅ WHERE Name = :userInput (auto-escaped)

Use IN Instead of OR for Multi-Values

Chaining OR conditions on the same field forces a full scan. IN can use an index across all values at once.

❌ WHERE Stage = 'A' OR Stage = 'B' OR Stage = 'C'
✅ WHERE Stage IN ('A','B','C')

LIMIT Every Query Unless Batch

An unguarded query can return 50,000 rows and exhaust heap or the row limit. Always LIMIT unless you're in a Batch Apex context with a QueryLocator.

❌ [SELECT Id FROM Lead WHERE IsConverted = false] // 200k leads
✅ [SELECT Id FROM Lead WHERE IsConverted = false LIMIT 200]

Use Semi-joins Over Code-Side Filtering

Filtering related records in SOQL (semi-join) is faster and uses one query. Loading both sets into Apex uses two queries plus heap.

❌ Load all Accounts; load all Opps; compare in loop
✅ WHERE Id IN (SELECT AccountId FROM Opportunity ...)

Prefer Date Literals Over Calculated Dates

Date literals like THIS_QUARTER adapt to fiscal year settings and are readable. Calculated bind dates require manual maintenance.

❌ WHERE CloseDate >= :Date.today().toStartOfMonth()
✅ WHERE CloseDate = THIS_MONTH
