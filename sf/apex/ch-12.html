Service Layer Pattern

The Service Layer is the central hub of business logic. It is called by triggers, REST controllers, LWC controllers, and batch jobs. It should not know where it's being called from.

Service Class Structure

// Service Layer — owns all business logic
// Called by: triggers, controllers, REST APIs, batch jobs
public with sharing class OpportunityService {

    // Static methods — no instantiation needed
    public static void onAfterInsert(List<Opportunity> newOpps) {
        createFollowUpTasks(newOpps);
        notifyAccountOwners(newOpps);
    }

    public static void onAfterUpdate(
            List<Opportunity> newOpps,
            Map<Id, Opportunity> oldOppMap) {
        List<Opportunity> closedWon =
            filterClosedWon(newOpps, oldOppMap);
        if (!closedWon.isEmpty()) {
            processClosedWon(closedWon);
        }
    }

    // Business logic method — reusable from anywhere
    public static void closeOpportunity(
            Id oppId, String reason) {
        Opportunity opp = OpportunitySelector.getById(oppId);
        if (opp == null) throw new ServiceException('Not found');

        opp.StageName = 'Closed Won';
        opp.CloseDate = Date.today();
        opp.CloseReason__c = reason;
        update opp;
        processClosedWon(new List<Opportunity>{opp});
    }

    // Private helpers
    private static List<Opportunity> filterClosedWon(
            List<Opportunity> opps,
            Map<Id, Opportunity> oldMap) {
        List<Opportunity> result = new List<Opportunity>();
        for (Opportunity o : opps) {
            if (o.StageName == 'Closed Won'
                    && oldMap.get(o.Id).StageName != 'Closed Won') {
                result.add(o);
            }
        }
        return result;
    }

    private static void processClosedWon(
            List<Opportunity> opps) {
        // Complex business logic here
    }

    public class ServiceException extends Exception {}
}

// Trigger — thin, delegates everything
trigger OpportunityTrigger on Opportunity (after insert, after update) {
    if (Trigger.isAfter) {
        if (Trigger.isInsert)
            OpportunityService.onAfterInsert(Trigger.new);
        if (Trigger.isUpdate)
            OpportunityService.onAfterUpdate(
                Trigger.new, Trigger.oldMap);
    }
}

Selector Layer Pattern

The Selector Layer centralises all SOQL queries for an sObject. Every other layer goes through the selector — never writes raw SOQL scattered across the codebase.

Selector Class

// Selector — the only place SOQL for Opportunity is written
public with sharing class OpportunitySelector {

    // Standard field set — always included
    private static final Set<String> BASE_FIELDS = new Set<String>{
        'Id', 'Name', 'StageName', 'Amount',
        'CloseDate', 'AccountId', 'OwnerId'
    };

    // Query by Id — returns null if not found
    public static Opportunity getById(Id oppId) {
        List<Opportunity> results =
            [SELECT Id, Name, StageName, Amount, CloseDate,
                    AccountId, OwnerId
             FROM Opportunity
             WHERE Id = :oppId
             WITH SECURITY_ENFORCED
             LIMIT 1];
        return results.isEmpty() ? null : results[0];
    }

    // Query by Account — used by multiple callers
    public static List<Opportunity> getByAccountId(Id accountId) {
        return [SELECT Id, Name, StageName, Amount
                FROM Opportunity
                WHERE AccountId = :accountId
                WITH SECURITY_ENFORCED
                ORDER BY CloseDate DESC];
    }

    // Query with related contacts
    public static List<Opportunity> getWithContacts(
            Set<Id> oppIds) {
        return [SELECT Id, Name, StageName,
                       (SELECT Id, FirstName, LastName
                        FROM OpportunityContactRoles
                        ORDER BY IsPrimary DESC)
                FROM Opportunity
                WHERE Id IN :oppIds
                WITH SECURITY_ENFORCED];
    }

    // Aggregate — count by stage
    public static Map<String, Integer> countByStage() {
        Map<String, Integer> result = new Map<String, Integer>();
        for (AggregateResult ar :
                [SELECT StageName, COUNT(Id) cnt
                 FROM Opportunity
                 GROUP BY StageName]) {
            result.put((String) ar.get('StageName'),
                       (Integer) ar.get('cnt'));
        }
        return result;
    }
}

Domain Layer Pattern

The Domain Layer encapsulates record-level behaviour — validation, defaulting, and business rules that operate on a collection of records. It is the object-oriented replacement for trigger logic.

Domain Class

// Domain class — operates on a batch of Opportunity records
public with sharing class Opportunities {

    private List<Opportunity> records;
    private Map<Id, Opportunity> oldRecordsMap;

    public Opportunities(List<Opportunity> records) {
        this.records = records;
    }

    public Opportunities(List<Opportunity> records,
            Map<Id, Opportunity> oldMap) {
        this.records       = records;
        this.oldRecordsMap = oldMap;
    }

    // Validation — called from before trigger
    public void validate() {
        for (Opportunity opp : records) {
            if (opp.Amount != null && opp.Amount < 0) {
                opp.Amount.addError('Amount cannot be negative');
            }
            if (opp.CloseDate < Date.today()) {
                opp.CloseDate.addError('Close date cannot be in the past');
            }
        }
    }

    // Defaulting — called from before trigger
    public void applyDefaults() {
        for (Opportunity opp : records) {
            if (opp.LeadSource == null) {
                opp.LeadSource = 'Web';
            }
            if (opp.Probability == null) {
                opp.Probability = 10;
            }
        }
    }

    // Domain method — only records where stage changed
    public List<Opportunity> getChangedStage() {
        if (oldRecordsMap == null) return records;
        List<Opportunity> changed = new List<Opportunity>();
        for (Opportunity opp : records) {
            if (opp.StageName !=
                    oldRecordsMap.get(opp.Id).StageName) {
                changed.add(opp);
            }
        }
        return changed;
    }
}

// Trigger uses Domain class
trigger OpportunityTrigger on Opportunity (
    before insert, before update, after update) {

    Opportunities domain = Trigger.isUpdate
        ? new Opportunities(Trigger.new, Trigger.oldMap)
        : new Opportunities(Trigger.new);

    if (Trigger.isBefore) {
        domain.validate();
        domain.applyDefaults();
    }
    if (Trigger.isAfter && Trigger.isUpdate) {
        List<Opportunity> changed = domain.getChangedStage();
        if (!changed.isEmpty()) {
            OpportunityService.onStageChange(changed);
        }
    }
}

Unit of Work Pattern

Unit of Work (UoW) collects all DML operations across multiple services and executes them in a single, optimised set of DML statements — reducing DML consumption and ensuring atomicity.

Simple Unit of Work Implementation

// Simple Unit of Work — collects DML, executes once
public with sharing class UnitOfWork {

    private List<SObject> toInsert = new List<SObject>();
    private List<SObject> toUpdate = new List<SObject>();
    private List<SObject> toDelete = new List<SObject>();

    public void registerNew(SObject record) {
        toInsert.add(record);
    }
    public void registerDirty(SObject record) {
        toUpdate.add(record);
    }
    public void registerDeleted(SObject record) {
        toDelete.add(record);
    }

    // Execute all collected DML in order
    public void commitWork() {
        if (!toInsert.isEmpty()) insert toInsert;
        if (!toUpdate.isEmpty()) update toUpdate;
        if (!toDelete.isEmpty()) delete toDelete;
    }
}

// Service uses UoW — 1 DML statement regardless of records
public with sharing class OrderFulfillmentService {

    public static void fulfillOrders(List<Order__c> orders) {
        UnitOfWork uow = new UnitOfWork();

        for (Order__c order : orders) {
            // Register changes without issuing DML yet
            order.Status__c = 'Fulfilled';
            uow.registerDirty(order);

            // Create related shipment
            Shipment__c ship = new Shipment__c(
                Order__c       = order.Id,
                ShippedDate__c = Date.today()
            );
            uow.registerNew(ship);
        }

        // One commitWork = 2 DML statements (update + insert)
        uow.commitWork();
    }
}

Factory & Strategy Patterns

🏭

Factory Pattern

Creates objects without specifying the exact class. Enables runtime polymorphism based on data or configuration.

  • Decouples creation from usage
  • Supports new types without changing callers
  • Driven by data (record type, field value)
  • Returns interface type for flexibility
  • Can use Custom Metadata for class names
  • Enables A/B testing of implementations
// Interface for all notification strategies
public interface INotificationStrategy {
    void notify(String recipient, String message);
}

// Implementations
public class EmailNotification implements INotificationStrategy {
    public void notify(String r, String m) {
        // send email
    }
}
public class SMSNotification implements INotificationStrategy {
    public void notify(String r, String m) {
        // send SMS via callout
    }
}
public class ChatterNotification implements INotificationStrategy {
    public void notify(String r, String m) {
        // post to Chatter
    }
}

// Factory — creates the right implementation at runtime
public class NotificationFactory {
    public static INotificationStrategy create(String channel) {
        switch on channel.toUpperCase() {
            when 'EMAIL'   { return new EmailNotification(); }
            when 'SMS'     { return new SMSNotification(); }
            when 'CHATTER' { return new ChatterNotification(); }
            default        { return new EmailNotification(); }
        }
    }
}

// Consumer — works with any notification type
String channel = user.PreferredChannel__c ?? 'EMAIL';
INotificationStrategy notifier = NotificationFactory.create(channel);
notifier.notify(user.Email, 'Your order has shipped!');
♟️

Strategy Pattern

Defines a family of algorithms behind a common interface. The algorithm can be swapped at runtime.

  • Encapsulates each algorithm in its own class
  • All strategies implement the same interface
  • Client code is unchanged when strategy changes
  • Excellent for discount, pricing, and routing logic
  • Testable in isolation
  • Combines well with Factory Pattern
// Strategy interface — all pricers implement this
public interface IPricingStrategy {
    Decimal calculatePrice(Decimal basePrice, Account account);
}

// Concrete strategies
public class StandardPricing implements IPricingStrategy {
    public Decimal calculatePrice(Decimal base, Account acc) {
        return base; // no discount
    }
}
public class PremiumPricing implements IPricingStrategy {
    public Decimal calculatePrice(Decimal base, Account acc) {
        return base * 0.85; // 15% discount
    }
}
public class EnterprisePricing implements IPricingStrategy {
    public Decimal calculatePrice(Decimal base, Account acc) {
        // Custom negotiated rate from account record
        Decimal rate = acc.NegotiatedRate__c ?? 0.75;
        return base * rate;
    }
}

// Context — uses whichever strategy is injected
public class QuoteCalculator {
    private IPricingStrategy strategy;

    public QuoteCalculator(IPricingStrategy s) {
        this.strategy = s;
    }

    public Decimal getTotal(
            List<Product2> products, Account acc) {
        Decimal total = 0;
        for (Product2 p : products) {
            total += strategy.calculatePrice(
                p.UnitPrice__c, acc);
        }
        return total;
    }
}

// Wire them together
Account acc = [SELECT Id, Type, NegotiatedRate__c
               FROM Account WHERE Id = :accId];
IPricingStrategy pricing = acc.Type == 'Enterprise'
    ? new EnterprisePricing()
    : acc.Type == 'Premium'
        ? new PremiumPricing()
        : new StandardPricing();

QuoteCalculator calc = new QuoteCalculator(pricing);
Decimal total = calc.getTotal(products, acc);

Singleton Pattern

Ensures a class has only one instance per transaction. Used for caches, configuration, and shared state.

  • Private constructor prevents external instantiation
  • Static getInstance() method
  • Lazy initialisation — created on first use
  • Resets at end of transaction (like all statics)
  • Good for expensive config queries
  • Anti-pattern if overused — prefer DI instead
// Singleton — loaded once per transaction, cached in memory
public with sharing class OrgSettings {

    private static OrgSettings instance;

    // Configuration loaded from Custom Metadata
    public final Boolean  enableEmailAlerts;
    public final Integer  maxBatchSize;
    public final String   defaultCurrency;

    // Private constructor — loads config once
    private OrgSettings() {
        Org_Settings__mdt settings = [
            SELECT Enable_Email_Alerts__c,
                   Max_Batch_Size__c,
                   Default_Currency__c
            FROM Org_Settings__mdt
            WHERE DeveloperName = 'Default'
            LIMIT 1
        ];
        enableEmailAlerts = settings.Enable_Email_Alerts__c;
        maxBatchSize      = Integer.valueOf(
                                settings.Max_Batch_Size__c);
        defaultCurrency   = settings.Default_Currency__c;
    }

    // Public access point — creates once, reuses
    public static OrgSettings getInstance() {
        if (instance == null) {
            instance = new OrgSettings();
        }
        return instance;
    }
}

// Usage — no repeated SOQL
if (OrgSettings.getInstance().enableEmailAlerts) {
    sendAlertEmail();
}
Integer batchSize = OrgSettings.getInstance().maxBatchSize;
🎭

Decorator Pattern

Adds behaviour to objects dynamically without modifying their class — wrapping one implementation with another.

  • Both decorator and component implement same interface
  • Decorator wraps and delegates to the component
  • Stack multiple decorators (logging + caching)
  • Open/Closed principle — extend without modifying
  • Useful for adding logging, caching, retry logic
  • Common in repository / selector patterns
// Interface
public interface IAccountSelector {
    List<Account> getByIds(Set<Id> ids);
}

// Real implementation
public with sharing class AccountSelectorImpl
        implements IAccountSelector {
    public List<Account> getByIds(Set<Id> ids) {
        return [SELECT Id, Name, Industry FROM Account
                WHERE Id IN :ids WITH SECURITY_ENFORCED];
    }
}

// Logging Decorator — wraps the real selector
public with sharing class LoggingAccountSelector
        implements IAccountSelector {

    private IAccountSelector inner;

    public LoggingAccountSelector(IAccountSelector inner) {
        this.inner = inner;
    }

    public List<Account> getByIds(Set<Id> ids) {
        Long start = System.currentTimeMillis();
        List<Account> results = inner.getByIds(ids);
        Long elapsed = System.currentTimeMillis() - start;
        System.debug(LoggingLevel.INFO,
            'AccountSelector.getByIds: ' + ids.size() +
            ' ids, ' + results.size() +
            ' results, ' + elapsed + 'ms');
        return results;
    }
}

// Wire up: wrap real selector with logging decorator
IAccountSelector selector = new LoggingAccountSelector(
    new AccountSelectorImpl());
List<Account> accs = selector.getByIds(accountIds);

Null Object & Builder Patterns

Builder Pattern — Fluent Object Construction

// Builder — fluent API for constructing complex objects
public class OpportunityBuilder {
    private Opportunity opp;

    public OpportunityBuilder() {
        opp = new Opportunity();
    }

    public OpportunityBuilder name(String n)         { opp.Name = n;         return this; }
    public OpportunityBuilder account(Id accId)      { opp.AccountId = accId; return this; }
    public OpportunityBuilder stage(String s)        { opp.StageName = s;    return this; }
    public OpportunityBuilder amount(Decimal a)      { opp.Amount = a;       return this; }
    public OpportunityBuilder closeDate(Date d)      { opp.CloseDate = d;    return this; }
    public OpportunityBuilder owner(Id ownerId)      { opp.OwnerId = ownerId; return this; }

    public Opportunity build() { return opp; }
    public Opportunity buildAndInsert() { insert opp; return opp; }
}

// Usage — readable, no positional argument confusion
Opportunity opp = new OpportunityBuilder()
    .name('ACME Deal Q4')
    .account(accountId)
    .stage('Prospecting')
    .amount(50000)
    .closeDate(Date.today().addDays(30))
    .buildAndInsert();

Best Practices

Separate Concerns with Layers

Trigger → Handler → Service → Selector. Each layer has one job. This makes code testable in isolation and prevents spaghetti dependencies.

❌ All logic in the trigger file
✅ Trigger → Service → Selector (each testable alone)

Program to Interfaces

Services and selectors should depend on interfaces, not concrete classes. This enables mocking in tests and swapping implementations without changing callers.

❌ AccountSelectorImpl selector = new AccountSelectorImpl();
✅ IAccountSelector selector = new AccountSelectorImpl();

One Unit of Work per Transaction

Create one UoW object at the transaction entry point (trigger, controller) and pass it down through service calls. Commit once at the end.

❌ Multiple insert/update calls scattered in services
✅ uow.registerDirty(x); ... uow.commitWork();

Keep Selectors Read-Only

Selectors only query — never modify. DML belongs exclusively in the Service Layer. This enforces clear responsibility.

❌ AccountSelector.getAndUpdate(ids); // selector with DML
✅ AccountService.update(accs); // service owns DML
