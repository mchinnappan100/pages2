What is the minimum code coverage percentage required to deploy Apex to a production org?
✓ Correct: C — 75%

Salesforce requires a minimum of 75% code coverage across all Apex classes and triggers for deployment to production. Individual classes can be below 75% as long as the overall org average meets the threshold. However, 75% is a floor — professional teams aim for 90%+ with meaningful assertions testing real business behaviour.

2
What is the purpose of calling Test.stopTest() when testing an async method like Queueable or @future?
✓ Correct: B

Test.stopTest() forces any queued @future, Queueable, or Batch jobs to run synchronously before continuing. Without it, async jobs would be queued but never execute during the test — your assertions would run before the async work completes. Test.startTest() also resets governor limits for code running between startTest/stopTest.

3
Why should you NEVER use @IsTest(SeeAllData=true)?
✓ Correct: B

@IsTest(SeeAllData=true) allows test methods to query live org data. This creates tests that pass in one org but fail in another (sandbox, scratch org, or after data changes). Always create test data explicitly inside @TestSetup or within the test method using a TestDataFactory. This makes tests self-contained, repeatable, and deployable anywhere.

4
What does Security.stripInaccessible(AccessType.READABLE, records) do?
✓ Correct: B

Security.stripInaccessible() removes field values from sObject records where the running user lacks the specified access (READABLE, CREATEABLE, UPDATABLE, UPSERTABLE). The method returns an SObjectAccessDecision; call .getRecords() to get the sanitised list. Use this before returning data from @AuraEnabled methods to prevent field-level data leakage.

5
A class declared without sharing is called by a class declared with sharing. Which sharing rules apply inside the without sharing class?
✓ Correct: B

without sharing is an absolute keyword — it always bypasses record sharing rules regardless of who called it or what their sharing context is. A without sharing class queries all records in the org. This is why you should document the business justification whenever using it, and minimise its scope to only the methods that genuinely require system-level access.

6
What is the role of @TestSetup?
✓ Correct: B

@TestSetup runs once before the first test method. The data it creates is shared across all test methods in the class, but Salesforce rolls back each test method's changes independently — the next test method always sees the original @TestSetup state. This is more efficient than creating data in every test method individually.

7
Which API security check verifies that the running user has CREATE permission on an sObject before performing a DML insert?
✓ Correct: B

Schema.SObjectType.Account.isCreateable() checks CRUD-level CREATE permission for the running user on the Account object. Similar checks: isAccessible() (READ), isUpdateable() (UPDATE), isDeletable() (DELETE). For field-level: Schema.SObjectType.Account.fields.Name.isCreateable(). These checks are important in classes that process user-supplied data.

8
Which Salesforce CLI command deploys Apex classes from a source project to a target org and runs all tests?
✓ Correct: B

The modern Salesforce CLI (sf, not sfdx) uses sf project deploy start to deploy source metadata. The --test-level RunAllTestsInOrg flag runs all tests in the org — required for production deployments. Use RunLocalTests to run only tests in the deployment package, or RunSpecifiedTests with --tests to run specific classes.

9
A test method achieves 80% code coverage but has no System.assertEquals calls. Is this sufficient for production-quality testing?
✓ Correct: B

Code coverage only measures that lines of code were executed during a test — it does not verify that the code produced correct results. A test with no assertions can achieve 100% coverage while masking bugs. Every test method should verify its result with System.assertEquals(expected, actual, 'descriptive message'). Coverage is a deployment gate, not a quality metric.

10
What is the difference between a Change Set deployment and an SFDX project deployment?
✓ Correct: C

Change Sets are a UI-based, manual process with no version control, no rollback, no automation, and limited to connected orgs. SFDX/Salesforce CLI is a modern, developer-first toolchain: source stored in Git, deployable to any org (sandbox, scratch, production), integrates with CI/CD pipelines (GitHub Actions, Jenkins), supports packages, and allows automated testing. All modern enterprise orgs use SFDX.
