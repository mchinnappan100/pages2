In ANTLR4 grammar convention, how do you distinguish a parser rule from a lexer rule?
✓ Correct: B

By ANTLR4 convention: parser rules are named starting with a lowercase letter (e.g., classDeclaration, statement) and define how tokens combine into structures. Lexer rules are named with ALL UPPERCASE (e.g., PUBLIC, DB_INSERT) and define how characters form tokens. Fragment rules (helper lexer rules) also use UPPERCASE but are preceded by the fragment keyword.

2
Why does the Apex grammar use fragment rules like [pP][uU][bB][lL][iI][cC] for the PUBLIC token?
✓ Correct: B

Unlike Java which is case-sensitive, Apex is case-insensitive. The grammar must match public, Public, PUBLIC, and every other capitalisation. ANTLR4 character classes [pP] match either lowercase or uppercase 'p'. Each letter position has its own [xX] pair, resulting in patterns like [pP][uU][bB][lL][iI][cC].

3
What grammar rule handles the inline SOQL query syntax [SELECT Id FROM Account]?
✓ Correct: B

The inline SOQL query is scanned as a single lexer token — SoqlLiteral. The lexer matches everything between [ and ] that starts with SELECT. The internal SOQL syntax (fields, WHERE clauses, etc.) is not parsed by this grammar — it's left as an opaque string for a separate SOQL parser. This is why SOQL appears as an expression in the Apex AST.

4
Which grammar rule handles Apex DML operations like insert accounts;?
✓ Correct: B

apexDbExpression is the parser rule that matches DML operations. It accepts any of the DML keyword tokens (DB_INSERT, DB_UPDATE, DB_DELETE, DB_UNDELETE, DB_UPSERT) followed by an expression (the sObject or List). This rule is referenced from the statement rule, making DML a valid statement form.

5
In the Apex grammar, what does the LAMBDA_LIKE token (=>) represent?
✓ Correct: B

In Apex, => is used exclusively as the map entry separator in map literal initialization: new Map<String, Integer>{'a' => 1}. Despite the name LAMBDA_LIKE, Apex does not support Java-style lambda expressions. The grammar names it this way because the syntax visually resembles a lambda arrow, but its semantics are entirely different.

6
What ANTLR pattern indicates that a lexer rule is skipped (not passed to the parser)?
✓ Correct: B

-> skip is the ANTLR4 lexer command that tells the lexer to consume the matched characters but not create a token. The Apex grammar uses this for whitespace (WS -> skip), line comments, block comments, and the QUOTE character. As an alternative, -> channel(HIDDEN) puts tokens on a hidden channel (still accessible but not seen by the parser).

7
Which Apex-specific grammar construct handles the with sharing and without sharing keywords — noting they are two words with a space?
✓ Correct: B

The Apex grammar defines APEX_WITH_SHARING as a single compound lexer token that matches the literal text with sharing (including the space between words) case-insensitively. This avoids ambiguity with with as a potential standalone keyword. Similarly, APEX_WITHOUT_SHARING matches without sharing as a unit.

8
What tool uses the Apex ANTLR grammar to provide real-time syntax checking in VS Code?
✓ Correct: C

The Apex Language Server, bundled with the Salesforce Extension Pack for VS Code, uses the Apex grammar (via ANTLR) to parse .cls files in real time. It provides syntax highlighting, error squiggles, autocomplete, hover documentation, and go-to-definition. PMD uses the grammar for static analysis. Checkmarx uses it for security scanning.

9
What are the three methods you implement when writing an ANTLR Visitor to traverse an Apex AST?
✓ Correct: C

ANTLR generates a base visitor class (apexBaseVisitor) with a visitXxx() method for every grammar rule. You override only the methods for rules you care about. For example, to process DML: visitApexDbExpression(). The Listener pattern uses enterXxx() and exitXxx() — that's option D (Listener, not Visitor). Both patterns are generated by ANTLR.

10
The Apex grammar is described as "derived from Java 1.7 grammar." Which of the following is an example of an Apex construct that does NOT exist in Java and required grammar extension?
✓ Correct: C

Java has no concept of DML keywords (insert, update, etc.) or inline query literals ([SELECT ...]). These are Apex-exclusive constructs requiring new grammar rules: apexDbExpression (for DML) and SoqlLiteral (for inline SOQL). The sharing keywords (with sharing), System.runAs, the => map operator, and property syntax (get; set;) are also Apex-specific extensions to the Java grammar.
