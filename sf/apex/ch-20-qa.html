A developer needs to find all records (Accounts, Contacts, Leads) containing the word 'healthcare' anywhere in their text fields. Which is better?
✓ Correct: B

SOSL is dramatically better here: one query, searches all indexed text fields across 3 objects simultaneously, uses the search index (not a TABLE_SCAN), and returns up to 2,000 rows per object. SOQL LIKE '%healthcare%' forces a TABLE_SCAN on each object separately — 3 queries, each scanning every row.

2
You need to find an Account record by its exact Id. Which should you use?
✓ Correct: B

SOQL is correct for exact Id lookups. SOQL with WHERE Id = :id uses the Id index — O(1), instant, guaranteed accurate. SOSL involves the search index which: (1) may have a lag, (2) doesn't guarantee the record is there if just created, and (3) is overkill for an exact match.

3
Your code must find all Opportunities closing THIS_MONTH with Amount > 50,000. Which tool?
✓ Correct: B

SOQL is required. Date fields and Number/Currency fields are NOT indexed in the SOSL search index. SOSL cannot filter on CloseDate or Amount. Only SOQL supports structured conditions on dates, numbers, and currency fields.

4
A user types 'joh' in a search box and you want autocomplete suggestions for Contact names. Which is correct?
✓ Correct: B

SOSL with a trailing wildcard ('joh*') and IN NAME FIELDS is the correct pattern for autocomplete. It uses the search index (fast, no table scan) and returns results from multiple object types if needed. SOQL LIKE with trailing % also works for Name, but SOSL scales better and can search multiple objects simultaneously.

5
SOSL results are stale immediately after an insert. When is this a problem?
✓ Correct: B

Index lag becomes a problem when code performs DML (inserts a record) and then immediately runs a SOSL query expecting to find that record. The new record may not be in the index yet. For immediate post-insert retrieval, use SOQL by Id. SOSL is for user-facing search where slight delay is acceptable.

6
You need to query 100,000 records by their AccountId to update them in bulk. Which tool?
✓ Correct: B

This is a SOQL use case. SOQL + Batch Apex QueryLocator can process up to 50 million records via a structured field filter. SOSL: (1) can return max 2,000 rows per object, (2) doesn't search by AccountId (a lookup field, not a text field), (3) is for free-text search, not bulk data processing.

7
Which combination correctly describes when to choose SOSL over SOQL?
✓ Correct: B

SOSL excels at: (1) user-typed free text, (2) searching across multiple objects at once, (3) full-text matching in text/email/phone fields, (4) stemming and relevance ranking. SOQL excels at: structured queries on specific fields, numeric/date filters, aggregation, guaranteed sort, and bulk data retrieval.

8
Can SOSL replace SOQL's GROUP BY / aggregate functions for reporting?
✓ Correct: B

SOSL has no aggregate functions — no GROUP BY, no COUNT, no SUM, no HAVING. For aggregation and reporting use SOQL with GROUP BY. SOSL is purely a search / retrieval tool, not an analytics tool.

9
You're building a global search feature that needs to search Accounts, Contacts, Cases, and Knowledge Articles with a single user query. How many SOQL governor queries does this consume?
✓ Correct: C

A SOSL query counts as 1 SOQL query regardless of how many objects appear in RETURNING. This is one of SOSL's key advantages — searching 4 objects in one query costs the same governor units as searching 1 object.

10
A record was just inserted with insert myRecord. A SOSL query immediately after returns empty. What is the correct fix?
✓ Correct: B

The fix is to use SOQL for post-insert retrieval. [SELECT Id FROM MyObject__c WHERE Id = :myRecord.Id LIMIT 1] reads directly from the database — guaranteed fresh. SOSL reads the search index, which updates asynchronously. For transactional correctness after DML, always use SOQL.
