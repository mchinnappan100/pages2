Wildcards — * and ?

SOSL supports two wildcard characters that enable partial-word matching. Understanding where to place them — and the performance implications — is essential.

Wildcard Syntax and Behaviour

// * — matches zero or more characters
// TRAILING wildcard — uses the index efficiently ✅
String prefix = 'cloud*';
[FIND :prefix IN NAME FIELDS RETURNING Account(Id,Name)]
// Matches: cloud, cloudforce, cloudtech, cloudfoundry

// LEADING wildcard — forces full scan ❌ (avoid)
// [FIND '*cloud' IN NAME FIELDS RETURNING Account]
// Matches: icloud, soundcloud — but is slow!

// ? — matches exactly ONE character
String pattern = 'cl?ud';
[FIND :pattern IN NAME FIELDS RETURNING Account(Id,Name)]
// Matches: cloud, cl0ud (exactly 5 chars)

// Combining wildcards
String combo = 'cl*d?';
[FIND :combo IN ALL FIELDS RETURNING Account(Id,Name LIMIT 20)]

// Append wildcard in Apex before binding
public static List<Account> autoComplete(String typed) {
    if (String.isBlank(typed) || typed.length() < 2) {
        return new List<Account>();
    }
    String term = typed.trim() + '*'; // trailing wildcard
    List<List<SObject>> results =
        [FIND :term IN NAME FIELDS
         RETURNING Account(Id, Name LIMIT 10)];
    return (List<Account>) results[0];
}
Performance rule: Trailing wildcards (term*) use the search index efficiently — O(log n). Leading wildcards (*term) require scanning the entire index — O(n). Use SOSL trailing wildcards for autocomplete; use SOQL for contains searches if SOSL isn't appropriate.

Stemming, Phrase Search & Operators

🌱

Stemming

The search index reduces words to their root form, so a search for one form matches all related forms.

  • "run" → runs, running, runner
  • "cloud" → clouds, cloudy
  • "manage" → managing, managed, manager
  • Language-aware (English default)
  • Cannot be disabled per query
  • Makes search more natural
// Stemming — searching 'manage' finds 'management', 'managing', 'manager'
String term = 'manage';
List<List<SObject>> results =
    [FIND :term IN ALL FIELDS
     RETURNING
         Case(Id, Subject, Description LIMIT 10),
         Knowledge__kav(Id, Title, Summary
             WHERE PublishStatus = 'Online' LIMIT 5)
    ];

// Results include records containing:
// 'manage', 'manages', 'managed', 'managing',
// 'management', 'manager', 'managers'

// This is why SOSL works better than SOQL LIKE for user search:
// SOQL [WHERE Subject LIKE '%manage%'] would miss 'management'
// unless you also query for '%management%', '%managing%' etc.
📝

Phrase Search

Wrap terms in double quotes to search for an exact phrase.

  • Wrap in double quotes: "exact phrase"
  • Words must appear adjacent in that order
  • Without quotes: both words anywhere (AND logic)
  • More precise than keyword search
  • Good for product names, error messages
  • Stemming still applies inside phrases
// Phrase search — words must appear adjacent in this order
String phrase = '"cloud services"';
List<List<SObject>> phraseResults =
    [FIND :phrase IN ALL FIELDS
     RETURNING Account(Id, Name), Knowledge__kav(Id, Title)];

// Without quotes — both words anywhere (AND logic)
String keywords = 'cloud services';
List<List<SObject>> keywordResults =
    [FIND :keywords IN ALL FIELDS
     RETURNING Account(Id, Name)];
// Matches: "our cloud and hosting services" (words not adjacent)
// vs. "cloud services" requires them adjacent

// Combined: phrase + extra term
String combined = '"cloud services" enterprise';
List<List<SObject>> combined =
    [FIND :combined IN ALL FIELDS
     RETURNING Account(Id, Name LIMIT 10)];
🔧

Boolean Operators in SOSL

SOSL supports AND, OR, AND NOT operators directly in the search term string.

  • Default (space): AND — all words must match
  • OR: either word matches
  • AND NOT: exclude records with this term
  • Use parentheses to group
  • Operators must be UPPERCASE
  • Mix with wildcards and phrases
// AND (default) — records must contain BOTH words
String andSearch = 'cloud software';
// Matches: "our cloud software platform"

// OR — records containing EITHER word
String orSearch = 'cloud OR saas';
List<List<SObject>> orResults =
    [FIND :orSearch IN ALL FIELDS
     RETURNING Account(Id,Name LIMIT 20)];

// AND NOT — exclude records with the second term
String excludeSearch = 'cloud AND NOT amazon';
// Matches records with 'cloud' but NOT 'amazon'

// Grouping with parentheses
String complex = '(cloud OR saas) AND (enterprise OR business)';
List<List<SObject>> complexResults =
    [FIND :complex IN ALL FIELDS
     RETURNING
         Account(Id, Name, Industry LIMIT 10),
         Opportunity(Id, Name, StageName LIMIT 10)
    ];

// Note: build the boolean string in Apex then bind:
String term = '(' + 'cloud OR saas' + ') AND enterprise';
List<List<SObject>> r = [FIND :term IN ALL FIELDS
    RETURNING Account(Id, Name)];
🔠

Escaping Special Characters

Certain characters have special meaning in SOSL and must be escaped with a backslash.

  • Special chars: ? * \ " ( ) { } [ ] ^ ~ : ! & | ' - + /
  • Escape with backslash: \?
  • In Apex strings: double the backslash
  • Use String.escapeSingleQuotes()
  • Bind variables handle most escaping
// Special characters must be escaped with backslash
// In an Apex string literal, backslash needs doubling

// Search for literal question mark
String withQuestion = 'What\\?'; // \? in SOSL

// Search for literal asterisk
String withStar = 'C\\+\\+'; // C\+\+ in SOSL

// Safer: use String.escapeSingleQuotes() and bind
// Bind variables auto-handle escaping in most cases
String userInput = 'cloud (2025)'; // has special chars
// When bound with :userInput, the ( ) are treated as literals
List<List<SObject>> safe =
    [FIND :userInput IN NAME FIELDS RETURNING Account(Id,Name)];

// For dynamic SOSL: escape before building string
public static String escapeSosl(String input) {
    return input
        .replace('\\', '\\\\')
        .replace('?',  '\\?')
        .replace('*',  '\\*')
        .replace('(',  '\\(')
        .replace(')',  '\\)')
        .replace('"',  '\\"')
        .replace('+',  '\\+')
        .replace('-',  '\\-');
}

WITH Clause — Modifiers

WITH Clause Options

// WITH SPELL_CORRECTION — corrects common misspellings
String misspelled = 'salesfroce'; // typo
List<List<SObject>> corrected =
    [FIND :misspelled IN ALL FIELDS
     RETURNING Account(Id,Name LIMIT 10)
     WITH SPELL_CORRECTION = true];
// Returns results for 'salesforce' (corrected)

// WITHOUT spell correction (default) — exact term only
List<List<SObject>> exact =
    [FIND :misspelled IN ALL FIELDS
     RETURNING Account(Id,Name LIMIT 10)
     WITH SPELL_CORRECTION = false];
// Returns nothing (no records contain 'salesfroce')

// WITH NETWORK = ALL NETWORKS — search across Experience Cloud sites
List<List<SObject>> allNetworks =
    [FIND 'partner' IN ALL FIELDS
     RETURNING User(Id, Name)
     WITH NETWORK = ALL NETWORKS];

// WITH NETWORK = :networkId — specific community
Id communityId = [SELECT Id FROM Network
    WHERE Name = 'Partner Portal' LIMIT 1].Id;
List<List<SObject>> communitySearch =
    [FIND 'portal' IN ALL FIELDS
     RETURNING FeedItem(Id, Body)
     WITH NETWORK = :communityId];

// WITH METADATA — include metadata in results
List<List<SObject>> withMeta =
    [FIND 'cloud' IN ALL FIELDS
     RETURNING Account(Id, Name)
     WITH METADATA = 'LABELS'];
// Returns additional metadata about each result

SNIPPET — Highlighted Results

SNIPPET returns an excerpt of the matching field with the search term highlighted — essential for building a search results page that shows users WHY a record matched.

Using SNIPPET in SOSL

// WITH SNIPPET returns highlighted excerpts
String searchTerm = 'cloud infrastructure';
List<List<SObject>> snippetResults =
    [FIND :searchTerm
     IN ALL FIELDS
     RETURNING
         Knowledge__kav(
             Id, Title, Summary
             WHERE PublishStatus = 'Online'
             LIMIT 10
         )
     WITH SNIPPET(target_length=120)];  // 120-char excerpt

List<Knowledge__kav> articles =
    (List<Knowledge__kav>) snippetResults[0];

for (Knowledge__kav art : articles) {
    System.debug('Title: ' + art.Title);

    // The snippet is in a special field on each result
    // Access via the Search.SearchResult API
}

// For accessing snippets, use the Search API response:
Search.SearchQuery query = new Search.SearchQuery(searchTerm);
query.addReturningSpec(
    new Search.SearchGroup(
        Schema.SObjectType.Knowledge__kav.getSObjectType(),
        new List<String>{'Id','Title','Summary'}
    )
);
query.setSnippetTargetLength(120);

List<Search.SearchResult> results = Search.find(query).getRecords();
for (Search.SearchResult sr : results) {
    String title   = (String) sr.getSObject().get('Title');
    String snippet = sr.getSnippet(); // highlighted excerpt
    System.debug('Title: ' + title);
    System.debug('Excerpt: ' + snippet);
}

Knowledge Article Search

SOSL is the recommended approach for searching Salesforce Knowledge articles — it uses the full-text index and supports rich filtering by publish status, language, and data category.

Searching Knowledge Articles

// Search Knowledge with SOSL — recommended approach
public with sharing class KnowledgeSearch {

    public class ArticleResult {
        public String id;
        public String title;
        public String summary;
        public String articleType;

        public ArticleResult(Knowledge__kav art) {
            this.id          = art.Id;
            this.title       = art.Title;
            this.summary     = art.Summary;
            this.articleType = art.RecordType.Name;
        }
    }

    public static List<ArticleResult> search(
            String searchTerm, String language) {

        String term = String.isBlank(searchTerm)
            ? '' : searchTerm.trim() + '*';
        String lang = String.isBlank(language)
            ? 'en_US' : language;

        List<List<SObject>> results =
            [FIND :term
             IN ALL FIELDS
             RETURNING
                 Knowledge__kav(
                     Id, Title, Summary,
                     RecordType.Name,
                     LastPublishedDate
                     WHERE PublishStatus = 'Online'
                       AND Language = :lang
                       AND IsLatestVersion = true
                     ORDER BY LastPublishedDate DESC
                     LIMIT 20
                 )
             WITH SPELL_CORRECTION = true
            ];

        List<ArticleResult> output = new List<ArticleResult>();
        for (Knowledge__kav art :
                (List<Knowledge__kav>) results[0]) {
            output.add(new ArticleResult(art));
        }
        return output;
    }
}

// Searching by Data Category (requires Knowledge + Data Categories setup)
List<List<SObject>> categorised =
    [FIND 'billing error'
     IN ALL FIELDS
     RETURNING Knowledge__kav(
         Id, Title
         WHERE PublishStatus = 'Online'
         LIMIT 10
     )
     WITH DATA CATEGORY
         Product__c AT Cloud__c
         AND Support__c ABOVE Level1__c
    ];

Best Practices

Append Wildcards in Apex, Not in Queries

Build the wildcard string in Apex before binding, so the bind variable receives the complete term with wildcard. This avoids SOSL injection and keeps the query readable.

✅ String term = userInput + '*'; [FIND :term IN NAME FIELDS ...]

Enable SPELL_CORRECTION for User-Facing Search

Users make typos. WITH SPELL_CORRECTION = true silently corrects common misspellings and returns relevant results instead of empty sets.

✅ [FIND :term IN ALL FIELDS ... WITH SPELL_CORRECTION = true]

Use Phrase Search for Multi-Word Product Names

Product names and error messages that must match exactly should be wrapped in double quotes. Without quotes, SOSL uses AND logic — words can be anywhere in the record.

❌ FIND 'Salesforce Sales Cloud' // OR logic across many records
✅ FIND '"Salesforce Sales Cloud"' // exact phrase

Minimum 2 Characters — Validate Before Querying

SOSL requires at least 2 characters in the search term. Sending a 1-character query throws an exception. Always validate length before executing.

❌ [FIND :userInput IN ALL FIELDS ...] // crashes on 1-char input
✅ if (userInput.length() >= 2) { [FIND :userInput ...] }

Use Boolean Operators to Refine Results

AND NOT helps exclude irrelevant results. OR broadens search for synonyms. Use these to improve relevance without writing complex Apex filtering code.

✅ String term = 'cloud AND NOT test AND NOT demo';

Use WITH SNIPPET for Search Results Pages

Show users why a record matched by including a highlighted excerpt. Without SNIPPET, users see a list of titles with no context — poor UX.

✅ WITH SNIPPET(target_length=150) // shows matching context
