What annotation allows a @future method to make HTTP callouts?
✓ Correct: B

The callout=true parameter on the @future annotation explicitly permits HTTP callouts. Without it, attempting a callout in a @future method throws a CalloutException. This flag is also why @future is the standard pattern for making callouts that are triggered from trigger contexts (where DML has already occurred).

2
Why can @future methods NOT accept sObject parameters?
✓ Correct: B

@future methods are queued and execute asynchronously — there could be a delay between the call and execution. If sObjects were passed directly, the data snapshot could be stale or the record could have been modified/deleted by the time the method runs. Instead, pass the record Ids (primitive Strings) and re-query fresh data inside the @future method. Use Queueable if you genuinely need to pass complex types.

3
Which async Apex type should you use when you need to chain one job after another upon completion?
✓ Correct: B

Queueable Apex supports chaining — from inside the execute() method you can call System.enqueueJob(new NextJob()) to queue the next step. @future cannot call another @future. Batch can be launched from a Scheduled job, but Queueable provides the cleanest chain pattern for sequential async workflows.

4
What is the purpose of Database.Stateful in Batch Apex?
✓ Correct: B

Without Database.Stateful, each execute() call gets a fresh instance — instance variables reset. With Database.Stateful, instance variable values (counters, error lists, accumulators) persist across all chunk executions. Use it when you need to aggregate results across chunks — for example, counting total records updated across all batches to report in finish().

5
You need to process 5 million Contact records nightly. Which Apex feature is purpose-built for this?
✓ Correct: C

Batch Apex is designed for large data volumes — it processes records in chunks (up to 2,000 per transaction), each with a fresh set of governor limits. To run it nightly, wrap it in a Scheduled Apex class that implements Schedulable and calls Database.executeBatch() from its execute() method. @future and Queueable have a single transaction context unsuitable for millions of records.

6
What is the maximum number of records that can be processed per Batch Apex execute() call?
✓ Correct: C — 2,000

The batch scope can be set to any value between 1 and 2,000 records per execute() call. The default is 200. Pass the desired size as the second argument: Database.executeBatch(new MyBatch(), 2000). Larger batches mean fewer transactions (and fewer governor-limit resets), so they run faster — but leave less margin if your per-record processing is complex.

7
How do you test a class that makes HTTP callouts in Apex?
✓ Correct: B

Real HTTP callouts are blocked in test contexts. To test callout code, create a class that implements HttpCalloutMock and returns a controlled HttpResponse. Register it before calling the code under test: Test.setMock(HttpCalloutMock.class, new MyMock()). Write separate mocks for success (200) and error (500) responses to test both paths.

8
Which cron expression schedules a job to run every day at midnight (12:00 AM)?
✓ Correct: B

Apex cron format is Seconds Minutes Hours Day Month DayOfWeek [Year]. 0 0 0 * * ? means: second=0, minute=0, hour=0 (midnight), every day of the month, every month, any day of week. The ? means "don't care" and is required in either Day or DayOfWeek when the other is specified.

9
What is the primary advantage of using a Named Credential for HTTP callouts instead of hard-coding the endpoint URL and credentials?
✓ Correct: B

Named Credentials store the endpoint URL and authentication (Basic Auth, OAuth, JWT) securely in Salesforce metadata — separate from code. This means: no credentials in source control; different sandbox/production endpoints configured without code changes; OAuth token refresh handled automatically. Reference them as callout:NamedCredentialName/path in the endpoint URL.

10
A developer tries to make an HTTP callout directly in an after insert trigger that also performs DML. What error occurs?
✓ Correct: B

Salesforce enforces a rule: you cannot make a callout after DML has occurred in the same transaction (the "mixed DML/callout" restriction). The reason: if the callout succeeds but the DML later rolls back, the external system would have received data that was never persisted in Salesforce. The fix: dispatch the callout to a @future(callout=true) method or a Queueable that implements Database.AllowsCallouts.
