SOQL — Salesforce Object Query Language

SOQL is Apex's built-in mechanism for querying Salesforce records. Queries are written inline, wrapped in square brackets, and return typed results.

🔍

Basic SOQL Syntax

SOQL syntax mirrors SQL but operates on Salesforce objects and fields.

  • SELECT fields FROM Object WHERE condition
  • ORDER BY field ASC|DESC NULLS FIRST|LAST
  • LIMIT n — cap result count (max 50,000 rows)
  • OFFSET n — skip first n rows (max 2,000)
  • Bind variables use the : prefix
  • No SELECT * — must specify field names
// Simple query returning a List
List<Account> accs = [SELECT Id, Name, AnnualRevenue
                       FROM Account
                       WHERE Type = 'Customer'
                       ORDER BY AnnualRevenue DESC NULLS LAST
                       LIMIT 50];

// Bind variable — prevents SOQL injection
String industry = 'Technology';
Integer minRevenue = 1000000;
List<Account> techAccounts =
    [SELECT Id, Name FROM Account
     WHERE Industry = :industry
     AND AnnualRevenue >= :minRevenue];

// Single record query — throws QueryException if 0 or >1 rows
Account bigCo = [SELECT Id, Name FROM Account
                  WHERE Name = 'ACME Corp' LIMIT 1];
📅

Date Literals & Filters

SOQL provides powerful date literals that eliminate the need to calculate date ranges manually.

  • TODAY, YESTERDAY, TOMORROW
  • THIS_WEEK, LAST_WEEK, THIS_MONTH, LAST_MONTH
  • THIS_QUARTER, THIS_YEAR, LAST_N_DAYS:n
  • Dates in WHERE use ISO format: 2025-01-01
  • Datetimes include timezone: 2025-01-01T00:00:00Z
// Date literals
List<Opportunity> thisQuarter =
    [SELECT Id, Name, Amount
     FROM Opportunity
     WHERE CloseDate = THIS_QUARTER
     AND StageName = 'Closed Won'];

// LAST_N_DAYS
List<Case> recentCases =
    [SELECT Id, Status FROM Case
     WHERE CreatedDate = LAST_N_DAYS:7];

// Bind variable date
Date cutoff = Date.today().addDays(-30);
List<Lead> staleLeads =
    [SELECT Id FROM Lead
     WHERE CreatedDate < :cutoff
     AND IsConverted = false];
⚙️

Dynamic SOQL

Build SOQL strings at runtime using Database.query(). Use carefully — prone to SOQL injection if not escaped.

  • Database.query(soqlString) — returns a List<SObject>
  • Always use String.escapeSingleQuotes() on user input
  • Bind variables are not available in dynamic SOQL string
  • Use when fields or objects are determined at runtime
// Dynamic SOQL — build query from parameters
String objectName = 'Account';
String fieldList  = 'Id, Name, Industry';
String filterValue = String.escapeSingleQuotes(userInput);

String soql = 'SELECT ' + fieldList
            + ' FROM ' + objectName
            + ' WHERE Name LIKE \'%' + filterValue + '%\''
            + ' LIMIT 100';

List<SObject> results = Database.query(soql);
for (SObject rec : results) {
    System.debug(rec.get('Name'));
}
🛡️

WITH SECURITY_ENFORCED

Enforce field- and object-level security directly inside a SOQL query — available since API 48.0.

  • Throws System.QueryException if the running user lacks access to any queried field or object
  • Replaces manual Schema.DescribeFieldResult FLS checks
  • Only applies to fields in the SELECT clause and WHERE condition
  • Use in with sharing classes for defence-in-depth
// SOQL with field-level security enforcement
try {
    List<Account> accs = [SELECT Id, Name, AnnualRevenue
                           FROM Account
                           WITH SECURITY_ENFORCED
                           LIMIT 100];
    // Proceeds only if user can read all 3 fields
} catch (System.QueryException e) {
    // User lacks access to one or more fields
    System.debug('FLS violation: ' + e.getMessage());
}

Relationship Queries

SOQL supports traversing parent-child and child-parent relationships in a single query, eliminating the need for separate queries per related object.

Child-to-Parent (Dot Notation)

Access parent fields from a child record query using dot notation on the relationship field name.

// From Contact, access parent Account fields
List<Contact> contacts =
    [SELECT Id, FirstName, LastName,
            Account.Name, Account.Industry,
            Account.Owner.Name  // traverse 2 levels
     FROM Contact
     WHERE Account.Type = 'Customer'];

for (Contact c : contacts) {
    String msg = c.FirstName + ' works at '
               + c.Account.Name;
    System.debug(msg);
}

Parent-to-Children (Sub-select)

Retrieve related child records in a nested query using the child relationship name (plural, e.g., Contacts).

// From Account, get related Opportunities
List<Account> accsWithOpps =
    [SELECT Id, Name,
            (SELECT Id, Name, Amount, StageName
             FROM Opportunities
             WHERE StageName != 'Closed Lost'
             ORDER BY Amount DESC)
     FROM Account
     WHERE Type = 'Customer'];

for (Account acc : accsWithOpps) {
    for (Opportunity opp : acc.Opportunities) {
        System.debug(acc.Name + ' / ' + opp.Name);
    }
}

Aggregate Queries

SOQL supports aggregate functions for counting, summing, averaging, and grouping records without loading them into heap memory.

Aggregate Functions & GROUP BY

// COUNT, SUM, AVG, MIN, MAX
AggregateResult[] summary =
    [SELECT StageName,
            COUNT(Id) cnt,
            SUM(Amount) total,
            AVG(Amount) average
     FROM Opportunity
     WHERE CloseDate = THIS_YEAR
     GROUP BY StageName
     ORDER BY SUM(Amount) DESC];

for (AggregateResult ar : summary) {
    String stage = (String)  ar.get('StageName');
    Integer count = (Integer) ar.get('cnt');
    Decimal total = (Decimal) ar.get('total');
    System.debug(stage + ': ' + count
                + ' deals, $' + total);
}

// HAVING — filter on aggregate result (like SQL HAVING)
AggregateResult[] bigStages =
    [SELECT StageName, SUM(Amount) total
     FROM Opportunity
     GROUP BY StageName
     HAVING SUM(Amount) > 100000];
AggregateResult: Always cast results from ar.get('alias') explicitly — the return type is Object. Use the field alias you define in the query or Salesforce's default alias format (expr0, expr1...).

SOSL — Salesforce Object Search Language

SOSL performs full-text search across multiple objects simultaneously. Use it when you need to search across fields and object types in one query.

SOSL Syntax & Usage

// SOSL — search across multiple objects
String searchTerm = 'cloud';
List<List<SObject>> results =
    [FIND :searchTerm
     IN ALL FIELDS  // or NAME FIELDS, EMAIL FIELDS, PHONE FIELDS
     RETURNING
         Account(Id, Name WHERE Industry = 'Technology'),
         Contact(Id, FirstName, LastName, Email),
         Lead(Id, FirstName, LastName, Company)
     LIMIT 20];

List<Account> accounts = (List<Account>) results[0];
List<Contact> contacts = (List<Contact>) results[1];
List<Lead>    leads    = (List<Lead>)    results[2];

System.debug('Accounts: ' + accounts.size());
System.debug('Contacts: ' + contacts.size());
⚠ SOSL vs SOQL: SOSL is a full-text search engine (searches indexed text). SOQL is a structured query (exact field matching). Use SOSL for "search box" scenarios; use SOQL for exact lookups. SOSL counts as 1 query against the 100-query governor.

DML Operations

DML (Data Manipulation Language) statements persist changes to the Salesforce database. All six operations count against the 150-statement governor limit.

➕

insert

Creates new records. Sets the Id field on each record after success.

  • All required fields must be populated
  • Throws DmlException on failure (allOrNone = true)
  • Use Database.insert(list, false) for partial success
// Bulk insert — always prefer bulk over single
List<Contact> newContacts = new List<Contact>();
for (Integer i = 0; i < 5; i++) {
    newContacts.add(new Contact(
        FirstName = 'User',
        LastName  = 'Test' + i,
        Email     = 'user' + i + '@test.com'
    ));
}
insert newContacts; // 1 DML statement, 5 rows

// Id is populated after insert
System.debug(newContacts[0].Id); // now has an 18-char Id
✏️

update & upsert

update modifies existing records. upsert inserts or updates based on an external ID.

  • update — record must have a populated Id
  • upsert — uses Salesforce Id or a specified External Id field
  • Only dirty (changed) fields are sent to the database
  • upsert list ExternalId__c — upsert on custom external ID
// update
List<Opportunity> toClose =
    [SELECT Id, StageName FROM Opportunity
     WHERE CloseDate < TODAY AND StageName != 'Closed Lost'];
for (Opportunity opp : toClose) {
    opp.StageName = 'Closed Lost';
    opp.Description = 'Auto-closed by batch';
}
update toClose;

// upsert on external ID
List<Account> accounts = parseCSV(); // from callout
upsert accounts ExternalId__c; // match on ExternalId__c
🗑️

delete, undelete & merge

Complete the DML toolkit with soft-delete, restore, and duplicate-merge operations.

  • delete — moves records to the Recycle Bin (soft delete)
  • undelete — restores from Recycle Bin within 15 days
  • merge master duplicate1, duplicate2 — merges up to 2 dupes into master
  • Merge is only available for Account, Contact, Lead, Case
// delete
List<Lead> junk = [SELECT Id FROM Lead WHERE IsConverted = false
                    AND CreatedDate < LAST_N_YEARS:2];
delete junk;

// undelete
List<Lead> restored = [SELECT Id FROM Lead
                         WHERE IsDeleted = true ALL ROWS];
undelete restored;

// merge — merge two duplicate contacts into master
Contact master = [SELECT Id FROM Contact WHERE Id = :masterId];
Contact dupe1  = [SELECT Id FROM Contact WHERE Id = :dupeId1];
merge master dupe1;
🧩

Database Class Methods

The Database class provides finer control than DML keywords, including partial success.

  • Database.insert(list, false) — allow partial success
  • Returns SaveResult[] — inspect per-row success/failure
  • Database.upsert(list, field, false)
  • Database.delete(list, false)
  • Also provides Database.setSavepoint() and Database.rollback()
// Partial success DML
List<Account> mixed = getMixedList(); // some valid, some not
Database.SaveResult[] results =
    Database.insert(mixed, false); // false = allow partial

for (Integer i = 0; i < results.size(); i++) {
    if (!results[i].isSuccess()) {
        for (Database.Error err : results[i].getErrors()) {
            System.debug('Row ' + i + ' failed: '
                + err.getMessage()
                + ' Fields: ' + err.getFields());
        }
    }
}

// Savepoint for manual rollback
Savepoint sp = Database.setSavepoint();
try {
    insert riskyRecord;
    callExternalSystem(); // may throw
} catch (Exception e) {
    Database.rollback(sp); // roll back only to savepoint
    throw e;
}

Best Practices

Never SOQL or DML Inside Loops

The single most important Apex rule. Query outside the loop, build a Map for lookup, collect changes in a List, then DML once after the loop.

❌ for (Opp o : opps) { Account a = [SELECT Id FROM Account WHERE Id = :o.AccountId]; }
✅ Map<Id,Account> m = new Map<Id,Account>([SELECT Id FROM Account WHERE Id IN :ids]);

Always Use Bind Variables

Never concatenate user-supplied values directly into a SOQL string. Bind variables prevent SOQL injection and are automatically escaped.

❌ [SELECT Id FROM Account WHERE Name = '" + name + "']
✅ [SELECT Id FROM Account WHERE Name = :name]

Use WITH SECURITY_ENFORCED

Enforce field-level security inside SOQL queries rather than writing manual FLS checks for every field.

❌ [SELECT SSN__c FROM Contact] // bypasses FLS
✅ [SELECT SSN__c FROM Contact WITH SECURITY_ENFORCED]

SELECT Only Needed Fields

Requesting unnecessary fields wastes heap memory and increases query time. There is no SELECT * — every field must be explicitly named.

❌ [SELECT Id, Name, Field1, Field2 ... Field50 FROM Account]
✅ [SELECT Id, Name FROM Account] // only what you need

Use Database.insert for Partial Success

When processing data from external systems, allow valid rows to commit while collecting errors for invalid rows instead of failing the whole batch.

❌ insert records; // all 500 fail if 1 is bad
✅ Database.insert(records, false); // 499 succeed

Use Aggregate Queries for Counts & Totals

Never load records into memory just to count them. Use COUNT(Id) in SOQL to count at the database level.

❌ Integer cnt = [SELECT Id FROM Account].size(); // 50k rows
✅ Integer cnt = [SELECT COUNT() FROM Account];
