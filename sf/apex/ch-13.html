Schema.describe — Runtime Reflection

The Schema class provides runtime access to org metadata — objects, fields, picklist values, relationships — without hardcoding names.

🔍

Describing Objects & Fields

Inspect sObject and field metadata at runtime using DescribeSObjectResult and DescribeFieldResult.

  • Schema.getGlobalDescribe()
  • Schema.describeSObjects()
  • .getFields() returns field map
  • .isAccessible() / .isCreateable()
  • Field type: .getType()
  • Label vs API name
// Describe an sObject at runtime
Schema.DescribeSObjectResult describeResult =
    Schema.SObjectType.Account;

System.debug('Label: '    + describeResult.getLabel());
System.debug('Plural: '   + describeResult.getLabelPlural());
System.debug('Key Prefix: '+ describeResult.getKeyPrefix()); // '001'
System.debug('Createable: '+ describeResult.isCreateable());
System.debug('Deletable: ' + describeResult.isDeletable());

// Get all fields on an object
Map<String, Schema.SObjectField> fieldMap =
    Schema.SObjectType.Account.fields.getMap();

for (String fieldApiName : fieldMap.keySet()) {
    Schema.DescribeFieldResult field =
        fieldMap.get(fieldApiName).getDescribe();

    System.debug(
        fieldApiName + ' | ' +
        field.getLabel() + ' | ' +
        field.getType() + ' | ' +
        'Accessible: ' + field.isAccessible()
    );
}

// Check a specific field
Schema.DescribeFieldResult annualRevField =
    Schema.SObjectType.Account.fields.AnnualRevenue.getDescribe();

System.debug('Type: '   + annualRevField.getType());   // CURRENCY
System.debug('Length: ' + annualRevField.getPrecision());
System.debug('Required: '+ !annualRevField.isNillable());
📋

Picklist Values at Runtime

Retrieve valid picklist values programmatically — for dynamic UI or validation logic.

  • .getPicklistValues()
  • Returns PicklistEntry[]
  • .getValue() — API value
  • .getLabel() — display label
  • .isActive() — skip inactive
  • .isDefaultValue()
// Get all active picklist values for Opportunity.StageName
Schema.DescribeFieldResult stageField =
    Schema.SObjectType.Opportunity.fields.StageName.getDescribe();

List<String> activeStages = new List<String>();
for (Schema.PicklistEntry entry : stageField.getPicklistValues()) {
    if (entry.isActive()) {
        activeStages.add(entry.getValue());
        System.debug(
            'Value: ' + entry.getValue() +
            ' | Label: ' + entry.getLabel() +
            ' | Default: ' + entry.isDefaultValue()
        );
    }
}
// activeStages = ['Prospecting','Qualification','Closed Won',...]

// Validate a value at runtime
public static Boolean isValidStage(String stage) {
    Schema.DescribeFieldResult field =
        Schema.SObjectType.Opportunity.fields.StageName.getDescribe();
    for (Schema.PicklistEntry e : field.getPicklistValues()) {
        if (e.isActive() && e.getValue() == stage) return true;
    }
    return false;
}
🔗

Relationship Describe

Traverse object relationships programmatically — discover parent and child objects at runtime.

  • .getReferenceTo() — parent objects
  • .getChildRelationships()
  • .getRelationshipName()
  • Enables generic relationship traversal
  • Used in migration and analysis tools
  • Powers dynamic SOQL builders
// Find all lookup fields on an object
Schema.DescribeSObjectResult objDescribe =
    Schema.SObjectType.Opportunity;

Map<String, Schema.SObjectField> fields =
    objDescribe.fields.getMap();

System.debug('=== Lookup fields on Opportunity ===');
for (String fieldName : fields.keySet()) {
    Schema.DescribeFieldResult f =
        fields.get(fieldName).getDescribe();
    if (f.getType() == Schema.DisplayType.REFERENCE) {
        System.debug(fieldName + ' → '
            + f.getReferenceTo()[0]); // parent object
    }
}

// List all child relationship names
Schema.DescribeSObjectResult acctDescribe =
    Schema.SObjectType.Account;
for (Schema.ChildRelationship cr :
        acctDescribe.getChildRelationships()) {
    System.debug(
        cr.getRelationshipName() +  // e.g., 'Opportunities'
        ' ← ' + cr.getChildSObject() // child sObject type
    );
}

Global Describe & Object Existence Checks

Check if objects and fields exist before using them — essential for managed packages and multi-org code.

  • Schema.getGlobalDescribe()
  • Returns all accessible sObject types
  • Check .containsKey(apiName)
  • Use for conditional logic based on installed packages
  • Expensive — cache the result
  • Prefer Schema.describeSObjects() for single objects
// Check if a custom object exists (useful in managed packages)
public static Boolean objectExists(String apiName) {
    return Schema.getGlobalDescribe().containsKey(apiName);
}

// Check if a field exists on an object
public static Boolean fieldExists(
        String objectApiName, String fieldApiName) {
    Map<String, Schema.SObjectType> globalMap =
        Schema.getGlobalDescribe();
    if (!globalMap.containsKey(objectApiName)) return false;

    Schema.SObjectType sObjType = globalMap.get(objectApiName);
    return sObjType.getDescribe()
                   .fields.getMap()
                   .containsKey(fieldApiName);
}

// Usage
if (objectExists('MyPackage__Custom_Object__c')) {
    // Package is installed, safe to use custom object
}

if (fieldExists('Account', 'Custom_Field__c')) {
    // Field exists, safe to include in SOQL
}

// Get sObject type from API name string
Schema.SObjectType sObjType =
    Schema.getGlobalDescribe().get('Account');
SObject newRecord = sObjType.newSObject();
newRecord.put('Name', 'ACME'); // dynamic field set
insert newRecord;

Dynamic SOQL

Build SOQL queries at runtime when the fields, objects, or conditions aren't known until execution. Always escape user input to prevent SOQL injection.

Safe Dynamic SOQL Patterns

// Dynamic SOQL builder — whitelist-validated fields
public with sharing class DynamicQueryBuilder {

    public static List<SObject> query(
            String objectApiName,
            List<String> requestedFields,
            String whereClause,
            Integer maxRows) {

        // 1. Validate object exists
        Map<String, Schema.SObjectType> globalDescribe =
            Schema.getGlobalDescribe();
        if (!globalDescribe.containsKey(objectApiName)) {
            throw new IllegalArgumentException(
                'Unknown object: ' + objectApiName);
        }

        // 2. Whitelist fields — only include fields user can read
        Schema.DescribeSObjectResult objDescribe =
            globalDescribe.get(objectApiName).getDescribe();
        Map<String, Schema.SObjectField> validFields =
            objDescribe.fields.getMap();

        List<String> safeFields = new List<String>{'Id'};
        for (String f : requestedFields) {
            String lower = f.toLowerCase();
            if (validFields.containsKey(lower) &&
                    validFields.get(lower).getDescribe()
                               .isAccessible()) {
                safeFields.add(lower);
            }
        }

        // 3. Build query string
        String soql = 'SELECT ' + String.join(safeFields, ', ')
            + ' FROM ' + String.escapeSingleQuotes(objectApiName);

        if (String.isNotBlank(whereClause)) {
            // Note: whereClause must be pre-validated by caller
            soql += ' WHERE ' + whereClause;
        }

        soql += ' WITH SECURITY_ENFORCED LIMIT '
            + (maxRows != null ? maxRows : 100);

        return Database.query(soql);
    }
}

// Usage
List<SObject> results = DynamicQueryBuilder.query(
    'Account',
    new List<String>{'Name','Industry','AnnualRevenue'},
    'Type = \'Customer\'',
    50
);

Dynamic DML & sObject Manipulation

Setting and Getting Field Values Dynamically

// Dynamic field access — key/value pairs on sObjects
SObject record = new Account();

// Set fields dynamically using string field names
record.put('Name',          'ACME Corp');
record.put('Industry',      'Technology');
record.put('AnnualRevenue', 5000000);

insert record;

// Get fields dynamically
String name    = (String)  record.get('Name');
Decimal rev    = (Decimal) record.get('AnnualRevenue');
Id recordId    = (Id)      record.get('Id');

// Copy fields between records dynamically
public static void copyFields(
        SObject source,
        SObject target,
        List<String> fieldNames) {
    for (String field : fieldNames) {
        target.put(field, source.get(field));
    }
}

// Dynamic DML on any sObject type
public static void bulkUpdate(
        List<SObject> records,
        String fieldName,
        Object value) {
    for (SObject rec : records) {
        rec.put(fieldName, value);
    }
    update records;
}

// Create sObject from type name at runtime
Schema.SObjectType sType =
    Schema.getGlobalDescribe().get('Opportunity');
SObject newOpp = sType.newSObject();
newOpp.put('Name', 'Dynamic Opp');
newOpp.put('StageName', 'Prospecting');
newOpp.put('CloseDate', Date.today().addDays(30));
insert newOpp;

Field Sets

Field Sets let admins configure which fields appear in a UI or query — without code changes. Defined in Setup, consumed in Apex.

Using Field Sets in SOQL

// Field Set defined in Setup → Object Manager → Field Sets
// Name: Account_Summary_Fields

public with sharing class AccountController {

    @AuraEnabled(cacheable=true)
    public static List<Account> getAccountsWithFieldSet(
            String fieldSetName) {

        // 1. Get field set from schema
        Schema.FieldSet fs = Schema.SObjectType.Account
            .fieldSets.getMap().get(fieldSetName);

        if (fs == null) {
            throw new IllegalArgumentException(
                'Field set not found: ' + fieldSetName);
        }

        // 2. Build field list from field set
        List<String> fields = new List<String>{'Id'};
        for (Schema.FieldSetMember fsm : fs.getFields()) {
            // Only include accessible fields
            if (fsm.getSObjectField().getDescribe().isAccessible()) {
                fields.add(fsm.getFieldPath());
            }
        }

        // 3. Build and execute dynamic SOQL
        String soql = 'SELECT ' + String.join(fields, ',')
            + ' FROM Account WITH SECURITY_ENFORCED LIMIT 100';

        return Database.query(soql);
    }
}

// In LWC, call: getAccountsWithFieldSet('Account_Summary_Fields')
// Admin adds/removes fields in Setup — no code change needed!
Admin-friendly: Field Sets allow non-developers to control which fields appear in your UI by adding/removing fields in Setup. The Apex code reads whatever the admin configured — zero redeployment required.

Custom Metadata Types & Custom Settings

Custom Metadata Types (CMT)

CMT records are metadata — deployed via SFDX, included in packages, and queryable in Apex. Perfect for configuration that needs to work across environments.

// Query Custom Metadata Type
// CMT: Discount_Rule__mdt
// Fields: Object_Name__c, Min_Amount__c, Discount_Pct__c

List<Discount_Rule__mdt> rules =
    [SELECT Object_Name__c,
            Min_Amount__c,
            Discount_Pct__c
     FROM Discount_Rule__mdt
     WHERE Object_Name__c = 'Opportunity'
     ORDER BY Min_Amount__c DESC];

public static Decimal getDiscount(Decimal amount) {
    for (Discount_Rule__mdt rule : rules) {
        if (amount >= rule.Min_Amount__c) {
            return rule.Discount_Pct__c;
        }
    }
    return 0;
}

Custom Settings

Custom Settings are org-specific key-value pairs not deployed with packages. Good for environment-specific config (sandbox URLs, feature flags).

// Hierarchy Custom Setting: Integration_Config__c
// Fields: Endpoint_URL__c, API_Key__c, Timeout_ms__c

// Get settings for current user's context
Integration_Config__c cfg =
    Integration_Config__c.getInstance();
// Checks: User → Profile → Org hierarchy

if (cfg == null) {
    throw new ConfigException(
        'Integration_Config__c not configured');
}

String endpoint = cfg.Endpoint_URL__c;
Integer timeout = Integer.valueOf(cfg.Timeout_ms__c);

// List Custom Setting (key-value store)
// Get a specific key
My_Settings__c setting =
    My_Settings__c.getValues('FeatureFlag_NewUI');
Boolean enabled = setting != null
    && setting.Value__c == 'true';

Best Practices

Cache Schema Describes

Schema.getGlobalDescribe() is expensive. Cache the result in a static variable within the transaction rather than calling it repeatedly.

❌ Schema.getGlobalDescribe().get(name); // called 50x in loop
✅ private static Map<...> globalMap = Schema.getGlobalDescribe();

Whitelist Object & Field Names

Never use user-supplied strings directly in dynamic SOQL object/field names. Validate against Schema.getGlobalDescribe() first.

❌ 'SELECT ' + userField + ' FROM ' + userObj
✅ Validate userField in validFields.keySet() first

Prefer CMT Over Custom Settings for Config

Custom Metadata Types are deployable, packageable, and version-controlled. Custom Settings are org-specific and cannot be packaged (except Hierarchy).

❌ Custom Setting for integration endpoint (breaks in sandbox)
✅ CMT for config (deployed per environment via SFDX)

Use Field Sets for Admin-Controlled Layouts

When admins need to control which fields appear in a UI component, use Field Sets. It avoids code changes for field additions.

❌ Hardcoded SELECT Id, Name, Phone FROM Account
✅ Read field set, build dynamic SELECT from admin config
