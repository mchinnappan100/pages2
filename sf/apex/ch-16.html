Relationship Queries

SOQL can traverse relationships in a single query, eliminating the need for separate queries per related object.

⬆️

Child-to-Parent (Dot Notation)

Access parent object fields from a child query using dot notation on the relationship name.

  • Use relationship name, not field name
  • AccountId field → Account.Name
  • Up to 5 levels deep
  • Custom lookup: My_Object__r.Name
  • Can filter in WHERE on parent fields
  • No extra SOQL consumed
// Standard lookup: AccountId → Account relationship
List<Contact> contacts = [
    SELECT Id, FirstName, LastName, Email,
           Account.Name,           // parent field
           Account.Industry,       // parent field
           Account.Owner.Name,     // 2 levels up (Account → User)
           Account.Owner.Email
    FROM Contact
    WHERE Account.Type = 'Customer'  // filter on parent field
      AND Account.AnnualRevenue > 500000
    ORDER BY Account.Name, LastName
];

for (Contact c : contacts) {
    System.debug(c.FirstName + ' at ' + c.Account.Name);
}

// Custom lookup field: Opportunity.Custom_Object__c lookup
// Field API name: Custom_Object__c
// Relationship name: Custom_Object__r
List<Opportunity> opps = [
    SELECT Id, Name,
           Custom_Object__r.Name,        // parent field
           Custom_Object__r.Status__c    // parent field
    FROM Opportunity
    WHERE Custom_Object__r.Status__c = 'Active'
];

// Polymorphic lookup (Who/What fields on Activity)
List<Task> tasks = [
    SELECT Id, Subject,
           Who.Name,    // Lead or Contact
           What.Name    // Account, Opportunity, etc.
    FROM Task
    WHERE ActivityDate = THIS_WEEK
];
⬇️

Parent-to-Child (Sub-select)

Retrieve related child records nested inside the parent query using the child relationship name.

  • Nested SELECT inside parentheses
  • Use child relationship name (plural)
  • Standard: Contacts, Opportunities
  • Custom: Custom_Objects__r
  • Up to 20 sub-selects per query
  • Max 600 rows per sub-select
// Account with related Contacts and Opportunities
List<Account> accountsWithChildren = [
    SELECT Id, Name, Industry,
           // Sub-select: child Contacts
           (SELECT Id, FirstName, LastName, Email
            FROM Contacts
            WHERE DoNotCall = false
            ORDER BY LastName
            LIMIT 10),
           // Sub-select: child Opportunities
           (SELECT Id, Name, StageName, Amount
            FROM Opportunities
            WHERE IsClosed = false
            ORDER BY Amount DESC
            LIMIT 5)
    FROM Account
    WHERE Type = 'Customer'
      AND Id IN (SELECT AccountId FROM Opportunity
                  WHERE StageName = 'Closed Won')
    LIMIT 50
];

for (Account acc : accountsWithChildren) {
    System.debug('Account: ' + acc.Name);

    // Access nested contacts
    if (acc.Contacts != null) {
        for (Contact c : acc.Contacts) {
            System.debug('  Contact: ' + c.FirstName);
        }
    }

    // Access nested opportunities
    if (acc.Opportunities != null) {
        for (Opportunity o : acc.Opportunities) {
            System.debug('  Opp: ' + o.Name
                + ' $' + o.Amount);
        }
    }
}

// Custom child relationship
List<Account> accs = [
    SELECT Id, Name,
           (SELECT Id, Name FROM Custom_Objects__r
            WHERE Status__c = 'Active')
    FROM Account
];
🔀

Polymorphic Queries & TYPEOF

Handle polymorphic relationships (Who/What on Activity) using TYPEOF to safely access type-specific fields.

  • Who = Lead or Contact
  • What = Account, Opportunity, Case, etc.
  • TYPEOF enables type-conditional field selection
  • Avoids QueryException on wrong-type fields
  • ELSE clause for unknown types
  • Use instanceof in Apex after query
// TYPEOF — handles polymorphic Who/What fields safely
List<Event> events = [
    SELECT Id, Subject, ActivityDate,
           TYPEOF Who
               WHEN Lead    THEN Id, FirstName, LastName, Company
               WHEN Contact THEN Id, FirstName, LastName, AccountId
               ELSE         Id, Name
           END,
           TYPEOF What
               WHEN Account     THEN Id, Name, Industry
               WHEN Opportunity THEN Id, Name, StageName, Amount
               ELSE             Id, Name
           END
    FROM Event
    WHERE ActivityDate = THIS_WEEK
];

for (Event e : events) {
    if (e.Who instanceof Lead) {
        Lead l = (Lead) e.Who;
        System.debug('Lead: ' + l.FirstName + ' at ' + l.Company);
    } else if (e.Who instanceof Contact) {
        Contact c = (Contact) e.Who;
        System.debug('Contact: ' + c.FirstName);
    }

    if (e.What instanceof Opportunity) {
        Opportunity opp = (Opportunity) e.What;
        System.debug('Linked to Opp: ' + opp.Name
            + ' (' + opp.StageName + ')');
    }
}
📊

Relationship Limits

Know the relationship query limits to design queries that stay within governor bounds.

  • 5 levels max — parent-to-parent-to-parent...
  • 20 sub-selects max per query
  • 600 child records max per sub-select
  • Counts as 1 SOQL query total
  • All child rows count toward 50k row limit
  • Use pagination for large child sets

Aggregate Functions

COUNT, SUM, AVG, MIN, MAX

// Aggregate functions without GROUP BY — single row result
AggregateResult[] totals = [
    SELECT COUNT(Id)       total,
           COUNT(Email)    withEmail,   // counts non-null values
           SUM(Amount)     totalAmount,
           AVG(Amount)     avgAmount,
           MIN(Amount)     minAmount,
           MAX(Amount)     maxAmount,
           MIN(CloseDate)  earliest,
           MAX(CloseDate)  latest
    FROM Opportunity
    WHERE StageName = 'Closed Won'
      AND CloseDate = THIS_YEAR
];

AggregateResult ar = totals[0];
Integer    total    = (Integer) ar.get('total');
Decimal    sum      = (Decimal) ar.get('totalAmount');
Decimal    avg      = (Decimal) ar.get('avgAmount');
Date       earliest = (Date)    ar.get('earliest');

// COUNT() without argument — no alias, returns Integer directly
Integer cnt = [SELECT COUNT() FROM Opportunity
                WHERE StageName = 'Closed Won'];

// COUNT(field) — counts non-null values; has alias
AggregateResult[] withAlias = [
    SELECT COUNT(Id) total FROM Opportunity
];
Integer count = (Integer) withAlias[0].get('total');
03

GROUP BY & Rollup

GROUP BY, ROLLUP, CUBE

// Basic GROUP BY — one group dimension
AggregateResult[] byStage = [
    SELECT StageName,
           COUNT(Id)    dealCount,
           SUM(Amount)  totalAmount,
           AVG(Amount)  avgDealSize
    FROM Opportunity
    WHERE CloseDate = THIS_YEAR
    GROUP BY StageName
    ORDER BY SUM(Amount) DESC
];

for (AggregateResult ar : byStage) {
    System.debug(
        ar.get('StageName') + ': ' +
        ar.get('dealCount') + ' deals, $' +
        ar.get('totalAmount')
    );
}

// Multiple GROUP BY dimensions
AggregateResult[] byOwnerAndStage = [
    SELECT OwnerId, StageName,
           COUNT(Id) cnt, SUM(Amount) total
    FROM Opportunity
    WHERE CloseDate = THIS_QUARTER
    GROUP BY OwnerId, StageName
    ORDER BY OwnerId
];

// GROUP BY ROLLUP — adds subtotal rows
// Each null grouping key = a subtotal
AggregateResult[] withRollup = [
    SELECT LeadSource, StageName,
           COUNT(Id) cnt, SUM(Amount) total
    FROM Opportunity
    GROUP BY ROLLUP(LeadSource, StageName)
];

// GROUP BY CUBE — cross-product of all groupings
AggregateResult[] withCube = [
    SELECT Industry, Type, COUNT(Id) cnt
    FROM Account
    GROUP BY CUBE(Industry, Type)
];

// GROUPING() function — identifies rollup rows
// Returns 1 if that dimension is a subtotal, 0 if real value
AggregateResult[] tagged = [
    SELECT LeadSource, COUNT(Id) cnt,
           GROUPING(LeadSource) isSubtotal
    FROM Opportunity
    GROUP BY ROLLUP(LeadSource)
];
04

HAVING — Filter on Aggregate Results

HAVING vs WHERE

// WHERE filters BEFORE aggregation (on individual rows)
// HAVING filters AFTER aggregation (on group results)

// Find stages with more than 5 deals and total > $100k
AggregateResult[] bigStages = [
    SELECT StageName,
           COUNT(Id)   dealCount,
           SUM(Amount) total
    FROM Opportunity
    WHERE CloseDate = THIS_YEAR        // pre-aggregation filter
    GROUP BY StageName
    HAVING COUNT(Id) > 5               // post-aggregation filter
       AND SUM(Amount) > 100000
    ORDER BY SUM(Amount) DESC
];

// Accounts with more than 3 open opportunities
AggregateResult[] hotAccounts = [
    SELECT AccountId, COUNT(Id) openOpps
    FROM Opportunity
    WHERE IsClosed = false
    GROUP BY AccountId
    HAVING COUNT(Id) >= 3
    ORDER BY COUNT(Id) DESC
];

// Get the AccountIds from aggregate result
Set<Id> hotAccountIds = new Set<Id>();
for (AggregateResult ar : hotAccounts) {
    hotAccountIds.add((Id) ar.get('AccountId'));
}
List<Account> hotAccList = [
    SELECT Id, Name FROM Account WHERE Id IN :hotAccountIds
];

// Average deal size over $50k by industry
AggregateResult[] premiumIndustries = [
    SELECT Account.Industry,
           AVG(Amount)  avgDeal,
           COUNT(Id)    deals
    FROM Opportunity
    WHERE StageName = 'Closed Won'
    GROUP BY Account.Industry
    HAVING AVG(Amount) > 50000
       AND COUNT(Id) >= 3
    ORDER BY AVG(Amount) DESC
];

Dynamic SOQL — Advanced Patterns

Parameterised Query Builder

// Advanced dynamic SOQL with filters, pagination, sorting
public with sharing class SoqlBuilder {

    private String objectName;
    private List<String> fields    = new List<String>{'Id'};
    private List<String> filters   = new List<String>();
    private String orderByField    = 'CreatedDate';
    private Boolean ascending      = false;
    private Integer limitRows      = 50;
    private Integer offsetRows     = 0;

    public SoqlBuilder forObject(String obj) {
        // Validate object exists
        if (!Schema.getGlobalDescribe().containsKey(obj)) {
            throw new IllegalArgumentException('Invalid object: ' + obj);
        }
        this.objectName = obj;
        return this;
    }

    public SoqlBuilder selectFields(List<String> f) {
        // Validate each field against schema
        Schema.DescribeSObjectResult d =
            Schema.getGlobalDescribe().get(objectName).getDescribe();
        Map<String, Schema.SObjectField> validFields =
            d.fields.getMap();
        for (String field : f) {
            if (validFields.containsKey(field.toLowerCase())) {
                this.fields.add(field);
            }
        }
        return this;
    }

    public SoqlBuilder whereEquals(String field, String value) {
        // Escape value to prevent injection
        this.filters.add(field + ' = \''
            + String.escapeSingleQuotes(value) + '\'');
        return this;
    }

    public SoqlBuilder orderBy(String field, Boolean asc) {
        this.orderByField = field;
        this.ascending    = asc;
        return this;
    }

    public SoqlBuilder limit(Integer n)  { this.limitRows  = n; return this; }
    public SoqlBuilder offset(Integer n) { this.offsetRows = n; return this; }

    public List<SObject> execute() {
        String soql = 'SELECT ' + String.join(fields, ', ')
            + ' FROM ' + objectName;
        if (!filters.isEmpty()) {
            soql += ' WHERE ' + String.join(filters, ' AND ');
        }
        soql += ' WITH SECURITY_ENFORCED';
        soql += ' ORDER BY ' + orderByField
                + (ascending ? ' ASC' : ' DESC');
        soql += ' LIMIT '  + limitRows;
        if (offsetRows > 0) soql += ' OFFSET ' + offsetRows;
        return Database.query(soql);
    }
}

// Usage — fluent builder
List<SObject> results = new SoqlBuilder()
    .forObject('Account')
    .selectFields(new List<String>{'Name','Industry','AnnualRevenue'})
    .whereEquals('Type', 'Customer')
    .orderBy('AnnualRevenue', false)
    .limit(25)
    .execute();

Best Practices

Use Relationship Names, Not Field Names

In child-to-parent traversal, the relationship name (no __c) is used, not the field API name. Custom: Custom__r; Standard: Account.

❌ SELECT AccountId.Name FROM Contact
✅ SELECT Account.Name FROM Contact

Always Null-Check Sub-select Results

If no child records exist, the sub-select returns null (not an empty list). Always null-check before iterating.

❌ for (Contact c : acc.Contacts) { } // NullPointerException
✅ if (acc.Contacts != null) { for (Contact c : acc.Contacts) { } }

Use Alias in Aggregate Queries

Always alias aggregate results. Without an alias, Salesforce auto-generates expr0, expr1... which is fragile.

❌ SELECT COUNT(Id) FROM Opportunity // ar.get('expr0')
✅ SELECT COUNT(Id) total // ar.get('total')

Cast Aggregate Results Explicitly

ar.get() returns Object. Always cast to the correct type — SUM → Decimal, COUNT → Integer, MIN/MAX Date → Date.

❌ Integer cnt = ar.get('total'); // ClassCastException
✅ Integer cnt = (Integer) ar.get('total');

Validate Object/Field Names in Dynamic SOQL

Never concatenate unvalidated strings. Always check against Schema.getGlobalDescribe() or the object's field map before building the query string.

❌ 'SELECT ' + userField + ' FROM ' + userObj
✅ Validate both against Schema before concatenating

Use HAVING Not WHERE for Post-Aggregate Filters

WHERE on aggregate functions causes a compile error. Use HAVING to filter on the results of COUNT, SUM, AVG, etc.

❌ WHERE COUNT(Id) > 5 // compile error
✅ HAVING COUNT(Id) > 5
