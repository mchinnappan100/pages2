Chapter 02 · Code Generation

AI-Powered Code Generation

How to use AI to generate production-quality Apex classes, LWC components, SOQL queries, and Flow designs — with concrete prompt templates, before/after examples, and real productivity measurements for each area.

Reading time: ~35 min
Multiplier: 4–10×
Key tools: Claude · GitHub Copilot · sf-apex-codegen

Code generation is the highest-ROI application of AI for Salesforce developers. The Salesforce platform has well-defined patterns for Apex triggers, service classes, LWC components, SOQL queries, and automation — and AI has learned these patterns deeply from the vast body of Salesforce documentation and open-source code it was trained on. This means that for the large class of "known pattern" tasks, AI generates correct, production-ready first drafts consistently.

This chapter covers the five major code generation areas — Apex, LWC, SOQL, Flows, and refactoring — with specific prompt templates for each that you can copy, customize, and use immediately.

Apex Code Generation

Trigger Handlers and Service Classes

Apex boilerplate is the highest-multiplier code generation task. A complete FFLIB trigger handler scaffold — trigger file, handler class, selector class, domain class, and service interface — takes an experienced developer 2–3 hours to write correctly from scratch. AI generates all five files correctly in under 2 minutes from a single prompt.

Prompt Template — FFLIB Scaffold
You are a Salesforce developer using the FFLIB Apex Common framework (API 61.0).
Generate the complete FFLIB scaffold for the [OBJECT_NAME] object, including:
1. Trigger: [ObjectName]Trigger.trigger — delegates to handler only
2. Domain class: [ObjectName]s.cls — implements fflib_SObjectDomain
3. Selector class: [ObjectName]sSelector.cls — implements fflib_SObjectSelector,
   with methods: selectById(Set<Id> ids), selectByAccountId(Set<Id> accountIds)
4. Service class: [ObjectName]Service.cls — interface with processRecords(List<[Object]>) method
5. Service impl: [ObjectName]ServiceImpl.cls — implements the service interface

Key fields on [OBJECT_NAME]: [list your fields here]
Related objects: [list relationships]
Business rule: [describe the trigger's purpose in one sentence]

Before AI: 2.5 hours to scaffold all 5 files, risk of pattern inconsistencies across files, common to miss the UnitOfWork wiring on first attempt.

After AI: 8 minutes — 2 minutes for generation, 6 minutes for review and customization. Files are consistent with each other and correctly wired from the start.

Invocable Methods for Flow Actions

Invocable methods are a common Salesforce pattern but have specific requirements: proper @InvocableMethod annotation, InvocableVariable inner classes, bulk-safe logic, and correct return type wrapping. AI generates all of this correctly in one shot.

Prompt Template — Invocable Method
Write a Salesforce Apex @InvocableMethod class that can be called from a Flow.
Method name: CalculateOrderDiscount
Purpose: Apply tiered discount to an Order based on Account's tier field.

Input variables:
- orderId (Id, required): the Order record Id
- accountTier (String, required): 'Gold', 'Silver', or 'Bronze'

Output variables:
- discountPercentage (Decimal): calculated discount (Gold=15%, Silver=10%, Bronze=5%)
- statusMessage (String): human-readable result

Requirements:
- Bulk-safe: handle a List of requests
- Use a single SOQL query — do not query inside loops
- Include null checks on all inputs
- API version 61.0
Productivity Gain

Writing a well-structured, bulk-safe invocable method from scratch takes 45–60 minutes including getting the inner class structure right and adding null safety. AI generates a correct implementation in 90 seconds. Across a project with 15 invocable methods, this saves nearly 12 hours of development time.

Batch Apex and Schedulable Classes

Batch Apex has a rigid structure that is perfectly suited to AI generation. The interface methods (start, execute, finish), scope size considerations, stateful implementation, and chaining patterns are all well-known to AI.

Prompt Template — Batch Apex
Write a Salesforce Batch Apex class that processes stale Opportunity records.
Class name: StaleOpportunityBatch

Logic:
- Query Opportunities where Stage != 'Closed Won' and 'Closed Lost'
  and LastModifiedDate < LAST_N_DAYS:90
- For each record: set a custom field Stale__c = true, add a note to Description
- Batch size: 200
- After completion: send an email to a configurable admin email address
  (stored in Custom Metadata Type BatchConfig__mdt.AdminEmail__c)
  with a summary of records processed

Also write a companion Schedulable class that runs this batch nightly at 2am.

Lightning Web Component Generation

LWC components have a well-defined three-file structure (HTML, JS, XML metadata) with established patterns for wire adapters, imperative Apex calls, SLDS styling, and event handling. AI generates all three files consistently and correctly for common component patterns.

Data Table with Server-Side Pagination

Prompt Template — LWC Data Table
Generate a complete Lightning Web Component named accountContactTable with:

HTML:
- lightning-datatable showing contact records for a given Account
- Columns: Name, Email, Phone, Title, CreatedDate (formatted)
- Server-side pagination: Previous/Next buttons, current page indicator
- Search bar filtering by Name (client-side filter on current page)
- Loading spinner while data is fetching

JavaScript:
- Wire adapter to call Apex method getContactsByAccount(accountId, pageSize, offset)
- pageSize = 10, handle pagination state in component properties
- Handle errors with toast notifications using ShowToastEvent

Apex Controller (ContactController.cls):
- @AuraEnabled(cacheable=true) getContactsByAccount method
- Returns Map with 'records' (List<Contact>) and 'totalCount' (Integer)
- Bulk-safe SOQL with LIMIT and OFFSET

XML: expose accountId as public property, set target to lightning__RecordPage

API version 61.0. Use SLDS classes throughout.

Before AI: Building this component from scratch takes 4–5 hours: designing the pagination state machine, wiring the Apex, handling the loading states, and getting SLDS layout right.

After AI: 15 minutes — 5 minutes for generation, 10 minutes for review, customization to field names, and deployment to scratch org.

Custom Record Form with Validation

Prompt Template — Custom Form LWC
Generate a Lightning Web Component named caseEscalationForm that:

Purpose: Allow service agents to escalate a Case with additional context.

Form fields:
- EscalationReason__c (required picklist): 'Customer Request', 'SLA Breach', 'Executive Escalation'
- EscalationNotes__c (required textarea, max 500 chars, show character count)
- NotifyManager__c (checkbox, default true)
- EscalationDate__c (date, defaults to today, cannot be in the past)

On submit:
- Client-side validation before server call
- Call Apex EscalationService.escalateCase(caseId, formData)
- Success: show toast, fire a refreshApex, close modal if in modal context
- Error: show field-level error messages returned from Apex

Include proper @track decorators, error handling, and reset functionality.
Target: lightning__RecordPage and FlowScreen.
Productivity Gain

Custom form LWCs with validation logic, error handling, and Apex integration typically take 6–8 hours for a developer building from scratch, including debugging the validation lifecycle. AI generates a working first draft in under 5 minutes — the developer spends 30 minutes adapting field names and testing, not writing framework boilerplate.

SOQL Query Building and Optimization

SOQL has complex syntax for relationship traversal, aggregate functions, semi-joins, and dynamic binding. AI excels at constructing correct SOQL for complex requirements because it understands both the query syntax and the Salesforce object model's relationship conventions.

Complex Relationship Queries

Prompt Template — Complex SOQL
Write a SOQL query for the following requirement:

Find all Accounts where:
- Type = 'Customer'
- Annual Revenue > 1,000,000
- They have at least one Open Opportunity (Stage NOT IN closed stages)
- They have NO active Cases opened in the last 30 days (i.e. no Cases where
  Status != 'Closed' AND CreatedDate >= LAST_N_DAYS:30)

Return: Account Id, Name, AnnualRevenue, Owner.Name, count of open Opportunities,
        most recent Opportunity CloseDate

Requirements:
- Use semi-join / anti-join subqueries where appropriate
- Must be selective (explain which field(s) make it selective)
- Flag any governor limit risks for large orgs (>1M Account records)

Dynamic SOQL Builder

When a feature requires dynamic query construction based on user input, AI can generate the full dynamic SOQL builder class with SOQL injection protection, field validation against the object's describe result, and proper escaping.

Prompt Template — Dynamic SOQL with Injection Protection
Write an Apex class DynamicQueryBuilder that builds safe dynamic SOQL queries.

Requirements:
- Constructor takes SObjectType (e.g. Account.SObjectType)
- Methods: addField(String fieldName), addCondition(String field, String operator, Object value),
  setLimit(Integer n), setOrderBy(String field, Boolean ascending)
- Before adding any field or condition, validate it exists on the SObject using
  Schema.describeSObjectResult — throw IllegalArgumentException if not found
- Escape all String values using String.escapeSingleQuotes()
- Build method returns the final SOQL string
- Include usage example in a comment at the top of the class
Productivity Gain

A SOQL injection-safe dynamic query builder is a 3–4 hour implementation task — getting the describe validation right, handling all value types, and writing the tests. AI generates a complete, correct implementation in 3 minutes. The developer reviews for completeness and deploys in 20 minutes total.

Flow and Automation Design with AI

While AI cannot click through Flow Builder, it excels at designing Flow logic before you build it, generating the Apex invocable methods that Flows call, and reviewing Flow XML for logic errors. Used in this way, AI becomes the architect of your automation before you build it.

AI as Flow Logic Designer

Prompt Template — Flow Design
Design the complete logic for a Salesforce Record-Triggered Flow on the Case object.

Trigger: After a Case record is created or updated.
Business requirement: Auto-escalate Cases that breach SLA thresholds.

Design the flow covering:
1. Entry conditions (which Cases should enter the flow)
2. Decision elements and their conditions (in plain English + pseudocode)
3. What data needs to be collected (Get Records elements)
4. What actions to take (Update Records, Send Email, Create Task, call Apex)
5. Error handling paths
6. Governor limit risks and how to mitigate them

After the design, generate the Apex @InvocableMethod class the Flow should call
to calculate SLA breach status, given Case Priority and CreatedDate as inputs.

Converting Process Builder to Flow

Many orgs have Process Builder automations that need to be migrated to Flow before the sunset deadline. AI can analyze a description of the Process Builder logic and generate the equivalent Flow design plus any required Apex actions.

Prompt Template — Process Builder Migration
I need to migrate the following Process Builder automation to a Record-Triggered Flow.

Process Builder description:
Object: Opportunity
Trigger: When Opportunity is created or edited
Criteria: Stage changes to 'Closed Won' AND Amount > 50000
Actions:
1. Update related Account: set Customer_Since__c to today's date
2. Create a Task: Subject='Send Contract', Due Date = Today+3, Assigned to Opp Owner
3. Send email alert: 'Big Win Notification' to Opp Owner and their Manager

Generate:
1. The equivalent Flow design (trigger conditions, decision logic, actions)
2. Any Apex @InvocableMethod needed (if Process Builder actions cannot be done natively in Flow)
3. List of any Process Builder behaviours that do NOT translate directly to Flow and how to handle them

AI-Assisted Refactoring and Code Review

Beyond generating new code, AI is a powerful refactoring partner. Given an existing Apex class, it can identify governor limit risks, suggest bulkification improvements, apply design pattern upgrades, and rewrite code to meet current best practices.

Bulkification Audit

Prompt Template — Bulkification Review
Review this Apex code for Salesforce governor limit risks and bulkification issues.
For each issue found:
1. Identify the specific anti-pattern (SOQL in loop, DML in loop, etc.)
2. Explain why it is a risk and at what data volume it will fail
3. Provide the refactored version of that code section

[PASTE YOUR APEX CODE HERE]

After the analysis, provide the complete refactored version of the class
with all issues resolved, maintaining the same business logic.

Security Vulnerability Review

Prompt Template — Security Review
Review this Apex class for Salesforce security vulnerabilities, specifically:
- SOQL injection risks (dynamic SOQL without escaping or binding)
- FLS/CRUD enforcement — are field-level and object-level permissions checked?
- Sharing enforcement — does the class use 'with sharing' where appropriate?
- Hardcoded credentials or org-specific IDs
- Exposure of sensitive fields in debug log statements

[PASTE YOUR APEX CODE HERE]

Categorize each finding as Critical / High / Medium / Low and provide the fix.
Productivity Gain

A thorough manual security review of a 200-line Apex class by an experienced developer takes 45–60 minutes. AI completes the same review in 30 seconds and consistently catches SOQL injection, FLS bypass, and sharing enforcement gaps that humans overlook under time pressure. Running every class through an AI security review before code review costs 2 minutes per class and dramatically raises the baseline quality that reaches human reviewers.

Summary

Key Takeaways — Chapter 2
  • FFLIB scaffolding, invocable methods, and batch classes are the highest-multiplier Apex generation tasks — AI reduces 2–3 hour tasks to minutes
  • LWC generation with full three-file output (HTML + JS + XML) is highly reliable for common patterns — always specify SLDS classes, error handling requirements, and API version in your prompt
  • For complex SOQL, explicitly ask AI to identify selectivity and flag governor limit risks — it will surface issues you might miss under time pressure
  • Use AI as a Flow logic designer before building — the design document AI produces prevents rework and surfaces requirements gaps early
  • The security review prompt is the single highest-value refactoring application — run every Apex submission through it before human code review
  • Always specify your design pattern (FFLIB, trigger framework, etc.) and API version in every prompt — without this context, AI generates valid but generic Salesforce code that requires significant rework
