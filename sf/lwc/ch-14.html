Locker Service

Locker Service is Salesforce's JavaScript security framework that isolates components from each other and from the global DOM, preventing cross-component data leakage and XSS attacks.

What Locker Enforces

// Locker Service restricts:
// - document.querySelector() across shadow boundaries
// - eval() and new Function() — code injection prevention
// - Access to window object properties (some restricted)
// - Cross-namespace script injection

// Each component gets a "secure" version of window, document, etc.
// document.querySelector('c-other-component') → returns null or throws
// window.location → works (read-only in some contexts)

// Allowed: standard DOM APIs on your own shadow root
const input = this.template.querySelector('input'); // ✅ within own shadow

// Blocked: querying across namespace or accessing other components' internals
const other = document.querySelector('[data-id="other"]'); // ❌ may return null

// Lightning Web Security (LWS) — newer, stricter security mode
// Enabled by default in new orgs and Experience Cloud
// Replaces Locker Service for LWC (Locker still used for Aura)
02

Lightning Web Security (LWS)

LWS vs Locker Service

// LWS key differences from Locker:
// 1. Native DOM access — direct access to native DOM nodes (not wrapped proxies)
// 2. Third-party JS — some previously blocked APIs now work
// 3. eval() still blocked — no code injection
// 4. Cross-component access still blocked

// Check which security mode your org uses:
// Setup → Session Settings → Lightning Web Security

// Writing LWS-compatible code:
// ✅ Use this.template.querySelector() for DOM access
// ✅ Use CustomEvent for communication
// ✅ Use window.location (read) for current URL
// ❌ Don't rely on Proxy wrapping behaviour
// ❌ Don't use document.write() or innerHTML with user data
// ❌ Don't use __proto__ manipulation

// Third-party library compatibility:
// Most modern libraries (Leaflet, D3, Chart.js) work with LWS
// Load via Static Resources or Lightning Locker-friendly CDN
03

XSS Prevention

Safe Output & User Input Handling

// LWC auto-escapes text content in templates — safe by default
// {userInput} in a template is HTML-escaped automatically ✅

// DANGER ZONE: innerHTML and lwc:inner-html
// These render raw HTML — only use with TRUSTED content

// ❌ DANGEROUS — never use user-supplied HTML
handleUserInput(event) {
    this.content = event.detail.value;
}
// template: <div lwc:inner-html={content}></div> // XSS if content is user input

// ✅ SAFE — always escape user-supplied content before innerHTML
import { sanitizeHtml } from 'c/sanitizeUtils'; // custom utility
handleUserInput(event) {
    this.content = sanitizeHtml(event.detail.value);
}

// ✅ Better: never use lwc:inner-html with user data
// Use {userInput} (auto-escaped) or render data as structured elements

// Content Security Policy checks:
// LWC components must not load resources from untrusted domains
// Use Static Resources and Named Credentials for external content
// Setup → Security → Content Security Policy
04

Content Security Policy & Trusted URLs

Loading External Resources Safely

// CSP in Salesforce — controls which external resources can load
// Setup → Security → Content Security Policy → Trusted URLs

// Loading external scripts (e.g., Google Maps, Chart.js)
// 1. Add domain to Trusted URLs in Setup
// 2. Use loadScript from lightning/platformResourceLoader

import { LightningElement } from 'lwc';
import { loadScript, loadStyle } from 'lightning/platformResourceLoader';
import CHARTJS from '@salesforce/resourceUrl/chartjs';

export default class ChartComponent extends LightningElement {
    chartInitialised = false;

    renderedCallback() {
        if (this.chartInitialised) return;
        this.chartInitialised = true;

        // Load external script safely via platformResourceLoader
        loadScript(this, CHARTJS + '/Chart.min.js')
            .then(() => this.initialiseChart())
            .catch(error => console.error('Failed to load Chart.js:', error));
    }

    initialiseChart() {
        const canvas = this.template.querySelector('canvas');
        // Chart.js is now available as window.Chart
        new Chart(canvas, { type: 'bar', data: this.chartData });
    }
}
05

Best Practices

Never Use innerHTML with User Data

LWC templates auto-escape {expressions}. Use lwc:inner-html only with fully trusted, sanitised content. Never pipe user input directly into it.

❌ <div lwc:inner-html={userInput}></div> // XSS risk
✅ <p>{userInput}</p> // auto-escaped by LWC template engine

Load External Scripts via platformResourceLoader

Don't dynamically create <script> tags. Use loadScript from lightning/platformResourceLoader — it respects CSP and the LWC security model.

✅ loadScript(this, RESOURCE_URL + '/lib.min.js').then(...)

Use @salesforce/userPermission for Feature Flags

Check Salesforce permissions in LWC to conditionally show UI elements based on what the user is allowed to do.

✅ import canEditAccounts from '@salesforce/userPermission/EditAllAccounts';
