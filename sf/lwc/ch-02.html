Template Expressions

Binding JS Properties to Templates

<!-- Curly brace expressions bind JS class properties -->
<template>
  <p>{message}</p>
  <p>Total: {total}</p>
  <input value={inputValue} onchange={handleChange}>

  <!-- Computed via getter -->
  <p class={statusClass}>{statusLabel}</p>

  <!-- HTML attributes -->
  <img src={imageUrl} alt={imageAlt}>
  <lightning-button label={buttonLabel} disabled={isDisabled}></lightning-button>
</template>
// myComponent.js
import { LightningElement } from 'lwc';
export default class MyComponent extends LightningElement {
    message = 'Hello LWC';
    total = 42;
    inputValue = '';
    isDisabled = false;
    imageUrl = '/resource/myImage';

    get statusClass() {
        return this.isActive ? 'slds-text-color_success' : 'slds-text-color_error';
    }
    get statusLabel() { return this.isActive ? 'Active' : 'Inactive'; }
    handleChange(event) { this.inputValue = event.target.value; }
}
02

Conditional Rendering

if:true / if:false & lwc:if

<template>
  <!-- Legacy syntax (still works) -->
  <template if:true={isLoaded}>
    <p>Data is loaded!</p>
  </template>
  <template if:false={isLoaded}>
    <lightning-spinner></lightning-spinner>
  </template>

  <!-- Modern syntax (API 55+) -->
  <template lwc:if={isLoaded}>
    <p>Loaded</p>
  </template>
  <template lwc:elseif={isError}>
    <p class="error">{errorMessage}</p>
  </template>
  <template lwc:else>
    <lightning-spinner alternative-text="Loading..."></lightning-spinner>
  </template>
</template>
03

List Rendering

for:each & iterator

<template>
  <!-- for:each — key is REQUIRED on the first child -->
  <template for:each={accounts} for:item="acc">
    <div key={acc.Id}>
      <p>{acc.Name}</p>
    </div>
  </template>

  <!-- iterator — gives first/last flags and index -->
  <template iterator:it={contacts}>
    <div key={it.value.Id}>
      <template if:true={it.first}><hr></template>
      <p>{it.index}: {it.value.Name}</p>
      <template if:true={it.last}><p>--- End ---</p></template>
    </div>
  </template>
</template>
04

<template> Tag Wrapper

Grouping Without Extra DOM

<!-- <template> renders no DOM element — pure grouping -->
<template>
  <template if:true={showDetails}>
    <!-- Renders multiple elements without a wrapper div -->
    <template for:each={fields} for:item="field">
      <div key={field.name}>
        <label>{field.label}</label>
        <span>{field.value}</span>
      </div>
    </template>
  </template>
</template>

Shadow DOM & Scoping

How Shadow DOM Isolates Components

// LWC uses Shadow DOM by default
// Your component's HTML is in its own shadow root
// CSS in myComponent.css ONLY affects myComponent's HTML

// Correct: query inside shadow root
this.template.querySelector('lightning-input')

// WRONG: breaks shadow boundary
document.querySelector('c-my-component lightning-input') // returns null

// lwc:ref — named references to elements (API 59+)
// <div lwc:ref="myDiv"></div>
const div = this.refs.myDiv; // no querySelector needed
06

Best Practices

Always Set key on Repeated Elements

Missing key causes a runtime error. Use a unique, stable identifier — never use array index as key.

❌ <template for:each={items} for:item="i"><div>
✅ <template for:each={items} for:item="i"><div key={i.Id}>

Use lwc:if for New Code (API 55+)

lwc:if/elseif/else is more expressive than if:true/if:false. Use it for all new components targeting API 55+.

✅ <template lwc:if={condition}>...<template lwc:else>

Prefer Getters Over Complex Expressions

LWC expressions must be simple property access. Move logic to JS getters — they are reactive and recalculate when dependencies change.

❌ {items.filter(i => i.active).length} // not allowed
✅ get activeCount() { return this.items.filter(i=>i.active).length; }
