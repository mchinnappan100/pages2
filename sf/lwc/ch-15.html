ARIA Basics

Accessible Rich Internet Applications (ARIA) attributes provide semantic meaning to custom UI elements, making them usable by screen readers and other assistive technologies.

Essential ARIA Attributes in LWC

<!-- Button role and state -->
<div role="button" tabindex="0"
     aria-label="Close dialog"
     aria-pressed={isPressed}
     onclick={handleClose}
     onkeydown={handleKeyDown}>
  <lightning-icon icon-name="utility:close"></lightning-icon>
</div>

<!-- Status/alert regions -->
<div role="alert" aria-live="assertive">{errorMessage}</div>
<div role="status" aria-live="polite">{statusMessage}</div>

<!-- Form field labelling -->
<label for="search-input">Search accounts</label>
<input id="search-input" type="text"
       aria-describedby="search-hint"
       aria-required="true">
<p id="search-hint">Enter at least 2 characters</p>

<!-- Expanded/collapsed state -->
<button aria-expanded={isExpanded} aria-controls="panel-content">
  Toggle Details
</button>
<div id="panel-content" aria-hidden={isCollapsed}>...</div>
02

Keyboard Navigation

Full Keyboard Accessibility

export default class AccessibleList extends LightningElement {
    focusedIndex = -1;
    items = [];

    // Handle keyboard navigation for a custom list
    handleKeyDown(event) {
        switch (event.key) {
            case 'ArrowDown':
                event.preventDefault();
                this.focusedIndex = Math.min(
                    this.focusedIndex + 1, this.items.length - 1);
                this.focusItem(this.focusedIndex);
                break;
            case 'ArrowUp':
                event.preventDefault();
                this.focusedIndex = Math.max(this.focusedIndex - 1, 0);
                this.focusItem(this.focusedIndex);
                break;
            case 'Enter':
            case ' ':
                event.preventDefault();
                this.selectItem(this.focusedIndex);
                break;
            case 'Escape':
                this.closeDropdown();
                break;
            case 'Home':
                this.focusedIndex = 0;
                this.focusItem(0);
                break;
            case 'End':
                this.focusedIndex = this.items.length - 1;
                this.focusItem(this.items.length - 1);
                break;
        }
    }

    focusItem(index) {
        const items = this.template.querySelectorAll('[role="option"]');
        if (items[index]) items[index].focus();
    }
}
03

Focus Management

Focus Trapping & Restoration

export default class ModalDialog extends LightningElement {
    _previousFocus; // element that had focus before modal opened

    openModal() {
        // Save focus position
        this._previousFocus = document.activeElement;
        // Open modal, then move focus to first focusable element
        this.isOpen = true;
        // setTimeout needed because template re-renders asynchronously
        setTimeout(() => {
            const firstFocusable = this.template.querySelector(
                'button, input, select, textarea, [tabindex]:not([tabindex="-1"])'
            );
            firstFocusable?.focus();
        }, 0);
    }

    closeModal() {
        this.isOpen = false;
        // Restore focus to where it was before opening
        this._previousFocus?.focus();
    }

    // Trap focus inside modal while it's open
    handleKeyDown(event) {
        if (event.key !== 'Tab') return;
        const focusable = this.template.querySelectorAll(
            'button:not([disabled]), input:not([disabled]), [tabindex="0"]'
        );
        const first = focusable[0];
        const last  = focusable[focusable.length - 1];

        if (event.shiftKey && document.activeElement === first) {
            event.preventDefault(); last.focus();
        } else if (!event.shiftKey && document.activeElement === last) {
            event.preventDefault(); first.focus();
        }
    }
}
04

Screen Reader Support

Announcements & Visually Hidden Text

<!-- Visually hidden but announced by screen readers -->
<span class="slds-assistive-text">{hiddenContext}</span>

<!-- Skip to main content link (WCAG 2.4.1) -->
<a href="#main-content" class="skip-link">Skip to main content</a>
<main id="main-content">...</main>

<!-- Live region for dynamic updates -->
<div aria-live="polite" aria-atomic="true" class="slds-assistive-text">
  {screenReaderAnnouncement}
</div>
// Announce dynamic changes to screen readers
export default class DataTable extends LightningElement {
    screenReaderAnnouncement = '';

    handleSortChange(field, direction) {
        this.sortData(field, direction);
        // Announce the result to screen reader users
        this.screenReaderAnnouncement =
            `Table sorted by ${field} in ${direction}ending order`;
    }

    handleDelete(id) {
        this.items = this.items.filter(i => i.Id !== id);
        this.screenReaderAnnouncement = 'Record deleted successfully';
    }
}
05

WCAG 2.1 AA Compliance

Colour Contrast (1.4.3)

Text must have a contrast ratio of at least 4.5:1 against its background. Use SLDS tokens — they're pre-tested for contrast compliance.

✅ Use var(--lwc-colorTextDefault) and SLDS-approved background combinations

Keyboard Accessible (2.1.1)

All interactive elements must be operable by keyboard. Never rely solely on hover or mouse events for functionality.

❌ onmouseover={showTooltip} with no keyboard equivalent
✅ onfocus={showTooltip} onfocusin={showTooltip} as well

Visible Focus (2.4.7)

Keyboard focus must be visually visible at all times. Never remove the focus outline with CSS unless you replace it with a custom visible indicator.

❌ :focus { outline: none; }
✅ :focus-visible { outline: 2px solid var(--cp); outline-offset: 2px; }

Error Identification (3.3.1)

Form errors must be identified in text — not just by colour. SLDS form validation messages include an icon and text.

✅ <lightning-input validity={nameValidity}> shows text error message

Images of Text (1.4.5)

Don't use images to display text. Use HTML/CSS text which can be resized and read by screen readers.

❌ <img src="submit-button.png" alt="Submit">
✅ <lightning-button label="Submit"></lightning-button>

Name, Role, Value (4.1.2)

All custom UI components must have a name (label/aria-label), a role, and communicate their state via ARIA attributes.

✅ role="checkbox" aria-checked={isChecked} aria-label={itemLabel}
06

Best Practices

Use Base Components Wherever Possible

Salesforce base components (lightning-button, lightning-input, etc.) are WCAG-compliant by default. Building custom equivalents requires significant accessibility work.

✅ <lightning-combobox> handles keyboard, ARIA, and focus automatically

Test with a Screen Reader

Use VoiceOver (macOS/iOS) or NVDA (Windows) to test your component. Automated tools catch ~30% of issues — manual testing is essential.

✅ VoiceOver: Cmd+F5 / NVDA: Ctrl+Alt+N to start testing

Always Provide Alternative Text for Icons

Icon-only buttons must have alternative-text or aria-label so screen readers can announce what the button does.

❌ <lightning-button-icon icon-name="utility:edit">
✅ <lightning-button-icon icon-name="utility:edit" alternative-text="Edit record">
