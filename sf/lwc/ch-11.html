LDS Overview

Lightning Data Service (LDS) is Salesforce's client-side data layer. It provides reactive wire adapters for reading and writing records, handles caching, automatically enforces FLS/sharing, and notifies all components when a record changes.

LDS vs Apex — When to Choose

// USE LDS when:
// - Reading/writing standard or custom sObject records
// - You need automatic FLS and sharing enforcement
// - You want built-in optimistic UI and cache management
// - Multiple components show the same record (cache sync)

// USE APEX when:
// - Complex business logic beyond CRUD
// - Multiple objects in one transaction
// - Aggregate queries / reporting
// - Operations requiring governor limit control

// LDS Adapters (from lightning/uiRecordApi):
// getRecord          — read a record
// getRecords         — read multiple records
// getRelatedListRecords — related records
// createRecord       — insert a new record
// updateRecord       — update existing record
// deleteRecord       — delete a record
// getObjectInfo      — object metadata
// getPicklistValues  — picklist field values
02

Reading Records

getRecord Wire Adapter

import { LightningElement, wire, api } from 'lwc';
import { getRecord, getFieldValue } from 'lightning/uiRecordApi';
import ACCOUNT_NAME    from '@salesforce/schema/Account.Name';
import ACCOUNT_PHONE   from '@salesforce/schema/Account.Phone';
import ACCOUNT_WEBSITE from '@salesforce/schema/Account.Website';
import ACCOUNT_OWNER   from '@salesforce/schema/Account.Owner.Name';

const FIELDS = [ACCOUNT_NAME, ACCOUNT_PHONE, ACCOUNT_WEBSITE, ACCOUNT_OWNER];

export default class AccountDetail extends LightningElement {
    @api recordId;

    @wire(getRecord, { recordId: '$recordId', fields: FIELDS })
    account;

    get name()    { return getFieldValue(this.account.data, ACCOUNT_NAME); }
    get phone()   { return getFieldValue(this.account.data, ACCOUNT_PHONE); }
    get website() { return getFieldValue(this.account.data, ACCOUNT_WEBSITE); }
    get owner()   { return getFieldValue(this.account.data, ACCOUNT_OWNER); }

    get isLoading() { return !this.account.data && !this.account.error; }
    get error()     { return this.account.error?.body?.message; }
}
// getFieldValue safely navigates the LDS data structure
// Returns undefined (not null/error) if field is missing

Writing Records — Create, Update, Delete

createRecord, updateRecord, deleteRecord

import { createRecord, updateRecord, deleteRecord } from 'lightning/uiRecordApi';
import { ShowToastEvent } from 'lightning/platformShowToastEvent';
import ACCOUNT_OBJECT from '@salesforce/schema/Account';
import NAME_FIELD     from '@salesforce/schema/Account.Name';
import INDUSTRY_FIELD from '@salesforce/schema/Account.Industry';

export default class AccountManager extends LightningElement {
    @api recordId;

    // CREATE
    async handleCreate() {
        const fields = {};
        fields[NAME_FIELD.fieldApiName]     = 'New Account';
        fields[INDUSTRY_FIELD.fieldApiName] = 'Technology';

        try {
            const result = await createRecord({
                apiName: ACCOUNT_OBJECT.objectApiName, fields
            });
            this.dispatchEvent(new ShowToastEvent({
                title: 'Created!', message: 'Account ID: ' + result.id,
                variant: 'success'
            }));
        } catch (e) { this.showError(e); }
    }

    // UPDATE
    async handleUpdate(name) {
        const fields = { Id: this.recordId };
        fields[NAME_FIELD.fieldApiName] = name;
        try {
            await updateRecord({ fields });
            this.dispatchEvent(new ShowToastEvent({
                title: 'Updated!', variant: 'success' }));
        } catch (e) { this.showError(e); }
    }

    // DELETE
    async handleDelete() {
        try {
            await deleteRecord(this.recordId);
            this.dispatchEvent(new ShowToastEvent({
                title: 'Deleted!', variant: 'success' }));
            this.navigateToList();
        } catch (e) { this.showError(e); }
    }

    showError(e) {
        this.dispatchEvent(new ShowToastEvent({
            title: 'Error', message: e.body?.message, variant: 'error'
        }));
    }
}

Declarative CRUD Without JS

<!-- Full CRUD without ANY JavaScript -->

<!-- Create new record -->
<lightning-record-form
    object-api-name="Account"
    layout-type="Compact"
    mode="edit"
    onsuccess={handleSuccess}>
</lightning-record-form>

<!-- View existing record -->
<lightning-record-form
    record-id={recordId}
    object-api-name="Account"
    layout-type="Full"
    mode="view">
</lightning-record-form>

<!-- Custom field selection -->
<lightning-record-form
    record-id={recordId}
    object-api-name="Account"
    fields={fieldList}
    mode="readonly"
    columns="2">
</lightning-record-form>
// fieldList can be schema imports or strings:
import NAME    from '@salesforce/schema/Account.Name';
import PHONE   from '@salesforce/schema/Account.Phone';
import REVENUE from '@salesforce/schema/Account.AnnualRevenue';

fieldList = [NAME, PHONE, REVENUE];

Cache Refresh

notifyRecordUpdateAvailable & refreshApex

import { notifyRecordUpdateAvailable } from 'lightning/uiRecordApi';
import { refreshApex } from '@salesforce/apex';

export default class RecordRefresher extends LightningElement {
    @api recordId;
    @wire(getRecord, { recordId: '$recordId', fields: FIELDS }) wiredRecord;
    @wire(getRelatedList, { recordId: '$recordId' }) wiredRelated;

    async handleExternalUpdate() {
        // 1. Tell LDS cache that this record changed
        // All components wired to this recordId will re-fetch
        notifyRecordUpdateAvailable([{ recordId: this.recordId }]);
    }

    async handleApexRefresh() {
        // 2. Refresh a specific @wire(apexMethod) result
        await refreshApex(this.wiredRecord);
        await refreshApex(this.wiredRelated);
    }
}
// LDS handles cache invalidation automatically after createRecord/updateRecord
// Call notifyRecordUpdateAvailable when you update a record via imperative Apex
06

Best Practices

Use Schema Imports for Field/Object Names

Always import field and object names via @salesforce/schema/ rather than hard-coding strings. Schema imports fail at deploy time if the field doesn't exist, catching errors early.

❌ fields: ['Account.Name'] // string — fails silently if renamed
✅ import NAME from '@salesforce/schema/Account.Name'; // compile-time check

Call notifyRecordUpdateAvailable After Apex DML

When you update a record via imperative Apex (not LDS), the LDS cache doesn't know. Call notifyRecordUpdateAvailable to invalidate the cache and trigger re-fetches across all components.

✅ notifyRecordUpdateAvailable([{ recordId: id }]);

Use lightning-record-form When Possible

For standard CRUD on a single record, lightning-record-form with layout-type="Full" requires zero JavaScript and handles everything automatically.

✅ <lightning-record-form record-id={recordId} object-api-name="Account">
