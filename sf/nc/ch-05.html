Salesforce-to-Salesforce Integration

Calling Another Org's REST API via Named Credentials

// Pattern: Org A (source) calls Org B (target) via Salesforce REST API
// Auth: JWT Bearer or Connected App OAuth (Client Credentials)

// In Org B (target):
// 1. Create a Connected App with Client Credentials flow enabled
// 2. Set the run-as user (integration user with minimal permissions)
// 3. Get the Consumer Key and Consumer Secret

// In Org A (source) — Setup:
// External Credential:
//   Protocol: OAuth 2.0
//   Flow: Client Credentials
//   Token URL: https://OrgB.my.salesforce.com/services/oauth2/token
//   Client ID: (Org B Connected App Consumer Key)
//   Client Secret: (Org B Consumer Secret)
//   Scope: api
//
// Named Credential:
//   URL: https://OrgB.my.salesforce.com
//   External Credential: (above)

// In Org A — Apex:
public with sharing class OrgBSyncService {

    private static final String NC = 'callout:OrgB_NC';

    public static List<Object> queryOrgB(String soql) {
        HttpRequest req = new HttpRequest();
        req.setEndpoint(NC + '/services/data/v61.0/query?q='
            + EncodingUtil.urlEncode(soql, 'UTF-8'));
        req.setMethod('GET');
        req.setHeader('Accept', 'application/json');

        HttpResponse res = new Http().send(req);
        if (res.getStatusCode() != 200)
            throw new CalloutException('OrgB query failed: ' + res.getBody());

        Map<String,Object> result =
            (Map<String,Object>) JSON.deserializeUntyped(res.getBody());
        return (List<Object>) result.get('records');
    }

    public static void createInOrgB(String objectApiName, Map<String,Object> fields) {
        HttpRequest req = new HttpRequest();
        req.setEndpoint(NC + '/services/data/v61.0/sobjects/' + objectApiName);
        req.setMethod('POST');
        req.setHeader('Content-Type', 'application/json');
        req.setBody(JSON.serialize(fields));
        HttpResponse res = new Http().send(req);
        if (res.getStatusCode() != 201)
            throw new CalloutException('Create in OrgB failed: ' + res.getBody());
    }
}

OpenAI / Einstein AI APIs

Named Credential for API key auth — one of the most common modern integrations.

  • External Credential → Custom protocol
  • Custom header: Authorization = Bearer {api_key}
  • URL: https://api.openai.com
  • POST to /v1/chat/completions
  • Stream responses with chunked reading
  • Respect rate limits — handle 429
// EC Custom Header: Authorization = Bearer {your_openai_key}
// NC URL: https://api.openai.com

public with sharing class OpenAIService {

    @future(callout=true)
    public static void generateSummary(Id recordId, String text) {
        HttpRequest req = new HttpRequest();
        req.setEndpoint('callout:OpenAI_NC/v1/chat/completions');
        req.setMethod('POST');
        req.setHeader('Content-Type', 'application/json');
        req.setTimeout(30000); // AI can be slow
        req.setBody(JSON.serialize(new Map<String,Object>{
            'model' => 'gpt-4o',
            'max_tokens' => 500,
            'messages' => new List<Object>{
                new Map<String,String>{
                    'role' => 'system',
                    'content' => 'Summarise the following in 2 sentences.'
                },
                new Map<String,String>{
                    'role' => 'user',
                    'content' => text.left(4000) // stay within token limits
                }
            }
        }));

        HttpResponse res = new Http().send(req);
        if (res.getStatusCode() == 200) {
            Map<String,Object> data =
                (Map<String,Object>) JSON.deserializeUntyped(res.getBody());
            List<Object> choices = (List<Object>) data.get('choices');
            Map<String,Object> firstChoice = (Map<String,Object>) choices[0];
            Map<String,Object> message = (Map<String,Object>) firstChoice.get('message');
            String summary = (String) message.get('content');

            // Update the record
            SObject record = recordId.getSObjectType().newSObject(recordId);
            record.put('AI_Summary__c', summary);
            update record;
        }
    }
}

Stripe Payment API

OAuth Bearer token auth — the standard for fintech APIs.

  • Bearer token in Authorization header
  • EC Custom Header: Authorization = Bearer {sk_live_key}
  • URL: https://api.stripe.com
  • POST form-encoded (not JSON)
  • Handle idempotency keys for retries
  • Separate test/live credentials per env
// EC: Custom protocol, header Authorization = Bearer {sk_live_key}
// NC URL: https://api.stripe.com

public with sharing class StripeService {

    public static String createCharge(Decimal amount, String currency, String customerId) {
        HttpRequest req = new HttpRequest();
        req.setEndpoint('callout:Stripe_NC/v1/charges');
        req.setMethod('POST');
        // Stripe uses form-encoded, not JSON
        req.setHeader('Content-Type', 'application/x-www-form-urlencoded');
        req.setTimeout(15000);
        req.setBody(
            'amount=' + (amount * 100).intValue() // Stripe uses cents
            + '¤cy=' + currency
            + '&customer=' + customerId
            + '&idempotency_key=' + EncodingUtil.convertToHex(
                Crypto.generateAesKey(128)).left(32)
        );

        HttpResponse res = new Http().send(req);
        if (res.getStatusCode() != 200) {
            Map<String,Object> err =
                (Map<String,Object>) JSON.deserializeUntyped(res.getBody());
            throw new CalloutException(
                'Stripe error: ' + (String)((Map<String,Object>)err.get('error')).get('message'));
        }
        Map<String,Object> charge =
            (Map<String,Object>) JSON.deserializeUntyped(res.getBody());
        return (String) charge.get('id');
    }
}

SendGrid / Twilio Messaging

API key authentication for notification services.

  • Bearer token or Basic auth
  • JSON payloads for modern APIs
  • Handle delivery receipts via Platform Events
  • Rate limit: use @future to avoid synchronous limits
  • Sandbox keys for dev/test environments
  • Webhook endpoints for inbound messages
// EC: Custom, header Authorization = Bearer {sendgrid_api_key}
// NC URL: https://api.sendgrid.com

public with sharing class SendGridService {

    @future(callout=true)
    public static void sendEmail(String toAddress, String subject, String htmlBody) {
        HttpRequest req = new HttpRequest();
        req.setEndpoint('callout:SendGrid_NC/v3/mail/send');
        req.setMethod('POST');
        req.setHeader('Content-Type', 'application/json');
        req.setTimeout(10000);
        req.setBody(JSON.serialize(new Map<String,Object>{
            'personalizations' => new List<Object>{
                new Map<String,Object>{
                    'to' => new List<Object>{
                        new Map<String,String>{ 'email' => toAddress }
                    }
                }
            },
            'from' => new Map<String,String>{ 'email' => 'noreply@yourcompany.com' },
            'subject' => subject,
            'content' => new List<Object>{
                new Map<String,String>{ 'type' => 'text/html', 'value' => htmlBody }
            }
        }));
        HttpResponse res = new Http().send(req);
        if (res.getStatusCode() != 202) {
            System.debug(LoggingLevel.ERROR, 'SendGrid failed: ' + res.getBody());
        }
    }
}

AWS APIs (S3, Lambda)

AWS Signature v4 — available as a Named Credential auth protocol.

  • Protocol: AWS Signature Version 4
  • Access Key + Secret Key stored in NC
  • Service (s3, lambda, etc.) + Region configured
  • Salesforce computes signature automatically
  • Supports GET, PUT, DELETE for S3 objects
  • Good for document storage integrations
// NC Setup: Protocol = AWS Signature Version 4
//   AWS Access Key ID: (from AWS IAM)
//   AWS Secret Access Key: (from AWS IAM)
//   AWS Region: us-east-1
//   AWS Service: s3
//
// NC URL: https://your-bucket.s3.amazonaws.com

public with sharing class S3Service {

    // Upload a file to S3
    public static void uploadFile(String fileName, Blob fileData, String contentType) {
        HttpRequest req = new HttpRequest();
        req.setEndpoint('callout:AWS_S3_NC/' + EncodingUtil.urlEncode(fileName, 'UTF-8'));
        req.setMethod('PUT');
        req.setHeader('Content-Type', contentType);
        req.setBodyAsBlob(fileData);
        req.setTimeout(30000); // Large files need more time

        HttpResponse res = new Http().send(req);
        if (res.getStatusCode() != 200 && res.getStatusCode() != 204) {
            throw new CalloutException('S3 upload failed: '
                + res.getStatusCode() + ' ' + res.getBody());
        }
    }

    // Read a file from S3
    public static Blob downloadFile(String fileName) {
        HttpRequest req = new HttpRequest();
        req.setEndpoint('callout:AWS_S3_NC/' + EncodingUtil.urlEncode(fileName, 'UTF-8'));
        req.setMethod('GET');
        req.setTimeout(30000);
        HttpResponse res = new Http().send(req);
        if (res.getStatusCode() != 200)
            throw new CalloutException('S3 download failed: ' + res.getStatusCode());
        return res.getBodyAsBlob();
    }
}

Debug Logs & Event Monitoring

// Or use sf apex log tail --target-org myorg

// Event Monitoring (add-on) provides callout audit:
// EventLogFile where EventType = 'ApiTotalUsage'
// EventLogFile where EventType = 'RestApi'

// Named Credential audit in Event Monitoring:
// Shows: which NC was used, which user, timestamp, response code

// Testing NC connectivity without code:
// Setup → Named Credentials → (select NC) → Test (button)
// This makes a HEAD or GET request to the base URL

// Common issues:
//
// 1. "Unauthorized endpoint" error
//    → Remote Site Setting missing (for non-NC callouts)
//    → Check that you're using 'callout:NC_Name' not raw URL

// 2. "No Named Credential found"
//    → Check DeveloperName spelling in setEndpoint()
//    → Check case: 'callout:MY_API' not 'callout:my_api'

// 3. 401 Unauthorized
//    → OAuth token expired and not refreshing → check EC config
//    → API key changed → update value in Setup → Named Credentials
//    → Wrong scope → add required scope in EC

// 4. "Callout not allowed" in trigger
//    → Use @future(callout=true) or Queueable + AllowsCallouts

// SOQL for troubleshooting:
// SELECT Id, Name, Protocol, Endpoint FROM NamedCredential
// (Note: cannot query credentials — only metadata structure)

Governance & Naming Conventions

Naming Convention

// External Credential DeveloperName:
// {Vendor}_{Service}_{Environment}_EC
// Examples:
// Stripe_Payments_Prod_EC
// Stripe_Payments_Sandbox_EC
// AWS_S3_Documents_EC
// Google_Gmail_OAuth_EC

// Named Credential DeveloperName:
// {Vendor}_{Service}_{Environment}
// Examples:
// Stripe_Payments_Prod
// Stripe_Payments_Sandbox
// AWS_S3_Documents
// OrgB_REST_API

// In Apex — use a constant for the NC name:
public class ApiConstants {
    public static final String STRIPE  = 'callout:Stripe_Payments_Prod';
    public static final String AWS_S3  = 'callout:AWS_S3_Documents';
    public static final String ORG_B   = 'callout:OrgB_REST_API';
}

Per-Environment Strategy

// Strategy: Same DeveloperName, different values per org
// This means Apex code doesn't change between environments

// DEV sandbox:
// NC: My_Payment_API → https://api.stripe.com/test
// Secret: test API key

// QA sandbox:
// NC: My_Payment_API → https://api.stripe.com/test
// Secret: test API key (different test account)

// PRODUCTION:
// NC: My_Payment_API → https://api.stripe.com
// Secret: live API key

// Apex code (same in all environments):
req.setEndpoint('callout:My_Payment_API/v1/charges');
// The URL and credentials differ — code does not

// Deploy: only the metadata structure travels with code
// Credential VALUES are entered by admin in each org's Setup
// Never commit actual credential values to source control

Comprehensive Best Practices

One Named Credential Per External System Per Environment

Don't reuse NCs across unrelated systems. Each integration should have its own NC so credentials can be rotated independently and permissions managed separately.

✅ Stripe_Prod, Stripe_Sandbox, OpenAI_Prod, SendGrid_Prod — all separate

Use Apex Constants for NC Names

Hard-coding the NC name string throughout your codebase makes it painful to rename. Define it once in a constants class and reference that everywhere.

✅ public static final String PAYMENT_NC = 'callout:Stripe_Payments';

Wrap All Callouts in Service Classes

All Named Credential callouts should be in dedicated service classes (not scattered in triggers or controllers). This centralises error handling, makes testing easier, and enables mocking.

✅ StripeService, OpenAIService, OrgBSyncService — each has its own class

Always Validate Status Before Parsing

The Named Credential handles auth — but the API can still return 404, 422, 500. Always validate getStatusCode() before deserialising the body.

❌ return JSON.deserializeUntyped(res.getBody()); // crashes on error response
✅ if (res.getStatusCode() != 200) throw new CalloutException(...);

Document Required Credential Values

When you deploy a new NC, document exactly what values the admin needs to enter in Setup (what URL, what credential type, where to get the API key). Deployments break when this knowledge is only in the developer's head.

✅ README: "After deploy, go to Setup → Named Credentials → Stripe_Payments → enter your Stripe API key as password"

Rotate Credentials Without Code Changes

Named Credentials make credential rotation a Setup change, not a deployment. When an API key expires or is compromised, the admin updates the value in Setup and all callouts immediately use the new credential.

✅ Admin goes to Setup → Named Credentials → edit → update key → save. Done.
