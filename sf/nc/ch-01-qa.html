What is the main purpose of a Named Credential in Salesforce?
✓ Correct: B

A Named Credential stores an external endpoint URL and its authentication configuration as metadata. It decouples connection details from Apex code — no hard-coded URLs, no secrets in source control. Use callout:NC_Name/path in setEndpoint().

2
Which syntax calls a Named Credential called My_API with path /v1/data in Apex?
✓ Correct: C

The callout: prefix is required to tell Salesforce to use the Named Credential. The DeveloperName follows (My_API), then the path appended to the base URL. The Named Credential's base URL and authentication are handled automatically.

3
Do you need a Remote Site Setting when using a Named Credential callout?
✓ Correct: C

When using callout:NC_Name, Salesforce automatically trusts the endpoint — no separate Remote Site Setting is needed. Remote Site Settings are only required when you call a raw URL directly without a Named Credential.

4
What is the key difference between a Legacy Named Credential and a modern External Credential?
✓ Correct: B

The modern architecture splits auth (External Credential) from the URL (Named Credential). One External Credential can serve multiple Named Credentials. Only External Credentials support per-user Named Principals.

5
Where are Named Credential secrets (API keys, passwords) stored?
✓ Correct: C

Credentials stored in Named Credentials are encrypted at rest in Salesforce. They never appear in Apex code, debug logs, or stack traces. The NC metadata XML in SFDX stores the structure but not the secret values — those are entered in Setup per org.

6
A developer hard-codes an API key in Apex code and commits it to git. What is the correct fix?
✓ Correct: B

The Named Credential is the correct solution — it stores the API key encrypted in Salesforce metadata, never in source code. Apex uses callout:NC_Name and Salesforce injects the credential automatically.

7
Which Setup path creates a Legacy Named Credential?
✓ Correct: B

Legacy Named Credentials are found at Setup → Security → Named Credentials → New. Modern External Credentials are at Setup → Security → External Credentials.

8
What does setting Allow Merge Fields in HTTP Header = true on a Named Credential enable?
✓ Correct: B

With this setting enabled, you can use Salesforce merge fields (like {!$Credential.UserName}, {!$User.Email}) in the Named Credential's custom header values, allowing dynamic credential injection.

9
In the new External Credentials architecture, which layer controls access via Permission Sets?
✓ Correct: B

Access to External Credentials is granted via Permission Set → External Credential Principal Access. Without the correct Permission Set, a user's callout using that NC will fail. This enables fine-grained access control.

10
After deploying a Named Credential's metadata XML via SFDX, what must an admin do?
✓ Correct: C

Named Credential metadata XML contains the structure (URL, protocol, settings) but NOT the secret values. After deployment, an admin must manually enter the password/API key/client secret in Setup → Named Credentials for each org. This is by design — secrets must never be in source control.
