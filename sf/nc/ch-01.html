What Are Named Credentials?

A Named Credential is a Salesforce metadata record that stores an external endpoint URL and its authentication configuration. It decouples connection details from Apex code — no hard-coded URLs, no secrets in source control.

Before Named Credentials

// ❌ Hard-coded — brittle and insecure
HttpRequest req = new HttpRequest();
req.setEndpoint('https://api.example.com/v2/data');
req.setHeader('Authorization', 'Bearer abc123secret');
// Problems:
// - Secret in source code / git history
// - Different URL per environment = code change needed
// - No admin visibility or control

With Named Credentials

// ✅ Clean, secure, environment-agnostic
HttpRequest req = new HttpRequest();
req.setEndpoint('callout:My_API/v2/data');
// Benefits:
// - No secrets in code
// - URL configured per environment by admin
// - Auth handled by Salesforce automatically
// - Full audit trail in Setup
Key principle: Named Credentials separate what your code does (make a callout) from where and how to authenticate (stored in Salesforce metadata). Developers write code; admins configure connections.
02

Types of Named Credentials

🔑

Legacy Named Credentials

Original format — URL and auth bundled together. Still widely used.

  • URL + auth in one record
  • Simpler setup
  • Supports basic auth, OAuth, JWT
  • One credential = one endpoint
  • Limited per-user auth options
  • In Setup → Named Credentials
🔗

External Credentials (API 53+)

Modern format — separates the External Credential (auth config) from the Named Credential (URL + path). Much more flexible.

  • Auth config in External Credential
  • URL in Named Credential
  • Multiple Named Creds → one External Cred
  • Per-user (Named Principal) auth support
  • Permission Set-based access control
  • In Setup → External Credentials
👤

Per-User vs Org-Wide Auth

Choose whether all users share one auth identity (org-wide) or each user authenticates independently (per-user).

  • Org-Wide: one shared credential
  • All API calls use same identity
  • Per-User (Named Principal): each user has their own token
  • Suitable for OAuth user consent flows
  • Users authenticate individually
  • Requires users to authorise via OAuth
🌐

Supported Protocols

Named Credentials support all major authentication protocols used by modern REST and SOAP APIs.

  • No Auth (public APIs)
  • Basic Auth (username:password)
  • OAuth 2.0 (Client Credentials)
  • OAuth 2.0 (JWT Bearer)
  • OAuth 2.0 (Authorization Code)
  • Custom Headers / AWS Signature v4
03

Creating Your First Named Credential

Step-by-Step: Legacy Named Credential

1

Navigate to Setup

Setup → Security → Named Credentials → New

2

Fill in the Label & Name

Label: My Weather API · Name: My_Weather_API (auto-generated, used in code as callout:My_Weather_API)

3

Set the URL

https://api.openweathermap.org/data/2.5 — base URL only, no path. The path goes in your Apex code.

4

Choose Authentication Protocol

Select "No Authentication" for API key APIs (you'll add the key as a header in code or via Custom Header). Select "Password Authentication" for Basic Auth.

5

Enable "Allow Merge Fields in HTTP Header" and "Allow Merge Fields in HTTP Body"

Required if you want to inject credentials from the Named Credential into headers or request body.

6

Save & Use in Apex

In Apex: req.setEndpoint('callout:My_Weather_API/weather?q=London');

Using Named Credential in Apex

public with sharing class WeatherService {
    public static String getCurrentWeather(String city) {
        HttpRequest req = new HttpRequest();
        // 'callout:' prefix tells Salesforce to use the Named Credential
        // Everything after the NC name is the path appended to the base URL
        req.setEndpoint('callout:My_Weather_API/weather?q='
            + EncodingUtil.urlEncode(city, 'UTF-8')
            + '&units=metric');
        req.setMethod('GET');
        req.setTimeout(10000);

        Http http = new Http();
        HttpResponse res = http.send(req);

        if (res.getStatusCode() == 200) {
            Map<String,Object> data =
                (Map<String,Object>) JSON.deserializeUntyped(res.getBody());
            return String.valueOf(data.get('main'));
        }
        throw new CalloutException('Weather API failed: ' + res.getStatusCode());
    }
}
04

Security & Remote Site Settings

Remote Site Settings vs Named Credentials

// Named Credentials AUTOMATICALLY add the endpoint to the allowlist
// You do NOT need a separate Remote Site Setting for Named Credential callouts

// BUT: if you use the raw URL (without 'callout:' prefix), you DO need
// a Remote Site Setting:

// ✅ Named Credential — no Remote Site Setting needed
req.setEndpoint('callout:My_API/path');

// ❌ Raw URL — requires Remote Site Setting at: Setup → Remote Site Settings
req.setEndpoint('https://api.example.com/path');

// Named Credentials also:
// - Store credentials encrypted at rest in Salesforce
// - Never expose credentials in debug logs or stack traces
// - Support IP restrictions via Connected Apps (OAuth)
// - Provide audit trail in Setup event log
05

Best Practices

Never Hard-Code Credentials

API keys, tokens, and passwords must never appear in Apex code, Custom Settings named with obvious keys, or anywhere that ends up in git history.

❌ req.setHeader('Authorization', 'Bearer hardCodedToken123');
✅ req.setEndpoint('callout:My_API/endpoint'); // token stored in NC

One Named Credential Per Environment

Use separate Named Credentials for sandbox and production with the same DeveloperName. Deploy the NC metadata — the credential values are set per-org by an admin.

✅ DeveloperName: Payment_API → sandbox points to test endpoint, prod to live

Use External Credentials for New Integrations

The new External Credentials + Named Credentials architecture is more flexible and supports per-user auth. Prefer it over legacy Named Credentials for all new builds.

✅ External Credential (auth) + Named Credential (URL) = flexible, scalable

Validate Response Status Before Parsing

Named Credentials handle auth, but the external API can still return errors. Always check res.getStatusCode() before deserialising the response body.

❌ JSON.deserializeUntyped(res.getBody()); // crashes on 401/500
✅ if (res.getStatusCode() == 200) { ... } else { throw... }
