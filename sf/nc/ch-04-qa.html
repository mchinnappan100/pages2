In the External Credentials architecture, what does the Named Credential store?
✓ Correct: B

The Named Credential stores the base URL and a reference to the External Credential that handles auth. The External Credential stores the protocol, token URL, client ID/secret, and scope. This separation allows multiple NCs to share one EC.

2
What is a Named Principal in the context of External Credentials?
✓ Correct: B

A Named Principal is a per-user auth configuration within an External Credential. When a user with the appropriate Permission Set makes a callout, Salesforce uses their individual OAuth token. This is required for Authorization Code (per-user) flows.

3
How is access to an External Credential controlled in Salesforce?
✓ Correct: B

External Credential access is granted via Permission Set → External Credential Principal Access. Users without this PS assignment cannot make callouts using that EC. This provides fine-grained, just-in-time access control separate from profiles.

4
What is the purpose of the merge field {!$Credential.OAuthToken} in a Named Credential?
✓ Correct: B

{!$Credential.OAuthToken} injects the current access token value. This is useful when an API expects the token in a custom header format other than the standard Authorization: Bearer header.

5
When you deploy a Named Credential's metadata XML via SFDX, what happens to the secret values?
✓ Correct: B

Credential values (passwords, API keys, client secrets) are intentionally excluded from SFDX metadata XML. This is a security design choice — secrets must never be in source control. After deployment, an admin enters the real values in Setup for each org.

6
Which merge field injects the currently logged-in Salesforce user's email into a Named Credential header?
✓ Correct: B

{!$User.Email} injects the running user's email from their Salesforce User record. Other useful user merge fields: {!$User.Id}, {!$User.UserName}. These are evaluated at callout time.

7
An External Credential with a custom header for API key authentication uses which Protocol setting?
✓ Correct: C

For API key authentication (injecting a key via a custom header like X-API-Key), choose Custom as the Protocol in the External Credential. This allows defining custom headers and values without OAuth flow overhead.

8
What metadata folder contains Named Credential definition files in an SFDX project?
✓ Correct: B

Named Credential files are in force-app/main/default/namedCredentials/ with extension .namedCredential-meta.xml. External Credential files are in force-app/main/default/externalCredentials/.

9
What is the benefit of multiple Named Credentials sharing one External Credential?
✓ Correct: B

When multiple NCs (e.g., one per environment, one per API version) reference one EC, you update auth config (rotate client secret, change token URL) in one place. All NCs automatically use the updated config.

10
Which AWS authentication protocol is natively supported as a Named Credential protocol?
✓ Correct: C

Salesforce Named Credentials natively support AWS Signature Version 4 as a protocol. Configure the AWS Access Key ID, Secret Access Key, Region, and Service — Salesforce computes the complex SigV4 signature automatically for every callout.
