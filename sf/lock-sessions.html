Salesforce Session Setting: Lock Sessions to Originating IP

Warning: Enabling Lock sessions to the IP address from which they originated can cause repeated authentication or "Too Many Redirects" in environments where client IP addresses change.

Overview

This setting binds an authenticated Salesforce session to the public IP address used during login. If subsequent requests arrive from a different IP, Salesforce invalidates the session and redirects the user for authentication.

Redirect Loop

User Login → Session Created (IP=A)
↓
Next Request (IP=B)
↓
Salesforce Invalidates Session
↓
Redirect to SSO/Login
↓
Authenticated Again
↓
Request from Different IP
↓
Loop Continues 🔁

Common Causes

  • F5 or load balancers using multiple SNAT addresses
  • VPN exit node changes
  • Zscaler / Netskope / Secure Web Gateway
  • Wi-Fi ↔ Cellular switching
  • Multiple Internet gateways or NAT pools

Symptoms

SymptomDescription
Too Many RedirectsBrowser repeatedly redirects to login.
Login LoopSuccessful authentication never reaches Salesforce.
OAuth FailuresConnected apps lose session.

Diagnosis

  1. Review Salesforce Login History.
  2. Review IdP logs for repeated SAML/OAuth authentication.
  3. Verify whether outbound IP changes during the session.
  4. Review F5 SNAT and persistence configuration.

Recommendations

Recommended

  • MFA
  • Trusted IP Ranges
  • Login IP Ranges
  • Conditional Access
  • Session Security Levels

Use with Caution

Enable IP locking only when outbound client IPs remain stable throughout the session.

F5 Considerations

  • Enable persistence (source IP or cookie).
  • Avoid rotating SNAT addresses.
  • Maintain consistent egress IP.
  • Validate SSL termination configuration.

Summary

If enabling this setting immediately causes redirect loops, IP address changes are the most likely root cause. Modern authentication controls such as MFA and conditional access usually provide stronger security with fewer usability issues.
