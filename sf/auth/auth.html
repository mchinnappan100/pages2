Salesforce CLI · Quick Guide

Authenticate a Salesforce Org

Use the browser-based OAuth flow to authorize an org and give it a memorable CLI alias.

Web Login OAuth MFA / SSO friendly
1

Run the login command

The legacy command below is still supported. For new scripts and documentation, Salesforce recommends the current sf org login web form.

Legacy syntax
sf force auth web login -r <org-url> -a uat-org
Current syntax · recommended
sf org login web --instance-url <org-url> --alias uat-org

-r is the short form of --instance-url; -a is the short form of --alias.

2

Complete browser authentication

  1. 01SF CLI opens your default browser at the specified Salesforce login endpoint.
  2. 02Sign in using your Salesforce credentials. Complete MFA or your organization's SSO steps if prompted.
  3. 03Review the access request and click Allow.
  4. 04Return to the terminal. The CLI stores the authorization locally and associates it with the alias uat-org.

Which URL should I use?

Use your org's enhanced My Domain login URL, not a Lightning UI URL ending in .lightning.force.com.

Production / My Domain

https://<domain>.my.salesforce.com

Sandbox

https://<domain>--<sandbox>.sandbox.my.salesforce.com

Useful follow-up commands

List authenticated orgs

sf org list

Display the UAT org

sf org display --target-org uat-org

Use the alias in a command

sf project deploy start -o uat-org

A couple of things to remember

  • The alias is a local nickname; uat-org is an example you can replace with your preferred name.
  • Use --set-default if you want this org to become the default target for commands that support a default org.
  • Your Salesforce user must be permitted to approve the CLI's connected-app access request.
  • Never share access tokens or verbose auth URLs; they can grant access to your org.
