Level 01

Overview

What this is: A headless backend that turns a folder of .pptx files into a queryable knowledge base. Text, speaker notes, and embedded audio/video are all indexed and searchable. AI agents connect through the MCP server using the same authorization model as the REST API.
📂

What it stores

Every uploaded .pptx is parsed into a normalized slide model. All content is indexed — including spoken words from embedded audio and video.

  • Slide titles, body text, bullet lists
  • Speaker notes (indexed separately)
  • Hyperlinks and image references
  • Audio/video transcripts via local Whisper
  • Presentation metadata (author, date, tags)
▶ See normalized slide model 
{
  "id": "ppt-123",
  "title": "Revenue Cloud Architecture",
  "author": "Jane Smith",
  "slideCount": 7,
  "slides": [
    {
      "number": 3,
      "title": "Order Processing Architecture",
      "text": "Orders flow through CPQ → OM → Fulfillment\nRepeated saves cause bottlenecks...",
      "notes": "Root cause: legacy trigger pattern\n[Transcript: demo.mp3]\nSpoken: as I showed on slide two...",
      "content": {
        "elements": [...],
        "links": [...],
        "images": [...]
      }
    }
  ]
}

Key: transcripts are appended to notes and flow into both FTS and vector indexes automatically.

🔍

Three search modes

Search works across all slide content — including transcripts — using keyword matching, semantic similarity, or a hybrid of both.

  • Keyword — PostgreSQL full-text search with ts_rank scoring
  • Semantic — pgvector cosine similarity via embeddings
  • Hybrid — merged score with +0.1 bonus for dual-matched slides
  • Results include relevance score and which modes matched
  • Filters: author, tags, date range, presentation ID
▶ See search result shape 
{
  "presentationId": "...",
  "presentationTitle": "Revenue Cloud Architecture",
  "slideNumber": 3,
  "slideTitle": "Order Processing Architecture",
  "score": 0.94,
  "snippet": "...order is persisted multiple times during the transaction lifecycle...",
  "matchedBy": ["semantic", "keyword"]
}

Result: spoken words in embedded audio rank alongside slide text.

🤖

MCP server

AI assistants (Claude, Cursor, custom agents) connect over stdio using the Model Context Protocol. Nine tools cover every retrieval use case.

  • Search presentations and slides by natural language
  • Retrieve full slide content including transcripts
  • Get presentation outlines and speaker notes
  • Find semantically related slides
  • Same authorization as the REST API — no bypass possible
▶ See Claude Desktop config 
{
  "mcpServers": {
    "pptrepo": {
      "command": "node",
      "args": [
        "/path/to/ppt-mcp/dist/cli/index.js",
        "mcp"
      ]
    }
  }
}

After connecting: ask Claude "Find slides about repeated database operations during order processing" and it will call search_slides and return slide content with relevance scores.

Level 02

Quick Start

Prerequisites: Node.js 20+, PostgreSQL 15+ with the pgvector extension installed, and the zip CLI (for generating sample files). Whisper and ffmpeg are optional and only needed if your presentations contain embedded audio or video.
⚙️

Install & configure

Clone, install, and create your .env from the example. Only DATABASE_URL is required to start.

▶ Commands 
git clone <repo> && cd ppt-mcp
npm install
cp .env.example .env
# edit .env — set DATABASE_URL at minimum
🗄️

Migrate & build

Apply the SQL migration (creates all tables including pgvector and FTS triggers), then compile TypeScript.

▶ Commands 
npm run migrate     # applies migrations/001_initial.sql
npm run build       # tsc → dist/

pgvector: if CREATE EXTENSION IF NOT EXISTS vector fails, install pgvector for your PostgreSQL version first: apt install postgresql-15-pgvector

🚀

Start & index

Start the server, generate three sample presentations, index them, then open the web UI.

▶ Commands 
node dist/index.js                        # start on :3000
npm run create-samples                    # create sample .pptx files
node dist/cli/index.js index run \
  ./data/samples                          # index all samples

Then open: http://localhost:3000 — sign in with any email address (demo mode).

Level 03

Search

Tip: Hybrid mode is the default and usually the best choice. It combines keyword relevance with semantic understanding — a slide about "repeated Order saves causing performance issues" will surface for a query like "database bottlenecks during checkout", even without the exact words.
🔤

Keyword search

Uses PostgreSQL tsvector and ts_rank. Fast and exact. Good for searching specific terms, names, or identifiers.

  • Searches: title, body text, notes, transcripts
  • Words joined by & in tsquery
  • No embedding provider required
  • Works offline and in air-gapped environments
▶ See API call 
POST /api/v1/search
Authorization: Bearer <token>

{
  "query": "Revenue Cloud performance",
  "mode": "keyword",
  "limit": 10
}
🧠

Semantic search

Converts the query and slide text to embedding vectors and finds nearest neighbours by cosine similarity. Finds conceptually related content even when exact words differ.

  • Requires Ollama or OpenAI embedding provider
  • pgvector ivfflat index (cosine ops, 100 lists)
  • Score = 1 − cosine distance
  • Transcripts embedded alongside slide text
▶ See .env setup 
# Ollama (local, free)
EMBEDDING_PROVIDER=ollama
EMBEDDING_MODEL=nomic-embed-text
EMBEDDING_URL=http://localhost:11434

# OpenAI (cloud)
EMBEDDING_PROVIDER=openai
EMBEDDING_MODEL=text-embedding-3-small
EMBEDDING_API_KEY=sk-...

Note: do not mix models after indexing — all slides must use the same embedding dimension.

⚡

Hybrid search

Runs both keyword and semantic passes in parallel, merges by (presentationId, slideNumber) key, and awards a bonus to slides that appear in both result sets.

  • Combined score = avg(fts_rank, vec_score) + 0.1 if both matched
  • Results sorted descending by combined score
  • Falls back to keyword-only if embeddings unavailable
  • matchedBy field shows which modes found each result
▶ See CLI search 
pptrepo search "repeated database operations order" \
  --mode hybrid \
  --limit 5 \
  --json

Output: JSON array of slides with score, snippet, and matchedBy.

Level 05

Audio / Video Transcription

Opt-in feature: Set WHISPER_ENABLED=true to activate. Transcription runs inside the background indexing job — upload still returns 202 immediately. A file that times out or fails is skipped with a warning; the rest of the presentation continues indexing.
🎙️

How it works

The PPTX parser detects audio/video relationships in each slide's .rels file. Media buffers are extracted from the ZIP once, written to a temp directory, and passed to the local whisper CLI.

  • Parser records mediaZipPaths[] on each ParsedSlide
  • extractMediaFiles() writes binaries to OS tmpdir
  • Video files: ffmpeg extracts 16 kHz mono WAV first
  • Whisper writes a .txt file; indexer reads and deletes it
  • Transcript appended as [Transcript: file.mp3]\n… in notes
  • Temp dir cleaned up in finally block
▶ See .env config 
WHISPER_ENABLED=true
WHISPER_MODEL=base        # tiny|base|small|medium|large
WHISPER_LANGUAGE=en       # or 'auto' for detection
WHISPER_TIMEOUT_MS=120000 # 2 min per file

# If not on PATH:
WHISPER_BINARY=/usr/local/bin/whisper
FFMPEG_BINARY=/usr/local/bin/ffmpeg
📦

Installation

Whisper is a Python package from OpenAI. It runs entirely locally — no API key, no data leaves your machine.

  • Python 3.8+ required
  • GPU optional but significantly faster
  • ffmpeg required only for video files
  • Model files downloaded on first use (~74 MB for base)
▶ Install commands 
# Install Whisper
pip install openai-whisper

# Install ffmpeg (for video files)
brew install ffmpeg           # macOS
sudo apt install ffmpeg       # Ubuntu / Debian
choco install ffmpeg          # Windows

# Verify
whisper --help
ffmpeg -version

After install: set WHISPER_ENABLED=true and re-index any presentations with embedded media.

⚖️

Model size guide

Larger models are more accurate but slower. For most business presentations with clear speech, base or small is a good starting point.

  • tiny — 39 MB, fastest, lowest accuracy
  • base — 74 MB, fast, good for clear speech
  • small — 244 MB, moderate, better accuracy
  • medium — 769 MB, slow, high accuracy
  • large — 1.5 GB, slowest, best accuracy
▶ See WebSocket events 
// fired when whisper starts on a file
{
  "event": "transcribe.started",
  "presentationId": "ppt-123",
  "slideNumber": 3,
  "mediaFile": "audio1.mp3"
}

// fired when transcript is ready
{
  "event": "transcribe.completed",
  "presentationId": "ppt-123",
  "slideNumber": 3,
  "mediaFile": "audio1.mp3",
  "chars": 842
}

The dashboard can display live transcription progress alongside indexing progress.

Level 06

Authentication & Roles

🔐

Demo mode

Out of the box, a local HS256 JWT is issued by POST /auth/login. No external IdP required. Any email address works.

▶ See login call 
curl -s -X POST http://localhost:3000/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"you@example.com","role":"admin"}' \
| jq .token

Production: replace with an OIDC Authorization Code + PKCE flow. Set OAUTH_ISSUER, OAUTH_CLIENT_ID, OAUTH_CLIENT_SECRET.

🛡️

RBAC roles

Four roles control what each user can do. Assign roles at login time in demo mode, or map them from OIDC claims in production.

  • admin — full access including delete and user management
  • editor — upload and re-index presentations
  • viewer — search, browse, view slides
  • mcp_user — MCP search and content retrieval only
🌐

OIDC providers

Any standards-compliant OIDC provider works. The API validates tokens for issuer, audience, expiry, and signature.

  • Microsoft Entra ID (Azure AD)
  • Okta
  • Auth0
  • Keycloak
  • Google Identity
  • Any OIDC-compliant provider

Best Practices

Never commit .env

.env is in .gitignore. Store secrets in a secrets manager (AWS Secrets Manager, HashiCorp Vault, 1Password Secrets Automation) and inject them as environment variables at runtime.

Change JWT_SECRET in production

The demo default is publicly known. Generate a random 64-character secret and rotate it periodically. In production, prefer a real OIDC provider over the demo JWT endpoint.

openssl rand -base64 48

Use hybrid search by default

Hybrid mode is more robust than either mode alone. It handles exact-match queries (keyword strength) and natural-language queries (semantic strength) without configuration per query.

Choose Whisper model by use case

For internal business presentations with clear speech, base is usually sufficient. For recorded demos, customer calls, or non-English content, use small or medium.

Keep embedding dimensions consistent

All slides in a repository must use the same model and dimension. If you change EMBEDDING_MODEL, re-index all presentations. Mixed dimensions silently break vector search — queries return nonsense scores.

Use the MCP server separately in production

Run pptrepo mcp as a separate process pointing at the same database. This isolates the AI access surface from your API, allows independent restarts, and limits blast radius if an agent misbehaves.

node dist/cli/index.js mcp
