Slide 2 of 8 · Installation

Installation & Requirements

# Install globally
npm install -g sf-data-util

Prerequisites

  • Node.js ≥ 18.0.0
  • Salesforce CLI (sf) installed and authenticated to both the source and target orgs
  • For load-plan mode: a load-plan.json describing the object and fields

Smart Key Detection

sf-data-util automatically identifies the record key from these fields (in priority order): StockKeepingUnit · ProductCode · ExternalId · Code · Name · Id

Slide 3 of 8 · Two Modes

Two Operating Modes

Mode 1 — Load-Plan (compare)

Use an existing load-plan.json to define which object and fields to compare.

sf-data-util compare \
  -s source-org@company.com \
  -t target-org@company.com \
  -l ./load-plan.json \
  -o Product2

Best when you already have a migration load plan and want to validate data drift for a specific object.

Mode 2 — Direct SOQL (query)

Write any SOQL query inline or point to a .soql file.

sf-data-util query \
  -s dev -t prod \
  -q "SELECT StockKeepingUnit,
      Name, ProductCode
      FROM Product2
      WHERE IsActive = true"

Best for ad-hoc comparisons or when no load plan exists.

Slide 5 of 8 · Query Examples

Query Mode Examples

# Inline SOQL — compare active products
sf-data-util query \
  -s dev -t prod \
  -q "SELECT StockKeepingUnit, Name, ProductCode FROM Product2 WHERE IsActive = true"

# From a .soql file
echo "SELECT Name, Status FROM ProductClassification" > myquery.soql
sf-data-util query -s dev -t uat -f myquery.soql

# Compare custom object data
sf-data-util query \
  -s staging -t production \
  -q "SELECT ExternalId__c, Name, Status__c FROM MyObject__c ORDER BY Name"
Slide 6 of 8 · HTML Report

Interactive HTML Report

The generated report auto-opens in the browser and is fully self-contained — share the HTML file with anyone, no server needed.

  • KPI Dashboard — counts of Source Only, Target Only, Values Differ, and Identical records at a glance
  • Raw tables — separate sortable tables for source and target records
  • Color-coded combined diff table — all four categories in one view with distinct row colours
  • Interactive filter buttons — click to show only Source Only / Target Only / Values Differ / Identical
  • Live search — search across all table columns with live row count feedback
  • Column sorting — click any header to sort ascending / descending
  • Copy SOQL button — copies the query used with a success animation
  • Safe Excel export — handles large text fields correctly

Output Filename

Reports are named sf-compare-<Object>-<timestamp>.html, e.g. sf-compare-Product2-1737412345678.html

Slide 7 of 8 · Use Cases

When to Use sf-data-util

Pre-Migration Validation

  • Identify records that exist in source but not yet in target before a go-live
  • Spot field-level differences between staging and production data
  • Confirm that a migration run produced zero remaining differences

Ongoing Drift Detection

  • Compare production and sandbox data after a hotfix to check for unintended changes
  • Track data drift between orgs over time using the same .soql file
  • Generate a shareable diff report for stakeholder sign-off

Works with smt-studio

Use sf-data-util to validate data before and after a migration run with smt-studio — same org aliases, same SOQL fields, closing the migration verification loop.

Slide 8 of 8 · Summary

Key Takeaways

  • Two modes: compare (load-plan based) and query (inline SOQL or .soql file)
  • Smart key detection — automatically picks the right record identifier from StockKeepingUnit, ProductCode, ExternalId, Name, or Id
  • Four diff categories — Source Only, Target Only, Values Differ, Identical — with interactive filter buttons
  • Self-contained HTML report auto-opens in the browser; shareable with no server required
  • Live search with row count feedback makes large datasets easy to navigate
  • Safe Excel export handles large text fields that would break standard exports
  • Pairs naturally with smt-studio for pre- and post-migration data validation
  • Zero config beyond org aliases and a SOQL query — results in seconds
