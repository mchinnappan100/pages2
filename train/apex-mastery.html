Apex Design Patterns

Chapter 12 covers the enterprise patterns that keep large Apex codebases maintainable, testable, and governor-limit-safe.

PatternPurpose
Service LayerEncapsulates business logic — called by triggers, controllers, and APIs
SelectorCentralises all SOQL queries; enforces FLS and sharing consistently
DomainHouses object-specific logic on the SObject itself (trigger handling)
Unit of WorkBatches all DML into a single transaction — one commitWork() call
FactoryCreates instances without coupling callers to concrete types
StrategySwaps algorithms at runtime via a common interface
SingletonEnsures one instance per transaction (e.g. settings cache)
DecoratorAdds behaviour to objects without modifying their class

  • Bind variables — always use :variable syntax
  • LIMIT / OFFSET for pagination

Slide 8 of 11 · SOQL Performance (Ch 17)

SOQL Performance & Query Optimisation

  • Selective queries — filter on indexed fields (Id, Name, ExternalId, lookup fields)
  • Use the query plan tool in Developer Console to check index usage
  • Keyset pagination — use WHERE Id > :lastId instead of OFFSET for large sets
  • SOQL for-loop — process large query results in batches of 200 to avoid heap limits
  • Avoid queries inside loops — bulk-query before the loop, index into a Map
// SOQL for-loop — avoids heap limit on large result sets
for (List<Account> batch : [SELECT Id, Name FROM Account]) {
  // process each batch of 200
}

// Keyset pagination — scalable alternative to OFFSET
SELECT Id, Name FROM Account WHERE Id > :lastId
ORDER BY Id LIMIT 200
Slide 9 of 11 · SOSL Deep Dive (Ch 18–19)

SOSL — Full-Text Search

Ch 18 — SOSL Fundamentals

  • FIND syntax with search groups: IN ALL / NAME / EMAIL / PHONE FIELDS
  • RETURNING clause to specify objects and fields
  • Bind variables work in SOSL just like SOQL
  • Always test with Test.setFixedSearchResults()
FIND {Acme*} IN ALL FIELDS
RETURNING Account(Id, Name),
          Contact(Id, Email)

Ch 19 — Advanced SOSL

  • Wildcards: * (multi-char) and ? (single-char)
  • Stemming — finds word variants (run → running, ran)
  • Phrase search with double quotes
  • Boolean operators: AND, OR, AND NOT
  • WITH SNIPPET for contextual search excerpts
  • Spell correction and Knowledge article search

SOSL vs SOQL & Agentforce / ANTLR

Ch 20 — SOSL vs SOQL

Use SOQL when…Use SOSL when…
You know which object to queryYou're searching across multiple objects
You need precise field filtersUser is typing a free-text search term
Counting or aggregating recordsYou need wildcard / stemmed matching
DML decisions depend on dataDiscovering which objects contain a value

Hybrid pattern: SOSL discovery → SOQL enrichment

Slide 11 of 11 · Summary

Key Takeaways

  • 20 chapters span from Apex primitives and governor limits all the way to ANTLR grammar and Agentforce actions
  • Always code with governor limits in mind — one SOQL query outside a loop can prevent a bulk trigger failure
  • The trigger handler pattern keeps triggers to a single line — all logic lives in a testable handler class
  • Enterprise design patterns (Service, Selector, Domain, Unit of Work) are the foundation of maintainable codebases
  • Use SOQL for-loops and keyset pagination to process large data sets without hitting heap limits
  • SOSL is the right tool for free-text, cross-object search; SOQL for structured, field-level filtering
  • @InvocableMethod exposes Apex logic to Agentforce agent actions and Flow — no code changes needed later
  • 200 practice Q&A questions (10 per chapter) reinforce every concept interactively
