sf-rest-client

A world-class Postman-like REST client for Salesforce & Generic APIs — with SOAP, GraphQL, Monaco editor, request collections, auto-logged history, and an AI assistant. Runs entirely locally, no cloud account needed.

Salesforce RESTSOAPGraphQL Monaco EditorCollections AI Assistantv4.0.3
npm install -g sf-rest-client
# Opens at http://localhost:3131
Slide 2 of 9 · Installation & CLI

Installation & CLI Options

# Install globally
npm install -g sf-rest-client

# Default port 3131
sf-rest-client

# Custom port
sf-rest-client --port 8080

# Bind to all interfaces
sf-rest-client --host 0.0.0.0 --port 8080

# Enable AI assistant panel
sf-rest-client --enable-ai

Prerequisites: Node.js ≥ 18, npm ≥ 9. Salesforce CLI (sf) only needed for the Salesforce tab.

Slide 4 of 9 · Salesforce Auth Flow

Salesforce Authentication Flow

  • Browser calls GET /api/sf/orgs → server runs sf org list --json → all orgs in dropdown
  • User clicks Run → server calls sf org display --target-org <username> to get a fresh token
  • Server injects Authorization: Bearer <token> and proxies the call via axios — no credentials stored
  • CLI update warnings stripped automatically — only JSON is parsed from stdout
  • Refresh button (↺) re-lists orgs without restarting the server
# Authenticate orgs before using the Salesforce tab
sf org login web --alias my-prod
sf org login web --alias my-sandbox --instance-url https://test.salesforce.com
sf org list # verify all orgs appear
Slide 5 of 9 · Salesforce REST Examples

Salesforce REST API Examples

# Query accounts
GET /services/data/v64.0/query?q=SELECT+Id,Name+FROM+Account+LIMIT+10

# Describe an SObject
GET /services/data/v64.0/sobjects/Opportunity/describe

# Create a record
POST /services/data/v64.0/sobjects/Contact
Body: { "FirstName": "Jane", "LastName": "Doe", "Email": "jane@example.com" }

# Update a record
PATCH /services/data/v64.0/sobjects/Contact/<Id>
Body: { "Title": "VP Engineering" }

# Tooling API — list Apex classes
GET /services/data/v64.0/tooling/query?q=SELECT+Id,Name+FROM+ApexClass

Slide 7 of 9 · Collections & History

Collections & History

Collections

  • Create named groups for SF or REST requests
  • Save any request into a collection with a name
  • Click a saved request to load it into the editor
  • Export all collections + history as sfutils-collections.json for team sharing
  • Stored at ~/.sf-rest-client/collections/data.json

History

  • Auto-logged for every request — up to 200 entries
  • Shows method, URL, status code, and response time
  • Click any entry to reload it into the editor
  • Clear All to reset
  • AI config stored at ~/.sf-rest-client/collections/ai-config.json
Slide 8 of 9 · AI Assistant

AI Assistant (--enable-ai)

  • Supported providers: Ollama (local), Claude (Anthropic), OpenAI, Gemini, xAI Grok
  • Configured via --enable-ai flag — panel appears in the UI
  • AI config saved to ~/.sf-rest-client/collections/ai-config.json
  • Useful for: generating SOQL from plain English, explaining API responses, writing request bodies, debugging authentication errors

Example AI prompts

"Write a SOQL query to find all Opportunities closing this quarter with Amount > 10000"
"Explain this Salesforce REST API error response"
"Generate a JSON body to create a Contact with all required fields"

Slide 9 of 9 · Summary

Key Takeaways

  • Self-hosted Postman alternative for Salesforce — runs locally, no cloud account, no data leaves your machine
  • Salesforce tab auto-injects Bearer tokens from sf CLI — no manual credential management
  • Three tabs: Salesforce REST, Generic REST, SOAP — plus GraphQL support
  • Monaco editor with auto-format, syntax highlighting, and Ctrl+Enter to send
  • Collections group and save requests; Export creates a portable JSON for teammates
  • History auto-logs every request with status and timing — last 200 entries
  • AI assistant (--enable-ai) supports Ollama, Claude, OpenAI, Gemini, and xAI
  • Data stored at ~/.sf-rest-client/ — human-readable JSON, easy to back up or share
