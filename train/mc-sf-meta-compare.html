Slide 2 of 9 · The Problem

Why Compare Metadata?

Salesforce orgs drift over time — hotfixes land in production that never made it back to staging. Knowing what's different is the first step to any deployment or audit.

  • No built-in tool to diff Apex classes, Flows, or LWC between two orgs
  • Manual comparison requires exporting metadata from both orgs and running a file diff locally
  • No easy way to identify components that exist in source but not target, or vice versa
  • Sharing diff results with stakeholders requires custom reports
  • No recurring/scheduled metadata drift detection

mc-sf-meta-compare solves this

One command compares any metadata type across two orgs and generates a shareable interactive HTML report with semantic diff, search, sort, and CSV export.

Slide 4 of 9 · Basic Usage

Getting Started

# Compare a single metadata type
mc-meta-compare compare -s source-org -t target-org -m ApexClass

# Compare all types listed in package.xml
mc-meta-compare compare -s source-org -t target-org -x package.xml

# Detailed file-level diff
mc-meta-compare compare -s source-org -t target-org --detailed -x package.xml

# Portable shareable ZIP
mc-meta-compare compare -s source-org -t target-org --detailed --zip -x package.xml
Slide 5 of 9 · All CLI Options

CLI Reference

-s, --source <alias>Source org alias (required)
-t, --target <alias>Target org alias (required)

-c, --cron <expr>Schedule recurring runs (5-field cron)
Slide 6 of 9 · Detailed Mode

--detailed & --zip

  • --detailed retrieves metadata source files into local SF projects and compares file-by-file
  • Generates a fully self-contained HTML report — no server needed to view it
  • Monaco diff editor embedded in the report for line-by-line comparison
  • --zip bundles the report into a portable ZIP that recipients open in any browser
# Detailed diff + ZIP for sharing
mc-meta-compare compare \
  -s prod-org -t staging-org \
  --detailed --zip \
  -x package.xml
# → report.zip (share with anyone)
Slide 7 of 9 · Git Comparison

Compare Git Repos (No Org Needed)

Use -g / --source-git to compare metadata from two git repos or branches directly — no Salesforce org access required.

# Compare two branches of the same repo
mc-meta-compare compare \
  -g https://github.com/myorg/sf-project \
  --source-branch feature/my-feature \
  --target-branch main

# Compare two different repos
mc-meta-compare compare \
  -g https://github.com/myorg/project-a \
  --target-git https://github.com/myorg/project-b

Supports HTTPS, SSH, and local paths. Uses git worktree for simultaneous checkouts.

Slide 8 of 9 · Scheduling & Notifications

Automated Drift Detection

Cron Scheduling

  • Standard 5-field cron syntax
  • Runs comparison on schedule, generates new report each time
-c "0 8 * * 1-5"
# 8am Mon-Fri

Notifications

  • Email: -e — send ZIP via SMTP (implies --detailed --zip)
  • Slack: --slack — Block Kit KPI summary + ZIP upload
  • Configure once: mc-meta-compare config smtp
# Schedule + email + Slack
mc-meta-compare compare -s prod -t staging -x pkg.xml \
  -c "0 8 * * 1-5" -e team@company.com --slack #deployments
Slide 9 of 9 · Summary

Key Takeaways

  • One command compares any Salesforce metadata type across two orgs or git repos
  • Identifies common, source-only, and target-only components instantly
  • Monaco semantic diff embedded in report — no external tool needed to view diffs
  • --detailed --zip produces a portable, self-contained report anyone can open
  • Git comparison mode works without any Salesforce org credentials
  • Cron + email + Slack enables fully automated metadata drift detection
  • Smart auth tries multiple sf CLI commands automatically
