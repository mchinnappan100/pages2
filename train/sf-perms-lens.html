sf-perms-lens

Salesforce Permissions Lens — inspect every permission a user has, see exactly which Profile, Permission Set, or PSG grants it, and explore a live force-directed graph.

Salesforce Permissions Security Node.js CLI MIT License v1.2.0
npm install -g sf-perms-lens
Slide 2 of 8 · Why sf-perms-lens?

The Problem

Salesforce permissions are spread across Profiles, Permission Sets, and Permission Set Groups. Debugging "why can this user do X?" requires clicking through many setup screens.

  • Permission lineage hidden across multiple objects — painful to trace manually
  • Field-level security requires drilling into each object separately
  • No built-in graph view showing the full permission chain
  • Difficult to audit security posture across many users at once
  • No AI assistant to explain permissions in natural language

sf-perms-lens solves this

One command gives you a complete, interactive browser UI showing the full permission picture for any Salesforce user — with graph, tables, FLS, and AI Sidekick.

Slide 4 of 8 · Architecture

How It Works

🖥 CLI
→
Express + WebSocket
→
Browser UI
Browser UI
→
WebSocket
→
sf CLI (SOQL)
→
Salesforce Org
  • CLI starts Express + WebSocket server on configured port (default 3579)
  • Browser connects via WebSocket — analysis status streams in real time
  • sf CLI invoked server-side for all SOQL queries
  • Permission fields discovered dynamically via sf sobject describe
  • Object/field permissions use the Profile's owned PermissionSet ID
Slide 5 of 8 · Installation

Quick Start

# Install globally
npm install -g sf-perms-lens

# Inspect all users in an org
sf-perms-lens -o my-org-alias

# Pre-select a specific user
sf-perms-lens -o my-org-alias -u user@example.com

# Custom port, don't open browser automatically
sf-perms-lens -o my-org-alias -p 8080 --no-open

Requires: Node.js ≥ 18, Salesforce CLI (sf) installed and authenticated

Slide 7 of 8 · Use Cases

When to Use sf-perms-lens

Security Audits

  • Audit a user's full permission footprint before a go-live
  • Find over-permissioned users — who has ModifyAll?
  • Export SVG graph as evidence for compliance reviews

Troubleshooting

  • Debug "User can't see field X" — check FLS inline
  • Trace exactly which PSG or PermSet grants a given permission
  • Ask AI Sidekick to explain complex permission chains

Admin & Dev Productivity

  • Drag the pane splitter to compare different sections side by side
  • Download JSON for scripting or further analysis
  • Switch dark/light theme — preference saved across sessions
