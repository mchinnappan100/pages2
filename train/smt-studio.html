smt-studio
Slide 2 of 10 · The Problem

Why smt-studio?

Salesforce data migration typically requires assembling multiple tools — Data Loader, custom scripts, manual comparisons — with no unified view of progress or differences.

  • No single tool covers the full migrate cycle: compare → extract CSV → load → verify
  • Data Loader requires Java, manual configuration, and produces no diff reports
  • Identifying value differences across orgs requires custom scripting
  • Bulk API batching, SOQL pagination, and error handling must all be hand-rolled
  • No built-in AI to help write SOQL, explain data issues, or review load plans

smt-studio solves this

One npm install gives you a web UI + CLI covering the full migration lifecycle — compare orgs, generate load plans, extract CSV, bulk-upload, verify — with real-time progress and an AI Sidekick.

Slide 3 of 10 · Key Features

What smt-studio Does

Migration Core

  • Load Plan editor — Monaco editor for VS Code-like JSON editing
  • Generate Load Plan — describes objects via REST API, no binary needed
  • Full migration with real-time terminal output & per-object pause dialogs
  • Chunked Bulk API — up to 100k rows per batch
  • SOQL pagination — follows nextRecordsUrl automatically

Comparison & Safety

  • Data comparison across orgs — 4 result categories
  • Deletion candidate detection with --allow-delete flag
  • Smart token retrieval — auto-fallback between sf CLI versions
  • AI Sidekick — Claude, OpenAI, Gemini, xAI, Ollama
  • Settings stored in ~/.migrationrc

3. Compare orgs
4. Generate CSV from source
→
5. Bulk upload to target
→
6. Verify / re-compare
  • Authentication uses sf CLI — no passwords stored in smt-studio
  • Load plan JSON defines which objects and fields to migrate
  • Real-time Socket.IO terminal — see each record batch as it uploads
  • Per-object pause dialogs let you review before proceeding to the next object
  • Re-run compare after migration to confirm zero differences remain
Slide 5 of 10 · Data Comparison

Four Comparison Result Categories

✓ Common
Exist in both orgs, values match
← Source Only
In source but not target
→ Target Only
In target but not source
≠ Value Diff
Same ID, different field values
  • Value Differences is the key category — records that exist in both orgs but have diverged field values
  • Source-Only records are candidates for migration to target
  • Target-Only records are candidates for deletion (requires --allow-delete)
  • Run comparison before and after migration to measure progress toward zero drift
Slide 6 of 10 · Load Plan

Load Plan JSON

The load plan is a JSON file defining which Salesforce objects and fields to migrate. Edit it in the Studio's Monaco editor or generate it automatically.

// Example load plan
[
  {
    "object": "Account",
    "query": "SELECT Id, Name, Industry FROM Account WHERE IsDeleted = false",
    "externalId": "Id"
  },
  {
    "object": "Contact",
    "query": "SELECT Id, FirstName, LastName, AccountId FROM Contact",
    "externalId": "Id"
  }
]
  • Use Generate Load Plan in the UI to auto-describe all fields via REST API
  • Configuration including selected objects stored in ~/.migrationrc
Slide 7 of 10 · CLI Usage

CLI Reference

# Launch web UI (default port)
smt-studio

# CLI mode — generate CSVs from source org
smt-studio cli \
  -s source-org-alias \
  -t target-org-alias \
  -l load-plan.json \
  -o gen-csv-file

# CLI mode — run full migration
smt-studio cli \
  -s source-org-alias \
  -t target-org-alias \
  -l load-plan.json \
  -o migrate \
  --csv-output-folder ./output

Slide 9 of 10 · API & Real-time

REST API & Socket.IO Events

REST Endpoints

PathPurpose
/api/authOrg authentication via sf CLI
/api/compareTrigger data comparison
/api/generate-csvExtract records to CSV
/api/migrateRun bulk upload migration
/api/bulk-deleteDelete target-only records
/api/ai/chatProxy to AI Sidekick provider

Socket.IO Events

  • terminal — live output line (server → client)
  • object-start — signals next object beginning
  • pause-prompt — server requests proceed/skip
  • pause-response — client sends proceed/skip back
  • migration-complete — final summary emitted
