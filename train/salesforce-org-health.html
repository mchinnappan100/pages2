Slide 2 of 7 · Installation & Usage

Installation & Usage

# Install globally
npm install -g salesforce-org-health

# Basic usage — generate report
sfoh -o <your-org-username-or-alias>

# Specify custom output file
sfoh -o myorg@company.com --output custom-report.html

# Using an org alias
sfoh -o ea11

# Also available as:
sf-org-health -o <org>

Prerequisites: Node.js ≥ 14, Salesforce CLI (sf), authenticated org with Security Health Check enabled.

Salesforce Objects Queried

  • SecurityHealthCheck — Overall org health score (0–100)
  • SecurityHealthCheckRisks — Detailed risk items filtered by HIGH_RISK, MEDIUM_RISK, LOW_RISK, MEETS_STANDARD
  • Fields: RiskType, Setting, SettingGroup, OrgValue, StandardValue
Slide 4 of 7 · KPI Dashboard

KPI Dashboard & Visualizations

4 KPI Cards

  • Health Score — Overall security score from Salesforce Security Health Check
  • Critical Issues — Count of HIGH_RISK items requiring immediate attention
  • Compliance Rate — % of checks meeting Salesforce standards
  • Total Issues — Complete count of non-compliant items
  • 📥 Download KPI section as PNG image for executive presentations

3 Chart.js Visualizations

  • Risk Level Distribution — Donut chart: High / Medium / Low / Compliant
  • Compliance Overview — Compliant vs. non-compliant at a glance
  • Risk by Category — Bar chart breaking down issues by SettingGroup

All charts are responsive, animated, and interactive.

Slide 5 of 7 · Data Table & Report

Advanced Data Table & Report Structure

  • Sortable columns — click any header to sort ascending / descending
  • Real-time search across all fields
  • Pagination — 20 rows per page with prev/next navigation
  • CSV export — download complete dataset for remediation tracking
  • Color-coded risk badges: 🔴 HIGH / 🟠 MEDIUM / 🔵 LOW / ✅ MEETS_STANDARD

Report Sections

Header (org name + timestamp) → KPI Dashboard (4 cards + PNG export) → 3 Charts → Advanced Data Table (sort / search / paginate / CSV). Fully self-contained HTML — no server needed to view or share.

Slide 6 of 7 · Best Practices

Best Practices & Troubleshooting

Best Practices

  • Run monthly or after major configuration changes
  • Address HIGH_RISK items first — focus on critical issues
  • Compare reports over time to measure improvement
  • Export KPI image for executive summaries
  • Use CSV export to track remediation efforts in a ticket system

Troubleshooting

  • Command not found: sf → Install Salesforce CLI
  • No org configuration found → Run sf org login web -a myorg
  • INVALID_FIELD: No such column 'Score' → Enable Security Health Check in Setup
  • Empty data → Run Security Health Check in your org first, verify Read permissions
Slide 7 of 7 · Summary

Key Takeaways

  • One command generates a fully self-contained, shareable HTML health report from the Salesforce Security Health Check API
  • 4 KPI cards give instant visibility into Health Score, Critical Issues, Compliance Rate, and Total Issues
  • 3 Chart.js charts (donut, compliance overview, risk-by-category bar) make patterns immediately visible
  • Advanced data table with sort, search, pagination, and CSV export supports systematic remediation
  • KPI section exportable as PNG — drop straight into executive slides or compliance reports
  • Runs entirely via the Salesforce CLI — no credentials stored, all queries are read-only
