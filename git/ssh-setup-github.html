Why use SSH instead of HTTPS

HTTPS works, but it means typing a username/token on every push, or wiring up a credential helper. SSH uses a key pair — Git and GitHub handle the handshake automatically, every time.

💡
The short version You generate a private key (stays on your machine) and a public key (goes on GitHub). GitHub trusts anyone who can prove they hold the matching private key.

1 Check for existing SSH keys

You may already have one — no need to generate a duplicate.

ls -al ~/.ssh

Look for a pair like id_ed25519 / id_ed25519.pub or id_rsa / id_rsa.pub. If you see one you already use for GitHub, skip to step 5.

2 Generate a new SSH key

Ed25519 is the current recommendation — smaller, faster, and stronger than RSA.

ssh-keygen -t ed25519 -C "your_email@example.com"
  1. When prompted for a file location, press Enter to accept the default (~/.ssh/id_ed25519), or type a custom path if you're managing multiple keys.
  2. When prompted for a passphrase, set one. It encrypts the private key on disk — recommended even on a personal machine.
My system doesn't support Ed25519
Older systems (or some corporate policies) may still require RSA. Use a 4096-bit key instead: 
ssh-keygen -t rsa -b 4096 -C "your_email@example.com"

3 Start the SSH agent and add your key

The agent holds your decrypted key in memory so you're not typing your passphrase on every single command.

eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
🖥️
macOS users Add UseKeychain yes and AddKeysToAgent yes to ~/.ssh/config so the key survives reboots without re-adding it manually.

4 Add the public key to GitHub

Copy the public key only — the file ending in .pub. Never share the private key.

OSCommand to copy public key
macOSpbcopy < ~/.ssh/id_ed25519.pub
Linuxxclip -sel clip < ~/.ssh/id_ed25519.pub
Windows (Git Bash)clip < ~/.ssh/id_ed25519.pub
Any OScat ~/.ssh/id_ed25519.pub then copy manually
  1. In GitHub, go to Settings → SSH and GPG keys (from your avatar menu, top right).
  2. Click New SSH key.
  3. Give it a descriptive title, e.g. mohan-laptop-coimbatore, and leave key type as Authentication Key.
  4. Paste the public key into the Key field, then click Add SSH key.

5 Test the connection

ssh -T git@github.com

First time, you'll be asked to confirm the host fingerprint — type yes. A successful setup replies with:

Hi your-username! You've successfully authenticated, but GitHub does not provide shell access.
⚠️
GitHub Enterprise Server Replace github.com with your instance's hostname, e.g. ssh -T git@github.yourcompany.com.

Clone a repo with SSH

Use the SSH URL (starts with git@), not the HTTPS one, from the repo's Code dropdown.

git clone git@github.com:username-or-org/project-name.git

Switch an existing repo from HTTPS to SSH

git remote set-url origin git@github.com:username-or-org/project-name.git
git remote -v

Managing multiple accounts (work + personal)

Generate a separate key per account, then map hosts to keys in ~/.ssh/config.

ssh-keygen -t ed25519 -C "work_email@company.com" -f ~/.ssh/id_ed25519_work
ssh-keygen -t ed25519 -C "personal_email@example.com" -f ~/.ssh/id_ed25519_personal

Then in ~/.ssh/config:

# Work
Host github-work
  HostName github.com
  User git
  IdentityFile ~/.ssh/id_ed25519_work

# Personal
Host github-personal
  HostName github.com
  User git
  IdentityFile ~/.ssh/id_ed25519_personal

Clone using the alias instead of github.com directly:

git clone git@github-work:username-or-org/project-name.git

Troubleshooting common issues

Permission denied (publickey)
Usually means the agent isn't holding your key, or the wrong key is being offered. 
ssh-add -l
ssh-add ~/.ssh/id_ed25519
ssh -vT git@github.com
The -v flag shows verbose output — check which identity file it's actually trying.
Still being asked for a username/password
Your remote URL is still HTTPS. Check with git remote -v and switch it — see Switch remote to SSH above.
Agent forgets my key after a reboot
On macOS, add these lines to ~/.ssh/config: 
Host *
  AddKeysToAgent yes
  UseKeychain yes
  IdentityFile ~/.ssh/id_ed25519
On Linux, add ssh-add ~/.ssh/id_ed25519 to your shell profile, or use keychain.
Host key verification failed
GitHub rotated its host key, or you're hitting a man-in-the-middle warning. Remove the stale entry and reconnect: 
ssh-keygen -R github.com
ssh -T git@github.com
Always verify the fingerprint against GitHub's published SSH key fingerprints before accepting.
Key works for one account but not another
GitHub ties each SSH key to a single account — the same key can't authenticate two different GitHub identities. Generate a distinct key per account and map them with host aliases; see Multiple accounts below.

Security notes

🔒
Never share or commit your private key The private key (no .pub extension) never leaves your machine — not in a repo, not in Slack, not in a support ticket.
🔁
Rotate keys periodically Set expiration dates on GitHub-side keys, and remove ones tied to devices you no longer use (old laptop, decommissioned CI runner, etc.).
🗝️
Use a passphrase A stolen private key without a passphrase is instantly usable. With one, it's just an encrypted blob.

Quick checklist

  • Checked for an existing key before generating a new one
  • Generated an Ed25519 key with a passphrase
  • Added the key to ssh-agent
  • Pasted the public key into GitHub → SSH Keys
  • ssh -T git@github.com returns a welcome message
  • Repo remote uses git@github.com:..., not https://
