Key question: How do we train a model to answer the question once, in the way the user actually requested?

01 · The observation

Correct facts. Unhelpful behavior.

The model may know that Paris is the capital of France and still produce an answer that loops, imitates a quiz template, or fails to stop naturally.

↻ Text continuation

“Keep going…”

The generation continues a learned pattern—even when that pattern has become repetitive and no longer helps the user.

Correct Answer: A. Paris
Correct Answer: A. Paris
Correct Answer: A. Paris…
✓ User-oriented response

“Answer the request.”

An assistant should identify the task, honor the requested length or format, give a useful answer, and finish.

The capital of France is Paris.

A careful scientific conclusion

Repetition alone does not prove a model was never instruction-trained. Prompt formatting, decoding settings, model variant, and other factors can also cause it. Treat the output as a useful clue—not a definitive diagnosis.

02 · The training pipeline

Three stages, different purposes

A common pipeline first builds language capability, then teaches response patterns, and may further optimize which responses are preferred.

Stage A📚

Pretraining

Learn language patterns

Train on large text collections to predict the next token from the tokens that came before it.

“The capital of France is”
→ Paris.
Stage B🧭

Supervised fine-tuning

Learn from demonstrations

Train on instructions paired with ideal answers so the model learns useful response patterns.

Instruction: Answer in one sentence.
Target: The capital is Paris.
Stage C⚖️

Preference optimization

Improve response choices

Use human or AI feedback, preference pairs, or other signals to favor responses that better meet objectives.

✓ Concise and useful
× Repetitive and unhelpful

This is a common conceptual pipeline, not a universal recipe. Some models use different combinations or orders of supervised fine-tuning, reinforcement learning, and other optimization methods.

03 · Under the hood

How instruction training works

Supervised fine-tuning (SFT) gives the model examples of what a good response looks like. The architecture stays broadly the same; the training examples and model weights change.

1

Collect examples

Pair instructions with accurate, helpful, well-formatted target responses.

2

Predict target tokens

Run the model on the instruction and response context, then measure prediction error on target response tokens.

3

Update weights

Backpropagation and an optimizer adjust the weights to make desirable responses more likely.

One training example

Instruction → target response → learning signal

User instruction

What is the capital of France? Answer in one sentence.

↓
Ideal response

The capital of France is Paris.

↓
Training signal

Compare predicted tokens with target tokens, calculate loss, backpropagate gradients, and update weights.

Simplified SFT pseudocode

Illustrative—not directly executable

for batch in training_data:
    inputs = tokenize_instructions_and_responses(batch)
    logits = model(inputs)

    # Usually calculate loss on target assistant tokens
    loss = cross_entropy(
        logits[response_positions],
        target_tokens[response_positions]
    )

    loss.backward()
    optimizer.step()
    optimizer.zero_grad()

Real training also handles tokenization, attention masks, padding, batching, and carefully selected loss positions. Many chat-training pipelines mask the loss on prompt tokens and train primarily on assistant responses.

04 · Preference learning

Not all correct answers are equally good

Preference methods can teach a model to favor a useful answer over a repetitive one, even when both contain the same fact.

👍 Preferred response

“The capital of France is Paris.”

Direct, accurate, and aligned with the request.

👎 Less preferred response

“Paris. Correct answer: Paris. Correct answer: Paris…”

Contains the fact, but wastes the user's time.

RLHF

Human preferences train a reward model; reinforcement learning can optimize the policy against that reward.

DPO

Direct Preference Optimization learns from preferred and less-preferred response pairs without a separate reward-model-plus-PPO pipeline.

Other signals

AI feedback and verifiable outcomes can also shape behavior, depending on the task and training recipe.

Preference optimization is not merely a repetition filter, and it does not guarantee truthfulness, safety, or perfect instruction following.

The takeaway

Knowing the next token is the foundation.
Knowing what the user wants is another level.

Pretraining builds language capability. Instruction training shapes how that capability responds to requests. Preference optimization can further refine the choices a model makes—but none of these alone guarantees a perfectly reliable assistant.
