Quick start

# Install (from /Users/mchinnappan/rllm)
make install          # release + ~/.local/bin + 112 man pages + zsh/bash/fish completions

# Check environment
rllm doctor           # verifies rustc, Metal, config, cache dirs

# ── Phase 1 ───────────────────────────────────────────────────────────────
# Download a model from HF Hub
rllm model download gpt2
rllm model list

# Tokenize
rllm tokenize encode "Hello, Rust!"
rllm tokenize count  "The quick brown fox"

# Tensor inspection & benchmarks
rllm tensor shape ~/.rllm/models/gpt2/model.safetensors
rllm tensor bench --device metal

# ── Phase 2 ───────────────────────────────────────────────────────────────
# Inference  (prompt is positional — no --prompt flag)
rllm infer generate "The quick brown" --model gpt2 --max-tokens 50
rllm infer chat     --model gpt2
rllm infer batch    --input prompts.txt --output results.jsonl

# Train from scratch
rllm train config-init --output train.toml
rllm train run         --config train.toml
rllm train status      --run-dir runs/tinygpt

# Checkpoints
rllm ckpt list   runs/tinygpt
rllm ckpt prune  runs/tinygpt --keep 3 --yes
rllm ckpt info   runs/tinygpt/ckpt_005000.safetensors

# Sampling strategy comparison
rllm sample compare "Once upon a time" --model gpt2

# Evaluation
rllm eval perplexity --model gpt2 test.txt
rllm eval bleu       --reference ref.txt --hypothesis hyp.txt

# ── Phase 3 ───────────────────────────────────────────────────────────────
# Benchmark inference
rllm bench memory     --model gpt2
rllm bench throughput --model gpt2 --n-runs 5
rllm bench latency    --model gpt2 --max-tokens 50
rllm bench suite      --model gpt2

# Quantize — 4× memory reduction
rllm quant int8    --model ~/.rllm/models/gpt2 --output gpt2-int8
rllm quant int4    --model ~/.rllm/models/gpt2 --output gpt2-int4
rllm quant inspect --model ~/.rllm/models/gpt2

# Inspect & validate safetensors files
rllm convert inspect     --model ~/.rllm/models/gpt2 --top 20
rllm convert validate    --model ~/.rllm/models/gpt2
rllm convert info        --model ~/.rllm/models/gpt2
rllm convert merge-shards --input-dir shards/ --output merged.safetensors

# Fine-tune with LoRA
rllm finetune lora         --base gpt2 --data finetune.jsonl --output ./gpt2-lora
rllm finetune merge-adapter --base gpt2 --adapter ./gpt2-lora --output gpt2-merged

# ── Phase 4 ───────────────────────────────────────────────────────────────
# Serve OpenAI-compatible API
rllm serve start --model gpt2 --port 8080
rllm serve status
rllm serve test  --prompt "The quick brown"

# Text embeddings (mean-pool GPT-2 wte)
rllm embed text "Rust is fast" --model gpt2
rllm embed dim  --model gpt2
rllm embed file corpus.txt --model gpt2 --output embeddings.jsonl

# RAG: build and query a vector store
rllm rag init
rllm rag add "Rust achieves memory safety without a GC" --model gpt2
rllm rag add @myfile.txt --model gpt2 --tag source=docs
rllm rag query "memory safety" --model gpt2 --top-k 3
rllm rag list
rllm rag delete <id>

# Datasets from Hugging Face
rllm dataset list --filter wikitext
rllm dataset pull wikitext/wikitext-2-raw-v1 --split train --max-rows 500
rllm dataset export wikitext--wikitext-2-raw-v1.json --field text --output corpus.txt

# Prompt templates
rllm prompt save instruct "Instruction: {task}\n\nResponse:"
rllm prompt list
rllm prompt render instruct task="summarize Rust ownership"
rllm prompt run  instruct task="summarize Rust ownership" --model gpt2

# ── Phase 5 ───────────────────────────────────────────────────────────────
# Agent: tool-calling loop
rllm agent tools
rllm agent run "calculate 42 * 7" --tools calc
rllm agent run "read the file README.md" --tools file --max-steps 3
rllm agent history

# MCP: expose rllm to Claude Desktop and MCP clients
rllm mcp list-tools
rllm mcp status
rllm mcp serve --port 3001 --model gpt2
rllm mcp call generate prompt="The quick brown"

# Python bindings (build with maturin)
# cd crates/rllm-pyo3 && maturin develop
# import rllm; rllm.generate("hello", model="gpt2", max_tokens=20)

# Config
rllm config set default_model gpt2
rllm config set device metal

# Shell completions — activate in ~/.zshrc
# fpath=(~/.zfunc $fpath)
# autoload -Uz compinit && compinit   ← NOT compinit -C

Tokenization
🔤
rllm tokenize — BPE Tokenizer Suite Phase 1
Full tokenization toolkit. encode: map text to token IDs, optionally show token strings side-by-side. decode: reconstruct text from token IDs. vocab: browse the full vocabulary (filterable). count: token count with per-sentence breakdown. merge-info: inspect BPE merge rules. diff: compare how two strings tokenize differently. Supports CharTokenizer (book) and Hugging Face tokenizer.json BPE loader.
tokenize encode tokenize decode tokenize vocab tokenize count tokenize merge-info tokenize diff BPE tokenizers crate tokenizer.json

Tensor Operations
🧮
rllm tensor — Safetensors Inspector & Benchmarks Phase 1
Four commands for working with tensors and safetensors files. shape: inspect every tensor's name, shape, dtype, and element count. stats: per-tensor mean/std/min/max summary. bench: matmul + softmax microbenchmarks on any device — reports GFLOP/s; use --device metal to benchmark Metal GPU. dtype-convert: cast all tensors to bf16/f16/f32 and save a new safetensors file.
tensor shape tensor stats tensor bench --device metal tensor dtype-convert --to bf16 safetensors candle-core GFLOP/s

rllm train — Full Training Loop Phase 2 ✓
Train TinyRustGPT from scratch. run: full training loop from a train.toml config — AdamW optimizer, cosine LR with linear warmup, gradient clipping, BF16 mode, Metal GPU. resume: continue from a checkpoint. config init: generate a default train.toml. status: show last run's loss curve and step count. rllm ckpt — Checkpoint Management Phase 2 ✓
Manage model checkpoints saved during training. list: all checkpoints with step, val_loss, and date. save/load: manual checkpoint operations. diff: compare weight tensors between two checkpoints. prune: keep only the N best by val_loss. export: convert to safetensors or GGUF for inference.
ckpt list ckpt diff ckpt prune --keep ckpt export --format gguf safetensors JSON sidecar

eval perplexity eval bleu eval rouge eval accuracy eval compare

Inference & Sampling Phase 2 ✓
⚡
rllm infer — Text Generation & Chat Phase 2 ✓
Run inference against a local model. generate: autoregressive text generation with temperature, top-k, top-p, and seed. chat: interactive multi-turn REPL with readline history. batch: bulk inference from a prompt file to JSONL. stream: SSE-style token-by-token streaming. KV cache and auto context-window trimming.
infer generate --prompt infer chat infer batch --input infer stream KV cache top-k/p temperature seed

Test and compare sampling strategies in isolation. Supports greedy, top-k, top-p (nucleus), beam search, min-p, and mirostat. compare: run multiple strategies side-by-side on the same prompt to understand quality vs diversity tradeoffs.
sample test --strategy greedy · top-k · top-p beam · min-p · mirostat sample compare

Quantization & Conversion Phase 3 ✓
🗜️
rllm quant — Model Quantization Phase 3 ✓
Reduce model memory footprint without quality loss. int8: per-tensor absmax INT8 quantization (2× memory reduction). int4: group-wise NF4 quantization (4× reduction). gptq: GPTQ with calibration data. inspect: show scales, zero-points, and error stats. dequantize: convert back to f32 for analysis.
quant int8 quant int4 NF4 quant gptq quant inspect quant dequantize absmax

rllm convert — Format Conversion Phase 3 ✓
Convert between model weight formats. to-gguf: safetensors → GGUF for llama.cpp. to-safetensors: GGUF or PyTorch .bin → safetensors. inspect: peek at any format's headers and tensor list. validate: checksum, dtype consistency, and shape sanity checks.
convert to-gguf convert to-safetensors convert inspect convert validate GGUF · safetensors · .bin
rllm-convert.html→
🎯
rllm finetune — LoRA & QLoRA Phase 3 ✓
Fine-tune pretrained models efficiently. lora: train low-rank adapters (LoRA) on JSONL data. qlora: QLoRA with INT4 base + FP16 adapters for large models on consumer GPUs. merge-adapter: fuse LoRA weights into the base model for deployment. Data format: {"prompt": ..., "completion": ...} JSONL.
finetune lora finetune qlora finetune merge-adapter rank · alpha · target_modules JSONL data

Comprehensive model performance measurement. throughput: tokens/sec at various batch sizes. latency: time-to-first-token (TTFT), p50/p95/p99. memory: peak VRAM/RAM usage. suite: run all benchmarks and produce an HTML report. Comparison mode with --baseline to diff two models side by side.
bench throughput bench latency TTFT bench memory bench suite --html tok/s · p50/p95/p99 Metal · CUDA · CPU

🌐
rllm serve — OpenAI-Compatible API Server Phase 4 ✓
Spin up an OpenAI-compatible HTTP server locally. Compatible with the official OpenAI Python and Node.js SDKs — just change the base URL. Endpoints: POST /v1/chat/completions (streaming SSE + non-streaming), POST /v1/completions, POST /v1/embeddings, GET /v1/models, GET /health. Built on axum. Single model instance with Arc<Mutex> concurrency.
serve start --port 8080 serve stop · serve status POST /v1/chat/completions SSE streaming axum · tokio OpenAI SDK compatible

rllm prompt — Template Library Phase 4 ✓
Manage a library of reusable prompt templates with Handlebars {{variable}} syntax. list: browse saved templates. add: save a new template from a file. test/render: fill in variables and preview the result. export: dump all templates to JSON or YAML. Built-in templates: chat, qa, summarize, classify, extract, cot.
prompt list · add · test · render · export Handlebars {{variable}} chat · qa · summarize · classify · cot

dataset download dataset stats dataset split dataset convert JSONL · Parquet · Arrow · CSV

RAG & Embeddings Phase 4 ✓
🧠
rllm rag — Retrieval-Augmented Generation Phase 4 ✓
Build a local RAG pipeline over your documents. index: chunk files or directories, embed them, and store in a SQLite-backed HNSW vector index. query: retrieve relevant chunks and generate an answer. sources: list all indexed documents. clear: wipe the index. Chunking strategies: fixed-size, sentence, paragraph. Re-ranking: BM25 + semantic hybrid.
rag index ./docs rag query "question" rag sources · rag clear SQLite · HNSW BM25 + semantic rsqlite (native)
rllm-rag.html→
🔢
rllm embed — Text Embeddings Phase 4 ✓
Generate and work with text embeddings. text: embed a string to a vector. file: embed document chunks from a file. batch: embed line-by-line from a text file, output JSONL. similarity: cosine similarity between two strings. nearest: nearest-neighbor search against a stored index.
embed text embed file embed batch embed similarity embed nearest cosine similarity

Agent & MCP Phase 5 ✓
🤖
rllm agent — ReAct Tool-Use Agent Phase 5 ✓
An autonomous ReAct agent loop — the model reasons, selects tools, executes them, and iterates until the task is done. run: run a task. tools: list available tools. history: view past agent runs. replay: step through a run interactively. Built-in tools: web_search, read_file, write_file, run_shell, rllm_generate. OpenAI function-calling JSON schema.
agent run "task" agent tools · history · replay ReAct loop function calling multi-turn context

rllm mcp — Model Context Protocol Server Phase 5 ✓
Expose rllm's capabilities to Claude Desktop and other MCP-compatible IDEs via JSON-RPC 2.0 over stdio. mcp serve: stdio server. mcp serve-http: HTTP MCP server on a configurable port. Exposed tools: rllm_generate, rllm_chat, rllm_embed, rllm_rag_query, rllm_tokenize, rllm_model_list, rllm_eval_perplexity. Claude Desktop claude_desktop_config.json integration guide included.
mcp serve (stdio) mcp serve-http JSON-RPC 2.0 Claude Desktop claude_desktop_config.json rllm_generate · rllm_rag_query
