sf-rust rest — Postman-like REST Client
A port of the sf-rest-client npm package — full browser UI + CLI mode. Salesforce-aware: auto-injects Bearer token and resolves relative endpoint paths. No Node.js required.
🌐
Browser UI (Serve Mode)
Full Postman-like interface at http://localhost:7777 — 5 tabs, dark/light toggle, keyboard shortcut.
⚡
Salesforce-Aware
Pass -o dev1 to auto-inject Bearer token + resolve relative paths to {instance_url}. No manual token juggling.
🔗
GraphQL Support
POST to Salesforce GraphQL endpoint with query + variables editor. All in the browser UI.
💾
Collections
Save named request collections to ~/.sf-rust/rest-collections.json. Run, delete, export from the UI.
📋
History (last 200)
Every request is auto-logged with status, timing, and URL to ~/.sf-rust/rest-history.json.
📟
CLI Mode
Use get / post / put / patch / delete subcommands for scripting. --datatable opens response in browser.
🔄
curl Equivalent
Every request shows the equivalent curl command in the browser UI for copy/paste.
🤖
Export
Download all collections + history as a single JSON file via the browser UI export button.
rest serve — Browser UI New

Starts a local axum HTTP server and opens the browser. The UI is entirely self-contained — no CDN, no build step, no Node.js. All data stays on your machine.

# Start on default port 7777 and open browser
sf-rust rest serve

# Custom port
sf-rust rest serve -p 8080

# Start server only, don't open browser
sf-rust rest serve --no-open
FlagDefaultDescription
-p / --port7777TCP port for the local server
--no-openfalseStart server without opening browser automatically

Each tab has: sample chips for one-click quick-start, method selector (GET/POST/PUT/PATCH/DELETE), URL bar, custom headers editor, Monaco Editor for the request body (JSON syntax highlighting, auto-format on blur, Format JSON button), and a response pane with status badge, live elapsed timer, syntax-highlighted body, collapsible Response Headers, and curl Equivalent — all with one-click copy buttons.

Salesforce auth flow

When -o / --target-org is provided (CLI) or an org is selected in the browser UI, sf-rust automatically:

  1. Loads credentials from ~/.sf-rust/credentials.json (AES-256-GCM encrypted)
  2. Injects Authorization: Bearer <access_token>
  3. Prepends {instance_url} to relative endpoint paths (e.g. /services/data/v62.0/...)
  4. On 401, auto-refreshes the token using grant_type=refresh_token and retries once
┌─────────────────────────────────────────────────────────────┐ │ Browser / CLI │ │ │ │ GET /services/data/v62.0/sobjects/Account/describe │ │ (relative path, no token needed from the user) │ └──────────────────────┬──────────────────────────────────────┘ │ ▼ ┌─────────────────────────────────────────────────────────────┐ │ sf-rust rest serve │ │ │ │ 1. Load ~/.sf-rust/credentials.json │ │ 2. Add Authorization: Bearer <token> │ │ 3. Prepend https://your-org.salesforce.com │ │ 4. Execute HTTP request via reqwest │ │ 5. Return { status, headers, body, duration_ms } │ │ 6. Append to ~/.sf-rust/rest-history.json │ └─────────────────────────────────────────────────────────────┘
CLI mode — scripting and piping
# Salesforce REST — auto-inject token + prepend instance URL
sf-rust rest get '/services/data/v62.0/sobjects/Account/describe' -o dev1
sf-rust rest post '/services/data/v62.0/sobjects/Account/' -o dev1 -d '{"Name":"Acme"}'
sf-rust rest patch '/services/data/v62.0/sobjects/Account/001Dn000003ZABC' -o dev1 -d '{"Phone":"555-1234"}'
sf-rust rest delete '/services/data/v62.0/sobjects/Account/001Dn000003ZABC' -o dev1

# Generic REST — explicit Bearer token
sf-rust rest get 'https://api.example.com/data' --bearer my-token
sf-rust rest post 'https://api.example.com/items' --bearer my-token -d '{"name":"test"}'

# Custom headers (repeatable)
sf-rust rest get 'https://api.example.com' -H 'X-API-Key:abc' -H 'Accept:application/json'

# Open response body as browser HTML viewer
sf-rust rest get '/services/data/v62.0/sobjects' -o dev1 --datatable

# JSON output for piping to jq
sf-rust rest get '/services/data/v62.0/limits' -o dev1 --json | jq '.body.DailyApiRequests'

# Save request to a named collection
sf-rust rest get '/services/data/v62.0/sobjects/Account/describe' -o dev1 --save 'account-describe'

# View request history
sf-rust rest history
sf-rust rest history --limit 50
sf-rust rest history --json

GraphQL

The GraphQL tab sends POST requests to {instance_url}/services/data/v62.0/graphql with Bearer token auto-injected. It features a Monaco Editor with GraphQL syntax highlighting, 10 built-in sample queries, auto-format on blur, and a custom GraphQL pretty-printer so queries are always nicely indented.

10 sample queries available via one-click chips:

Accounts
Contacts
Opportunities
Cases
Leads
Contacts (vars)
Account+Contacts
Account Filter
Create Account
Update Account

Important: Id is a plain ID! scalar in Salesforce's uiapi — use bare Id, not Id { value }. All other string fields use the { value } wrapper.

# In browser UI: GraphQL tab → click "Accounts" sample → Execute
{
  uiapi {
    query {
      Account(first: 10) {
        edges {
          node {
            Id
            Name { value }
            Industry { value }
            AnnualRevenue { value }
          }
        }
      }
    }
  }
}

# With variables (click "Contacts (vars)" sample)
query GetContacts($first: Int) {
  uiapi {
    query {
      Contact(first: $first) {
        edges {
          node {
            Id
            Name { value }
            Email { value }
          }
        }
      }
    }
  }
}
# Variables JSON: { "first": 5 }

# Filter accounts by industry (click "Account Filter" sample)
{
  uiapi {
    query {
      Account(first: 10, where: { Industry: { eq: "Technology" } }) {
        edges {
          node {
            Id
            Name { value }
            Industry { value }
          }
        }
      }
    }
  }
}
Collections

Named collections save request details (method, URL, headers, body, org). Access from CLI via --save or from the browser UI Collections tab.

~/.sf-rust/rest-collections.json
Named request collections — JSON array of SavedRequest objects. Updated when you use --save <name> or save from the browser UI. Saving with the same name replaces the previous entry.
~/.sf-rust/rest-history.json
Auto-logged request history — last 200 entries. Each entry has: method, url, status, duration_ms, timestamp, target_org, error (if any). Viewable via sf-rust rest history or the History tab.
Export all data: The browser UI has an Export button that calls GET /api/export and downloads a JSON file containing both collections and history merged — equivalent to the sfutils-collections.json export from the Node.js version.
Server API routes

When sf-rust rest serve is running, these routes are available at http://localhost:7777:

MethodRouteDescription
GET/Serve the HTML SPA
GET/api/orgsList all sf-rust authenticated orgs (from config.toml)
POST/api/sf/executeExecute Salesforce REST call: { org, method, endpoint, headers, body }
POST/api/rest/executeExecute generic REST call: { method, url, headers, body, bearer, basic }
POST/api/graphql/executeExecute Salesforce GraphQL: { org, query, variables }
GET/api/collectionsList all saved collections
POST/api/collectionsSave a named collection
DELETE/api/collections/:nameDelete a named collection
GET/api/historyGet last 200 history entries
GET/api/exportExport all collections + history as JSON
curl examples — start the server first: sf-rust rest serve
# ── List authenticated orgs ───────────────────────────────
curl http://localhost:7777/api/orgs

# ── Salesforce REST: GET a relative endpoint ─────────────
# org = alias or username from sf-rust; endpoint is relative (token auto-injected)
curl -X POST http://localhost:7777/api/sf/execute \
  -H 'Content-Type: application/json' \
  -d '{ "org": "dev1", "method": "GET", "endpoint": "/services/data/v62.0/limits" }'

# ── Salesforce REST: POST — create an Account ─────────────
curl -X POST http://localhost:7777/api/sf/execute \
  -H 'Content-Type: application/json' \
  -d '{ "org": "dev1", "method": "POST",
       "endpoint": "/services/data/v62.0/sobjects/Account/",
       "body": "{\"Name\":\"Acme Corp\"}" }'

# ── Salesforce REST: add custom headers ───────────────────
curl -X POST http://localhost:7777/api/sf/execute \
  -H 'Content-Type: application/json' \
  -d '{ "org": "dev1", "method": "GET",
       "endpoint": "/services/data/v62.0/sobjects/Account/describe",
       "headers": { "Accept": "application/json", "X-PrettyPrint": "1" } }'

# ── Generic REST: explicit Bearer token ───────────────────
curl -X POST http://localhost:7777/api/rest/execute \
  -H 'Content-Type: application/json' \
  -d '{ "method": "GET", "url": "https://api.example.com/data",
       "bearer": "my-api-token" }'

# ── Generic REST: Basic auth ──────────────────────────────
curl -X POST http://localhost:7777/api/rest/execute \
  -H 'Content-Type: application/json' \
  -d '{ "method": "GET", "url": "https://api.example.com/items",
       "basic": "user:password" }'

# ── Salesforce GraphQL ────────────────────────────────────
curl -X POST http://localhost:7777/api/graphql/execute \
  -H 'Content-Type: application/json' \
  -d '{ "org": "dev1",
       "query": "{ uiapi { query { Account(first:5) { edges { node { Id Name { value } } } } } } }",
       "variables": {} }'

# ── Collections: list ─────────────────────────────────────
curl http://localhost:7777/api/collections

# ── Collections: save a named request ────────────────────
curl -X POST http://localhost:7777/api/collections \
  -H 'Content-Type: application/json' \
  -d '{ "name": "account-describe", "method": "GET",
       "url": "/services/data/v62.0/sobjects/Account/describe",
       "headers": {}, "body": "", "target_org": "dev1" }'

# ── Collections: delete ───────────────────────────────────
curl -X DELETE http://localhost:7777/api/collections/account-describe

# ── History: last 200 ─────────────────────────────────────
curl http://localhost:7777/api/history

# ── Export: all collections + history ────────────────────
curl http://localhost:7777/api/export -o sf-rust-export.json
Pipe to jq for pretty-print and filtering:
curl -s -X POST http://localhost:7777/api/sf/execute -H 'Content-Type: application/json' \
  -d '{"org":"dev1","method":"GET","endpoint":"/services/data/v62.0/limits"}' \
  | jq '.body.DailyApiRequests'
Quick reference
# ── Browser UI (Postman-like) ────────────────────────────
sf-rust rest serve                                   # open at http://localhost:7777
sf-rust rest serve -p 8080                           # custom port

# ── Salesforce REST (CLI) ────────────────────────────────
sf-rust rest get    '/services/data/v62.0/limits'              -o dev1
sf-rust rest get    '/services/data/v62.0/query?q=SELECT+Id+FROM+Account+LIMIT+5' -o dev1
sf-rust rest post   '/services/data/v62.0/sobjects/Account/'   -o dev1 -d '{"Name":"Acme"}'
sf-rust rest put    '/services/data/v62.0/sobjects/Account/001...' -o dev1 -d '{"Name":"Acme2"}'
sf-rust rest patch  '/services/data/v62.0/sobjects/Account/001...' -o dev1 -d '{"Phone":"555"}'
sf-rust rest delete '/services/data/v62.0/sobjects/Account/001...' -o dev1

# ── Output options ───────────────────────────────────────
sf-rust rest get '/services/data/v62.0/limits' -o dev1 --json
sf-rust rest get '/services/data/v62.0/limits' -o dev1 --datatable

# ── History ──────────────────────────────────────────────
sf-rust rest history
sf-rust rest history --limit 50 --json

# ── jq integration ───────────────────────────────────────
sf-rust rest get '/services/data/v62.0/limits' -o dev1 --json \
  | jq '.body | to_entries[] | select(.value.Remaining < 100)'
