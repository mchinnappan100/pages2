🔌 sf-rust mcp

Model Context Protocol server — expose all sf-rust Salesforce tools directly to Claude Desktop, Claude Code, and any MCP-compatible AI assistant.

MCP 2024-11-05 stdio transport 7 tools no key required V1

Overview

sfr mcp server starts a stdio-transport MCP server that speaks JSON-RPC 2.0 over stdin/stdout. Claude Desktop (or any MCP-compatible client) spawns it as a child process and can then call Salesforce operations directly from a conversation — no copy-paste, no switching tabs.

Claude / Claude Code
→ JSON-RPC 2.0 →
sfr mcp server
→ sfr sub-process →
Salesforce API
→ result →
AI response
How it works: each MCP tool call spawns the current sf-rust binary with the appropriate sub-command and --json flag, captures the output, and returns it as MCP content. No extra dependencies — just the same sf-rust binary you already use.

Available Tools

query_soql
Run a SOQL query against Salesforce and return all matching records as JSON.
soql required string — SOQL query
org string, optional — org alias (uses server default if omitted)
org_display
Show details for a connected Salesforce org: instance URL, username, API version, token expiry.
org string, optional
org_list
List all locally authenticated Salesforce orgs.
No parameters.
apex_execute
Execute an anonymous Apex script in a Salesforce org and return the debug log.
code required string — Apex code
org string, optional
apex_get_log
Retrieve the most recent Apex debug log from a Salesforce org.
org string, optional
deploy_metadata
Deploy a local Salesforce metadata directory to an org using the Metadata API.
directory required string — path to source directory
org string, optional
sysone_parse_email
Classify an email using System-One structured inference: category, urgency, requires_action, is_automated.
email required string — full email text
model string, optional — Ollama model (default: nimble:latest)

Usage

Start the server (manual test)

# default org is dev1 for all tool calls
sfr mcp server -o dev1

# no default org — each tool call must pass org explicitly
sfr mcp server

Test with raw JSON-RPC from the terminal

# sfr json auto-detects NDJSON — works for single or multiple responses
printf '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}\n{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}\n' \
  | sfr mcp server -o sf-rust-1 2>/dev/null | sfr json

# Query across all responses — extract .result.protocolVersion from each object
printf '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}\n{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}\n' \
  | sfr mcp server 2>/dev/null | sfr json -q ".result.protocolVersion"

# Or use jq — both work identically for NDJSON
printf '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}\n{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"query_soql","arguments":{"soql":"SELECT Id, Name FROM Account LIMIT 5","org":"dev1"}}}\n' \
  | sfr mcp server -o dev1 2>/dev/null | jq
sfr json handles NDJSON: sfr json auto-detects NDJSON — it tries single-JSON first; if that fails it processes each line as a separate object, exactly like jq. Queries (-q), --minify, --keys, and --raw all apply per-object across the full stream.

Claude Desktop Integration

Add this to your claude_desktop_config.json (macOS: ~/Library/Application Support/Claude/claude_desktop_config.json):

{
  "mcpServers": {
    "salesforce": {
      "command": "/Users/YOUR_NAME/.local/bin/sf-rust",
      "args": ["mcp", "server", "-o", "dev1"],
      "env": {}
    }
  }
}
Replace YOUR_NAME with your macOS username, and dev1 with your org alias. Restart Claude Desktop after editing the config — the MCP servers panel should show salesforce connected.

Claude Code integration

# Add to your project's .mcp.json
{
  "mcpServers": {
    "salesforce": {
      "command": "sfr",
      "args": ["mcp", "server", "-o", "dev1"]
    }
  }
}
With Claude Code, you can also run /mcp to view connected servers and their available tools.

stderr vs stdout: [sf-rust mcp] log lines go to stderr — they appear in the terminal but are never on the MCP wire. Claude Desktop captures only stdout (JSON-RPC). To suppress them: 2>/dev/null.

What's next — V2 (HTTP/SSE)

V2 will add an HTTP + Server-Sent Events transport for use cases where spawning a process is not possible (remote servers, cloud deployments):

# V2 — HTTP transport (planned)
sfr mcp serve-http --port 3100 -o dev1

V2 will also add resource support (org schema, metadata list) and additional tools (sysone classify, schema describe, audit log).
