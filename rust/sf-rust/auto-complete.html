sf-rust Auto-Complete — How It Works

Shell auto-completion lets users press <Tab> after sf-rust to see and complete subcommand names, flags, and option values without having to remember them.

sf-rust supports zsh, bash, and fish out of the box.

The approach in one sentence

clap_complete inspects the same Cli struct that drives argument parsing and generates a shell-specific completion script at runtime. The binary ships the generator; users run it once to produce and install the script.

Step 1 — Add the dependency

Cargo.toml (workspace manifest):

[workspace.dependencies]
clap          = { version = "4", features = ["derive", "env"] }
clap_complete = "4"

crates/sf-cli/Cargo.toml (the binary crate):

[dependencies]
clap          = { workspace = true }
clap_complete = { workspace = true }

clap_complete is the official companion crate for clap 4. It knows the grammar of zsh comdef, bash complete, and fish complete scripts and generates them from any clap Command tree.

Step 2 — Expose the Cli struct in a library

Because both the main binary and the gen-man helper binary need to import Cli, the struct lives in crates/sf-cli/src/lib.rs (not main.rs):

// crates/sf-cli/src/lib.rs
use clap::{Parser, Subcommand};
use clap_complete::Shell;          // Shell enum used by the Completion variant

#[derive(Debug, Parser)]
#[command(name = "sf-rust", version = "0.1.0", ...)]
pub struct Cli {
    #[command(subcommand)]
    pub command: Commands,

    #[arg(long, global = true)] pub json: bool,
    #[arg(long, global = true)] pub no_time: bool,
    // ... other global flags
}

#[derive(Debug, Subcommand)]
pub enum Commands {
    Org(OrgCommands),
    Data(DataCommands),
    // ... all subcommands
    Version,

    #[command(about = "Generate shell completion scripts")]
    Completion {
        #[arg(value_enum, help = "Shell to generate completions for")]
        shell: Shell,              // zsh | bash | fish | elvish | powershell
    },
}

Shell is a clap::ValueEnum provided by clap_complete. Declaring it as value_enum means clap validates the shell name at parse time and shows the list in --help.

Step 3 — Handle the completion subcommand in main.rs

// crates/sf-cli/src/main.rs
use std::io;
use clap::{CommandFactory, Parser};
use clap_complete::{generate, Shell};
use sf_cli::{Cli, Commands};

async fn run(cli: Cli) -> SfResult<()> {
    match cli.command {
        Commands::Completion { shell } => {
            let mut cmd = Cli::command();          // build the Command tree
            generate(shell, &mut cmd, "sf-rust", &mut io::stdout());
            // generate() writes the completion script to stdout and returns
        }
        // ... all other arms
    }
    Ok(())
}

Cli::command() is the CommandFactory method that returns the underlying clap::Command without parsing any arguments. generate() traverses the full subcommand tree — including every nested subcommand and every flag — and emits a shell-specific script.

Step 4 — Install the scripts with make completions

The Makefile runs the binary, captures its output, and drops the files in the standard locations for each shell:

ZFUNC    := $(HOME)/.zfunc
BASH_COMP := $(HOME)/.bash_completion.d
FISH_COMP := $(HOME)/.config/fish/completions

completions: release
    @mkdir -p $(ZFUNC) $(BASH_COMP) $(FISH_COMP)
    @target/release/sf-rust completion zsh  > $(ZFUNC)/_sf-rust
    @target/release/sf-rust completion bash > $(BASH_COMP)/sf-rust
    @target/release/sf-rust completion fish > $(FISH_COMP)/sf-rust.fish

Run once after the first build:

make completions
# or build + install + completions in one step:
make install-completions

Step 5 — Activate in your shell

zsh

Add to ~/.zshrc (if not already there):

fpath=(~/.zfunc $fpath)
autoload -Uz compinit && compinit

Then reload:

source ~/.zshrc

The generated file ~/.zfunc/_sf-rust follows the _sf-rust naming convention that zsh's completion system expects.

bash

Add to ~/.bashrc:

source ~/.bash_completion.d/sf-rust

fish

No extra configuration needed. Fish automatically sources every *.fish file under ~/.config/fish/completions/.

How the generated script works

For zsh, clap_complete emits a script beginning with:

#compdef sf-rust
autoload -U is-at-least

It then defines shell functions — one per subcommand level — that list valid completions for each position. For example, after sf-rust org , it offers login, logout, display, list, open, etc. Flag completions include the long name (--page-size), the short alias (-p), and whether the flag takes an argument.

No manual .zsh / .bash scripting is required; the entire script is derived automatically from the clap Command tree at build time.

Keeping completions up to date

Because the script is generated at runtime by the binary itself, adding a new subcommand or flag to the Rust code means:

  1. make install rebuilds the binary (and now also regenerates man pages).
  2. Run make completions again to refresh the completion scripts.

Alternatively, combine both steps permanently:

make install-completions

Verifying the installation

# zsh — list all top-level completions
sf-rust <Tab>

# Confirm the completion file was generated
cat ~/.zfunc/_sf-rust | head -5
# Expected: #compdef sf-rust

# Smoke test (no shell needed)
sf-rust --no-time completion zsh | grep -q "sf-rust" && echo OK
sf-rust --no-time completion bash | grep -q "sf-rust" && echo OK
sf-rust --no-time completion fish | grep -q "sf-rust" && echo OK

These same checks are run automatically by make test via tests/smoke.sh.
