sf-rust --datatable

Every table-displaying command in sf-rust supports --datatable — open any result set as a sortable, searchable HTML page in your browser. No extra tooling required.

sortable columns live search row count dark mode auto-opens in browser /tmp output

How it works

Pass --datatable to any table-displaying command and sf-rust will fetch the data as normal, then generate a self-contained HTML page and open it in your default browser automatically.

1. Fetch Data is retrieved from Salesforce exactly as it would be for a normal table print.
2. Generate A standalone HTML file is written to /tmp/sf-rust-{name}-{ts}.html.
3. Open The file is opened with the system browser (open on macOS, xdg-open on Linux).
4. Offline The generated file is fully self-contained — no network required after generation.
ℹ

The file path is printed to stderr after opening: Datatable: /tmp/sf-rust-org-limits-1731600000000.html

Shared helper

All commands use the same shared implementation in sf-output:

  • Output::open_datatable(title, cols, rows) — for multi-column result sets
  • Output::open_kv_datatable(title, rows) — for key-value pages like org display

Examples

Add --datatable to any command that normally prints a table.

shell# SOQL query — open 586 Account rows in the browser
sf-rust data query -q "SELECT Id, Name, Industry FROM Account" -o dev1 --datatable

# Login history — last 100 logins
sf-rust audit login -o dev1 --last 100 --datatable

# API governor limits
sf-rust org limits -o dev1 --datatable

# Code coverage report
sf-rust apex coverage -o dev1 --datatable

# Who can read Account records?
sf-rust perms who-can Account Read -o dev1 --datatable

# Config key-value table
sf-rust config list --datatable

# Salesforce report inventory
sf-rust report list -o dev1 --datatable

# Deployed Apex classes
sf-rust metadata list -o dev1 --types ApexClass --datatable

# Flow list
sf-rust flow list -o dev1 --datatable

# Org display (key-value page)
sf-rust org display -o dev1 --datatable
✓

Tip: --datatable and --json / --csv are mutually exclusive. If you need both a browser view and a file export, run the command twice with the respective flags.

HTML output features

Every generated HTML datatable has the same interactive features, powered by a small inline JavaScript engine — no CDN, no React, no build step.

FeatureDetails
Dark modeVS Code palette — #1e1e1e background, #9cdcfe column headers
Sortable columnsClick any header to sort ascending (▲) or descending (▼); numeric and string-aware
Live searchFilters all columns in real time as you type — no page reload
Row counterShows N / Total rows updating as you filter
Sticky headerColumn headers remain visible while scrolling long result sets
Self-containedSingle HTML file — all data embedded as JSON constants, no network after generation
Row hoverSubtle highlight on hover for easier row tracking
Path on stderrDatatable: /tmp/sf-rust-{slug}-{ts}.html printed after opening
ℹ

Generated files are written to /tmp/ and are not automatically cleaned up. On macOS, /tmp/ is cleared on reboot. On Linux it persists until manually removed.

For contributors

Adding --datatable to a new command takes four lines. The HTML template and browser-open logic live entirely in sf-output.

Shared helpers (sf-output/src/lib.rs)

FunctionUse when
Output::open_datatable(title, cols, rows) Multi-column result rows (&[serde_json::Value])
Output::open_kv_datatable(title, rows) Key-value pairs (&[(&str, String)]) — e.g. org display

Both return Result<(), String>. Map the error with .map_err(SfError::Other)?.

Pattern

Rust// 1. Add flag to your args struct
#[derive(Debug, Args)]
pub struct MyCommandArgs {
    #[arg(long, help = "Open results in a browser datatable")]
    pub datatable: bool,
    // ... other fields
}

// 2. Early-return before the existing print call
if args.datatable {
    return Output::open_datatable("My Title", &cols, &rows)
        .map_err(SfError::Other);
}

// 3. Normal table print (unchanged)
Output::print_table_from_json(&rows, &cols);

No extra Cargo dep needed

✓

The open crate (browser launch) is a dependency of sf-output, not of individual command crates. You only need sf-output = { path = "../sf-output" } which every command crate already has.

Key-value variant

Rustif args.datatable {
    let kv_rows = vec![
        ("Username",  org.username.clone()),
        ("Instance",  org.instance_url.clone()),
    ];
    return Output::open_kv_datatable("Org Display", &kv_rows)
        .map_err(SfError::Other);
}
