sf-rust ask NEW

Send a natural-language prompt to any of five LLM providers — Claude, OpenAI, xAI (Grok), Ollama (local), or Gemini. The provider, model, and API key are stored in ~/.sf-rust/settings.json. With -o <alias> the prompt can reference live org context.

FlagDescription
-o, --target-org <alias>Org alias — passes org context to the prompt
<PROMPT>Positional: the question or instruction
 
# Ask a general Salesforce development question
sf-rust ask "What is a SOQL aggregate query?"

# Org-aware: ask for Apex code relevant to your org
sf-rust ask -o dev1 "Write an Apex trigger to validate email format"

# Generate SOQL from natural language
sf-rust ask -o dev1 "Write a SOQL query to get all Accounts created this month with their primary Contact"
▶ sf-rust ask "What is a SOQL aggregate query?" A SOQL aggregate query uses aggregate functions — COUNT(), SUM(), AVG(), MIN(), MAX() — with a GROUP BY clause to summarise record sets rather than returning individual rows. Example: SELECT AccountId, COUNT(Id) total FROM Opportunity WHERE IsClosed = false GROUP BY AccountId ORDER BY COUNT(Id) DESC LIMIT 10 This returns one row per AccountId showing the number of open opportunities. You can filter aggregated results with HAVING (e.g. HAVING COUNT(Id) > 5). Provider: claude · Model: claude-opus-4-5 · 0.8s
ℹ

Run sf-rust ask config show to see the active provider and model. Switch providers any time with sf-rust ask config set-provider <name>.

sf-rust ask config

Manage the AI provider configuration stored in ~/.sf-rust/settings.json. All subcommands read and write that file; API keys are stored as-is (the file is 600).

SubcommandDescription
set-provider <name>Switch provider: claude | openai | xai | ollama | gemini
set-model <model>Model ID for the current provider (e.g. claude-opus-4-5)
set-key <API_KEY>Save API key to settings.json (chmod 600)
set-url <url>Base URL override — required for Ollama (http://localhost:11434)
showDisplay current settings; API key is masked to first 8 chars
 
# Switch to OpenAI and set your key
sf-rust ask config set-provider openai
sf-rust ask config set-model gpt-4o
sf-rust ask config set-key sk-proj-...

# Switch to local Ollama (no API key needed)
sf-rust ask config set-provider ollama
sf-rust ask config set-url http://localhost:11434
sf-rust ask config set-model llama3.2

# Show current configuration
sf-rust ask config show

Provider: Claude (Anthropic)

Calls the Anthropic Messages API. Requires an API key from console.anthropic.com. 

# Configure
sf-rust ask config set-provider claude
sf-rust ask config set-model claude-opus-4-5
sf-rust ask config set-key sk-ant-api03-...

# HTTP request (internal)
POST https://api.anthropic.com/v1/messages
  x-api-key: <API_KEY>
  anthropic-version: 2023-06-01
  Content-Type: application/json

{
  "model": "claude-opus-4-5",
  "max_tokens": 4096,
  "messages": [{ "role": "user", "content": "..." }]
}
✦

Recommended models: claude-opus-4-5 (best reasoning), claude-sonnet-4-5 (balanced), claude-haiku-4-5 (fast).

Provider: Ollama (local)

Runs against a local Ollama instance — no API key required, completely offline. Start Ollama with ollama serve before running sf-rust ask. 

# Start Ollama first
ollama pull llama3.2
ollama serve

# Configure sf-rust
sf-rust ask config set-provider ollama
sf-rust ask config set-model llama3.2
sf-rust ask config set-url http://localhost:11434

# HTTP request (internal) — stream:false
POST http://localhost:11434/api/chat
  Content-Type: application/json

{
  "model": "llama3.2",
  "stream": false,
  "messages": [{ "role": "user", "content": "..." }]
}
✦

Ollama is ideal for air-gapped environments or when API costs matter. No data leaves the machine.

sf-rust report run NEW

Run a Salesforce report and display the results. Uses the Analytics REST API (GET /analytics/reports/{id}?includeDetails=true) and parses the tabular factMap["T!T"].rows[].dataCells[].label structure. Supports table, CSV, and datatable (interactive HTML) output modes.

FlagDescription
<id>Report ID (18-char Salesforce Id from report list)
-o, --target-org <alias>Org to run against (required)
--csvCSV output to stdout
--datatableOpen interactive HTML browser with dark mode and sort/filter
--jsonRaw JSON from Analytics API
 
# Run a report and display as a table
sf-rust report run 00O5g000005AbCdEAF -o dev1

# Export to CSV
sf-rust report run 00O5g000005AbCdEAF -o dev1 --csv > pipeline.csv

# Open interactive datatable in browser
sf-rust report run 00O5g000005AbCdEAF -o dev1 --datatable

sf-rust data query --pivot NEW

Post-process SOQL results as a cross-tabulation pivot table. Rows are one field, columns are another, and each cell shows an aggregated value. The pivot renders as an interactive HTML heatmap with blue-intensity cells — darker = larger value.

FlagDescription
--pivotEnable pivot mode (opens HTML browser)
--pivot-row <field>Field to use as row labels
--pivot-col <field>Field to use as column labels
--pivot-val <field>Numeric field to aggregate
--pivot-agg <fn> Aggregation: sum | count | avg | min | max
Default: sum
 
# Pivot: Opportunities by Stage (rows) × CloseDate month (cols), sum Amount
sf-rust data query \
  -q "SELECT StageName, CloseDate, Amount FROM Opportunity WHERE IsClosed = false" \
  -o dev1 \
  --pivot \
  --pivot-row StageName \
  --pivot-col CloseDate \
  --pivot-val Amount \
  --pivot-agg sum

# Count of Cases by Priority vs Status
sf-rust data query \
  -q "SELECT Priority, Status, Id FROM Case" \
  -o dev1 \
  --pivot \
  --pivot-row Priority \
  --pivot-col Status \
  --pivot-val Id \
  --pivot-agg count
✦

The HTML heatmap opens at /tmp/sf-rust-pivot-{ts}.html. Each cell's background intensity scales with the value — hover for the exact number. Empty cells render as –.

sf-rust data schema-view NEW

Browse the full Salesforce schema interactively. Calls describe_global() to list all SObjects, then lazy-loads describe_object() for each selected object. Opens a self-contained HTML page with a sidebar object list, searchable field table, and field-type badges.

FlagDescription
-o, --target-org <alias>Org to describe (required)
--object <name>Open schema-view focused on a specific SObject
 
# Open full schema browser
sf-rust data schema-view -o dev1

# Open focused on the Account object
sf-rust data schema-view -o dev1 --object Account

# Open focused on a custom object
sf-rust data schema-view -o dev1 --object Vehicle__c
ℹ

The HTML page is generated at /tmp/sf-rust-schema-{ts}.html. The sidebar lists all SObjects (filterable by name). Clicking an object loads its fields in the main panel showing: Field Name, Label, Type, Length, Nillable, Relationship. Custom fields are highlighted.

sf-rust apex log-profile NEW

Parse a debug log and produce a hotspot analysis. Builds an execution timeline from METHOD_ENTRY / METHOD_EXIT pairs, rolls up cumulative time per method, and displays the top-N methods sorted by total execution time. Color-coded: red (>20%), yellow (5–20%), green (<5%).

FlagDescription
-o, --target-org <alias>Org to fetch log from
--log-id <id>Debug log ID (from apex list-logs)
--top <n>Show top N hotspots
Default: 20
--flamegraphOpen interactive flamegraph HTML instead of table
 
# Show top 20 hotspot methods
sf-rust apex log-profile -o dev1 --log-id 07L5g000007MnOpEAF

# Show top 10 methods
sf-rust apex log-profile -o dev1 --log-id 07L5g000007MnOpEAF --top 10

sf-rust apex log-profile --flamegraph NEW

Renders the hotspot rollup as an interactive horizontal bar chart (flamegraph-style) using an HTML Canvas. Bars are sized proportionally to execution share. Hover a bar to see the exact method name, time, and percentage in a tooltip. 

# Open flamegraph HTML
sf-rust apex log-profile -o dev1 --log-id 07L5g000007MnOpEAF --flamegraph
✦

The HTML is written to /tmp/sf-rust-flamegraph-{ts}.html and opened automatically. The Canvas 2D chart uses the same color thresholds as the table: red >20%, yellow 5–20%, green <5%. The page has no external dependencies.

sf-rust watch NEW

Watch a source directory and automatically deploy to Salesforce whenever the filesystem is quiet for the debounce window (default 500 ms). Uses the native OS filesystem event API (FSEvents on macOS, inotify on Linux) via the notify = "6" crate — zero polling, zero CPU when idle.

FlagDescription
--dir <path>Source directory to watch
Default: force-app
-o, --target-org <alias>Org to deploy to (required)
--debounce <ms> Quiet period before triggering deploy
Default: 500
--check-onlyValidate-only deploy (does not commit to org)
 
# Watch force-app and auto-deploy on save
sf-rust watch --dir force-app -o dev1

# Validate-only mode (no changes committed)
sf-rust watch --dir force-app -o dev1 --check-only

# Custom debounce: 1 second quiet window
sf-rust watch --dir force-app -o dev1 --debounce 1000
