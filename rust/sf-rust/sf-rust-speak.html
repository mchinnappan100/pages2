sfr speak

Speak any sf-rust output aloud using the local Ollama phonon model. No cloud, no API key — 38 character voices running entirely on your Mac.

phonon:latest 38 voices fully offline --speak flag sfr speak stdin afplay · aplay

Quick Start

# 1. Start phonon-studio (Ollama phonon TTS server)
phonon-studio --port 3000
# or: sfr phonon-studio --port 3000   (after make install-phonon)

# 2. Use --speak on any OS command
sfr os memory  --speak
sfr os battery --speak
sfr os info    --speak

# 3. Pipe any command output to sfr speak
sfr os battery | sfr speak
echo "Hello from sf-rust" | sfr speak
Prerequisites: Ollama must be running with phonon:latest pulled (ollama pull phonon). phonon-studio must be started before using --speak. The model is 112 MB and runs fully locally.

Setup

# Install the phonon-studio wrapper (points to ~/my-speech-apps/phonon-studio/)
make install-phonon

# Pull the Ollama phonon model (one-time, 112 MB)
ollama pull phonon

# Start phonon-studio in one terminal
phonon-studio --port 3000

# Now speak from sf-rust in another terminal
sfr os memory --speak

phonon-studio health check

curl http://127.0.0.1:3000/api/health
# {"ok":true,"installed":true,"ffmpeg":true}

Examples

OS commands with --speak

# Memory status spoken aloud
sfr os memory --speak
# → "RAM usage is 69 percent, elevated. 31 percent available. Swap is at 94 percent, critically high."

# Battery with custom voice and port
sfr os battery --speak --voice Micah --phonon-port 3000
# → "Battery at 85 percent. Status: Discharging. Power source: Battery Power. Time remaining: 1:44 remaining."

# System info
sfr os info --speak
# → "System: mac-mini. OS: macOS Sequoia 15.1. CPU: Apple M2 Pro with 12 cores. Memory 69 percent used. Uptime: 3 days, 2h 15m."

PDF — view and speak

# Create a PDF, open in system viewer, and speak the summary
sfr pdf image1.png image2.png -o slides.pdf --view --speak

# Custom voice
sfr pdf diagram.png -o report.pdf --view --speak --voice Harper

# Speak only (no viewer)
sfr pdf cover.png -o doc.pdf --speak
# → "PDF created: doc.pdf with 1 page."

# View only (no audio)
sfr pdf page1.png page2.png -o deck.pdf --view

Pipe mode — sfr speak

# Speak a plain text file
cat notes.txt | sfr speak
# e.g. notes.txt: "this is the time for all good men to go for the aid of the country!"

# Speak the output of any sf-rust command (box-drawing chars auto-stripped)
sfr os battery | sfr speak
sfr os battery | sfr speak --voice Harper
sfr os memory  | sfr speak --voice Micah

# Speak a custom message
echo "Deploy succeeded. All tests passed." | sfr speak

# Debug: see exactly what text would be spoken (no audio)
sfr os battery | sfr speak --dry-run

How it Works

sfr os memory
→
speak_summary()
→
POST /api/speech
→
phonon-studio
→
Ollama phonon
→
WAV bytes
→
afplay
  1. Command runs normally (table output to terminal)
  2. speak_summary() builds a clean natural-language sentence (no box-drawing chars)
  3. reqwest POSTs { "text": "...", "voice": "default" } to phonon-studio
  4. phonon-studio forwards to Ollama's /v1/audio/speech endpoint
  5. phonon model synthesises 24 kHz mono PCM WAV using its built-in character voices
  6. WAV written to /tmp/sf-rust-speak-<ts>.wav
  7. afplay plays it synchronously — prompt returns after audio finishes
Soft failure: if phonon-studio is not reachable, --speak prints a warning to stderr and the command still exits 0 with normal output. It never blocks or fails the main command.
