Overview

sfr agent is a natural-language interface to sf-rust. You describe what you want to do with Salesforce in plain English; the agent calls an LLM (local via Ollama, or cloud via Anthropic / OpenAI), and the LLM returns the exact sf-rust command to run. The agent shows you the command and explanation, then executes it — or shows only the command with --dry-run.

The LLM is given a system prompt listing every valid sfr subcommand. Only sf-rust commands are ever executed — the agent rejects anything else.

How it works

  1. You describe the task: "query all open cases from org dev1"
  2. Agent builds a system prompt listing all sf-rust subcommands + your task
  3. LLM returns { "command": "sf-rust data query …", "explanation": "…" }
  4. Agent validates the command starts with sf-rust / sfr (no shell injection)
  5. Agent executes the current sf-rust binary with the extracted args

Usage

# Basic — uses Ollama (llama3.2 by default) sfr agent --task "show all orgs" sfr agent -t "query 10 accounts from dev1" -o dev1 # Dry-run — show the command without executing sfr agent -t "deploy force-app to dev1" -o dev1 --dry-run # Use a specific Ollama model sfr agent -t "list logs for dev1" -o dev1 --llm ollama:gemma4 # Use Claude (requires ANTHROPIC_API_KEY or --anthropic-key) sfr agent -t "run disk scan" --llm claude:claude-haiku-5-5 --anthropic-key $ANTHROPIC_API_KEY # Target mac-mini Ollama sfr agent -t "list all logs" --ollama http://192.168.1.9:11434 # JSON output (for scripting) sfr agent -t "query accounts" -o dev1 --dry-run --json

LLM providers

ProviderFormatRequirementNotes
ollama ollama:llama3.2 Ollama running locally (or via --ollama) Default; free; fully local; works offline. llama3.2, gemma4, qwen3.8, etc.
claude claude:claude-haiku-5-5 --anthropic-key KEY Fastest for structured JSON output. claude-haiku-5-5 is cheap and accurate.
openai openai:gpt-4o-mini --openai-key KEY OpenAI GPT models. gpt-4o-mini is fast and inexpensive.

Flags

FlagDefaultDescription
-t / --taskrequiredTask description in plain language
-o / --target-orgOrg alias — injected as a hint into the LLM prompt and used in the generated command
--llmollama:llama3.2LLM as provider:model
--ollamahttp://localhost:11434Ollama base URL (OLLAMA_HOST env var also supported)
--anthropic-keyAnthropic API key (claude provider)
--openai-keyOpenAI API key (openai provider)
--dry-runfalseShow the generated command and explanation without executing
--jsonfalseOutput LLM response as raw JSON (implies --dry-run semantics for the JSON block)

More examples

# org operations (gemma4 works well for agent) sfr agent -t "show my org details" -o dev1 --llm ollama:gemma4:latest sfr agent -t "list all orgs" --llm ollama:gemma4:latest sfr agent -t "open dev1 in browser" -o dev1 --llm ollama:gemma4:latest # SOQL queries sfr agent -t "query 10 accounts from af102" -o af102 --llm ollama:gemma4:latest sfr agent -t "get all accounts with more than 50 employees" -o dev1 --llm ollama:gemma4:latest sfr agent -t "export contacts to csv" -o dev1 --llm ollama:gemma4:latest sfr agent -t "query opportunities closing this quarter" -o dev1 --llm ollama:gemma4:latest # Apex sfr agent -t "run apex tests for AccountTriggerHandler" -o dev1 --llm ollama:gemma4:latest sfr agent -t "show recent debug logs" -o dev1 --llm ollama:gemma4:latest # metadata sfr agent -t "deploy force-app to staging" -o staging --dry-run --llm ollama:gemma4:latest sfr agent -t "list metadata types in dev1" -o dev1 --llm ollama:gemma4:latest # permissions sfr agent -t "show field permissions for Contact object" -o dev1 --llm ollama:gemma4:latest # sysone (AI classification) sfr agent -t "classify cases by priority using sysone" --dry-run --llm ollama:gemma4:latest # use Claude or OpenAI instead of Ollama sfr agent -t "query 10 accounts" -o dev1 --llm claude:claude-haiku-5-5 --anthropic-key $ANTHROPIC_API_KEY sfr agent -t "deploy force-app" -o dev1 --llm openai:gpt-4o-mini --openai-key $OPENAI_API_KEY
The agent executes only sf-rust sub-commands. It refuses to run arbitrary shell commands, scripts, or binaries. If the LLM returns something unexpected, the agent errors rather than running it.
