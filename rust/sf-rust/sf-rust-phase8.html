sf-rust Phase 8 — Real-time & Streaming

Live debug log streaming, Platform Event pub/sub via CometD, org audit trails, and CLI config management — all from a single native binary.

apex debug-tail event subscribe event publish audit login audit setup audit field-history config get/set/list

Phase 8 adds nine new commands focused on real-time observability and org management. Developers can now tail Apex logs as they fire, subscribe to Platform Events as they arrive, audit who changed what in the org, and manage CLI configuration — all without leaving the terminal.

apex debug-tail

Polls ApexLog via the Tooling API every 2 seconds. For each new log entry, a header line is printed showing the timestamp, running user, entry point, and log size. With --body, filtered body lines are also streamed — surfacing USER_DEBUG output, exceptions, SOQL statements, and DML events without downloading the full log. Runs until Ctrl-C.

Flags

FlagDescriptionDefault
-o, --target-org Target org alias or username default org
--level Log level hint displayed in the header DEBUG
--body Also stream filtered body lines (USER_DEBUG, EXCEPTION_THROWN, SOQL_EXECUTE_BEGIN, DML_BEGIN) off

Usage

sf-rust apex debug-tail -o dev1
sf-rust apex debug-tail -o dev1 --body
sf-rust apex debug-tail -o dev1 --body --level FINEST

Example output — header mode

$ sf-rust apex debug-tail -o dev1 Tailing Apex debug logs for dev1. Ctrl-C to stop. ─── [2026-11-14T10:23:11Z] Admin User | /apex/MyController | 48,201B ─── ─── [2026-11-14T10:23:45Z] Admin User | Execute Anonymous | 1,204B ───

Example output — with --body

$ sf-rust apex debug-tail -o dev1 --body Tailing Apex debug logs for dev1. Ctrl-C to stop. ─── [2026-11-14T10:24:01Z] Admin User | /apex/InvoiceController | 72,440B ─── 14:24:01.012 (12345)|USER_DEBUG|[42]|DEBUG|Invoice processed: INV-0042 14:24:01.098 (98765)|SOQL_EXECUTE_BEGIN|[18]|SELECT Id FROM Invoice__c WHERE Status = 'Open' ─── [2026-11-14T10:24:33Z] Admin User | Execute Anonymous | 3,801B ─── 14:24:33.004 (4000)|USER_DEBUG|[1]|DEBUG|Hello from execute anonymous
ℹ Polling interval is 2 seconds. Use --body to surface USER_DEBUG and exception lines without downloading the full log. The Tooling API tracks a last_id cursor so only new logs since the previous poll are shown.

event subscribe

Subscribes to a Salesforce Platform Event channel using CometD/Bayeux long-polling. Performs the full CometD handshake (handshake → subscribe → connect loop) against /cometd/{api_version} and prints each event payload as JSON as it arrives. Runs until Ctrl-C.

Flags

FlagDescriptionDefault
<event> Platform Event API name (e.g. OrderEvent__e) required
-o, --target-org Target org alias or username default org
--replay-id CometD replay ID: -1 = new events only, -2 = all retained -1

Usage

sf-rust event subscribe OrderEvent__e -o dev1
sf-rust event subscribe OrderEvent__e -o dev1 --replay-id -2
sf-rust event subscribe MyPlatformEvent__e -o prod

Example output

$ sf-rust event subscribe OrderEvent__e -o dev1 Subscribed to /event/OrderEvent__e (replay_id=-1). Waiting for events... Ctrl-C to stop. [replayId=42] { "OrderNumber__c": "ORD-9001", "Amount__c": 2500.00, "Status__c": "Confirmed" } [replayId=43] { "OrderNumber__c": "ORD-9002", "Amount__c": 150.00, "Status__c": "Pending" }
✓ Use --replay-id -2 to replay all retained events (up to 72 hours) from the beginning of the retention window. This is useful for debugging missed events or replaying a sequence during development.

event publish

Publishes a Platform Event to the org via the Salesforce REST API (POST /services/data/v{api_version}/sobjects/{Event__e}/). The JSON payload is passed directly as the event's field values.

Flags

FlagDescription
<event> Platform Event API name (e.g. OrderEvent__e)
-o, --target-org Target org alias or username
--data JSON payload with the event's field values

Usage

sf-rust event publish OrderEvent__e -o dev1 \
    --data '{"OrderNumber__c":"ORD-9003","Amount__c":750.00,"Status__c":"New"}'

Example output

$ sf-rust event publish OrderEvent__e -o dev1 \ --data '{"OrderNumber__c":"ORD-9003","Amount__c":750.00,"Status__c":"New"}' Published event OrderEvent__e · Id: e00xx0000000001AAA
ℹ Combine event publish in one terminal with event subscribe in another to test end-to-end Platform Event flows without writing any Apex or Flow.

Architecture

Phase 8 adds two new crates (sf-event, sf-audit) and extends sf-apex and sf-cli. All commands follow the existing async Tokio pattern and share the SalesforceClient from sf-api.

sf-event

CometD/Bayeux protocol implemented with reqwest async HTTP. Flow: POST handshake → extract clientId → POST subscribe → long-poll connect loop. The replay extension uses a dynamic channel key so each reconnect carries the latest replayId.

sf-audit

Standard SOQL queries via SalesforceClient::query(). Nested relationship fields (CreatedBy.Name) are flattened by flatten_record() before rendering. All three audit commands share a common print_results() path for table / JSON / CSV output.

apex debug-tail

Tooling API — polls ApexLog every 2 seconds. Tracks a last_id cursor to query only new logs since the previous poll. With --body, fetches the log body and line-filters to relevant event types: USER_DEBUG, EXCEPTION_THROWN, SOQL_EXECUTE_BEGIN, DML_BEGIN.

config commands

Synchronous (no .await) — directly calls sf_core::Config::load() for reads and cfg.save() for writes. No network calls needed; operates entirely on ~/.sf-rust/config.toml.
