Custom Labels live in the ExternalString SOQL object and can be queried over the standard REST API — no Tooling API, no SOAP. sf-rust fetches them all via query_all() (pagination-safe) and renders them in table, CSV, JSON, or interactive datatable form.

Tip: Every table-output subcommand supports --datatable to open results in a browser with sortable, filterable columns.

📋 sfr custom-label list

Fetch all custom labels with optional filters by language, category, or full-text search.

Usage

sfr custom-label list -o dev1 sfr custom-label list -o dev1 --lang en_US sfr custom-label list -o dev1 --category Errors sfr custom-label list -o dev1 --search inprogress sfr custom-label list -o dev1 --json sfr custom-label list -o dev1 --csv sfr custom-label list -o dev1 --datatable

📤 sfr custom-label export

Export all labels (or a filtered set) to a CSV or JSON file for archiving, review, or import into a translation tool.

Usage

sfr custom-label export -o dev1 --csv labels.csv sfr custom-label export -o dev1 --json-file labels.json sfr custom-label export -o dev1 --lang en_US --csv en_labels.csv sfr custom-label export -o dev1 --category Errors --csv errors.csv sfr custom-label export -o dev1 --json # print JSON to stdout

🌐 sfr custom-label translate

Filter labels by language — useful as a step in a manual translation workflow. Shows which labels exist for a given language so you can spot gaps.

Usage

sfr custom-label translate -o dev1 --lang fr sfr custom-label translate -o dev1 --lang de --csv sfr custom-label translate -o dev1 --lang ja --datatable

🤖 sfr custom-label ai-translate

Automatically translate all label values into a target language using a local Ollama LLM. Placeholder tokens like {0}, {1} are preserved verbatim in the prompt instructions.

Usage

sfr custom-label ai-translate -o dev1 --to fr sfr custom-label ai-translate -o dev1 --to de --model llama3.2 sfr custom-label ai-translate -o dev1 --to ja --csv ja_labels.csv sfr custom-label ai-translate -o dev1 --to zh_CN --model gemma4:latest --csv zh_labels.csv sfr custom-label ai-translate -o dev1 --to es --limit 5 --datatable # test with 5 labels sfr custom-label ai-translate -o dev1 --to pt_BR --category Errors --json

Single-label translation (like get)

Pass --name to translate one specific label and get a clean key-value view with Original vs Translated side by side:

sfr custom-label ai-translate -o sf-rust-1 --to fr-CA --name "Action_already_inprogress_for_x_on_y" --model llama3.2:latest

Prerequisite: Ollama must be running locally (ollama serve) and the chosen model must be pulled (ollama pull llama3.2).

🔄 End-to-end Translation Workflow

  1. Export source labels — export all en_US labels to a CSV baseline:
    sfr custom-label export -o dev1 --lang en_US --csv labels_en.csv
  2. AI-translate — generate a translated CSV using Ollama:
    sfr custom-label ai-translate -o dev1 --to fr --model llama3.2 --csv labels_fr.csv
  3. Review — open in a datatable to spot-check the translations:
    sfr file view labels_fr.csv
  4. Deploy — package the translated labels into your metadata and deploy:
    sfr metadata deploy -d force-app -o dev1
