Current phase

mc-webconf is a standalone binary (also invokable as sf-rust webconf …) that provides encrypted, fully peer-to-peer conferencing from the terminal — no browser, no Electron, no cloud relay.

How to use

1. Start the signaling server

# On any machine (can be local or remote) mc-webconf serve --port 8080 mc-webconf signaling server port 8080 Browser UI: http://localhost:8080 Waiting for peers… (Ctrl+C to stop) # Also available as: sf-rust webconf serve --port 8080

W7: The signaling server now also serves a companion browser page at the same port. Open http://<host>:8080 in any browser — no extension needed. Browser peers and TUI peers share the same room.

2. Join from each peer

# Terminal 1 — Alice mc-webconf join 192.168.1.5:8080 --name Alice # Terminal 2 — Bob (different machine) mc-webconf join 192.168.1.5:8080 --name Bob # Custom STUN server (default: stun.l.google.com:19302) mc-webconf join 192.168.1.5:8080 --name Alice --stun stun:stun1.l.google.com:19302

Automatic P2P mesh (Phase W3)

No manual steps required. When you join a room, the client immediately auto-offers to every existing peer. When a new peer joins later, the peer with the lexicographically lower ID initiates the offer — this deterministic rule prevents simultaneous-offer glare. ICE candidates are exchanged through the signaling hub; once the RTCDataChannel opens, all subsequent traffic is fully P2P.

/offer <peer-id> is still accepted for manual reconnection when needed.

mc-webconf | room: default | you: Alice | id: a3f9c1b2… | peers: 1 [P2P: 1] [Voice: on] [TURN]
-- Joined! Auto-mesh P2P active — connecting to all peers automatically. /peers = list room. --
-- Your ID: a3f9c1b2… (1 peer(s) already in room) --
-- [WebRTC] auto-mesh: initiating P2P with 1 peer(s)… --
-- [WebRTC] ✓ P2P channel open (d7e21f04…) --
-- [Voice] mic active — /voice off to stop, /mute to toggle mic --
[14:22:18] [P2P] Bob: I can hear you!
Message | /peers /voice on|off /mute /send <peer> <file> /offer <id> | Enter=send Esc=exit
> |

P2P messages are shown in [P2P] magenta; they arrive directly from the peer's data channel, not relayed through the signaling server. The title bar shows [P2P: N] when N data channels are open.

TUI commands

CommandAction
/peersList peers in the room (shows [P2P] tag for connected peers)
/send <peer> <filepath>W4 — send a file over the encrypted file channel; peer name or ID prefix; AES-256-GCM per chunk; receiver auto-saves
/voice onW5 — start mic capture; Opus-encodes at 48 kHz; streams audio to all P2P-connected peers via WebRTC media track + renegotiation
/voice offW5 — stop mic capture and all voice playback streams
/muteW5 — toggle mic mute while voice is active; title shows [Voice: muted]
/offer <peer-id>Manually initiate WebRTC to a peer (auto-mesh normally handles this)
plain textChat via signaling to all peers; also mirrored over open P2P data channels
Esc / Ctrl+CExit
