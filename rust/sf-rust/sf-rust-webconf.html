mc-webconf is a standalone binary (also invokable as sf-rust webconf …) that provides WebRTC-based web conferencing from the terminal.

Phase W1 (signaling) added a WebSocket hub and a ratatui TUI join client. Phase W2 (P2P data channels) wired webrtc-rs RTCPeerConnection objects to those signals — peers exchange SDP and ICE through the hub and communicate directly via an encrypted DTLS/SCTP data channel. Phase W3 (auto-mesh) makes the entire process automatic: when a peer joins, it auto-offers to every existing peer; when a new peer arrives, the lower peer-ID side initiates to avoid simultaneous-offer glare. The signaling server is now used exclusively for bootstrapping — all message traffic flows P2P.

How to use

1. Start the signaling server

# On any machine (can be local or remote) mc-webconf serve --port 8080 # Also available as: sf-rust webconf serve --port 8080

2. Join from each peer

# Terminal 1 — Alice mc-webconf join 192.168.1.5:8080 --name Alice # Terminal 2 — Bob (different machine) mc-webconf join 192.168.1.5:8080 --name Bob # Custom STUN server (default: stun.l.google.com:19302) mc-webconf join 192.168.1.5:8080 --name Alice --stun stun:stun1.l.google.com:19302

Automatic P2P mesh (Phase W3)

No manual steps required. When you join a room, the client immediately auto-offers to every existing peer. When a new peer joins later, the peer with the lexicographically lower ID initiates the offer — this deterministic rule prevents simultaneous-offer glare. ICE candidates are exchanged through the signaling hub; once the RTCDataChannel opens, all subsequent traffic is fully P2P.

/offer <peer-id> is still accepted for manual reconnection when needed.

mc-webconf | room: default | you: Alice | id: a3f9c1b2… | peers: 1 [P2P: 1]
-- Joined! Auto-mesh P2P active — connecting to all peers automatically. /peers = list room. --

P2P messages are shown in [P2P] magenta; they arrive directly from the peer's data channel, not relayed through the signaling server. The title bar shows [P2P: N] when N data channels are open.

Implementation phases

Phase W1 ✅
WebSocket signaling hub
tokio-tungstenite server, room-based peer map, offer/answer/ice relay, ratatui TUI join client
Phase W2 ✅
WebRTC data channels
webrtc-rs RTCPeerConnection, RTCDataChannel, STUN/ICE, auto SDP exchange, [P2P] message routing
Phase W3 ✅
Automatic mesh
Newcomer auto-offers to all existing peers; lower peer-ID initiates on new join; full P2P mesh without manual /offer
Phase W4 ⏳
File transfer + encryption
Chunked file transfer over data channels; application-layer AES-256-GCM on top of DTLS
