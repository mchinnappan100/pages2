Basic usage

# Start with built-in seed data, opens /log in browser sfr mock-server # Custom port sfr mock-server -p 9090 # Load your own JSON seed data sfr mock-server --data my-data.json # Load a Postman collection for custom API routes sfr mock-server --collection sf-custom-api.postman_collection.json # Both — built-in Salesforce CRUD + custom Apex REST routes sfr mock-server --data seed.json --collection my-api.postman_collection.json # Don't open browser sfr mock-server --no-open

Pointing sfr at the mock server

Use sfr org login access-token to register the mock as an org — no browser, no OAuth, no Salesforce org needed. It stores the fake access token in ~/.sf-rust/credentials.json (AES-256-GCM encrypted) and adds the alias to your config.

# Step 1 — start the mock server in the background sfr mock-server -p 8080 --no-open & # Step 2 — register it as org alias "mock" sfr org login access-token \ --access-token mock-access-token-sf-rust \ --instance-url http://localhost:8080 \ --username mock-user@localhost \ --alias mock \ --set-default → Registered org as mock-user@localhost → Instance URL: http://localhost:8080 → Alias: mock
Short form: sfr org login access-token -t mock-access-token-sf-rust -u http://localhost:8080 -a mock --set-default

CRUD operations via curl

# Create a new Account curl -s -X POST http://localhost:8080/services/data/v62.0/sobjects/Account/ \ -H "Authorization: Bearer mock-access-token-sf-rust" \ -H "Content-Type: application/json" \ -d '{"Name":"Wayne Enterprises","Industry":"Finance"}' → {"id":"001e7f000001Abc","success":true,"errors":[]} # Get record by Id curl -s http://localhost:8080/services/data/v62.0/sobjects/Account/001xx0000001AaaAAA \ -H "Authorization: Bearer mock-access-token-sf-rust" → {"Id":"001xx0000001AaaAAA","Name":"Acme Corp","Industry":"Technology",...} # Update a record curl -s -X PATCH http://localhost:8080/services/data/v62.0/sobjects/Account/001xx0000001AaaAAA \ -H "Authorization: Bearer mock-access-token-sf-rust" \ -H "Content-Type: application/json" \ -d '{"Industry":"Energy"}' → 204 No Content # Delete a record curl -s -X DELETE http://localhost:8080/services/data/v62.0/sobjects/Account/001xx0000001AaaAAA \ -H "Authorization: Bearer mock-access-token-sf-rust" → 204 No Content

MCP agent workflow against the mock

# Start mock, register alias, then use the MCP server pointed at mock sfr mock-server --no-open & sfr mcp server -o mock # → Claude Desktop can now run SOQL, deploy, execute Apex — all against the local mock
Note: The mock server holds data in memory only. Data resets when the server restarts. Use --data seed.json to persist your fixture data across restarts.

Postman collection support

Pass any Postman Collection v2.1 JSON file with --collection. The server reads every item, extracts the method + path, and registers the first saved response as the reply. Nested folders are supported. These routes act as a fallback — the built-in Salesforce endpoints take priority.

# Wire a custom Apex REST service from an existing collection sfr mock-server --collection examples/postman/sf-custom-api.postman_collection.json # curl the custom route curl http://localhost:8080/services/apexrest/health → {"status":"UP","version":"2.1.0","checks":{"database":"UP","cache":"UP","externalApi":"UP"}} curl -X POST http://localhost:8080/services/apexrest/orders \ -H 'Content-Type: application/json' \ -d '{"accountId":"001xx0000001AaaAAA","items":[{"sku":"PROD-A","qty":2}]}' → {"orderId":"ORD-002","status":"Pending","total":59.98}

Custom seed data

Create a JSON file with SObject names as keys (case-insensitive) and an array of records as values:

{ "Account": [ { "Id": "001xx0001", "Name": "My Corp", "Industry": "Technology" }, { "Id": "001xx0002", "Name": "Their Corp","Industry": "Finance" } ], "Contact": [ { "Id": "003xx0001", "FirstName": "Jane", "LastName": "Doe", "AccountId": "001xx0001" } ] }
sfr mock-server --data seed.json
Query it: curl "http://localhost:8080/services/data/v62.0/query?q=SELECT+Id,Name+FROM+Account"
