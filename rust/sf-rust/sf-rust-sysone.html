Overview

sfr sysone calls Ollama's /v1/systemone endpoint — a structured inference API that returns typed, machine-readable answers instead of free text. You provide context (state) and a set of questions; the model returns probabilities, confidence scores, and classifications directly usable in code or pipelines.

The nimble model is purpose-built for System-One inference — fast, accurate, and runs entirely offline on your Mac or mac-mini. Any Ollama-compatible model can be selected with --model.

Answer types

TypeWhat it returnsUse case
choice classification Winning label + per-label probabilities + confidence Classify email category, ticket priority, sentiment, record type
noul likelihood 0–1 score (like a yes/no probability) Requires action?, Is automated?, Is urgent?, Is spam?
score rating Numeric score on a 0–N scale + per-label breakdown Urgency level, sentiment strength, complexity rating

Usage

# Run a sysone request JSON file sfr sysone run -f request.json sfr sysone run -f request.json --model nimble sfr sysone run -f request.json --model nimble:latest # Target mac-mini Ollama sfr sysone run -f request.json --ollama http://192.168.1.9:11434 # JSON output (for scripting / piping) sfr sysone run -f request.json --format json # Read from stdin cat request.json | sfr sysone run -f - # List available Ollama models sfr sysone models sfr sysone models --ollama http://192.168.1.9:11434 # Triage a plain-text email file (hardcoded questions: category, urgency, requires_action, is_automated) sfr sysone parse-email invoice.txt sfr sysone parse-email invoice.txt --format json sfr sysone parse-email - < email.txt # SOQL classify — run a query and classify each record via sysone sfr sysone classify -o dev1 \ -q "SELECT Id, Subject, Description FROM Case LIMIT 20" \ -Q "priority:choice:What is the support priority?:Critical=Blocker,High=Important,Medium=Normal,Low=Minor" \ -Q "escalate:noul:Should this case be escalated to L2?"

Request JSON format

A sysone request has three top-level fields: model, state (the context), and questions (what to answer about that context).

// sample-sysone-request.json { "model": "nimble", "state": { "email": "Subject: Invoice #INV-2024-0847 Overdue – Action Required\n\nDear Accounts Team,\n\nThis is a reminder that invoice #INV-2024-0847 for $4,250.00 was due on\nNovember 1st, 2026 and remains unpaid. Please arrange payment within 48\nhours to avoid a late fee.\n\nKind regards,\nAccounts Receivable\nAcme Corp" }, "questions": { "category": { "type": "choice", "instructions": "What category best describes this email?", "criteria": { "invoice": "Invoice, receipt, or payment request", "support": "Customer support or service request", "meeting_invite": "Meeting invitation or calendar request", "marketing": "Marketing, newsletter, or promotion", "spam": "Spam or phishing attempt", "other": "None of the above" } }, "requires_action": { "type": "noul", "instructions": "Does this email require a response or action from the recipient?" }, "urgency": { "type": "score", "instructions": "How urgent is this email?", "criteria": ["Not urgent", "Low", "Medium", "High", "Critical"] }, "is_automated": { "type": "noul", "instructions": "Is this an automated or system-generated email (not written by a human)?" } } }
The --model flag overrides the "model" field in the JSON — no need to edit the file to switch models.

sfr sysone parse-email new

Triages a plain-text email file with hardcoded, Salesforce-ready questions — no JSON authoring needed. Answers: category (choice), requires_action (noul), urgency (score), is_automated (noul).

# table output (bar charts) sfr sysone parse-email ~/sysone/data/email-invoice.txt sfr sysone parse-email ~/sysone/data/email-support.txt --model nimble:latest # clean JSON for scripting / piping sfr sysone parse-email ~/sysone/data/email-invoice.txt --format json # pipe from stdin cat ~/sysone/data/email-invoice.txt | sfr sysone parse-email -

Sample input — email-invoice.txt

From: accounts@acme-corp.com To: payments@yourcompany.com Subject: Invoice #INV-2024-0847 Overdue – Action Required Dear Accounts Team, This is a reminder that invoice #INV-2024-0847 for $4,250.00 was due on November 1st, 2026 and remains unpaid. Please arrange payment within 48 hours to avoid a late fee of 2% per month. Kind regards, Accounts Receivable, Acme Corp

Expected JSON output (--format json)

{ "category": "invoice", "category_confidence": 0.976, "requires_action": true, "requires_action_score": 0.938, "urgency_label": "High", "urgency_score": 2.87, "is_automated": true, "model": "nimble", "ms": 4979 }

Sample input — email-support.txt (critical escalation)

From: john.smith@customer.com Subject: URGENT: Production system completely down — cannot process orders Hi Support Team, Our production environment has been completely non-functional since 9:15 AM PST. We are unable to process ANY new orders — 2,000 active users affected. Error: "System Error: Connection timeout to backend service (ERR_CONN_REFUSED)" Please escalate immediately. We need a response within 15 minutes. John Smith, VP of Engineering

sfr sysone classify new

Runs a SOQL query against a Salesforce org, then calls sysone on each record with custom questions. Answer columns (prefixed _) are appended to the table or JSON output.

# classify Case records by priority and escalation likelihood sfr sysone classify -o dev1 \ -q "SELECT Id, CaseNumber, Subject, Description, Priority FROM Case WHERE IsClosed = false LIMIT 10" \ -Q "ai_priority:choice:What should be the support priority?:Critical=Production down or data loss,High=Major feature broken,Medium=Partial degradation,Low=Minor inconvenience" \ -Q "escalate:noul:Should this case be escalated to Tier 2 or engineering?" # lead scoring (3 questions per lead) sfr sysone classify -o dev1 \ -q "SELECT Id, FirstName, LastName, Title, Company, Description FROM Lead WHERE IsConverted = false LIMIT 20" \ -Q "industry:choice:What industry does this lead belong to?:Technology=SaaS software tech,Financial=Banking finance insurance,Healthcare=Medical pharma,Retail=Consumer e-commerce,Other=None of the above" \ -Q "buying_intent:noul:Does this lead show strong buying intent?" \ -Q "deal_size:score:How large is the potential deal size?:Small,Medium,Large,Enterprise" # JSON output for downstream processing sfr sysone classify -o dev1 \ -q "SELECT Id, Subject, Description FROM Case LIMIT 5" \ -Q "priority:choice:Support priority?:Critical=P1,High=P2,Medium=P3,Low=P4" \ --format json | jq '.[] | {Id, Subject: .Subject, priority: ._priority}'

Sample scripts (in sf-rust/samples/)

# classify-cases.sh — cases by priority and escalation #!/bin/bash ORG=${1:-dev1} sfr sysone classify -o "$ORG" \ -q "SELECT Id, CaseNumber, Subject, Description FROM Case WHERE IsClosed = false LIMIT 10" \ -Q "ai_priority:choice:Support priority?:Critical=Production down,High=Major broken,Medium=Partial,Low=Minor" \ -Q "escalate:noul:Should this case be escalated to L2?" \ --model nimble # classify-leads.sh — leads by industry, buying intent, and deal size #!/bin/bash ORG=${1:-dev1} sfr sysone classify -o "$ORG" \ -q "SELECT Id, FirstName, LastName, Title, Company FROM Lead WHERE IsConverted = false LIMIT 20" \ -Q "industry:choice:Industry?:Technology=SaaS software,Financial=Banking finance,Healthcare=Medical" \ -Q "buying_intent:noul:Shows strong buying intent?" \ -Q "deal_size:score:Potential deal size?:Small,Medium,Large,Enterprise" \ --model nimble
Question spec format: NAME:TYPE[:INSTRUCTIONS[:CRITERIA]] — choice criteria: label=description,… — score criteria: Level0,Level1,Level2,… (comma-separated ordered labels) — noul needs no criteria — Use -Q multiple times to ask several questions per record.
