sf-rust doctor NEW

Runs a full environment health check and prints a colour-coded status table. Checks include: config and key files, credential store, default org, live token ping per org, shell completion scripts (zsh & bash), man pages, and the installed binary. Use this to quickly diagnose setup issues without reading error logs.

FlagTypeDescription
--jsonboolOutput results as JSON instead of table
 
$ sf-rust doctor

Token ping makes a live GET /services/data/ request with the stored Bearer token to verify it has not expired. Run sf-rust org login web -o <alias> to refresh an expired credential.

sf-rust flow activate

Activates a flow by PATCHing the FlowDefinition record with the latest ActiveVersionNumber. Use flow list first to obtain the definition ID.

FlagTypeDescription
--idstringFlowDefinition record ID (required)
-o, --target-orgstringOrg alias or username
 
$ sf-rust flow activate --id 3005g000003kFXcAAM -o dev1
✓ Flow activated (ActiveVersionNumber → 2)

sf-rust flow deactivate

Deactivates a flow by setting ActiveVersionNumber to 0 via a Tooling API PATCH request. The flow remains in Draft state and can be reactivated.

FlagTypeDescription
--idstringFlowDefinition record ID (required)
-o, --target-orgstringOrg alias or username
 
$ sf-rust flow deactivate --id 3005g000003kFXcAAM -o dev1
⊘ Flow deactivated
⚠

Running interviews are not interrupted. Deactivating a flow only prevents new interviews from starting. In-flight automation continues until it completes or errors.

Password reset uses POST /sobjects/User/{id}/password with an empty body, which triggers Salesforce to send a standard reset email. The user's current session is not invalidated until they complete the reset flow.

sf-rust ci generate NEW

Generates a production-ready CI/CD pipeline YAML for GitHub Actions or GitLab CI. Uses JWT Bearer flow for unattended authentication — the standard for CI environments. The generated file includes validate-only jobs on pull requests and full deploy jobs on merge to the production branch.

FlagTypeDescription
--platformstringgithub or gitlab (required)
--source-dirstringSource directory to deploy (default: force-app)
--prod-branchstringBranch that triggers deployment (default: main)
--outputpathWrite YAML to this file (default: stdout)

GitHub Actions

$ sf-rust ci generate \
    --platform github \
    --source-dir force-app \
    --prod-branch main \
    --output .github/workflows/deploy.yml
✓ Written: .github/workflows/deploy.yml
# Generated .github/workflows/deploy.yml
name: Salesforce Deploy

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  validate:
    if: github.event_name == 'pull_request'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Validate
        run: sf-rust metadata validate -d force-app -o prod
        env:
          SF_JWT_KEY: ${{ secrets.SF_JWT_KEY }}
          SF_CLIENT_ID: ${{ secrets.SF_CLIENT_ID }}
          SF_USERNAME: ${{ secrets.SF_USERNAME }}

  deploy:
    if: github.event_name == 'push'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Deploy
        run: sf-rust metadata deploy -d force-app -o prod
        env:
          SF_JWT_KEY: ${{ secrets.SF_JWT_KEY }}
          SF_CLIENT_ID: ${{ secrets.SF_CLIENT_ID }}
          SF_USERNAME: ${{ secrets.SF_USERNAME }}

GitLab CI

$ sf-rust ci generate --platform gitlab --output .gitlab-ci.yml
✓ Written: .gitlab-ci.yml
✦

Store SF_JWT_KEY, SF_CLIENT_ID, and SF_USERNAME as encrypted CI secrets. Never commit private keys to source control.

sf-rust metadata backup NEW

Creates a full or partial org backup by building a wildcard package.xml (using * members for each type), submitting a Retrieve request via the SOAP Metadata API, polling until the job completes, and writing the returned zip to disk. Optionally commits the zip to the current git repository with an auto-generated message.

FlagTypeDescription
-o, --target-orgstringOrg alias or username (required)
--outputpathOutput zip file path (required)
--typesstringComma-separated types to back up (default: all)
--git-commitboolCommit the zip to git after writing
 
$ sf-rust metadata backup -o dev1 --output backup-$(date +%Y%m%d).zip
Building package.xml (wildcard)…
Submitting Retrieve request…
  ⟳ InProgress [5s]
  ⟳ InProgress [10s]
  ✓ Succeeded  [15s]
Backup written: backup-20261113.zip (2.4 MB)  ·  15s
$ sf-rust metadata backup -o dev1 \
    --output backup-apex.zip \
    --types ApexClass,ApexTrigger,Flow \
    --git-commit
✓ Backup written: backup-apex.zip
✓ Committed: "chore: metadata backup 2026-11-13 (ApexClass,ApexTrigger,Flow)"
ℹ

Without --types the backup attempts all metadata types. For large orgs this can take several minutes. Use --types to scope the backup to the component types you care about.

sf-rust metadata diff NEW

Compares local source files against their deployed counterparts retrieved from the org via the Tooling API. Walks .cls, .trigger, and lwc/*/ directories, fetches each component's Body remotely, and diffs using the similar crate's unified diff engine. Produces a colour-coded diff to stdout or a self-contained HTML datatable with expandable diffs.

FlagTypeDescription
-o, --target-orgstringOrg alias or username (required)
--source-dirpathLocal source root (default: force-app/main/default)
--typesstringLimit to comma-separated types: ApexClass, ApexTrigger, LWC
--datatableboolOpen an HTML datatable with inline coloured diffs
--jsonboolJSON diff output
 
$ sf-rust metadata diff -o dev1 --types ApexClass
─── AccountController.cls ─────────────────────── 1 | public class AccountController { 2 | public static List<Account> getAccounts() { -3 | return [SELECT Id, Name FROM Account LIMIT 50]; +3 | return [SELECT Id, Name, Industry FROM Account LIMIT 100]; 4 | } 5 | } ─── LeadHandler.trigger ───────────────────────── No diff — matches deployed version 2 files checked · 1 modified · 1 clean 
$ sf-rust metadata diff -o dev1 --datatable
Datatable opened: /tmp/sf-rust-diff-1731456789000.html
✦

Use metadata diff before a deploy to confirm exactly which lines have drifted between your local source and what's live in the org — a quick sanity check in a release workflow.
