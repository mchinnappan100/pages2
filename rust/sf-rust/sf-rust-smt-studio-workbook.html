1Generate Load Plan

plan generate Calls the Salesforce Describe API on the source org (af102), filters to writable fields, picks composite keys, and generates a Vehicle__c-plan.json ready for migration. 

$ sf-rust smt plan generate \
    -o af102 \
    --object Vehicle__c

Plan written to: Vehicle__c-plan.json
Generated plan for Vehicle__c (5 writable fields, composite keys: ["Global_Key__c"])
Time: 1.08s

What the generator does

StepAction
1GET /sobjects/Vehicle__c/describe/ on af102
2Filter to createable = true, exclude system fields (Id, OwnerId, CreatedDate, …)
3Pick composite key: Global_Key__c (first found in priority list)
4Emit composite key field first in SELECT and fieldMappings
5Custom __c reference fields → relationship traversal (Manufacturer__r.Global_Key__c)
6Generate fallback query_v1 and compositeKeys_v1 for orgs without Global_Key__c

Composite key priority order

// checked in this order; first field found on the object wins
Global_Key__c  →  Name  →  Email  →  ProductCode  →  DeveloperName

2Load Plan Anatomy

The generated Vehicle__c-plan.json — flat format, compatible with smt-studio.

[
  {
    "object": "Vehicle__c",

    // composite key used to match source ↔ target records
    "compositeKeys": [ "Global_Key__c" ],

    // fallback for orgs that don't have Global_Key__c
    "compositeKeys_v1": [ "Name" ],

    // SOQL run on the source org  (no Id in SELECT)
    "query": "SELECT Global_Key__c, Name, Model__c,
               Manufacturer__r.Global_Key__c,
               VehicleCustomer__r.Global_Key__c
             FROM Vehicle__c",

    // fallback query for orgs without Global_Key__c
    "query_v1": "SELECT Name, Model__c,
                 Manufacturer__r.Name,
                 VehicleCustomer__r.Name
               FROM Vehicle__c",

    "fieldMappings": {
      // Direct — same field name on both orgs
      "Global_Key__c": "Global_Key__c",
      "Name":          "Name",
      "Model__c":      "Model__c",

      // Lookup — custom __c reference; engine reads traversal path,
      // resolves via Global_Key__c → Id map on target
      "Manufacturer__c": {
        "lookup": {
          "object": "Manufacturer__c",
          "key":    "Global_Key__c",
          "field":  "Manufacturer__r.Global_Key__c"   // where to read the key value
        }
      },
      "VehicleCustomer__c": {
        "lookup": {
          "object": "VehicleCustomer__c",
          "key":    "Global_Key__c",
          "field":  "VehicleCustomer__r.Global_Key__c"
        }
      }
    }
  }
]

Field mapping modes

FieldModeJSON formEngine action
Global_Key__c Direct "Global_Key__c": "Global_Key__c" Copy value as-is
Name Direct "Name": "Name" Copy value as-is
Model__c Direct "Model__c": "Model__c" Copy value as-is
Manufacturer__c Lookup + Traversal lookup { object, key, field } Read Manufacturer__r.Global_Key__c from source row; query SELECT Id, Global_Key__c FROM Manufacturer__c on target; resolve to target Id
VehicleCustomer__c Lookup + Traversal lookup { object, key, field } Same pattern for VehicleCustomer__c

Important The field property tells the engine which path in the SOQL result contains the lookup key. Without it, the engine would read the raw Salesforce ID (Manufacturer__c) instead of the traversed Global_Key__c value.

    -s af102 \

What gen-csv writes

FileContents
Vehicle__c_insert.csv Records in source but not in target (by composite key). Submitted as a Bulk API insert job.
Vehicle__c_update.csv Records in both orgs where at least one field value differs. Includes Id column for the target record. Submitted as a Bulk API update job.

Null handling Salesforce Bulk API v2 uses #N/A (unquoted) to clear a field. sf-rust writes #N/A for both null source values and unresolved lookup references.

⌘Quick Reference

All smt commands

# Generate plan from source org describe
$ sf-rust smt plan generate -o af102 --object Vehicle__c
$ sf-rust smt plan generate -o af102 --object Account -f account-plan.json

# Validate plan against both orgs (no data moved)
$ sf-rust smt plan validate -l Vehicle__c-plan.json -s af102 -t af200

# Dry-run: write CSVs only, don't load
$ sf-rust smt gen-csv  -l Vehicle__c-plan.json -s af102 -t af200 --output ./csvs

# Full migration (interactive — press Enter between objects)
$ sf-rust smt migrate  -l Vehicle__c-plan.json -s af102 -t af200

# CI-safe migration (no stdin reads)
$ sf-rust smt migrate  -l plan.json -s af102 -t af200 --no-pause

# Compare source vs target (count diff by composite key)
$ sf-rust smt compare  -l Vehicle__c-plan.json -s af102 -t af200
$ sf-rust smt compare  -l Vehicle__c-plan.json -s af102 -t af200 --json

# Export snapshot ZIP (source + target JSONs)
$ sf-rust smt export   -l Vehicle__c-plan.json -s af102 -t af200 --output ./audit

# Bulk delete from target (always dry-run first!)
$ sf-rust smt delete   -l Vehicle__c-plan.json -t af200 --dry-run
$ sf-rust smt delete   -l Vehicle__c-plan.json -t af200

# Man pages
$ man sf-rust-smt
$ man sf-rust-smt-migrate

Multi-object plan example

# Manufacturer__c must come before Vehicle__c (dependency order)
$ sf-rust smt plan generate -o af102 --object Manufacturer__c
$ sf-rust smt plan generate -o af102 --object Vehicle__c

# Combine into one file
$ jq -s '.[0] + .[1]' Manufacturer__c-plan.json Vehicle__c-plan.json > full-plan.json

$ sf-rust smt migrate -l full-plan.json -s af102 -t af200
