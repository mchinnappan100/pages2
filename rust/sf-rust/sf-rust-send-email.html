📧 sf-rust send-email

Send email via Gmail SMTP using a Google App Password — plain text, HTML, or with attachments.

Plain text

Inline body via --body or from a file via --body-file.

HTML email

--html sends multipart/alternative with a plain-text fallback.

Attachments

--attach (repeat for multiple). MIME type auto-detected from extension.

Multi-recipient

Repeat --to, --cc, --bcc for multiple addresses.

App password

Reads from ~/.gmail/access.json — no OAuth dance required.

Pure Rust

Uses the lettre crate with rustls — no C libs, no OpenSSL.

One-time setup

You need a Google App Password. 2FA must be enabled on the Google account.

  1. Go to myaccount.google.com/apppasswords
  2. Create a new app password → copy the 16-character code (displayed as 4 groups of 4)
  3. Save it to ~/.gmail/access.json:
# Create credentials file mkdir -p ~/.gmail echo '{"you@gmail.com": "abcd efgh ijkl mnop"}' > ~/.gmail/access.json chmod 600 ~/.gmail/access.json
Security: The credentials file is read at runtime only. It is never stored in sf-rust's own credential store. Keep the file chmod 600 and never commit it to git.

Basic usage

# Minimal example — sends a plain-text email sfr send-email --to mohan.chinnappan.n@gmail.com --subject "Test from sf-rust" --body "Hello from the CLI" Connecting to smtp.gmail.com:587 ... ✓ Sent: "Test from sf-rust" → mohan.chinnappan.n@gmail.com Time: 1.28s # Multi-line form (same command) sfr send-email \ --to colleague@example.com \ --subject "Hello from sf-rust" \ --body "Just shipped the new CLI build!" # Send body from a text file sfr send-email \ --to colleague@example.com \ --subject "Deploy report" \ --body-file deploy-summary.txt # Multiple recipients (repeat the flag) sfr send-email \ --to alice@example.com \ --to bob@example.com \ --cc manager@example.com \ --subject "Sprint summary" \ --body "All 23 stories merged."

File attachments

# Attach one file sfr send-email \ --to boss@example.com \ --subject "Q4 report" \ --body "Please find the report attached." \ --attach q4-report.xlsx # Attach multiple files sfr send-email \ --to team@example.com \ --subject "Data dump" \ --body "CSV + Parquet attached." \ --attach accounts.csv \ --attach accounts.parquet # Combine with sfr data query to email a CSV inline sfr data query -q "SELECT Id,Name FROM Account" -o dev1 --csv > /tmp/accounts.csv sfr send-email \ --to team@example.com \ --subject "Accounts export" \ --body "Today's account list attached." \ --attach /tmp/accounts.csv

HTML email

When --html is given, the message is sent as multipart/alternative: the HTML part is shown by modern clients; the --body (or empty string) is the plain-text fallback.

# Send a styled HTML report sfr send-email \ --to stakeholder@example.com \ --subject "Deployment complete" \ --body "Deployment complete. See HTML for details." \ --html deploy-report.html # HTML only (no plain-text fallback) sfr send-email \ --to user@example.com \ --subject "Dashboard" \ --html dashboard.html
Tip: Use sfr data query --datatable to generate an HTML page, then send it as the email body with --html.

All flags

FlagShortRequiredDescription
--to-tYesRecipient address(es) — repeat for multiple
--ccCC address(es) — repeat for multiple
--bccBCC address(es) — repeat for multiple
--subject-sYesEmail subject line
--body-b*Plain-text body inline
--body-file*Read plain-text body from file
--html*HTML body file — sends multipart/alternative
--attach-aFile to attach — repeat for multiple; MIME auto-detected
--from-fSender address (defaults to the key in access.json)
--credentialsPath to credentials JSON (default: ~/.gmail/access.json)

* At least one of --body, --body-file, or --html is required.
