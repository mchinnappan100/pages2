sf-rust data · SOQL

Query, inspect, and manage Salesforce data from the terminal. Every output format in one binary — no Node.js, no Python, no pandas.

SOQL with auto-pagination Parquet · Arrow · Excel · SQLite Interactive datatable browser view SObject describe & field metadata Single-record CRUD · SOQL explain plan

Output formats

data query supports ten output modes. All modes except the interactive pager and --datatable are suitable for piping and automation. Column order is always preserved — serde_json is built with preserve_order so SELECT Id, Name, Industry always renders in that exact sequence.

(default) UTF8_FULL table, interactive pager when TTY
--json Pretty-printed JSON array
--csv RFC 4180 CSV with header row
--ndjson Newline-delimited JSON (one object per line)
--markdown GitHub-flavored Markdown table
--datatable Self-contained HTML page, opens in browser
--parquet FILE Apache Parquet (Snappy compression)
--arrow FILE Apache Arrow IPC file
--xlsx FILE Excel workbook (pure Rust, bold headers)
--sqlite FILE SQLite database (single transaction)

Pagination

Salesforce returns at most 2,000 records per REST batch. data query handles this automatically depending on the mode and flags.

ModePagination behaviour
Table (TTY, no --all) Interactive pager — --page-size N (default 50) rows per screen. Press Enter for next page, q to quit.
Table with --all query_all() fetches every record via nextRecordsUrl before rendering. No pager.
--json / --csv / --ndjson / --markdown Always calls query_all() — returns every record regardless of batch size.
Piped stdout (non-TTY) Pager is skipped automatically; query_all() is used.
File formats (Parquet / Arrow / Excel / SQLite) Always query_all() — no partial files.
◆

Token refresh on 401. Every request retries once on HTTP 401 — the refresh token is used to obtain a new access token and persist it to ~/.sf-rust/credentials.json. Long-running queries across many batches never prompt for re-authentication.

sf-rust data query

Run a SOQL query and render the results. Accepts the query inline (-q) or from a file (-f). Relationship fields are flattened to dot-notation keys (Account.Name). Attributes are stripped from output.

Flags

FlagDescription
-q, --query SOQLSOQL query string
-f, --file PATHRead SOQL from a file
-o, --target-org ALIASOrg alias or username
-n, --page-size NRows per page in table mode (default: 50)
--allDisable pager, fetch all records
--jsonOutput as JSON array
--csvOutput as CSV
--ndjsonOutput as NDJSON (one record per line)
--markdownOutput as Markdown table
--datatableOpen interactive browser datatable
--parquet [FILE]Write Parquet file (default: /tmp/sf-rust-query-<ts>.parquet)
--arrow [FILE]Write Arrow IPC file
--xlsx [FILE]Write Excel workbook
--sqlite [FILE]Write SQLite database (default: /tmp/sf-rust-query-<ts>.db)
--sqlite-table NAMETable name in the SQLite database (default: records)
--grep PATTERNPost-filter: keep only rows where any field matches this regex
--grep-ignore-caseCase-insensitive --grep matching
--use-tooling-apiUse the Tooling API instead of the REST API

Examples

── basic queries ──────────────────────────────────────────────
$ sf-rust data query -q "SELECT Id, Name FROM Account" -o dev1
$ sf-rust data query -f queries/accounts.soql -o dev1
$ sf-rust data query -q "SELECT Id, Name FROM Account" -o dev1 --all
$ sf-rust data query -q "SELECT Id, Name FROM Account" -o dev1 --page-size 25

── relationship fields (auto-flattened to dot notation) ──────
$ sf-rust data query -q "SELECT Id, Account.Name FROM Contact" -o dev1
# → columns: Id, Account.Name

── text output formats ────────────────────────────────────────
$ sf-rust data query -q "SELECT Id, Name FROM Account" -o dev1 --json
$ sf-rust data query -q "SELECT Id, Name FROM Account" -o dev1 --csv
$ sf-rust data query -q "SELECT Id, Name FROM Account" -o dev1 --ndjson
$ sf-rust data query -q "SELECT Id, Name FROM Account" -o dev1 --markdown

── pipe to other tools ────────────────────────────────────────
$ sf-rust data query -q "SELECT Id, Name FROM Account" -o dev1 --csv > accounts.csv
$ sf-rust data query -q "SELECT Id, Name FROM Account" -o dev1 --json | jq '.[0]'
$ sf-rust data query -q "SELECT Name FROM Account" -o dev1 --ndjson | wc -l

data query --datatable

Fetches all records, flattens relationship fields to dot-notation keys, strips attributes, and generates a self-contained HTML page at /tmp/sf-rust-query-<ts>.html. Opens the file automatically with the system open command.

  • Dark mode auto-follows prefers-color-scheme; manual toggle persisted in localStorage
  • Sort by clicking any column header
  • Filter rows with the search box — applies instantly across all columns
  • Query text and generation timestamp appear in the footer
  • No external dependencies — works fully offline
$ sf-rust data query -q "SELECT Id, Account.Name, Title FROM Contact" -o dev1 --datatable
# → generates /tmp/sf-rust-query-1731504000.html and opens it

# also works with --grep to pre-filter before the browser opens:
$ sf-rust data query -q "SELECT Id, Name FROM Account" -o dev1 --datatable --grep "Tech"

data query --grep

Post-filters results after all records are fetched. Keeps only rows where at least one field value matches the regex. Applied to every output mode — table, CSV, JSON, NDJSON, Markdown, Parquet, Arrow, Excel, SQLite, and datatable. 

── case-sensitive (default) ───────────────────────────────────
$ sf-rust data query -q "SELECT Id, Name, Industry FROM Account" -o dev1 --grep "Tech"
$ sf-rust data query -q "SELECT Id, Name FROM Account" -o dev1 --grep "^Acme"

── case-insensitive ───────────────────────────────────────────
$ sf-rust data query -q "SELECT Id, Name FROM Account" -o dev1 --grep "tech" --grep-ignore-case

── combined with file format output ──────────────────────────
$ sf-rust data query -q "SELECT Id, Name, Industry FROM Account" -o dev1 \
    --csv --grep "Finance|Healthcare"

── also works with arrow-view ─────────────────────────────────
$ sf-rust data arrow-view accounts.parquet --grep "Technology"
◆

--grep uses the regex crate — full Rust regex syntax including ^, $, |, character classes, lookaheads. Anchors match against each individual field value, not the whole row string.

Parquet & Arrow

Uses the arrow = "53" and parquet = "53" crates. Schema is inferred from the first non-null value per column. Parquet uses Snappy compression. Arrow uses FileWriter (IPC format). Both can be read back with data arrow-view. 

── write ──────────────────────────────────────────────────────
$ sf-rust data query -q "SELECT Id, Name, AnnualRevenue FROM Account" -o dev1 \
    --parquet accounts.parquet
$ sf-rust data query -q "SELECT Id, Name FROM Account" -o dev1 --arrow accounts.arrow

── read back ──────────────────────────────────────────────────
$ sf-rust data arrow-view accounts.parquet
$ sf-rust data arrow-view accounts.parquet --schema
$ sf-rust data arrow-view accounts.parquet --limit 10
$ sf-rust data arrow-view accounts.parquet --csv > accounts.csv
$ sf-rust data arrow-view accounts.parquet --xlsx accounts.xlsx
$ sf-rust data arrow-view accounts.parquet --grep "Technology"

── default paths (no FILE argument) ──────────────────────────
$ sf-rust data query -q "SELECT Id FROM Account" -o dev1 --parquet
# → /tmp/sf-rust-query-1731504000.parquet

Excel

Uses rust_xlsxwriter = "0.80" — pure Rust, no COM objects, no LibreOffice. Writes a bold header row and uses correct numeric types for numeric columns. 

$ sf-rust data query -q "SELECT Id, Name, AnnualRevenue FROM Account" -o dev1 \
    --xlsx accounts.xlsx

# also from an existing Parquet file:
$ sf-rust data arrow-view accounts.parquet --xlsx accounts.xlsx

# default path if no FILE given:
$ sf-rust data query -q "SELECT Id FROM Account" -o dev1 --xlsx
# → /tmp/sf-rust-query-1731504000.xlsx

SQLite

Uses rusqlite = "0.32" with the bundled feature (statically linked libsqlite3). Schema affinity is inferred from the data; all inserts are wrapped in a single transaction for speed. 

── write to SQLite ────────────────────────────────────────────
$ sf-rust data query -q "SELECT Id, Name, Industry FROM Account" -o dev1 \
    --sqlite accounts.db
# table name defaults to 'records'

$ sf-rust data query -q "SELECT Id, Name, Industry FROM Account" -o dev1 \
    --sqlite sf.db --sqlite-table accounts

── query it afterwards ────────────────────────────────────────
$ sqlite3 sf.db "SELECT Industry, COUNT(*) FROM accounts GROUP BY Industry"
$ sf-rust data rsql -o dev1 --load Account --db sf.db

sf-rust data describe

Fetches the full Salesforce describe metadata for one SObject and renders a UTF8_FULL fields table: name, label, type, required, updateable, unique, and length/precision. The same information as Setup → Object Manager → Fields, instantly at the terminal.

Flags

FlagDescription
SOBJECTAPI name of the SObject — positional argument (e.g. Account, Contact)
-o, --target-orgOrg alias or username
--jsonOutput the full raw describe JSON
--picklistShow picklist values for each enum/picklist field in separate sub-tables
--relationshipsShow only reference (lookup / master-detail) fields

Field type legend

string textarea email phone url int double currency percent boolean → reference picklist multipicklist date datetime base64 id

Reference fields show the target object as → Account or → User, Group (polymorphic). Len/Prec shows max length for text fields and precision,scale for numeric fields.

Examples

── basic describe ─────────────────────────────────────────────
$ sf-rust data describe Account -o dev1
$ sf-rust data describe Contact -o dev1
$ sf-rust data describe Opportunity -o dev1

── show picklist values ───────────────────────────────────────
$ sf-rust data describe Account -o dev1 --picklist
# → fields table, then per-enum sub-tables for Industry, Rating, etc.

── reference fields only ──────────────────────────────────────
$ sf-rust data describe Contact -o dev1 --relationships
# → only fields of type 'reference' (AccountId → Account, OwnerId → User, etc.)

── raw JSON (pipe to jq) ──────────────────────────────────────
$ sf-rust data describe Account -o dev1 --json | jq '.fields[] | .name'
$ sf-rust data describe Account -o dev1 --json | jq '[.fields[] | select(.type == "reference")]'

sf-rust data record

Single-record CRUD without writing SOQL. Uses the REST Composite SObject endpoint (/services/data/vXX.0/sobjects/<Type>/<id>). All four operations support --json for scripting.

Subcommands

SubcommandHTTP methodDescription
record get <Type> <Id> GET Fetch a single record by Id. Renders as a key/value table or --json. Use --fields Name,Industry to include only specific fields.
record create <Type> --values '...' POST Create a new record. Returns the new Id on success.
record update <Type> <Id> --values '...' PATCH Update field values on an existing record. Returns 204 — only the changed fields need to be in --values.
record delete <Type> <Id> DELETE Delete a record. Prompts for confirmation unless --no-prompt is passed.

--values syntax

--values accepts two forms — a JSON object (most flexible) or space-separated Key=Value pairs (convenient for simple cases with no spaces in values): 

JSON object (recommended)$ sf-rust data record create Account -o dev1 \
    --values '{"Name":"Acme","Industry":"Technology"}'

$ sf-rust data record update Account 001xxx -o dev1 \
    --values '{"AnnualRevenue":5000000,"Rating":"Hot"}'
Key=Value pairs$ sf-rust data record create Account -o dev1 \
    --values "Name=Acme Industry=Technology"

$ sf-rust data record update Account 001xxx -o dev1 \
    --values "Rating=Hot"

Examples

── get ────────────────────────────────────────────────────────
$ sf-rust data record get Account 001Dn00000NpXr1 -o dev1
$ sf-rust data record get Account 001Dn00000NpXr1 -o dev1 --json
$ sf-rust data record get Account 001Dn00000NpXr1 -o dev1 --fields Name,Industry,AnnualRevenue

── create ─────────────────────────────────────────────────────
$ sf-rust data record create Account -o dev1 --values '{"Name":"Acme Corp","Industry":"Technology"}'
Created Account record: 001Dn00000NpXr9

$ sf-rust data record create Account -o dev1 --values '{"Name":"Acme"}' --json
{"id":"001Dn00000NpXr9","success":true,"errors":[]}

── update ─────────────────────────────────────────────────────
$ sf-rust data record update Account 001Dn00000NpXr9 -o dev1 --values '{"Industry":"Finance"}'
Updated Account 001Dn00000NpXr9

── delete ─────────────────────────────────────────────────────
$ sf-rust data record delete Account 001Dn00000NpXr9 -o dev1
Delete Account 001Dn00000NpXr9? This cannot be undone. [y/N]

$ sf-rust data record delete Account 001Dn00000NpXr9 -o dev1 --no-prompt
Deleted Account 001Dn00000NpXr9

── scripting pattern: create + capture Id ────────────────────
$ ID=$(sf-rust data record create Account -o dev1 \
    --values '{"Name":"Acme"}' --json | jq -r .id)
$ echo $ID
001Dn00000NpXr9

sf-rust data soql-explain

Calls the Salesforce SOQL explain plan endpoint (GET /query?explain=<soql>) and renders the query plans as a UTF8_FULL table. Catch full table scans and missing indexes before they hit production.

Flags

FlagDescription
-q, --query SOQLSOQL query to explain
-o, --target-org ALIASOrg alias or username
--jsonOutput the full raw explain plan JSON

Output columns

ColumnMeaning
Rel. CostRelative cost of this plan vs a full table scan at 1.0. Values below 1.0 indicate good index use. ≥ 1.0 triggers a warning.
Leading OpThe leading operation type: Index, TableScan, Other
SObjectThe object being scanned
CardinalityEstimated number of rows returned
Obj. RowsTotal rows in the object (for context)
FieldsFields used by this plan step
NotesHuman-readable hint from Salesforce (e.g. "Not Selective")

Examples

── explain plan for a simple query ───────────────────────────
$ sf-rust data soql-explain -q "SELECT Id, Name FROM Account WHERE Industry = 'Technology'" -o dev1

── subquery / join ────────────────────────────────────────────
$ sf-rust data soql-explain \
    -q "SELECT Id FROM Opportunity WHERE AccountId IN (SELECT Id FROM Account WHERE Industry = 'Finance')" \
    -o dev1

── raw JSON for scripting ─────────────────────────────────────
$ sf-rust data soql-explain -q "SELECT Id FROM Account" -o dev1 --json | jq .plans

── pipe to grep for high-cost plans ─────────────────────────
$ sf-rust data soql-explain -q "SELECT Id FROM Account WHERE Name LIKE '%Corp%'" -o dev1
# ⚠  Relative cost ≥ 1.0 — this plan may perform a full table scan.

◆

Leading with LIKE '%value%' always causes a table scan. Salesforce indexes do not support leading wildcards. If you need fuzzy name search, consider SOSL (FIND) or a custom index on a different field that filters first.

sf-rust data bulk

High-volume data operations via the Salesforce Bulk API v2. Processes millions of records asynchronously — Salesforce runs the job on its own infrastructure and you poll for results. The underlying REST endpoints are /services/data/vXX.0/jobs/ingest (DML) and /services/data/vXX.0/jobs/query (bulk SOQL).

◆

When to use Bulk API vs REST query. Use data query for ad-hoc SOQL (up to a few hundred thousand records). Use data bulk query when you need to export millions of records reliably — the Bulk API v2 query job is designed for large data sets and handles timeouts automatically.

Subcommands

SubcommandBulk API endpointDescription
bulk insert -f FILE -s Type POST /jobs/ingest Insert records from CSV into a Salesforce object
bulk update -f FILE -s Type POST /jobs/ingest Update existing records (Id column required in CSV)
bulk upsert -f FILE -s Type -e Field POST /jobs/ingest Insert or update based on an external ID field
bulk delete -f FILE -s Type POST /jobs/ingest Delete records by Id (Id column required in CSV)
bulk query -q SOQL POST /jobs/query Run a SOQL query as a Bulk API v2 job and stream results
bulk status JOB_ID GET /jobs/ingest/{id} Check the status of an ingest job
bulk results JOB_ID GET /jobs/ingest/{id}/{kind}Results Download successful / failed / unprocessed results as CSV

DML flags (insert / update / delete)

FlagDescription
-f, --file FILECSV file path (required)
-s, --sobject TYPESObject API name (required)
-o, --target-orgOrg alias or username
--wait SECSPolling interval in seconds (default: 5)
--no-waitSubmit job and return immediately with the job ID — no polling
-j, --jsonOutput final status as JSON

Upsert additional flag

FlagDescription
-e, --external-id FIELDExternal ID field name used to match records (required)

Query flags

FlagDescription
-q, --query SOQLSOQL query to run (required)
--output FILEWrite CSV results to file (default: stdout)
-j, --jsonParse CSV and output as JSON array
--wait SECSPolling interval in seconds (default: 5)

Results flags

FlagDescription
JOB_IDBulk API v2 ingest job ID (positional)
--kindsuccessful (default), failed, or unprocessed
--output FILEWrite CSV to file (default: stdout)

Insert examples

── insert from CSV ────────────────────────────────────────────
$ sf-rust data bulk insert -f accounts.csv -s Account -o dev1
# accounts.csv header: Name,Industry,AnnualRevenue,BillingCity

── insert with faster polling (1 second) ─────────────────────
$ sf-rust data bulk insert -f accounts.csv -s Account -o dev1 --wait 1

── insert and capture job ID for later (fire and forget) ─────
$ JOB=$(sf-rust data bulk insert -f big-file.csv -s Lead -o dev1 --no-wait --json | jq -r .jobId)
$ echo "Job submitted: $JOB"
# ... do other work ...
$ sf-rust data bulk status "$JOB" -o dev1

── insert and output JSON result (CI/scripting) ──────────────
$ sf-rust data bulk insert -f accounts.csv -s Account -o dev1 --json | jq .result
# → {"jobId":"...","state":"JobComplete","recordsProcessed":5000,...}

── insert with stricter error handling ────────────────────────
$ sf-rust data bulk insert -f accounts.csv -s Account -o dev1 --json
$ if [ $? -ne 0 ]; then echo "Bulk insert failed"; exit 1; fi

Update examples

── update records (Id column required) ───────────────────────
$ sf-rust data bulk update -f updates.csv -s Contact -o dev1
# updates.csv header: Id,Title,Department,Phone

── mass-update a field from query results ────────────────────
$ # Step 1: export current records
$ sf-rust data bulk query -q "SELECT Id, Industry FROM Account WHERE Industry = 'Technology'" \
    -o dev1 --output tech_accounts.csv

# Step 2: transform with awk / sed / Python, update Rating column
$ awk -F, 'NR==1{print $0",Rating"} NR>1{print $0",Hot"}' tech_accounts.csv > to_update.csv

# Step 3: push back
$ sf-rust data bulk update -f to_update.csv -s Account -o dev1

Upsert examples

── upsert by external ID ──────────────────────────────────────
$ sf-rust data bulk upsert -f accounts.csv -s Account -e ExternalId__c -o dev1
# accounts.csv header: ExternalId__c,Name,Industry
# records matching ExternalId__c are updated; new ones are inserted

── upsert contacts by email (custom external ID) ──────────────
$ sf-rust data bulk upsert -f contacts.csv -s Contact -e Email__c -o dev1

$ # export from ERP, then sync to Salesforce
$ erp_export.sh > /tmp/erp_accounts.csv
$ sf-rust data bulk upsert -f /tmp/erp_accounts.csv -s Account -e ErpId__c -o prod \

Delete examples

── delete a list of records ───────────────────────────────────
$ sf-rust data bulk delete -f ids.csv -s Account -o dev1
# ids.csv contains a single column: Id

── query IDs to delete, then delete ──────────────────────────
$ sf-rust data bulk query \
    -q "SELECT Id FROM Account WHERE CreatedDate = THIS_YEAR AND IsDeleted = false AND Name = 'Test'" \
    -o dev1 --output to_delete.csv
$ sf-rust data bulk delete -f to_delete.csv -s Account -o dev1

── safe delete: check count first ────────────────────────────
$ COUNT=$(sf-rust data query -q "SELECT COUNT() FROM Account WHERE Name LIKE 'Test%'" \
    -o dev1 --json | jq '.result.totalSize')
$ echo "About to delete $COUNT records"
$ read -p "Proceed? [y/N] " confirm
$ [[ "$confirm" == "y" ]] && sf-rust data bulk delete -f test_ids.csv -s Account -o dev1

$ sf-rust data bulk query \
    -q "SELECT Id, Name, BillingState, AnnualRevenue FROM Account WHERE BillingState = 'CA'" \
    -o dev1 --output ca_accounts.csv

$ echo "[$JOB] job submitted"
# ... later, in a separate step or cron job ...
$ STATE=$(sf-rust data bulk status "$JOB" -o prod --json | jq -r .state)
$ echo "[$JOB] state: $STATE"
$ if [ "$STATE" = "JobComplete" ]; then
    sf-rust data bulk results "$JOB" -o prod --kind failed --output "/logs/$JOB-failed.csv"
  fi

sf-rust data arrow-view

Read and display Apache Arrow IPC (.arrow) or Parquet (.parquet) files as a terminal table. Supports all output formats, schema inspection, row limits, datatable browser view, Excel export, and --grep post-filtering. No org connection required — works entirely offline on local files.

FlagDescription
FILEPath to .arrow or .parquet file (positional)
--schemaShow column names and types only (no data rows)
--limit NOutput only the first N rows
--jsonOutput as JSON array
--csvOutput as CSV
--ndjsonOutput as NDJSON
--markdownOutput as Markdown table
--datatableOpen interactive browser datatable
--xlsx [FILE]Write as Excel workbook
--sqlite [FILE]Write as SQLite database
--grep PATTERNPost-filter rows by regex
 
$ sf-rust data arrow-view accounts.parquet
$ sf-rust data arrow-view accounts.parquet --schema
$ sf-rust data arrow-view accounts.parquet --limit 20
$ sf-rust data arrow-view accounts.parquet --csv > accounts.csv
$ sf-rust data arrow-view accounts.parquet --xlsx accounts.xlsx
$ sf-rust data arrow-view accounts.parquet --datatable
$ sf-rust data arrow-view accounts.arrow --grep "Technology" --csv > tech_accounts.csv

sf-rust data rsql

Interactive SQL REPL over Salesforce data powered by rsqlite — a pure-Rust SQL engine. Fetches one or more Salesforce objects, loads them into an in-memory (or on-disk) SQLite database, then drops you into a readline prompt where you can run any SQL. No org connection is needed after the initial --load phase.

FlagDescription
--load OBJECTSalesforce object to pre-load (repeatable: --load Account --load Contact)
--limit NMax records per object (default: all)
--db FILEPersist the SQLite database to a file (default: in-memory)
-o, --target-orgOrg alias or username
 
── load one object ────────────────────────────────────────────
$ sf-rust data rsql -o dev1 --load Account

── load multiple objects ──────────────────────────────────────
$ sf-rust data rsql -o dev1 --load Account --load Contact --load Opportunity

── persist to a file (survive REPL exit) ─────────────────────
$ sf-rust data rsql -o dev1 --load Account --load Contact --db sf.db

── limit rows for quick exploration ─────────────────────────
$ sf-rust data rsql -o dev1 --load Account --limit 500

REPL commands

rsql> SELECT Industry, COUNT(*) FROM Account GROUP BY Industry ORDER BY 2 DESC; rsql> SELECT a.Name, c.FirstName, c.LastName FROM Account a JOIN Contact c ON c.AccountId = a.Id; rsql> .tables ← list loaded tables rsql> .schema ← show CREATE TABLE DDL for all loaded objects rsql> .quit ← exit the REPL
◆

REPL history is saved to ~/.sf-rust/rsql_history via rustyline. Arrow keys and Ctrl+R history search work as expected.

sf-rust data erd

Generates an ER diagram for one or more Salesforce objects, showing relationships between them. Outputs Mermaid (default) or Graphviz DOT. Opens in the browser as an interactive Mermaid diagram unless --stdout or -f FILE is specified.

FlagDescription
--objects A,B,CComma-separated list of SObject API names (required)
--dotOutput Graphviz DOT instead of Mermaid
--stdoutPrint to stdout instead of opening browser
-f, --file PATHWrite to a file instead of opening browser
--simpleShow only PK and FK fields (Id + lookup fields) — cleaner diagram
-o, --target-orgOrg alias or username
 
$ sf-rust data erd --objects Account,Contact,Opportunity -o dev1
$ sf-rust data erd --objects Account,Contact --simple -o dev1
$ sf-rust data erd --objects Account,Contact,Opportunity -o dev1 --dot > schema.dot
$ sf-rust data erd --objects Account,Contact -o dev1 --stdout | pbcopy
