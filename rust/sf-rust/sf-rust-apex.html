sf-rust apex

Execute, test, debug, and analyse Apex code — offline and live — from a single native binary. No Node.js, no npm, no JVM required.

Execute Anonymous Apex Async test run + report Debug log timeline Per-class coverage Native lint rules + PMD No Node.js

Command overview

All apex subcommands at a glance. Three commands added in v0.2.0: log-parse, coverage, and lint. New in v0.3.0: apex test run --watch (live streaming) and apex coverage --datatable (browser view).

apex execute Execute anonymous Apex code from file or stdin
apex test run Start an async Apex test run
apex test report Retrieve results for a test run ID
apex get-log List or download Apex debug logs
apex log-parse ✦ Parse a local .log file into a structured timeline
apex coverage ✦ Per-class coverage table from last test run
apex lint ✦ Native static analysis rules + optional PMD
apex list List all Apex classes in the org

✦ New in v0.2.0 — works offline (no org required).

apex execute

Execute Anonymous Apex against a live org via the SOAP /services/Soap/s/{version} endpoint. Reads Apex code from a file (-f) or from stdin. Prints compile errors, runtime exceptions, and stack traces on failure; exits 0 on success.

FlagShortDescription
--file <FILE>-fPath to .apex script file. If omitted, reads from stdin.
--target-org <ALIAS>-oOrg alias or username. Defaults to the configured default org.
--json-jOutput result as JSON (compiled, success, line, exceptionMessage, etc.).

Examples

# Execute a script file
sf-rust apex execute -f scripts/hello.apex -o dev1

# Execute and get JSON output for scripting
sf-rust apex execute -f scripts/hello.apex -o dev1 --json

# Pipe Apex code from stdin
echo "System.debug('hello world');" | sf-rust apex execute -o dev1

# Multi-line from shell heredoc
sf-rust apex execute -o dev1 <<'APEX'
List<Account> accs = [SELECT Id, Name FROM Account LIMIT 5];
System.debug('Found: ' + accs.size());
APEX

Success output

JSON output

{ "status": 0, "result": { "compiled": true, "compileProblem": null, "success": true, "line": -1, "column": -1, "exceptionMessage": null, "exceptionStackTrace": null } }

Compile error output

Tip: Use --json in CI pipelines to reliably detect failures. The exit code is 1 on runtime exception or compile error regardless of --json.

apex test run

Enqueue an async Apex test run. Returns a test run ID immediately. Use apex test report to poll for results, or pass --wait to block until completion (polling every 5 seconds).

FlagShortDescription
--class-names <NAMES>-nApex test class names. Repeatable or comma-separated: -n MyTest -n OtherTest or -n "MyTest,OtherTest".
--suite-names <NAMES>-sApexTestSuite names to run.
--test-level <LEVEL>RunLocalTests, RunAllTestsInOrg, or RunSpecifiedTests.
--target-org <ALIAS>-oOrg alias or username.
--json-jReturn test run ID as JSON.
--wait <SECONDS>Block and poll for up to N seconds; print results on completion.
--watchStream per-method ✓/✗ results as each test completes. Implies --wait 600 unless --wait is also set.
--output-dir <DIR>Directory to write test result files (reserved for future use).

Examples

# Run a single test class
sf-rust apex test run -n MyApexTest -o dev1

# Run multiple classes
sf-rust apex test run -n "AccountTriggerTest,ContactTriggerTest" -o dev1

# Run all local tests and wait up to 2 minutes
sf-rust apex test run --test-level RunLocalTests -o dev1 --wait 120

# Get test run ID as JSON (for CI)
sf-rust apex test run -n MyApexTest -o dev1 --json

# Stream live per-method results as they complete
sf-rust apex test run -n MyApexTest -o dev1 --watch

# Run all local tests with live streaming + 5-minute timeout
sf-rust apex test run --test-level RunLocalTests -o dev1 --watch --wait 300

apex test report

Retrieve and display results for a previously started test run by its ID. Shows passed/failed counts and details of any failing methods.

FlagShortDescription
--test-run-id <ID>-iThe test run ID returned by apex test run.
--target-org <ALIAS>-oOrg alias or username.
--json-jReturn full results as JSON.

Examples

# Check results for a test run
sf-rust apex test report -i 7076g000003GnxRAAS -o dev1

# Extract only failing tests with jq
sf-rust apex test report -i 7076g000003GnxRAAS -o dev1 --json \

apex get-log

List recent Apex debug logs or download the body of a specific log by ID. Uses the Tooling API (ApexLog SObject). Without -i, returns a JSON list of recent logs ordered by StartTime DESC. With -i, streams the raw log body to stdout — pipe to a file and then parse offline with apex log-parse.

FlagShortDescription
--log-id <ID>-iLog ID. If set, streams the raw log body. If omitted, lists recent logs.
--number <N>-nHow many logs to list (default: 10). Ignored when -i is set.
--target-org <ALIAS>-oOrg alias or username.
--json-jReturn log list as JSON. Ignored when streaming body.

Examples

# List the 10 most recent logs
sf-rust apex get-log -o dev1

# List the 25 most recent logs as JSON
sf-rust apex get-log -n 25 -o dev1 --json

# Download a specific log body to a file
sf-rust apex get-log -i 07L6g000006lLy2EAE -o dev1 > debug.log

# Download and immediately parse
sf-rust apex get-log -i 07L6g000006lLy2EAE -o dev1 > debug.log \
  && sf-rust apex log-parse debug.log

Log list output (JSON)

{ "status": 0, "result": { "records": [ { "Id": "07L6g000006lLy2EAE", "Application": "Unknown", "DurationMilliseconds": 312, "LogLength": 48291, "Operation": "Execute", "StartTime": "2026-11-13T17:52:04.000+0000", "Status": "Success" } ] } }

apex log-parse NEW in v0.2.0

Offline structured viewer for Salesforce Apex debug log files. Parses the raw HH:MM:SS.mmm (nanos)|EVENT_TYPE|... format into a human-readable summary + timeline table. No org connection required.

ℹ

Offline command. Download logs first with apex get-log -i <ID> -o dev1 > trace.log, then parse locally at any time. The log file never leaves your machine.

FlagShortDescription
<LOG_FILE>Path to the Apex debug log file (positional argument).
--datatableGenerate a self-contained dark HTML page and open it in the browser. Sortable, filterable, with event-type dropdown.
--filter <KEYWORD>Show only events whose type or details contain the keyword (case-insensitive).
--json-jOutput {"summary": {...}, "events": [...]} as JSON for scripting.

Events parsed

The parser extracts and pairs begin/end events to compute durations:

Event pairDetails extracted
EXECUTION_STARTED / FINISHEDTotal execution time baseline
METHOD_ENTRY / METHOD_EXITClass.method name, duration (ms)
SOQL_EXECUTE_BEGIN / ENDSOQL query text, row count, duration
DML_BEGIN / DML_ENDOp (Insert/Update/Delete), SObject type, row count, duration
USER_DEBUGLog level (DEBUG/INFO/WARN), message text
EXCEPTION_THROWNException type and message
HEAP_ALLOCATEBytes allocated (cumulative)

Examples

# Download then parse
sf-rust apex get-log -i 07L6g000006lLy2EAE -o dev1 > my.log
sf-rust apex log-parse my.log

# Show only SOQL events
sf-rust apex log-parse my.log --filter SOQL

# Show only events related to a specific class
sf-rust apex log-parse my.log --filter AccountService

# Open interactive browser datatable
sf-rust apex log-parse my.log --datatable

# Full JSON output
sf-rust apex log-parse my.log --json

# Extract just the summary
sf-rust apex log-parse my.log --json | jq '.summary'

# All SOQL statements with their durations
sf-rust apex log-parse my.log --json \
  | jq '[.events[] | select(.event == "SOQL_EXECUTE_BEGIN")]'

# Find the slowest method call
sf-rust apex log-parse my.log --json \
  | jq '[.events[] | select(.event == "METHOD_EXIT" and .duration_ms != null)]
    | sort_by(.duration_ms) | reverse | .[0]'

apex coverage NEW in v0.2.0

Retrieve per-class Apex code coverage from the Tooling API (ApexCodeCoverageAggregate) after a test run. Shows a coverage bar, percentage, and 75% pass/fail marker for every class and trigger.

⚠

75% rule: Salesforce requires at least 75% aggregate coverage to deploy to production. Classes below this threshold are marked ✗. Use --below 75 to show only failing classes.

FlagShortDescription
--target-org <ALIAS>-oOrg alias or username. Required (live org connection needed).
--below <PCT>Show only classes with coverage strictly below this percentage. E.g., --below 75.
--sort-ascSort by ascending coverage (lowest first). Default: true.
--json-jOutput results as JSON array with name, covered, uncovered, total, pct fields.
--datatableGenerate a self-contained dark HTML page and open it in the browser. Features search, All / ≥75% / <75% filter chips, and sortable columns.

Examples

# Show all class coverage, sorted ascending
sf-rust apex coverage -o dev1

# Show only classes below 75% (deployment blockers)
sf-rust apex coverage -o dev1 --below 75

# Show all classes with less than 100% coverage
sf-rust apex coverage -o dev1 --below 100

# JSON output for CI reporting
sf-rust apex coverage -o dev1 --json

# Extract classes below 75% via jq
sf-rust apex coverage -o dev1 --json \
  | jq '[.result[] | select((.pct | tonumber) < 75)]'

# Open interactive browser datatable
sf-rust apex coverage -o dev1 --datatable

# Show only failing classes in browser datatable
sf-rust apex coverage -o dev1 --below 75 --datatable

apex lint NEW in v0.2.0

Static analysis for Apex .cls and .trigger files. Runs fully offline — no org, no JVM, no PMD installation required by default. Seven built-in rules cover the most critical Apex anti-patterns. Optionally delegates to an installed PMD binary (--pmd) for the full Salesforce rule set.

ℹ

Offline command. apex lint reads .cls files from your local filesystem. No org connection needed. Accepts individual files, glob patterns, or directories (recursive).

FlagShortDescription
<PATHS>...One or more .cls files or directories to lint. Directories are scanned recursively for *.cls files.
--pmdDelegate to the installed PMD binary on your PATH. Runs category/apex/bestpractices.xml, errorprone.xml, and security.xml.
--json-jReturn findings as JSON: {"findings": [{file, line, rule, severity, message}]}.
--failExit with code 1 if any findings are found. Use in CI pre-flight gates.

Built-in rules

RuleSeverityWhat it catches
ApexSQLInjection Critical Database.query( or Database.queryWithBinds( — possible SOQL injection via string concatenation
EmptyCatchBlock High catch (Exception e) { } — swallows exceptions silently, hides bugs
MissingSharingDeclaration High public class Foo without with sharing or without sharing — defaults to inherited sharing, may expose records
HardcodedId High 15/18-character Salesforce ID literals — will break in sandboxes and orgs; use SOQL or custom metadata
SystemDebugInProduction Medium System.debug( calls left in production code — wastes governor limit and leaks info to debug logs
CRUDViolation Medium DML (insert, update, delete, upsert, merge) without isCreateable()/isUpdateable() CRUD checks
NoNullCheck Low list.size() > 0 — prefer !list.isEmpty() which short-circuits without counting

Examples

# Lint a single class file
sf-rust apex lint MyClass.cls

# Lint an entire classes directory recursively
sf-rust apex lint force-app/main/default/classes/

# Lint and exit non-zero if anything found (CI gate)
sf-rust apex lint force-app/main/default/classes/ --fail

# JSON output for processing or dashboards
sf-rust apex lint MyClass.cls --json

# Delegate to PMD if installed
sf-rust apex lint MyClass.cls --pmd

# Group findings by rule with jq
sf-rust apex lint force-app/ --json \
  | jq '.findings | group_by(.rule)
    | map({rule: .[0].rule, severity: .[0].severity, count: length})
    | sort_by(.count) | reverse'

# Show only Critical and High findings
sf-rust apex lint force-app/ --json \
  | jq '[.findings[] | select(.severity == "Critical" or .severity == "High")]'

Sample output

┌───────────────────────────────────────┬──────┬──────────┬───────────────────────────┬──────────────────────────────────────────────────────────────────┐ │ File │ Line │ Severity │ Rule │ Message │ ├───────────────────────────────────────┼──────┼──────────┼───────────────────────────┼──────────────────────────────────────────────────────────────────┤ │ …/classes/AccountService.cls │ 3 │ Critical │ ApexSQLInjection │ Possible SOQL injection — prefer static queries or bind variables │ │ …/classes/AccountService.cls │ 8 │ High │ EmptyCatchBlock │ Empty catch block swallows exceptions silently │ │ …/classes/AccountService.cls │ 1 │ High │ MissingSharingDeclaration │ Class missing 'with sharing' or 'without sharing' declaration │ │ …/classes/LeadConversionHandler.cls │ 11 │ Medium │ SystemDebugInProduction │ System.debug() left in production code — consider removing │ └───────────────────────────────────────┴──────┴──────────┴───────────────────────────┴──────────────────────────────────────────────────────────────────┘ 4 finding(s) total
💡

PMD integration: If you have PMD installed (Java-based, full Salesforce rule set), pass --pmd to delegate entirely. sf-rust will locate the pmd binary on your PATH and pass it the category rule sets. Install PMD from pmd.github.io. Without --pmd, only the 7 built-in rules run — zero install required.

⚠

CI usage: Add --fail to your pre-commit or CI step so that any Critical/High finding blocks the pipeline. Combined with --json, downstream tools can parse and annotate PRs with per-finding comments.

apex list

List all Apex classes in the org ordered by name. Queries SELECT Id, Name, Status, ApiVersion, LastModifiedDate FROM ApexClass via the REST API and renders a UTF8_FULL table.

FlagShortDescription
--target-org <ALIAS>-oOrg alias or username.
--json-jReturn full record array as JSON.

Examples

# List all Apex classes as a table
sf-rust apex list -o dev1

# Get list as JSON
sf-rust apex list -o dev1 --json

# Count active classes
sf-rust apex list -o dev1 --json \
  | jq '[.result.records[] | select(.Status == "Active")] | length'
