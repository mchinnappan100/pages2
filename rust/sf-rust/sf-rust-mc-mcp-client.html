Quick Start

# Test sfr's own MCP server — no Claude Desktop needed mc-mcp-client tools --named af200 mc-mcp-client repl --named af200 # Inside the REPL — bare tool name, no 'call' prefix needed mcp> query_soql soql="SELECT Id, Name FROM Account LIMIT 2" mcp> org_list mcp> org_display org=af200 mcp> schema_describe sobject=Account org=af200 # One-shot call from the command line mc-mcp-client call --named af200 --tool query_soql \ --arg soql='SELECT Id, Name FROM Account LIMIT 5' # Same via sfr passthrough sfr mcp client tools --named af200 sfr mcp client repl --named af200 # List configured named servers mc-mcp-client servers

sfr mcp client is a thin passthrough — same pattern as sfr webconf → mc-webconf.

Subcommands

tools

Connect, handshake, call tools/list. Prints a table of all tools with parameter names (* = required).

call

Call one tool and print its output. Pass arguments as --arg key=value (repeatable). Values auto-parsed as JSON or string.

repl

Interactive session. Commands: tools, call <name> k=v…, help, quit. History saved to ~/.sf-rust/mcp_client_history.

servers

List named servers from ~/.sf-rust/mcp-servers.toml. Shows alias, command, args, and env var keys.

Salesforce Official MCP Server

Salesforce publishes @salesforce/mcp — an MCP server that wraps the sf CLI and exposes 20+ tools across DX, Apex, metadata, agents, LWC, Aura, and DevOps. It uses the same org auth as the sf CLI (~/.sf/credentials.json). Note: the package is deprecated upstream (see issue #46) but remains fully functional.

PostgreSQL MCP — query any local database

The @modelcontextprotocol/server-postgres server exposes a single query tool that accepts any SQL statement against the configured database. Add one entry per database in mcp-servers.toml.

MCP Protocol (stdio)

# What mc-mcp-client does on connect: Client → Server: initialize { protocolVersion, clientInfo } Server → Client: { serverInfo, capabilities } Client → Server: notifications/initialized Client → Server: tools/list {} Server → Client: { tools: [ { name, description, inputSchema } ] } # On call: Client → Server: tools/call { name, arguments } Server → Client: { content: [ { type: "text", text: "..." } ], isError: false }

Implementation

transport.rs

Async JSON-RPC 2.0 over stdio. Spawns child process, matches responses by ID via oneshot channels. 30 s timeout per request.

client.rs

McpClient::connect() — handshake + tools/list. call_tool(name, args) returns CallToolResult.

config.rs

Loads ~/.sf-rust/mcp-servers.toml. Shell-splits --server strings. Applies per-server env vars before spawning.

commands.rs

Four commands: tools, call, repl, servers. REPL uses rustyline with persistent history.

No new crate dependencies — uses existing workspace deps: tokio, serde_json, clap, comfy-table, rustyline, colored, toml, dirs.
