⚡ sfr org compare

Compare Salesforce metadata between two orgs — with a Monaco diff viewer, package.xml filtering, and on-demand content fetching via the Tooling API.

Monaco diff viewer

Click any component to open a semantic diff (Modified) or read-only viewer (Source/Target only) powered by Monaco Editor.

package.xml filtering

Pass -x package.xml to compare only the types and members listed — wildcard * means all members of that type.

On-demand content

Content is fetched live from each org via the Tooling API when you click a row — nothing is downloaded upfront.

Keyboard navigation

↑/↓ arrow keys move through the filtered list. KPI chips and status buttons narrow the view instantly.

Download per side

⬇ buttons in the toolbar let you save the source or target content of any selected component.

Existing modes

--datatable, --json, --missing, and --types still work as before.

Basic usage

# Compare default types (ApexClass, ApexTrigger, Flow, CustomObject, LWC, Aura) sfr org compare --source dev --target uat # Open Monaco diff viewer — interactive browser UI sfr org compare --source dev --target uat --view # Compare a single type with viewer sfr org compare --source dev --target uat --types ApexClass --view # Filter by package.xml, open viewer sfr org compare --source dev --target uat -x package.xml --view # Show only components missing from target (source-only) sfr org compare --source dev --target uat --missing # JSON output for scripting sfr org compare --source dev --target uat --json # Datatable — sortable browser table sfr org compare --source dev --target uat --datatable # Custom viewer port sfr org compare --source dev --target uat --view --view-port 8900

Monaco diff viewer

When --view is passed, sfr starts a local HTTP server (default port 7801) and opens the Monaco viewer in your browser. The server stays alive until you press Ctrl-C.

Filtering with package.xml

Pass -x package.xml to restrict the comparison to only the types and members listed in the file. Use * to include all members of a type.

<?xml version="1.0" encoding="UTF-8"?> <Package xmlns="http://soap.sforce.com/2006/04/metadata"> <types> <members>*</members> <name>ApexClass</name> </types> <types> <members>MyFlow</members> <members>AnotherFlow</members> <name>Flow</name> </types> <types> <members>*</members> <name>LightningComponentBundle</name> </types> <version>62.0</version> </Package>
sfr org compare --source dev --target uat -x package.xml --view → Compares ApexClass (all), Flow (MyFlow + AnotherFlow only), LWC (all)

Supported content types

When you click a component row, the viewer fetches its content from the Tooling API or REST API on demand:

Metadata TypeAPI UsedField / MethodMonaco Language
ApexClassTooling APISELECT Body FROM ApexClassJava (Apex)
ApexTriggerTooling APISELECT Body FROM ApexTriggerJava (Apex)
ApexPageTooling APISELECT Markup FROM ApexPageHTML
ApexComponentTooling APISELECT Markup FROM ApexComponentHTML
LightningComponentBundleTooling APIBundle ID → all LightningComponentResource sourcesJavaScript
AuraDefinitionBundleTooling APIBundle ID → all AuraDefinition sources by DefTypeJavaScript
FlowTooling APISELECT MasterLabel,Status,ProcessType FROM FlowDefinitionJSON (metadata only)
CustomObjectREST API/sobjects/{name}/describe — full field metadataJSON
All others—Fallback message with sfr metadata retrieve tipPlain text
Inaccessible—🔒 "Content not available" panel — shown when the Tooling/REST API returns NOT_FOUND (e.g. managed/system objects with restricted metadata)—
Note on Flow: The viewer shows FlowDefinition metadata (name, status, type) rather than the full XML. For full Flow XML, use sfr metadata retrieve -m Flow -o <alias>.
🔒 Content not available: Some standard or managed objects (e.g. AiEvalPrmptRagTestCsRslt) are not exposed via the Tooling or REST API. When this happens the viewer shows a friendly panel with a sfr metadata retrieve suggestion instead of a raw error. The diff/list view is unaffected — you can still see they're Modified, Src Only, etc.
