sfr validation-rule queries the ValidationRule Tooling API object. Validation rules are defined per sObject and enforce data quality constraints. During bulk data migrations it is common to disable validation rules temporarily, load the data, then re-enable them — sfr validation-rule enable/disable automates this.

Tip: Use --active / --inactive together with --json to capture a list of rules before a migration, so you can re-enable exactly what was active.

📋 sfr validation-rule list

List all validation rules across all sObjects, or filter by object, name, or active/inactive status.

Usage

🔍 sfr validation-rule get

Show full details of a single validation rule, including the error condition formula.

Usage

sfr validation-rule get "Require_Phone_for_Hot" --sobject Account -o dev1 sfr validation-rule get "Require_Phone_for_Hot" -o dev1 --json sfr validation-rule get "Require_Phone_for_Hot" -o dev1 --datatable
Fields shown: Id, Name, Object, Active, Description, ErrorMessage, DisplayField, ErrorConditionFormula

✅ sfr validation-rule enable

Enable (activate) a validation rule by API name and sObject. Uses a Tooling API PATCH to set Metadata.active = true.

Usage

sfr validation-rule enable "Require_Phone_for_Hot" --sobject Account -o dev1 sfr validation-rule enable "No_Delete_With_Opps" --sobject Account -o dev1 --json
$ sfr validation-rule enable "Require_Phone_for_Hot" --sobject Account -o dev1 --no-time Validation rule 'Require_Phone_for_Hot' on 'Account' is now ENABLED ✓.

🚫 sfr validation-rule disable

Disable (deactivate) a validation rule. Uses a Tooling API PATCH to set Metadata.active = false.

Usage

sfr validation-rule disable "Require_Phone_for_Hot" --sobject Account -o dev1 sfr validation-rule disable "No_Delete_With_Opps" --sobject Account -o dev1 --json
$ sfr validation-rule disable "Require_Phone_for_Hot" --sobject Account -o dev1 --no-time Validation rule 'Require_Phone_for_Hot' on 'Account' is now DISABLED ✗.

🔄 Bulk Migration Workflow

  1. Capture active rules — save which Account rules are currently active:
    sfr validation-rule list -o prod --sobject Account --active --json > account_rules.json
  2. Disable each rule — disable before the data load:
    sfr validation-rule disable "Require_Phone_for_Hot" --sobject Account -o prod
  3. Run data load — import records (Bulk API, Data Loader, etc.)
  4. Re-enable rules — restore each rule that was active:
    sfr validation-rule enable "Require_Phone_for_Hot" --sobject Account -o prod
  5. Verify — confirm all rules are back on:
    sfr validation-rule list -o prod --sobject Account --active
Caution: Disabling validation rules in production carries risk. Always capture the active rule list before disabling and re-enable immediately after the data load completes.
