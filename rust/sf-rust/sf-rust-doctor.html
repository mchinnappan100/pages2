sf-rust doctor — Installation Diagnostics

One command to verify your entire sf-rust installation: binary freshness, credentials, org connectivity, man pages, and shell completions.

build freshness org token check credentials man pages completions --datatable --json

Overview

sf-rust doctor runs a suite of local and network checks and prints a pass/fail table. No subcommands — just run it. It is safe to run at any time; it makes no changes to your org or credentials.

sf-rust doctor
sf-rust doctor --json
sf-rust doctor --datatable

Doctor is the first command to run when something feels off — expired tokens, missing completions, or a stale binary after editing source code.

The Checks

Doctor runs 10+ checks in sequence. Local checks require no network; network checks hit each org's REST endpoint with its stored Bearer token.

Check Type What it verifies
Config file Local ~/.sf-rust/config.toml exists
Key file Local ~/.sf-rust/.key exists (AES-256-GCM encryption key, chmod 600)
Credentials file Local ~/.sf-rust/credentials.json exists (encrypted token store)
Man pages Local ~/.local/share/man/man1/sf-rust.1 exists
Binary Local ~/.local/bin/sf-rust exists and is accessible
Completions (zsh) Local ~/.zfunc/_sf-rust exists
Completions (bash) Local ~/.bash_completion.d/sf-rust exists
Build freshness Local No .rs source files newer than the installed binary (see Build Freshness)
Default org Config A default org is set in config.toml
Org token: <alias> Network Bearer token returns HTTP 200 from /services/data/ (one row per org)

Build Freshness

The build freshness check is the most useful check for active developers. It compares the modification time of the installed binary against every .rs source file under ~/sf-rust/crates/. If any source file is newer, the check fails and lists the offending files.

When the binary is current

✓ PASS Build freshness │ binary is up to date

After editing source (before make install)

✗ FAIL Build freshness │ 2 file(s) newer than binary — run `make install` │ crates/sf-api/src/rest.rs │ crates/sf-report/src/commands.rs
💡 Override the source directory with SF_RUST_SRC=/path/to/crates if your project lives somewhere other than ~/sf-rust. See SF_RUST_SRC below.

The check uses std::env::current_exe() to find the running binary, so it works correctly even if the binary was renamed or symlinked.

Org Connectivity

For every org in ~/.sf-rust/config.toml, doctor fires a live GET /services/data/ request with the stored Bearer token. This catches expired sessions before you waste time running data query or metadata deploy against a dead token.

Valid token

✓ PASS Org token: dev1 │ HTTP 200

Expired token

✗ FAIL Org token: dev1 │ HTTP 401 — token may be expired
ℹ If a token is expired, re-authenticate with sf-rust org login web -o <alias>. The new token is persisted automatically and subsequent commands will use it.

Doctor checks every org listed in your config — not just the default. This is useful when you have multiple sandboxes and want to validate all of them in one shot.

Browser datatable (--datatable)

Writes a self-contained HTML file to /tmp/sf-rust-doctor-<ts>.html and opens it. Supports full-text search, column sort, and row filtering — handy when reviewing a large multi-org installation.

SF_RUST_SRC — Custom Source Directory

By default, the build freshness check scans ~/sf-rust/crates/. If your repository lives somewhere else, set SF_RUST_SRC to the absolute path of the crates/ directory:

# Repository cloned to /workspace/sf-rust
export SF_RUST_SRC=/workspace/sf-rust/crates
sf-rust doctor

# Or inline for a one-off check
SF_RUST_SRC=/workspace/sf-rust/crates sf-rust doctor
⚠ If the crates/ directory cannot be found, the Build freshness check reports FAIL with a clear message rather than silently skipping. This prevents false positives from a misconfigured path.

The variable affects only the freshness check — all other doctor checks are independent of it.

Examples

# Quick install health check
sf-rust doctor

# Machine-readable output for CI scripts — only print failures
sf-rust doctor --json | jq '.result[] | select(.pass == false)'

# Interactive browser table — great for sharing a snapshot
sf-rust doctor --datatable

# Check with a custom source directory
SF_RUST_SRC=/workspace/sf-rust/crates sf-rust doctor

# Validate all orgs before a deployment session
sf-rust doctor && sf-rust metadata deploy -d force-app -o dev1
💡 Pipe --json output into jq '.result[] | select(.pass == false)' to get a clean failure list in CI — exit code is 0 even with FAIL checks, so the jq filter is the right gate.
