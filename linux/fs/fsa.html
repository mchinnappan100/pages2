01 / The families

Five file systems to know

Different designs solve different storage problems.

LEGACY

ext3

The dependable classic

Third Extended Filesystem brought journaling to the ext family and remains relevant when maintaining older Linux installations.

  • Metadata journaling
  • Mature recovery tools
  • Simple, familiar design
GENERAL PURPOSE

ext4

The practical everyday choice

A mature evolution of ext3, designed for strong general-purpose performance, scalability and dependable administration.

  • Extents and delayed allocation
  • Journal checksumming
  • Broad tooling and support
ADVANCED FEATURES

Btrfs

Flexible, snapshot-oriented storage

A modern copy-on-write filesystem with integrated volume-management capabilities and tools for managing data over time.

  • Snapshots and subvolumes
  • Data and metadata checksums
  • Compression and send/receive
LARGE WORKLOADS

XFS

High-throughput, scalable storage

A mature journaling filesystem known for parallel I/O and handling large filesystems and demanding workloads.

  • Allocation groups
  • Strong parallelism
  • Online growth
FLASH STORAGE

F2FS

Designed with flash in mind

A log-structured filesystem designed around the characteristics of NAND flash devices such as eMMC, SD cards and SSDs.

  • Flash-aware layout
  • Segment-based allocation
  • Background garbage collection
💡
One important distinction: journaling is not the same as a backup.

A journal helps recover filesystem consistency after a crash. It does not protect you from accidental deletion, malware, device failure or every form of data corruption. Keep independent backups.

03 / Under the hood

Five concepts that explain the differences

The vocabulary behind filesystem design.

📓

Journaling

Records intended metadata changes so the filesystem can replay or discard incomplete operations after an unexpected shutdown.

🧬

Copy-on-write

Writes changed blocks to new locations instead of overwriting the old data in place. This enables efficient snapshots.

🛡️

Checksums

Stores fingerprints of data or metadata so later reads or scrubs can detect certain forms of corruption.

📸

Snapshots

Captures a point-in-time view of a filesystem or subvolume. Useful for rollback—but not a substitute for off-device backups.

🧱

Extents

Represent runs of contiguous blocks as ranges, reducing metadata overhead compared with tracking every block separately.

⚡

Flash-aware layout

F2FS organizes writes and cleaning around NAND flash behavior and the translation layer inside flash devices.

05 / Practical selection

Which one should you choose?

Start with workload, operational needs and distribution support.

Everyday Linux desktopext4 — a dependable default with broad support.
Snapshots and rollbackBtrfs — when you want integrated snapshots and checksums.
Large server workloadsXFS — a strong candidate for scalable, parallel I/O.
Flash-focused systemsF2FS — evaluate for NAND-based devices and real workloads.

Useful inspection commands

07 / See it in code

Inspect filesystem attributes with C and Rust

Query the filesystem mounted at a path: type identifier, block size and capacity.

🔎
What these examples inspect

They call Linux statfs(2) to read filesystem information for a path such as / or /home. The values describe the filesystem containing that path—not an individual file.

C · Linux statfs()
filesystem type + capacity
#define _DEFAULT_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <sys/vfs.h>

static const char *fs_name(long type) {
    switch (type) {
        case 0xEF53:     return "ext family (ext2/3/4)";
        case 0x9123683E: return "Btrfs";
        case 0x58465342: return "XFS";
        case 0xF2F52010: return "F2FS";
        default:         return "unknown / other";
    }
}

int main(int argc, char **argv) {
    const char *path = argc > 1 ? argv[1] : "/";
    struct statfs s;

    if (statfs(path, &s) != 0) {
        perror("statfs");
        return EXIT_FAILURE;
    }

    unsigned long long total =
        (unsigned long long)s.f_blocks * s.f_bsize;
    unsigned long long free_bytes =
        (unsigned long long)s.f_bfree * s.f_bsize;
    unsigned long long avail =
        (unsigned long long)s.f_bavail * s.f_bsize;

    printf("Path:       %s\n", path);
    printf("Filesystem: %s\n", fs_name(s.f_type));
    printf("Magic:      0x%lx\n", (unsigned long)s.f_type);
    printf("Block size: %ld bytes\n", (long)s.f_bsize);
    printf("Total:      %llu MiB\n", total / (1024 * 1024));
    printf("Free:       %llu MiB\n", free_bytes / (1024 * 1024));
    printf("Available:  %llu MiB\n", avail / (1024 * 1024));
    return EXIT_SUCCESS;
}
Build: gcc -Wall -Wextra fsinfo.c -o fsinfo
Run: ./fsinfo /home
Rust · libc statfs()
same Linux kernel interface
// Cargo.toml: libc = "0.2"
use std::{env, ffi::CString, os::unix::ffi::OsStrExt};

fn fs_name(magic: i64) -> &'static str {
    match magic as u64 {
        0xEF53     => "ext family (ext2/3/4)",
        0x9123683E => "Btrfs",
        0x58465342 => "XFS",
        0xF2F52010 => "F2FS",
        _          => "unknown / other",
    }
}

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let path = env::args().nth(1).unwrap_or("/".into());
    let c_path = CString::new(path.as_bytes())?;
    let mut info: libc::statfs = unsafe { std::mem::zeroed() };

    let rc = unsafe { libc::statfs(c_path.as_ptr(), &mut info) };
    if rc != 0 {
        return Err(std::io::Error::last_os_error().into());
    }

    let block = info.f_bsize as u64;
    let total = info.f_blocks as u64 * block;
    let free = info.f_bfree as u64 * block;
    let available = info.f_bavail as u64 * block;

    println!("Path:       {path}");
    println!("Filesystem: {}", fs_name(info.f_type as i64));
    println!("Magic:      0x{:x}", info.f_type as u64);
    println!("Block size: {block} bytes");
    println!("Total:      {} MiB", total / 1_048_576);
    println!("Free:       {} MiB", free / 1_048_576);
    println!("Available:  {} MiB", available / 1_048_576);
    Ok(())
}
Run: cargo add libc, then cargo run -- /home
⚠️
A useful limitation to teach

The magic value 0xEF53 is shared by the ext2/ext3/ext4 family. statfs() alone cannot tell those three apart. For the mounted filesystem's reported type, compare with findmnt -no FSTYPE --target /path or inspect /proc/self/mountinfo. Filesystem magic values are Linux-specific identifiers, not portable cross-platform IDs.
