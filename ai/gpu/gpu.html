The GPU Story

From Pixels to Intelligence — how a gaming chip became the engine of modern AI.

02 / 15

What Is a GPU?

A Graphics Processing Unit is a specialized processor designed to perform many calculations simultaneously.

Where a CPU has a few powerful cores optimized for sequential tasks, a GPU has thousands of smaller cores optimized for doing the same operation on many data points at once.

Processor Cores Strength
CPU 8–64 high-power cores Sequential logic, complex branching
GPU 3,000–18,000+ small cores Massively parallel computation

The key insight: most real-world computations — rendering pixels, training neural networks, running physics simulations — are embarrassingly parallel. The same operation applied to thousands of independent values at once.

03 / 15

GPU Architecture Fundamentals

A modern GPU is organized as a hierarchy of parallel compute units.

GPU Die
 └── Streaming Multiprocessors (SM) — dozens to hundreds
       └── Warps — groups of 32 threads executing in lockstep
             └── Cores (CUDA / shader units)
                   └── Registers · Shared memory · L1 cache

Global VRAM (HBM / GDDR) — high bandwidth memory
  ↕  bandwidth up to 3,500 GB/s (H100 SXM)

Key GPU memory concepts:

  • VRAM — fast on-chip memory (24–80 GB on modern data-centre GPUs)
  • Shared memory — ultra-fast scratchpad within each SM; latency ~5 cycles
  • Memory bandwidth — the dominant performance bottleneck for most workloads
  • Tensor Cores — dedicated hardware units for matrix multiply-accumulate (introduced in Volta, 2017)

The Gaming Revolution — 1990s to 2000s

Before dedicated GPUs, every pixel was computed by the CPU — one at a time.

The problem: a 1920×1080 frame at 60 fps = 124 million pixels per second, each requiring lighting, shading, texture lookups and depth testing.

The solution — the GPU pipeline:

  1. Vertex processing — transform 3D coordinates to 2D screen space
  2. Rasterisation — determine which pixels a triangle covers
  3. Fragment / pixel shading — compute colour, lighting and texture for each pixel
  4. Output merger — depth test, blend, write to frame buffer

NVIDIA's GeForce 256 (1999) was the world's first GPU. It offloaded geometry transformation and lighting from the CPU, enabling complex 3D scenes at playable frame rates for the first time.

Gaming Pushes GPU Engineering Forward

Demand from the games industry drove extraordinary GPU hardware progress over two decades.

Year Milestone Impact
1999 NVIDIA GeForce 256 Hardware T&L — first true GPU
2001 Shader Model 1.0 Programmable vertex & pixel shaders
2006 NVIDIA GeForce 8800 Unified shader architecture (CUDA era begins)
2010 Fermi architecture ECC memory, true caches — GPU becomes compute platform
2016 Pascal — GTX 1080 FP16 half-precision, NVLink
2018 Turing — RTX 2080 RT Cores (ray tracing) + Tensor Cores (AI)
2022 Ada Lovelace — RTX 4090 76 billion transistors, 4th-gen Tensor Cores

Every console generation and every AAA title pushed manufacturers to ship faster, more programmable, more power-efficient silicon — directly funding the hardware that now trains AI models.

06 / 15

GPGPU — General Purpose Computing on GPUs

By 2007, researchers realised the GPU's parallel muscle could do far more than render pixels.

NVIDIA CUDA (2007) — Compute Unified Device Architecture — gave programmers a C-like interface to run arbitrary code on GPU cores, not just graphics shaders.

CPU (host) → copies data to VRAM
CPU        → launches kernel (grid of thread blocks)
GPU        → executes kernel: thousands of threads in parallel
GPU        → writes results back to VRAM
CPU        → copies results to main memory

Early GPGPU successes:

  • Fluid simulation and physics (2008)
  • Molecular dynamics (folding proteins 100× faster)
  • Financial derivatives pricing (Monte Carlo)
  • Seismic imaging for oil exploration
  • Video encoding (H.264 / H.265)

The GPU was no longer just a display adapter. It was a massively parallel supercomputer attached to every gaming PC.

07 / 15

The Deep Learning Breakthrough — 2012

ImageNet 2012 — AlexNet changes everything.

Alex Krizhevsky trained a convolutional neural network on two NVIDIA GTX 580 GPUs and achieved a top-5 error rate of 15.3% — 10 percentage points lower than the next-best entry.

The key was not just the network architecture. It was training it on GPUs instead of CPUs — reducing training time from weeks to days.

Why GPUs are perfect for deep learning:

Neural network operation Why GPU excels
Matrix multiplication Thousands of multiplications in parallel — exactly what GPU cores do
Convolution Sliding-window dot products — data-parallel across spatial positions
Batch processing Same forward pass on 256+ images simultaneously
Backpropagation Gradient computation mirrors the forward pass — same parallelism
08 / 15

The GPU Becomes an AI Accelerator

NVIDIA recognised the deep learning opportunity and redesigned the GPU from the ground up for AI workloads.

Key architectural innovations:

Generation Year AI Feature
Pascal (P100) 2016 FP16 half-precision — 2× throughput at half the memory
Volta (V100) 2017 Tensor Cores — 4×4 matrix multiply in one clock cycle
Ampere (A100) 2020 3rd-gen Tensor Cores, TF32, BF16, sparsity acceleration
Hopper (H100) 2022 4th-gen Tensor Cores, Transformer Engine, FP8, NVLink 4.0
Blackwell (B200) 2024 5th-gen Tensor Cores, 20 PetaFLOPS FP4, 192 GB HBM3e

Tensor Cores perform D = A × B + C on 4×4 matrices per clock — the fundamental operation of every neural network layer. A single H100 delivers 3,958 TFLOPS at FP8 precision.

Training Large Language Models

LLMs are trained by running gradient descent over trillions of tokens and billions of parameters.

The numbers that make GPUs essential:

Model Parameters Training compute
GPT-2 (2019) 1.5 B ~100 GPU-days
GPT-3 (2020) 175 B ~355 GPU-years (3.14×10²³ FLOPs)
LLaMA 3.1 405B (2024) 405 B ~30M GPU-hours on H100
GPT-4 (est.) ~1–1.8 T Months on tens of thousands of H100s

GPU cluster architecture for LLM training:

Node (8× H100 SXM)
  ↕ NVLink (900 GB/s GPU-to-GPU)

  ↕ InfiniBand HDR (400 Gb/s)
Pod (1,024 GPUs)
  ↕ Spine switches
Supercluster (tens of thousands of GPUs)

Parallelism Strategies for LLM Training

Training a 405B-parameter model on a single GPU is impossible — it requires distributing work across thousands of devices.

Strategy What is split Use case
Data parallelism Each GPU trains on a different batch; gradients are averaged Most common baseline
Tensor parallelism Individual weight matrices split across GPUs Large layers that exceed one GPU's VRAM
Pipeline parallelism Layers split across GPUs; microbatches flow through the pipeline Very deep models
Expert parallelism (MoE) Different experts (sub-networks) on different GPUs Mixture-of-experts models
Context parallelism Long sequences split across GPUs 128K+ context windows

Modern LLM training combines all five strategies simultaneously — called 3D parallelism or 5D parallelism — coordinated by frameworks like Megatron-LM, DeepSpeed and PyTorch FSDP.

11 / 15

Inference — GPUs at Runtime

Training is a one-time cost. Inference happens billions of times per day.

LLM inference characteristics:

  • Memory-bound — not compute-bound; loading weights from VRAM to cores dominates latency
  • Autoregressive decoding — one token generated per forward pass; each pass reads all weights
  • KV cache — attention keys and values cached across tokens; grows with sequence length

Inference optimisation techniques:

Technique Benefit
Quantisation (INT8, INT4, FP4) Smaller weights → more fits in VRAM, faster loads
Continuous batching Interleave requests in flight → maximise GPU utilisation
Flash Attention Recomputes attention tiles; reduces HBM traffic by 10–20×
Speculative decoding Small draft model proposes tokens; large model verifies in parallel
Paged attention (vLLM) Manage KV cache like virtual memory; eliminate fragmentation

The GPU Ecosystem for AI

The GPU is not just hardware — it anchors a complete software and infrastructure stack.

Applications
  LLMs · Image generation · Video · Speech · Robotics

Frameworks
  PyTorch · JAX · TensorFlow

Compiler & runtime
  CUDA · ROCm · XLA · Triton · cuDNN · cuBLAS · NCCL

Hardware
  NVIDIA H100 / B200 · AMD MI300X · Google TPU v5 · Intel Gaudi

CUDA's moat: NVIDIA's CUDA ecosystem, built up since 2007, includes tens of thousands of optimised kernels, profilers, debuggers and libraries. It is one of the most significant software competitive advantages in technology.

The Future of GPU Computing

The trajectory is clear: more parallelism, more specialisation, more memory bandwidth.

Near-term directions:

  • Blackwell Ultra / Rubin (2025–2026) — NVLink 5.0, HBM4, FP4 native training
  • NVL72 rack-scale GPU — 72 B200 GPUs sharing a unified memory space via NVLink Switch
  • In-memory computing — processing-in-memory (PIM) to close the memory bandwidth wall
  • Optical interconnects — co-packaged optics to replace copper at scale

Longer-term questions:

  • Can GPU-like parallelism be delivered at dramatically lower power?
  • Will photonic or neuromorphic chips displace silicon for inference?
  • How do we program heterogeneous systems — GPU + NPU + LPU + TPU — as one?

The GPU story is not over. Each generation doubles what seemed impossible the generation before.

15 / 15

Conclusion

The GPU began as a single-purpose chip for rendering game worlds.

It became a general-purpose parallel computer. Then the platform for the deep learning revolution. Then the infrastructure for training trillion-parameter models. Now the foundation of every frontier in artificial intelligence.

The pattern:

Hardware designed for one demanding domain — gaming — turned out to be the perfect substrate for the next demanding domain — intelligence.

The transistor budget, the memory bandwidth, the programming model, the software ecosystem: all built for games, all repurposed for AI.

Build the parallel compute. The applications will follow.
