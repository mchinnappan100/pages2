Fixing npm ENOVERSIONS

When min-release-age prevents installation of newly published npm packages.

Problem

Attempting to install a recently published package fails with (note: this is valid for any package you want to install): 

npm install -g sf-perms-lens

npm ERR! code ENOVERSIONS
npm ERR! No versions available for sf-perms-lens

However, querying the package succeeds: 

npm view sf-perms-lens

The package clearly exists, making the error confusing.

Root Cause

The local npm configuration contained: 

~/.npmrc

prefix=~/.npm-global
min-release-age=7

The package had been published only 2 days earlier.

The min-release-age setting instructs npm to ignore package versions newer than the specified number of days.

Why ENOVERSIONS?

If every published version is newer than the configured minimum age, npm filters out every version and behaves as though the package has no published versions.

Diagnosis Steps

1. Verify package exists 

npm view sf-perms-lens

2. Inspect npm configuration 

cat ~/.npmrc

npm config list

3. Check min-release-age 

npm config get min-release-age

Solution

Remove the restriction 

npm config delete min-release-age

npm install -g sf-perms-lens

✓ Installation succeeds immediately.

Alternative Solutions

Option Command
Temporarily disable npm install --min-release-age=0 ...
Reduce waiting period npm config set min-release-age 1
Delete setting completely npm config delete min-release-age

Why use min-release-age?

The setting is intended to reduce software supply-chain risk by preventing automatic installation of packages that have only recently been published. This provides time for the community to identify malicious or compromised packages before they are widely adopted.

While valuable for production environments, it can surprise package authors who need to install and test their own newly published releases immediately.

Summary

  • If npm view works but npm install reports ENOVERSIONS, inspect your npm configuration.
  • A configured min-release-age may hide all available versions.
  • Deleting or lowering the value immediately restores package visibility.
  • This issue commonly affects authors testing packages immediately after publishing.
