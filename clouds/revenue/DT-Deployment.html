Revenue Cloud Advanced (RCA) Deployment Guide: Deploying Decision Tables and Dependent Metadata

Overview

When deploying Revenue Cloud Advanced (RCA) metadata, Decision Tables have dependencies that require a specific deployment sequence. Deploying metadata in the wrong order can result in validation or deployment failures, especially for metadata such as Expression Set Definitions that reference Decision Tables.

This article describes the recommended deployment approach to ensure a successful deployment.

Deployment Sequence

Step 1: Deploy the Decision Table

Before deploying the Decision Table, ensure that it is inactive.

Source Metadata

Update the Decision Table metadata file (for example):

Location_Pricing.decisionTable-meta.xml

Set the status to:

<status>InActive</status>

Target Org

Before deployment, verify that the corresponding Decision Table in the target org is also Inactive.

This is an important prerequisite because deploying an active Decision Table can lead to deployment conflicts or dependency issues.

Deployment

Deploy the Decision Table directly.

Do not perform a Validation + Quick Deploy for this step.

After the deployment completes successfully:

  1. Open the Decision Table in the target org.
  2. Activate the Decision Table.

At this point, the Decision Table is available for dependent metadata.

Step 2: Deploy Dependent Metadata

Once the Decision Table has been successfully deployed and activated, deploy the remaining dependent metadata.

Typical dependent metadata includes:

  • ExpressionSetDefinitionVersion
  • ExpressionSetDefinition

For these metadata types, the standard deployment process can be used:

  • Validate Deployment
  • Quick Deploy

Since the Decision Table already exists and is active, these metadata components can be deployed without dependency issues.

Recommended Deployment Order

Order Metadata Deployment Method
1 Decision Table (Location_Pricing) Direct Deployment (No Validation)
2 Activate Decision Table Manual Activation
3 ExpressionSetDefinitionVersion Validation + Quick Deploy
4 ExpressionSetDefinition Validation + Quick Deploy

Why This Sequence Is Required

Expression Sets reference Decision Tables during deployment. If the referenced Decision Table:

  • does not exist,
  • is not deployed, or
  • is not in the expected state,

the deployment may fail because the dependency cannot be resolved.

Deploying the Decision Table first establishes the required metadata dependency, allowing subsequent deployments to succeed.

Best Practices

  • Always deploy Decision Tables before Expression Sets.
  • Keep the Decision Table Inactive during deployment.
  • Deploy the Decision Table directly rather than using Validation + Quick Deploy.
  • Activate the Decision Table immediately after deployment.
  • Deploy dependent metadata only after the Decision Table has been activated.
  • Follow the dependency order consistently across all RCA environments (Development, QA, UAT, and Production).
