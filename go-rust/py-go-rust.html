Section 01

Introduction

01

Whenever I give a talk, someone eventually asks me the familiar question: "What is your favorite programming language?"

My answer is always the same: there is no single language that is perfect for every job. I love Python for its elegance, accessibility, and expressive power. I admire Go for its simplicity, its networking capabilities, and the engineering philosophy of its creators. And then there is Rust.

Rust is a different experience. Its ownership rules, borrowing system, lifetimes, and compiler diagnostics can make even experienced programmers stop and think. Yet I have begun to wonder whether some of Rust's greatest frustrations for human programmers could become some of its greatest advantages in the age of AI coding agents.

What if the strictness that frustrates human programmers is precisely what makes a programming language especially useful for AI coding agents?
🐍

Python

The language of expression, teaching, and AI workflows. Elegant and accessible, with a vibrant ecosystem for data science and rapid prototyping.

Approachable syntax, gentle learning curve
Dominant in data science and ML
Dynamic; many errors appear only at runtime
CPython runtime implemented in C
🦫

Go

The language of practical services and infrastructure. Designed with simplicity, concurrency, and engineering discipline by Ken Thompson and the Go team.

Statically typed with compiler checks
Garbage-collected; simple memory model
Strong for APIs, microservices, networking
Fast compile times and simple tooling
🦀

Rust

The language of explicit guarantees. Ownership and borrowing rules checked at compile time — no garbage collector required.

Compile-time memory and type safety
No mandatory GC pauses
Steep learning curve for humans
Potentially ideal for AI-driven development
Section 02

The Strict Mother: Rust's Compiler

02

I like to think of the Rust compiler as a very strict mother. You cannot easily escape her rules. You cannot simply promise that a memory reference will be valid, or that a value will remain alive long enough. The compiler demands evidence in the form of code that satisfies its rules.

For human programmers, this discipline can feel exhausting. But now consider a different programmer: an AI coding agent.

An AI coding agent does not experience compiler strictness the way a human does. It can read diagnostics, modify code, compile again, and repeat. Its job is to produce working software — not to avoid frustration.

Central Hypothesis: Rust's strict compiler may turn software generation into a more disciplined feedback loop, helping AI coding agents produce safer and more reliable code. The compiler becomes an always-available, machine-checkable source of feedback. The strict mother never gets tired.
🔒

Ownership & Borrowing

Rust's ownership rules prevent dangling references, use-after-free, and data races — at compile time, before the program ever runs.

Each value has exactly one owner
Borrows are checked at compile time
No null pointers in safe Rust
Memory freed automatically when owner drops
// This is rejected by the compiler: let s = String::from("hello"); let r1 = &mut s; let r2 = &mut s; // ERROR: cannot borrow `s` // as mutable more than once println!("{}, {}", r1, r2);
The error is caught before execution — an AI agent gets this as structured feedback to fix.
📋

Structured Diagnostics

Rust's compiler produces some of the clearest, most actionable error messages of any systems language — machine-readable and rich with context.

Error codes (E0502, E0505, …) for each rule violation
Inline source annotations pointing to the problem
Suggested fixes often included in the diagnostic
JSON output format available for tooling
error[E0502]: cannot borrow `s` as mutable because it is also borrowed as immutable --> src/main.rs:5:14 | 4 | let r1 = &s; | -- immutable borrow occurs here 5 | let r2 = &mut s; | ^^^^^^ mutable borrow occurs here
An AI agent can parse this precisely and generate a targeted repair without guessing.
⚡

Zero-Cost Abstractions

Rust's safety guarantees come with no mandatory runtime overhead — the strict rules are enforced entirely at compile time.

No garbage collector pause at runtime
Abstractions compile down to optimal machine code
Predictable latency for real-time systems
Competitive with C and C++ in benchmarks
Section 03

Why AI Agents Change the Equation

03

Traditional programming languages were designed around human developers. Readability, simplicity, and the speed of writing code all matter when a person is doing the work.

AI coding agents change some of these trade-offs. A coding agent can generate code, run a compiler, inspect errors, modify its implementation, run tests, and repeat. In the right environment this loop can be fully automated.

🚀 Validate
🔄

Approach A: Generate and Hope

An agent writes code that looks plausible. The program compiles, but a bug may remain hidden until a particular input or production condition exposes it.

Errors surface only at runtime
No structured signal to guide repair
Relies entirely on tests to catch defects
Typical of dynamically typed languages
🎯

Approach B: Generate, Check, Repair

An agent writes code, receives compiler feedback, repairs rejected implementations, then runs tests and other checks. Rust makes this loop especially productive.

Compiler catches memory and type errors before runtime
Structured diagnostics guide precise repairs
Constrained solution space reduces wrong turns
Machine-readable feedback at every iteration
🤖

The Agent Workflow

A typical AI coding agent loop with compiler-assisted feedback in seven steps.

1. Developer gives the agent a task
2. Agent generates an implementation
3. Compiler checks the implementation
4. Agent receives diagnostics
5. Agent repairs the code
6. Tests and checks evaluate the result
7. Repeat until criteria are met
Section 04

Three Languages, Three Strengths

04

I do not believe that Rust should replace Python or Go. The three languages solve different problems well, and their strengths complement one another.

🐍

Python: The Language of Expression

Python is an exceptionally productive language for teaching, prototyping, automation, data science, and AI development. Its syntax is approachable and expressive.

Gentle learning curve — express ideas quickly
CPython runtime written in C under the hood
Dynamic typing is powerful but errors emerge at runtime
Optional type checkers (mypy, pyright) add safety
✅ Teaching and learning programming ✅ Data science and machine learning ✅ Rapid prototyping and scripting ✅ Orchestrating AI workflows ✅ API clients and automation
Python remains an excellent language for expressing ideas and working with AI.
🦫

Go: The Language of Practical Services

Go was designed with simplicity, concurrency, and practical software engineering in mind. Its garbage collector simplifies memory management while goroutines power high-throughput services.

Static typing and compiler checks catch many errors
Garbage-collected — simpler mental model
Goroutines and channels for concurrency
Modern GC is highly optimized — not a simple stop-the-world
✅ Networking and microservices ✅ REST and gRPC APIs ✅ Infrastructure tooling (Docker, K8s) ✅ CLI applications ✅ Services where simplicity matters
Go is an excellent choice when operational simplicity and productivity matter.
🦀

Rust: The Language of Explicit Guarantees

Rust's ownership system and borrowing rules are checked at compile time, allowing safe Rust code to avoid common memory-management errors without a garbage collector.

Memory safety without a GC
Thread safety enforced at compile time
AI agents may delegate compiler-satisfaction to the machine
Predictable latency — no GC pauses
✅ Systems programming and embedded ✅ Performance-sensitive components ✅ Safety-critical libraries ✅ WebAssembly targets ✅ AI-agent generated code where safety matters
Rust deserves serious consideration for performance-sensitive and safety-critical components.

Section 05

The Hypothesis & How to Test It

05

My central argument is not that Rust is universally superior. It is that the arrival of capable AI coding agents may change the practical cost of programming-language strictness.

For a human developer, every compiler error can mean another interruption, another investigation, and another round of changes. For an AI coding agent, a compiler error becomes structured feedback for the next iteration.

Research Question: Do AI coding agents produce more reliable software in Rust than in Go when given equivalent programming tasks and comparable development conditions? Does Rust's compiler feedback help agents identify and repair defects more effectively, or does the additional complexity outweigh the benefits?

Three Potential Advantages

1 Earlier Defect Detection

Certain memory-safety and type errors can be rejected before execution, reducing the defects that reach tests or production.

2 A More Constrained Solution Space

The compiler prevents safe Rust programs from violating important language-enforced invariants, reducing the range of broken implementations the agent can produce.

3 A Machine-Readable Correction Loop

Compiler diagnostics give the agent concrete, structured evidence about which constraints its implementation has failed to satisfy.

Limits of Compiler Strictness

✓ Use Compiler Checks

Type-system and borrow checker constraints eliminate entire categories of defects before execution.

✓ Add Automated Tests

Compilation does not prove correctness — business logic errors, edge cases, and algorithmic bugs still require tests.

✓ Include Static Analysis

Security vulnerabilities, logic errors, and misuse of unsafe code still require tooling beyond the compiler.

✓ Maintain Runtime Observability

Resource exhaustion, incorrect assumptions, and flawed external dependencies require production monitoring.
