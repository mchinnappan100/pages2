npm install failed · EPROTO

Fix the npm EPROTO TLS error

On a corporate Windows laptop, this error can indicate a proxy mismatch, HTTPS inspection, or a network device interrupting the TLS connection. Diagnose the connection before changing npm settings.

Understand the failure

What could be going wrong?

The TLS client expected encrypted HTTPS records but received data that did not match the expected TLS framing.

⇄

Proxy protocol mismatch

npm may be configured to speak TLS to a proxy endpoint that expects plain HTTP, or vice versa.

First thing to check
◈

TLS / SSL inspection

A corporate gateway may inspect HTTPS traffic. Its certificate chain or proxy behavior may need IT configuration.

Check with IT
⌁

VPN / firewall / network

A VPN, firewall, or security appliance may block, redirect, or interfere with outbound HTTPS connections.

Step-by-step

Diagnose before you change anything

Run these commands in PowerShell. Copy each command with one click.

1

Inspect npm's current settings

Check registry, proxy endpoints, and certificate verification.

PowerShell 
npm config get registry
npm config get proxy
npm config get https-proxy
npm config get strict-ssl
2

Inspect proxy environment variables

Look for conflicting uppercase/lowercase proxy variables or unexpected values.

PowerShell 
Get-ChildItem Env: | Where-Object {
    $_.Name -match 'PROXY'
}
3

Test HTTPS outside npm

This helps determine whether the issue is npm-specific or affects the network connection generally.

PowerShell 
curl.exe -Iv https://registry.npmjs.org/
4

Test npm registry connectivity

After reviewing the configuration, run npm's lightweight registry check.

PowerShell 
npm ping

Resolution paths

Apply the fix that matches your network

●If your company requires a proxy

Get the approved proxy URL and port from IT. For many corporate HTTP proxy deployments, the proxy URL itself begins with http://, even when npm is fetching an HTTPS website.

Example only — replace with IT's values 
npm config set proxy http://proxy.company.example:8080
npm config set https-proxy http://proxy.company.example:8080

Do not paste a real proxy password into a shared terminal, ticket, screenshot, or chat.

●If no explicit proxy is required

If IT confirms that direct internet access is expected, remove stale npm proxy entries and test again.

PowerShell 
npm config delete proxy
npm config delete https-proxy
npm ping

Only remove these settings if direct access is permitted on your corporate network.

!

Do not disable TLS verification as a workaround

Avoid setting strict-ssl=false. It disables certificate verification and makes package downloads less secure. If corporate TLS inspection is used, ask IT for the approved CA certificate and configure npm to trust it using the supported cafile setting.

Escalate with useful evidence

What to send your IT / network team

If the tests fail, provide the diagnostic results and ask these focused questions.

  • ✓ Is outbound HTTPS to registry.npmjs.org permitted?
  • ✓ Is an explicit HTTP proxy required?
  • ✓ Does the network perform TLS / SSL inspection?
  • ✓ Is there an approved corporate CA certificate for Node.js/npm?
  • ✓ Are registry.npmjs.org and required package endpoints allow-listed?
  • ✓ Is there an internal npm registry or artifact mirror we should use?
