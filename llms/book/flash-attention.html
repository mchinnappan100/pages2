Background

The Attention Bottleneck

Self-attention is the core operation of every Transformer. For a sequence of length N, standard attention computes an N × N matrix — making it quadratic in both time (O(N²)) and memory (O(N²)). At N = 4096, that's 16 million entries. At N = 128k (long-context models), it's over 16 billion.

But the deeper problem is memory bandwidth, not just compute. GPUs have fast Tensor Cores for matrix math, but reading/writing that huge attention matrix through the relatively slow HBM (GPU DRAM) creates a massive I/O bottleneck — the computation waits for data, not the other way around.

GPU Memory Hierarchy

Root cause: Standard attention writes the full N×N attention matrix to HBM, then reads it back for softmax, then again for the output multiply. For long sequences this causes dozens of slow HBM round-trips — and the Tensor Cores sit idle waiting for data.

Standard Attention — How It Works

Standard scaled dot-product attention computes:
Attention(Q, K, V) = softmax(QKᵀ / √d) · V

Standard Attention — HBM Round Trips

Memory: O(N²)

N=4096 → 16M floats (64 MB in FP32). N=32k → 4 GB. The N×N matrix alone exhausts GPU memory for long contexts.

Compute: O(N²d) but IO-bound

The math is fast on Tensor Cores but the bottleneck is reading/writing that N×N matrix back and forth through HBM multiple times per layer.

⚡ FlashAttention 1 Dao et al., 2022 · Stanford

FlashAttention's key insight: never materialise the full N×N attention matrix in HBM. Instead, tile the computation into blocks that fit in the fast on-chip SRAM, compute exact (not approximate) attention entirely within SRAM, and only write the final output back to HBM once.

Core Idea: Tiling

Split Q, K, V into blocks. Load one block of K and V into SRAM at a time. Compute the partial attention scores and accumulate into the output — all within SRAM.

Core Idea: Recomputation

During the backward pass, instead of storing the N×N attention matrix from the forward pass, FlashAttention recomputes it on-the-fly from Q, K stored in HBM — trading compute for memory.

FlashAttention 1 — Tiled Computation

Online Softmax trick: Softmax normally requires two passes — one to find the max for numerical stability, one to compute the exponentials. FlashAttention uses the log-sum-exp trick to compute softmax incrementally as new K/V blocks arrive, needing only one pass through the data.

Memory: O(N)

Linear in sequence length — no N×N matrix. Enables 8–32× longer contexts in the same GPU memory.

2–4× Faster

Wall-clock speedup on A100 over standard PyTorch attention. Arithmetic intensity jumps from memory-bound to near compute-bound.

Exact, Not Approximate

Produces bit-for-bit identical results to standard attention — unlike linear/sparse approximations. No quality trade-off.

🚀 FlashAttention 2 Dao, 2023

FlashAttention 2 keeps the same IO-aware tiling approach but rewrites the algorithm with three targeted improvements to close the remaining gap to peak GPU throughput.

FA2 — Three Key Improvements over FA1

New Features in FA2

  • Multi-Query Attention (MQA) support
  • Grouped-Query Attention (GQA) support
  • Causal masking without padding overhead
  • Sliding window / local attention masks
  • Varlen — different seq lengths in one batch

Impact

  • 2× faster than FA1 on A100 (FP16)
  • ~72% of A100 theoretical peak FLOPs
  • Adopted by: LLaMA 3, Mistral, Falcon, Gemma, GPT-NeoX…
  • Default in PyTorch 2.0 SDPA
  • Enables 100k+ context length in practice

🔬 FlashAttention 3 Shah et al., 2024 — Targeting Hopper (H100/H200)

FA3 is a ground-up rewrite for NVIDIA's Hopper architecture (H100/H200), exploiting hardware features that didn't exist on Ampere (A100) and that FA2 couldn't use. The goal: push attention to ~75% of H100's theoretical peak FLOPs for FP16/BF16 and unlock FP8 at ~1.2 PFLOPS.

FlashAttention 3 — New Techniques on Hopper

WGMMA — Warpgroup Matrix Multiply

Hopper introduces a new instruction where 4 warps (128 threads) cooperate as a single unit to execute a large matrix multiply. FA3 rewrites all GEMMs to use WGMMA, achieving much larger tile sizes and higher register reuse than the per-warp mma.sync instructions FA2 used.

TMA — Tensor Memory Accelerator

TMA is a dedicated hardware DMA engine that copies tensor tiles from HBM to SRAM asynchronously, completely freeing the SMs from load/store instructions. FA3 uses TMA to overlap data movement with compute — tiles arrive in SRAM just in time for the GEMM that needs them.

FP8 + Incoherent Processing

FP8 doubles throughput on H100 but attention scores are very sensitive to quantisation errors. FA3 applies random Hadamard transforms to Q and K before quantising — spreading quantisation error incoherently so it averages out rather than accumulating. Combined with stochastic rounding on the accumulator, this preserves output quality at FP8 precision.

2-Stage Ping-Pong Pipelining

FA3 splits the thread block into two warpgroups that take turns: while group A runs the QK GEMM for the current tile, group B runs softmax + output GEMM for the previous tile. The non-matmul softmax cost is almost entirely hidden behind the next tile's matmul, reaching near-peak Tensor Core utilisation.

Why FA2 couldn't just use these features: WGMMA, TMA, and the asynchronous pipeline they enable are Hopper-only hardware features. FA2 was designed for Ampere (A100). Using them requires a fundamentally different thread/warpgroup organisation — FA3 is a new kernel, not a patch on FA2.

Impact on Modern LLMs

Long Context

FlashAttention is the primary reason 100k–1M token contexts are feasible. Without it, the N×N matrix would require hundreds of GB of HBM for long documents.

Training Speed

FA2/FA3 reduce attention's wall-clock contribution by 4–8×. For a 70B model trained on a 32k context, attention was previously a major bottleneck. Now it is largely amortised.

Inference Cost

Faster prefill (lower TTFT) and lower memory use per request means more requests can run in a batch simultaneously — directly reducing cost per token served.

Adoption

FA2 is the default in PyTorch 2.0 SDPA, vLLM, HuggingFace Transformers, xformers, LLaMA 3, Mistral, Gemma, DeepSeek, and almost every production LLM stack.
