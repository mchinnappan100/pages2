Section 1

IEEE 754 Floating Point Representation

Every floating-point number is encoded as a sign bit, a biased exponent, and a fractional mantissa. The three formats used in deep learning — FP32, FP16, and BF16 — trade range against precision in very different ways. BF16 keeps the same 8-bit exponent as FP32 (same dynamic range) but drops mantissa bits, while FP16 halves the exponent field instead.

Bit Layout: FP32 / FP16 / BF16

The decoded value of a normal FP32 number and its machine epsilon:

$$\text{value} = (-1)^s \cdot 2^{e-\text{bias}} \cdot \left(1 + \frac{m}{2^{23}}\right)$$
$$\epsilon_{\text{mach}} = 2^{-23} \approx 1.2 \times 10^{-7} \quad \text{(FP32)}$$ 
import torch

for dtype in [torch.float32, torch.float16, torch.bfloat16]:
    info = torch.finfo(dtype)
    print(f"{str(dtype):<20}  eps={info.eps:.2e}  max={info.max:.2e}  min={info.tiny:.2e}")

# float32              eps=1.19e-07  max=3.40e+38  min=1.18e-38
# float16              eps=9.77e-04  max=6.55e+04  min=6.10e-05
# bfloat16             eps=7.81e-03  max=3.39e+38  min=1.18e-38
Section 2

Catastrophic Cancellation

When two nearly-equal numbers are subtracted, most significant digits cancel and the result is dominated by rounding noise. A classic example is naive variance: computing $\mathbb{E}[X^2] - (\mathbb{E}[X])^2$ in a single pass over large numbers can yield negative variance or gross errors. Welford's online algorithm avoids this by accumulating a stable mean and sum-of-squared-deviations simultaneously.

Relative error of a subtraction $\text{fl}(a - b)$ when $a \approx b$:

$$\frac{|(a - b) - \text{fl}(a-b)|}{|a - b|} \leq \frac{2\,\epsilon_{\text{mach}} \cdot |a|}{|a - b|}$$

If $|a - b| \ll |a|$, the relative error blows up by a factor of $|a|/|a-b|$. 

import torch

# Naive variance — catastrophic cancellation with large offset
x = torch.tensor([1e8 + 1.0, 1e8 + 2.0, 1e8 + 3.0], dtype=torch.float32)
naive_var = x.pow(2).mean() - x.mean().pow(2)
print(f"Naive variance:   {naive_var.item():.4f}")   # may be 0.0 or negative!
print(f"Correct variance: {x.var(unbiased=False).item():.4f}")  # 0.6667

# Welford's online algorithm (stable)
def welford_var(data):
    n, mean, M2 = 0, 0.0, 0.0
    for x in data:
        n += 1; delta = x - mean
        mean += delta / n; M2 += delta * (x - mean)
    return M2 / n

vals = [1e8 + 1.0, 1e8 + 2.0, 1e8 + 3.0]
print(f"Welford variance: {welford_var(vals):.4f}")  # 0.6667
Section 3

Condition Numbers

The condition number of a matrix $\mathbf{A}$ measures how much a small perturbation in $\mathbf{b}$ amplifies the error in the solution $\mathbf{x}$ of $\mathbf{A}\mathbf{x}=\mathbf{b}$. In training, weight matrices with high condition numbers cause gradient directions to differ wildly across dimensions, leading to slow convergence and vanishing or exploding gradients.

$$\kappa(\mathbf{A}) = \|\mathbf{A}\| \cdot \|\mathbf{A}^{-1}\| = \frac{\sigma_{\max}}{\sigma_{\min}}$$
$$\frac{\|\delta\mathbf{x}\|}{\|\mathbf{x}\|} \leq \kappa(\mathbf{A})\,\frac{\|\delta\mathbf{b}\|}{\|\mathbf{b}\|}$$ 
import torch

# Well-conditioned matrix
A_good = torch.eye(4) + 0.1 * torch.randn(4, 4)
print(f"Condition (good): {torch.linalg.cond(A_good).item():.2f}")

# Ill-conditioned matrix — near-singular
A_bad = torch.tensor([[1e4, 1e4 - 1], [1e4 + 1, 1e4]], dtype=torch.float32)
print(f"Condition (bad):  {torch.linalg.cond(A_bad).item():.2e}")

b = torch.ones(2)
x = torch.linalg.solve(A_bad, b)
# Small change in b
b_perturbed = b + 1e-3 * torch.randn(2)
x_p = torch.linalg.solve(A_bad, b_perturbed)
print(f"Relative change in b: {((b_perturbed-b).norm()/b.norm()).item():.2e}")
print(f"Relative change in x: {((x_p-x).norm()/x.norm()).item():.2e}")
Section 4

Numerically Stable Softmax

Naive softmax computes $e^{z_i}/\sum_j e^{z_j}$, which overflows to inf for logits above ~88 in FP32. Subtracting the row maximum before exponentiation costs nothing mathematically (the constant cancels) but keeps all exponentials in $[0, 1]$. The log-softmax variant is further stabilised by avoiding a separate log of a potentially tiny sum.

$$\text{softmax}(\mathbf{z})_i = \frac{e^{z_i - m}}{\sum_j e^{z_j - m}}, \quad m = \max_j z_j$$
$$\log\text{softmax}(\mathbf{z})_i = z_i - m - \log\!\sum_j e^{z_j - m}$$ 
import torch

z = torch.tensor([1000.0, 1001.0, 999.0])

# Naive softmax — overflows
exp_z = torch.exp(z)
print("Naive exp:", exp_z)            # [inf, inf, inf]
naive_sm = exp_z / exp_z.sum()
print("Naive softmax:", naive_sm)     # [nan, nan, nan]

# Stable softmax
m = z.max()
exp_z_stable = torch.exp(z - m)
stable_sm = exp_z_stable / exp_z_stable.sum()
print("Stable softmax:", stable_sm)   # [0.2689, 0.7311, 0.0900]

# PyTorch built-in (uses stable version internally)
print("torch.softmax:", torch.softmax(z, dim=0))
Section 5

Numerically Stable LayerNorm

LayerNorm divides by the standard deviation, so a near-zero variance causes division by zero. The $\epsilon$ term in the denominator prevents this. For variance computation a single-pass naive method suffers cancellation for large inputs; Welford's two-pass or online algorithm computes the mean first, then accumulates squared deviations, achieving full numerical stability.

Single-pass vs Two-pass Variance Computation

$$\hat{x}_i = \frac{x_i - \mu}{\sqrt{\sigma^2 + \epsilon}}, \quad \mu = \frac{1}{d}\sum_i x_i, \quad \sigma^2 = \frac{1}{d}\sum_i (x_i - \mu)^2$$ 
import torch, torch.nn as nn

def stable_layernorm(x, eps=1e-5):
    mu = x.mean(dim=-1, keepdim=True)
    var = ((x - mu) ** 2).mean(dim=-1, keepdim=True)  # two-pass
    return (x - mu) / (var + eps).sqrt()

x = torch.randn(4, 128) * 1e4  # large values to stress test
out_custom = stable_layernorm(x)
out_torch  = nn.functional.layer_norm(x, [128])
print("Max diff:", (out_custom - out_torch).abs().max().item())  # ~0.0

Flash Attention Numerical Stability

FlashAttention processes the N×N attention matrix in tiles that never leave SRAM. To apply softmax correctly without seeing all scores at once, it maintains a running maximum $m_i$ and normalisation constant $\ell_i$ per query row and updates them incrementally as each key-value block arrives — yielding bit-exact results without materialising the full matrix.

Online softmax update when merging a new block:

$$m_{\text{new}} = \max(m,\, m_{\text{block}}), \quad \ell_{\text{new}} = e^{m - m_{\text{new}}}\,\ell + e^{m_{\text{block}} - m_{\text{new}}}\,\ell_{\text{block}}$$

The output accumulator is rescaled by $e^{m - m_{\text{new}}}$ before adding the new block's contribution — this is exact regardless of how many blocks are processed. 

import torch, math

def online_softmax_2block(scores_b1, scores_b2):
    """Merge two blocks with online softmax (no full materialisation)."""
    m1 = scores_b1.max();  exp1 = torch.exp(scores_b1 - m1);  l1 = exp1.sum()
    m2 = scores_b2.max();  exp2 = torch.exp(scores_b2 - m2);  l2 = exp2.sum()

    m_new = torch.maximum(m1, m2)
    l_new = torch.exp(m1 - m_new) * l1 + torch.exp(m2 - m_new) * l2
    scores = torch.cat([scores_b1, scores_b2])
    return torch.exp(scores - m_new) / l_new   # final softmax

s1 = torch.tensor([1.0, 2.0, 0.5])
s2 = torch.tensor([3.0, 1.5, 2.5])
print("Online:", online_softmax_2block(s1, s2).round(decimals=4))
print("Ref:   ", torch.softmax(torch.cat([s1, s2]), 0).round(decimals=4))

Quantization Mathematics

Uniform quantization maps a floating-point tensor to a $b$-bit integer grid using a scale $s$ and zero-point $z$. The maximum quantization error per element is $s/2$, so minimising $s$ (tightening the range) reduces error but risks clipping large values. INT8 is standard for inference; INT4 requires more careful calibration and block-wise scaling.

$$s = \frac{x_{\max} - x_{\min}}{2^b - 1}, \quad z = -\operatorname{round}\!\left(\frac{x_{\min}}{s}\right), \quad x_q = \operatorname{round}\!\left(\frac{x}{s}\right) + z$$
$$\text{Quantization error} \leq \frac{s}{2} = \frac{x_{\max} - x_{\min}}{2(2^b - 1)}$$ 
import torch

def fake_quantize(w, bits=8):
    qmin, qmax = 0, 2**bits - 1
    s = (w.max() - w.min()) / (qmax - qmin)
    z = (-w.min() / s).round().clamp(qmin, qmax)
    w_q = ((w / s) + z).round().clamp(qmin, qmax)
    return (w_q - z) * s   # dequantize back to float

w = torch.randn(256, 256)
w_int8 = fake_quantize(w, bits=8)
w_int4 = fake_quantize(w, bits=4)

def sqnr(orig, quant):
    signal = orig.pow(2).mean()
    noise  = (orig - quant).pow(2).mean()
    return 10 * torch.log10(signal / noise)

print(f"SQNR INT8: {sqnr(w, w_int8):.1f} dB")
print(f"SQNR INT4: {sqnr(w, w_int4):.1f} dB")
Section 8

Kahan Summation

When accumulating many floating-point values, standard summation accrues $O(n\epsilon)$ error. Kahan's compensated summation keeps a separate "compensation" variable that captures the rounding error of each addition and feeds it into the next step, reducing total error to $O(\epsilon)$ regardless of $n$. This is directly relevant to gradient accumulation across hundreds of micro-batches.

$$y = x_i - c, \quad t = \text{sum} + y, \quad c = (t - \text{sum}) - y, \quad \text{sum} = t$$

Standard summation error: $O(n\epsilon_{\text{mach}})$. Kahan error: $O(\epsilon_{\text{mach}})$. 

import torch

x = torch.ones(1_000_000, dtype=torch.float32) * 0.1

naive = x.sum().item()

def kahan_sum(t):
    s, c = 0.0, 0.0
    for v in t:
        y = v.item() - c;  tmp = s + y
        c = (tmp - s) - y; s = tmp
    return s

kahan = kahan_sum(x)
exact = 100_000.0   # 1e6 * 0.1
print(f"Naive  error: {abs(naive  - exact):.4f}")
print(f"Kahan  error: {abs(kahan  - exact):.2e}")

Iterative Solvers & Conjugate Gradient

The Conjugate Gradient (CG) method solves $\mathbf{A}\mathbf{x}=\mathbf{b}$ for symmetric positive-definite $\mathbf{A}$ without forming $\mathbf{A}^{-1}$. Each iteration requires only a matrix-vector product, making it practical for very large systems. CG appears in second-order optimisers such as K-FAC, where the Fisher matrix is too large to invert directly.

CG minimises the quadratic objective:

$$\min_{\mathbf{x}}\; \frac{1}{2}\mathbf{x}^T\!\mathbf{A}\mathbf{x} - \mathbf{b}^T\mathbf{x}$$

Converges in at most $n$ steps (exact); practical convergence is $O(\sqrt{\kappa(\mathbf{A})})$ iterations. 

import torch

def conjugate_gradient(A, b, max_iter=100, tol=1e-6):
    x = torch.zeros_like(b)
    r = b - A @ x;  p = r.clone()
    r_dot = r @ r
    for _ in range(max_iter):
        Ap = A @ p
        alpha = r_dot / (p @ Ap)
        x = x + alpha * p
        r = r - alpha * Ap
        r_dot_new = r @ r
        if r_dot_new.sqrt() < tol: break
        p = r + (r_dot_new / r_dot) * p
        r_dot = r_dot_new
    return x

n = 64
A = torch.eye(n) + 0.1 * torch.rand(n, n)
A = A @ A.T   # make SPD
b = torch.randn(n)
x = conjugate_gradient(A, b)
print(f"Residual: {(A @ x - b).norm().item():.2e}")

Numerical Precision in Practice

Mixed-precision training stores a FP32 "master copy" of weights and optimizer states, while forward and backward passes run in BF16 for speed. Crucially, loss must be accumulated in FP32 to avoid underflow of small gradient signals. The table below summarises recommended dtypes for common operations in a production LLM training stack.

Operation Recommended dtype Reason
Loss accumulation FP32 Prevent underflow of small losses
Attention (QKV, softmax) BF16 Wide range prevents overflow; speed
Embedding lookup FP32 Precision needed for rare tokens
Optimizer states (Adam m, v) FP32 v must resolve small gradients²
MatMul (linear layers) BF16 Tensor Core throughput; range ok
LayerNorm / RMSNorm FP32 Variance computation sensitive to ε
Inference (weights) INT8 / INT4 Memory bandwidth savings at serve
Key rule: Always accumulate loss and optimizer second moments in FP32. BF16 has epsilon ~7.8e-3; a gradient of magnitude 1e-4 is below its precision floor and will round to zero, silently killing learning for those parameters. 
import torch, torch.nn as nn

# Master-weight pattern for mixed-precision training
model = nn.Linear(512, 512)
master_weights = {n: p.float().clone() for n, p in model.named_parameters()}
optimizer = torch.optim.AdamW(list(master_weights.values()), lr=1e-4)

def train_step(x, target):
    # Cast master weights -> BF16 for forward pass
    for n, p in model.named_parameters():
        p.data.copy_(master_weights[n].bfloat16())
    with torch.autocast(device_type='cpu', dtype=torch.bfloat16):
        loss = nn.functional.mse_loss(model(x), target)
    loss.backward()            # grads in BF16
    # Copy grads to FP32 master, then optimise
    for n, p in model.named_parameters():
        if p.grad is not None:
            master_weights[n].grad = p.grad.float()
    optimizer.step();  optimizer.zero_grad()
