Section 1

Why Sequences Need Special Math

Language, audio, and time-series data carry temporal dependencies: the meaning of token $x_t$ depends on the tokens that came before it. Two dominant paradigms handle this: recurrence compresses history into a fixed hidden state $\mathbf{h}_t$ — sequential but $O(T)$ memory — while attention looks directly at every past token via a full $T \times T$ matrix, enabling parallel training at the cost of $O(T^2)$ memory. Modern architectures (Mamba, RWKV) try to capture the best of both worlds.

Section 2

Vanilla RNN

Recurrence Equations

$$\mathbf{h}_t = \tanh(\mathbf{W}_h\mathbf{h}_{t-1} + \mathbf{W}_x\mathbf{x}_t + \mathbf{b}), \qquad \mathbf{y}_t = \mathbf{W}_o\mathbf{h}_t$$

BPTT unrolls the graph through time; the gradient of the loss w.r.t. an early hidden state involves a product of Jacobians:

$$\frac{\partial\mathcal{L}}{\partial\mathbf{h}_t} = \prod_{k=t}^{T}\mathbf{W}_h^{\top}\,\text{diag}(\tanh'(\cdot))$$

A long product of matrices with spectral radius $\neq 1$ either vanishes (signal dies) or explodes (training diverges).

The vanilla RNN is the simplest recurrent model: a single matrix multiplication plus a nonlinearity updates the hidden state at each step. Despite its simplicity it cannot reliably propagate gradients over more than ~10–20 steps, motivating gated variants.

PyTorch — nn.RNN and manual cell

import torch, torch.nn as nn

# --- using nn.RNN ---
rnn = nn.RNN(input_size=32, hidden_size=64, batch_first=True)
x   = torch.randn(8, 20, 32)          # (batch, seq_len, input)
out, h_n = rnn(x)                      # out: (8,20,64), h_n: (1,8,64)

# --- manual RNN cell ---
class RNNCell(nn.Module):
    def __init__(self, d_in, d_h):
        super().__init__()
        self.Wh = nn.Linear(d_h, d_h, bias=False)
        self.Wx = nn.Linear(d_in, d_h)
    def forward(self, x, h):           # x:(B,d_in), h:(B,d_h)
        return torch.tanh(self.Wh(h) + self.Wx(x))

cell = RNNCell(32, 64)
h = torch.zeros(8, 64)
for t in range(20):
    h = cell(x[:, t, :], h)
Section 3

LSTM

Four-Gate Equations

$$\mathbf{f}_t=\sigma(\mathbf{W}_f[\mathbf{h}_{t-1},\mathbf{x}_t]+\mathbf{b}_f)$$ $$\mathbf{i}_t=\sigma(\mathbf{W}_i[\mathbf{h}_{t-1},\mathbf{x}_t]+\mathbf{b}_i)$$ $$\tilde{\mathbf{c}}_t=\tanh(\mathbf{W}_c[\mathbf{h}_{t-1},\mathbf{x}_t]+\mathbf{b}_c)$$ $$\mathbf{c}_t=\mathbf{f}_t\odot\mathbf{c}_{t-1}+\mathbf{i}_t\odot\tilde{\mathbf{c}}_t, \qquad \mathbf{h}_t=\mathbf{o}_t\odot\tanh(\mathbf{c}_t)$$

The cell state $\mathbf{c}_t$ is updated additively: gradients flow back through the forget gate $\mathbf{f}_t$ rather than through a weight matrix product, creating a gradient highway that keeps long-range signals alive.

LSTMs (Hochreiter & Schmidhuber, 1997) dominated sequence modeling for over a decade — powering speech recognition, machine translation, and language modeling before Transformers. The key insight is separating what to remember (input gate) from what to forget (forget gate) from what to output (output gate).

PyTorch — nn.LSTM

import torch, torch.nn as nn

lstm = nn.LSTM(input_size=32, hidden_size=64,
               num_layers=2, batch_first=True, dropout=0.1)

x   = torch.randn(8, 50, 32)          # (batch, seq, feat)
h0  = torch.zeros(2, 8, 64)           # (num_layers, batch, hidden)
c0  = torch.zeros(2, 8, 64)

out, (h_n, c_n) = lstm(x, (h0, c0))
# out: (8, 50, 64) — all hidden states
# h_n: (2, 8, 64) — final hidden per layer
# c_n: (2, 8, 64) — final cell  per layer
print(out.shape, h_n.shape, c_n.shape)
Section 4

GRU

Simplified Gating

$$\mathbf{r}_t=\sigma(\mathbf{W}_r[\mathbf{h}_{t-1},\mathbf{x}_t]), \quad \mathbf{z}_t=\sigma(\mathbf{W}_z[\mathbf{h}_{t-1},\mathbf{x}_t])$$ $$\tilde{\mathbf{h}}_t=\tanh(\mathbf{W}[\mathbf{r}_t\odot\mathbf{h}_{t-1},\mathbf{x}_t]), \quad \mathbf{h}_t=(1-\mathbf{z}_t)\odot\mathbf{h}_{t-1}+\mathbf{z}_t\odot\tilde{\mathbf{h}}_t$$

GRU merges the cell state and hidden state into one vector and uses only two gates (reset $\mathbf{r}$ and update $\mathbf{z}$), reducing parameters by ~25% vs LSTM with comparable performance.

LSTM (4 gates) vs GRU (2 gates)

PyTorch — nn.GRU + parameter count

import torch, torch.nn as nn

gru  = nn.GRU(input_size=32, hidden_size=64, batch_first=True)
lstm = nn.LSTM(input_size=32, hidden_size=64, batch_first=True)
x    = torch.randn(8, 20, 32)

out_g, _ = gru(x)
out_l, _ = lstm(x)

gru_params  = sum(p.numel() for p in gru.parameters())
lstm_params = sum(p.numel() for p in lstm.parameters())
print(f"GRU  params: {gru_params:,}")   # 18,432

Vanishing Gradients: The Math

Gradient Norm Bound

$$\left\|\frac{\partial\mathbf{h}_T}{\partial\mathbf{h}_1}\right\| \leq \bigl(\rho(\mathbf{W}_h)\cdot\max|\sigma'|\bigr)^{T-1}$$

If the spectral radius $\rho(\mathbf{W}_h) < 1$, the bound decays exponentially to zero (vanishing). If $\rho(\mathbf{W}_h) > 1$, it grows exponentially (exploding — mitigated by gradient clipping). LSTM/GRU solve vanishing by replacing the matrix product with an additive cell update: $\mathbf{c}_t = \mathbf{f}_t \odot \mathbf{c}_{t-1} + \ldots$, so $\partial\mathbf{c}_T/\partial\mathbf{c}_1 \approx \prod \mathbf{f}_k$ — a product of scalars near 1 rather than a matrix product.

Vanishing gradients were identified as the core obstacle to training deep recurrent networks (Hochreiter 1991, Bengio et al. 1994). Gradient clipping addresses exploding gradients; gated architectures address vanishing ones.

PyTorch — gradient norm comparison over 100 steps

import torch, torch.nn as nn

def grad_norm(model, x_seq):
    h = torch.zeros(1, model.hidden_size)
    loss = torch.tensor(0.0)
    for x in x_seq:
        h = model(x.unsqueeze(0), h)
        loss = loss + h.sum()
    loss.backward()
    return h.grad.norm().item() if h.grad else float('nan')

T   = 100
seq = [torch.randn(1, 16).requires_grad_(False) for _ in range(T)]

rnn_cell  = nn.RNNCell(16, 32)
lstm_cell = nn.LSTMCell(16, 32)

# RNN gradient norm (often near 0 at step 1 due to vanishing)
x_seq = torch.randn(T, 1, 16)
rnn   = nn.RNN(16, 32, batch_first=False)
out_r, _ = rnn(x_seq); out_r[0].sum().backward()
rnn_gnorm = sum(p.grad.norm() for p in rnn.parameters() if p.grad is not None)
print(f"RNN  grad norm: {rnn_gnorm:.4f}")

Linear Recurrence & S4

Continuous-Time SSM & Discretization

Continuous system:

$$\dot{\mathbf{h}}(t)=\mathbf{A}\mathbf{h}(t)+\mathbf{B}x(t), \qquad y(t)=\mathbf{C}\mathbf{h}(t)$$

Zero-order hold discretization (step size $\Delta$):

$$\bar{\mathbf{A}}=e^{\Delta\mathbf{A}}, \qquad \bar{\mathbf{B}}=(\Delta\mathbf{A})^{-1}(e^{\Delta\mathbf{A}}-\mathbf{I})\Delta\mathbf{B}$$

Convolution mode for efficient training:

$$y = \bar{\mathbf{K}} * x, \qquad \bar{\mathbf{K}} = \bigl(\mathbf{C}\bar{\mathbf{B}},\;\mathbf{C}\bar{\mathbf{A}}\bar{\mathbf{B}},\;\mathbf{C}\bar{\mathbf{A}}^2\bar{\mathbf{B}},\;\ldots\bigr)$$

S4 parameterizes $\mathbf{A}$ as a structured (diagonal + low-rank) matrix to enable efficient computation of the convolution kernel via the HiPPO framework.

State space models unify differential equations and sequence modeling. During training the model runs as a global convolution (parallel, $O(T \log T)$); during inference it runs as a recurrence ($O(1)$ per step), giving the best of both worlds.

PyTorch — S4-style linear recurrence

import torch, torch.nn as nn, torch.nn.functional as F

class S4Layer(nn.Module):
    def __init__(self, d_model, d_state=16):
        super().__init__()
        self.A = nn.Parameter(torch.randn(d_state))          # diagonal A
        self.B = nn.Parameter(torch.randn(d_state, 1))
        self.C = nn.Parameter(torch.randn(1, d_state))
        self.D = nn.Parameter(torch.ones(1))
        self.dt = nn.Parameter(torch.ones(1) * 0.01)

    def kernel(self, L):
        Ab = torch.exp(self.dt * self.A)                     # discretised A
        Bb = self.dt * self.B                                # discretised B
        powers = Ab.unsqueeze(0) ** torch.arange(L, device=Ab.device).unsqueeze(1)
        return (self.C @ (powers * Bb).T).squeeze(0)         # (L,)

    def forward(self, u):                                    # u: (B, L, 1)
        L = u.shape[1]
        K = self.kernel(L)                                   # (L,)
        y = F.conv1d(u.transpose(1,2), K.flip(0).view(1,1,-1),
                     padding=L-1)[..., :L].transpose(1,2)
        return y + self.D * u

Mamba: Selective SSM

Input-Dependent Selection

$$\Delta_t,\;\mathbf{B}_t,\;\mathbf{C}_t = \text{Linear}(\mathbf{x}_t)$$ $$\bar{\mathbf{A}}_t = \exp(\Delta_t \mathbf{A}), \qquad \bar{\mathbf{B}}_t = (\Delta_t\mathbf{A})^{-1}(e^{\Delta_t\mathbf{A}}-\mathbf{I})\Delta_t\mathbf{B}_t$$

Unlike S4 where $\mathbf{B},\mathbf{C},\Delta$ are fixed, Mamba makes them input-dependent per token. This selective mechanism allows the model to focus on or ignore tokens dynamically, mimicking attention's content-based selection at $O(T)$ cost. A hardware-aware parallel scan algorithm enables efficient GPU training despite the sequential recurrence.

Mamba (Gu & Dao, 2023) achieves Transformer-quality language modeling while scaling linearly with sequence length. The hardware-aware implementation fuses the scan into a single CUDA kernel, avoiding the memory bottleneck of materializing intermediate states.

PyTorch — selective SSM cell (simplified)

import torch, torch.nn as nn

class SelectiveSSM(nn.Module):
    def __init__(self, d_model, d_state=16, d_conv=4):
        super().__init__()
        self.d_state = d_state
        self.in_proj  = nn.Linear(d_model, d_model * 2)
        self.conv1d   = nn.Conv1d(d_model, d_model, d_conv,
                                  padding=d_conv-1, groups=d_model)
        self.x_proj   = nn.Linear(d_model, d_state * 2 + 1)  # B,C,dt
        self.A_log    = nn.Parameter(torch.log(torch.arange(1, d_state+1).float()))
        self.D        = nn.Parameter(torch.ones(d_model))
        self.out_proj = nn.Linear(d_model, d_model)

    def forward(self, x):              # x: (B, L, d_model)
        B, L, _ = x.shape
        xz = self.in_proj(x)
        x_, z = xz.chunk(2, dim=-1)
        x_ = self.conv1d(x_.transpose(1,2))[..., :L].transpose(1,2)
        x_ = torch.silu(x_)
        # selective parameters
        bcd = self.x_proj(x_)          # (B, L, 2*d_state+1)
        dt, B_sel, C_sel = bcd.split([1, self.d_state, self.d_state], dim=-1)
        dt = torch.softplus(dt)
        A  = -torch.exp(self.A_log)    # (d_state,) — fixed diagonal
        # simplified recurrence (not parallel scan)
        h = torch.zeros(B, self.d_state, device=x.device)
        ys = []
        for t in range(L):
            Ab = torch.exp(dt[:, t] * A)             # (B, d_state)
            h  = Ab * h + dt[:, t] * B_sel[:, t] * x_[:, t, :1]
            ys.append((C_sel[:, t] * h).sum(-1, keepdim=True))
        y = torch.stack(ys, dim=1) + self.D * x_[:, :, :1]
        return self.out_proj(torch.silu(z) * y)
Section 8

Attention vs Recurrence Trade-offs

No architecture dominates all axes. Transformers parallelize perfectly but pay quadratic memory; RNNs are compact but sequential; Mamba/SSMs thread the needle with linear-cost parallel training via scan. The right choice depends on sequence length, hardware, and whether you need random access to context.

Architecture Memory (seq T) Depth / steps Training parallelism Inference per step
Transformer $O(T^2)$ $O(1)$ layers Full parallel $O(T \cdot d^2)$ with KV-cache
LSTM / GRU $O(T)$ $O(T)$ sequential Sequential only $O(d^2)$ constant
Mamba / SSM $O(T)$ $O(\log T)$ w/ scan Parallel scan $O(d \cdot N)$ constant

PyTorch — inference speed timing harness

import torch, time

def time_model(fn, x, reps=50):
    # warm-up
    for _ in range(5): fn(x)
    torch.cuda.synchronize() if x.is_cuda else None
    t0 = time.perf_counter()
    for _ in range(reps): fn(x)
    torch.cuda.synchronize() if x.is_cuda else None
    return (time.perf_counter() - t0) / reps * 1000   # ms

import torch.nn as nn
T, B, D = 512, 4, 256
x = torch.randn(B, T, D)

transformer_layer = nn.TransformerEncoderLayer(D, nhead=8, batch_first=True)
rnn_layer         = nn.GRU(D, D, batch_first=True)

t_tf  = time_model(transformer_layer, x)
t_rnn = time_model(lambda z: rnn_layer(z)[0], x)
print(f"Transformer: {t_tf:.2f} ms | GRU: {t_rnn:.2f} ms  (T={T})")

Encoder-Decoder Architecture

Cross-Attention Formulation

$$\mathbf{H}_{enc} = \text{Encoder}(\mathbf{x}_{src}), \qquad \mathbf{H}_{dec}^{(l)} = \text{SelfAttn}(\mathbf{H}_{dec}^{(l-1)})$$ $$\text{CrossAttn}(\mathbf{Q},\mathbf{K},\mathbf{V}) = \text{softmax}\!\left(\frac{\mathbf{Q}\mathbf{K}^\top}{\sqrt{d_k}}\right)\mathbf{V}, \quad \mathbf{Q}=\mathbf{H}_{dec}\mathbf{W}^Q,\;\mathbf{K}=\mathbf{V}=\mathbf{H}_{enc}\mathbf{W}^{K,V}$$

The encoder compresses the full source sequence; each decoder layer attends to encoder outputs via cross-attention, enabling the model to align source and target tokens. Use encoder-decoder for seq2seq tasks: machine translation, summarization, speech recognition.

The original Transformer (Vaswani et al., 2017) uses this encoder-decoder design. Decoder-only models (GPT) drop the encoder and cross-attention, reading context from the same sequence. Encoder-only models (BERT) drop the decoder, producing representations for classification.

PyTorch — cross-attention module

import torch, torch.nn as nn, torch.nn.functional as F, math

class CrossAttention(nn.Module):
    def __init__(self, d_model, n_heads):
        super().__init__()
        self.h, self.dk = n_heads, d_model // n_heads
        self.Wq = nn.Linear(d_model, d_model, bias=False)
        self.Wk = nn.Linear(d_model, d_model, bias=False)
        self.Wv = nn.Linear(d_model, d_model, bias=False)
        self.out = nn.Linear(d_model, d_model, bias=False)

    def forward(self, q, kv):          # q: (B,Tq,D), kv: (B,Ts,D)
        B = q.size(0)
        def split(x, W):
            return W(x).view(B, -1, self.h, self.dk).transpose(1, 2)
        Q, K, V = split(q, self.Wq), split(kv, self.Wk), split(kv, self.Wv)
        scores = (Q @ K.transpose(-2,-1)) / math.sqrt(self.dk)
        attn   = F.softmax(scores, dim=-1)
        out    = (attn @ V).transpose(1,2).contiguous().view(B, -1, self.h*self.dk)
        return self.out(out)

ca  = CrossAttention(256, 8)
dec = torch.randn(2, 10, 256)          # decoder queries
enc = torch.randn(2, 20, 256)          # encoder keys/values
print(ca(dec, enc).shape)              # (2, 10, 256)

Connectionist Temporal Classification (CTC)

CTC Loss

$$\mathcal{L}_{CTC} = -\log\sum_{\pi\,:\,\mathcal{B}(\pi)=\mathbf{y}} P(\pi\mid\mathbf{x})$$

$\mathcal{B}$ collapses repeated characters and removes blank tokens; the sum marginalizes over all valid alignments of the output label sequence $\mathbf{y}$ to the input frames. The forward-backward (Baum-Welch) algorithm computes this sum in $O(T \cdot |\mathbf{y}|)$ via dynamic programming. At inference time, beam search decoding with a language model prior dramatically outperforms greedy decoding.

CTC (Graves et al., 2006) removes the need to pre-align audio frames to phoneme labels, enabling end-to-end speech recognition. It is still used in fast streaming ASR systems (wav2vec 2.0, Whisper encoder stages) where alignment-free training is essential.

PyTorch — nn.CTCLoss example

import torch, torch.nn as nn

ctc = nn.CTCLoss(blank=0, reduction='mean', zero_infinity=True)

T, B, C = 50, 4, 28                   # frames, batch, num_classes (incl. blank)
log_probs    = torch.randn(T, B, C).log_softmax(2)  # (T, B, C) required
targets      = torch.randint(1, C, (B * 10,))       # flattened target labels
input_lengths  = torch.full((B,), T, dtype=torch.long)
target_lengths = torch.full((B,), 10, dtype=torch.long)

loss = ctc(log_probs, targets, input_lengths, target_lengths)
print(f"CTC loss: {loss.item():.4f}")
