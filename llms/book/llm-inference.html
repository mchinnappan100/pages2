Section 2

Dense vs. Sparse Models

📦 Dense Model

Same parameters participate for every token. Everything comes along for every request.

"Carry every textbook Mon–Fri, even though you only need 2–3 books on any given day."

⚡ Sparse / MoE

Only a subset of parameters activates per token. A router selects the relevant experts.

"On Monday I only need math and physics, so I carry only those two."
Key distinction: Total parameters ≠ active parameters. An MoE model can have hundreds of billions of total parameters while activating only a small fraction per token.
Section 3

Why the Transformer Was Revolutionary

RNN (sequential) vs Transformer (parallel)

The revolution was not inventing each component from scratch — it was assembling them into a scalable architecture that could exploit massive parallel computation. The "Frankenstein" of embeddings, positional info, attention, residuals, norms, and FFNs worked extraordinarily well together.

Section 4

Self-Attention: Why Position Matters

Attention allows tokens to interact with other tokens. But attention by itself has no inherent sense of order.

Same words, opposite meanings

"The dog bites the man."

"The man bites the dog."

Without position, the model can't distinguish these.

Solution: encode position

Tell the model where each token is in the sequence — position 1, position 2, etc. — so attention scores are position-aware.

RoPE — Rotary Positional Embeddings

Modern LLMs (LLaMA, Mistral, Gemma…) use RoPE rather than additive sinusoidal encodings. Position isn't added to the input — instead, position-dependent rotations are applied to Q and K before computing attention scores.

❌ Common misconception

Input + Attention + Position

✅ Correct: RoPE

Section 7

Residual Connections

The output of each sublayer (attention, FFN) is added back to the input that entered it. This preserves information and makes deep networks easier to optimise.

Section 9

Why Attention Can Become Memory-Bound

The problem is not: "The GPU cannot calculate this."

It is: "The GPU spends too much time moving data between memory levels." Tensor Cores sit idle waiting for HBM reads/writes to complete.

Memory-bound signals

  • HBM bandwidth → very high
  • Tensor-core use → relatively low
  • Cache behavior → heavy traffic

Compute-bound signals

  • Tensor-core use → very high
  • HBM bandwidth → not saturated
Section 10

FlashAttention — Tiling

FlashAttention makes attention much more memory-efficient while computing the exact same result. Key technique: tiling — work on small tiles entirely within fast SRAM instead of materialising the N×N matrix in HBM.

Key idea: FlashAttention does not make SRAM larger. It makes much better use of the memory that already exists.
Section 11

FlashAttention 1 → 2 → Future Generations

Each generation optimises: memory movement, tiling, parallelisation, work partitioning, GPU utilisation, hardware-specific execution.

Highway Traffic Analogy

Standard Attention

Highway with constant stopping, merging, and back-and-forth. Traffic jams everywhere.

FlashAttention 1

Redesigned flow: cars move efficiently, fewer trips, better coordination. Same destination, much smarter route.

FlashAttention 2

Better traffic organisation, better lane utilisation, better use of all available infrastructure.

Exact gains depend heavily on hardware, sequence length, workload, and baseline — headline numbers are benchmark-specific, not universal.

Section 24

The Questions an Inference Lead Should Ask

Compute-bound?

  • Tensor cores saturated?
  • Arithmetic near hw limit?

Memory-bound?

  • HBM bandwidth saturated?
  • Cache behaviors poor?
  • Cores waiting for data?

Scheduling-bound?

  • GPUs sitting idle?
  • Batching effective?
  • Requests arriving inefficiently?

Communication / Algorithm-bound?

  • GPUs waiting on others?
  • Attention optimisable?
  • Speculative decode / quant viable?

Section 28

Final Takeaways

1

Inference is the delivery system for intelligence. Training creates the model; inference brings it to users.

2

Dense means "carry every book." Sparse / MoE means "bring only the books you need today."

3

The Transformer revolution was about scalable parallel computation. Attention replaced RNN sequential dependency and mapped well to GPUs.

4

Position matters. Original Transformers add positional encodings to input; modern ones use RoPE on Q and K.

5

Memory movement can be as important as computation. A powerful GPU can still be underutilised if it is waiting for data.

6

FlashAttention is fundamentally a memory-efficiency story. Tiling + on-chip compute reduces HBM traffic while preserving exact results.

7

Profile before optimising. Nsight Systems = big picture. Nsight Compute = kernel-level analysis.

8

Quantization is an inference performance and deployment strategy, not merely model compression. Choose the right vehicle for the terrain.

9

Local inference is becoming increasingly important. Apple Silicon + Ollama + quantized models make capable LLMs accessible outside data centers.

10

Build a culture of measurement. If you can't measure it, you can't systematically improve it. Don't optimise what you assume is the bottleneck — measure what is actually limiting the system.
