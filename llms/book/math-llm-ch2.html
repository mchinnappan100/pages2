Section 1

Why Calculus Powers LLMs

Every large language model is, at its core, a parameterized function $f_\theta : \mathcal{X} \to \mathcal{Y}$ whose billions of parameters $\theta$ are tuned by minimizing a scalar loss $\mathcal{L}(\theta)$ over massive datasets. That tuning process — training — is entirely governed by calculus. Without derivatives, there is no gradient; without gradients, there is no direction to move the parameters; without a direction, there is no learning.

The core loop of LLM training is:

  1. Forward pass — compute predictions and the scalar loss $\mathcal{L}$.
  2. Backward pass — apply the chain rule recursively through the computation graph to obtain $\frac{\partial \mathcal{L}}{\partial \theta_i}$ for every parameter $\theta_i$.
  3. Parameter update — move each parameter in the direction that decreases $\mathcal{L}$, scaled by a learning rate $\eta$.
  4. Repeat billions of times across trillions of tokens.

The Training Loop at a Glance

Key Insight: A 70B-parameter LLM has 70 billion partial derivatives computed every single forward-backward pass. The entire edifice of modern AI rests on efficient, exact, automatic differentiation of deep computational graphs — which is pure applied calculus.

This chapter builds the calculus foundation from first principles: derivatives, partial derivatives, the chain rule, gradients, Jacobians, and Hessians — then shows how they combine in automatic differentiation, backpropagation, and the Adam optimizer that trains virtually every modern LLM.

Section 2

Derivatives & Partial Derivatives

The derivative of a function $f : \mathbb{R} \to \mathbb{R}$ at a point $x$ is defined as:

$$\frac{d}{dx}f(x) = \lim_{h \to 0} \frac{f(x+h) - f(x)}{h}$$

It measures the instantaneous rate of change — the slope of the tangent line at $x$.

Partial Derivatives

For a multivariate function $f : \mathbb{R}^n \to \mathbb{R}$, the partial derivative with respect to $x_i$ treats all other variables as constants:

$$\frac{\partial f}{\partial x_i} = \lim_{h \to 0} \frac{f(x_1, \ldots, x_i + h, \ldots, x_n) - f(x_1, \ldots, x_n)}{h}$$

In a neural network with loss $\mathcal{L}(\mathbf{W}, \mathbf{b})$, we need $\frac{\partial \mathcal{L}}{\partial W_{ij}}$ for every weight $W_{ij}$.

The Chain Rule

The chain rule is the engine of backpropagation. For composed functions $h(x) = f(g(x))$:

$$\frac{d}{dx}[f(g(x))] = f'(g(x)) \cdot g'(x)$$

In the multivariate case, if $\mathbf{y} = g(\mathbf{x})$ and $z = f(\mathbf{y})$:

$$\frac{\partial z}{\partial x_i} = \sum_j \frac{\partial z}{\partial y_j} \cdot \frac{\partial y_j}{\partial x_i}$$

Every layer in a deep network is one application of this rule. A 100-layer network applies it 100 times in sequence — that is backpropagation.

Common Derivatives in Neural Networks

Function Formula Derivative
Sigmoid $\sigma(x) = \frac{1}{1+e^{-x}}$ $\sigma(x)(1 - \sigma(x))$
Tanh $\tanh(x) = \frac{e^x - e^{-x}}{e^x + e^{-x}}$ $1 - \tanh^2(x)$
ReLU $\text{ReLU}(x) = \max(0, x)$ $\mathbf{1}[x > 0]$
GELU $\text{GELU}(x) = x \cdot \Phi(x)$ $\Phi(x) + x\phi(x)$
Softmax $j$ $s_j = \frac{e^{x_j}}{\sum_k e^{x_k}}$ $s_j(\delta_{ij} - s_i)$
Log-Softmax $\log s_j$ $\delta_{ij} - s_i$
Cross-Entropy $-\log s_{y}$ $s_i - \mathbf{1}[i=y]$

Numerical vs Analytical Derivatives

Numerical differentiation approximates the derivative using finite differences: $\frac{\partial f}{\partial x_i} \approx \frac{f(\mathbf{x} + h\mathbf{e}_i) - f(\mathbf{x} - h\mathbf{e}_i)}{2h}$ for small $h$ (central difference). It requires two function evaluations per parameter — $O(n)$ extra forward passes for $n$ parameters. For a 70B model that is completely impractical, but it is invaluable for gradient checking (verifying autograd implementations).

Analytical differentiation applies calculus rules symbolically or algorithmically (autograd) and computes all partial derivatives in a single backward pass — $O(1)$ passes regardless of parameter count. 

import torch

# Numerical gradient check
def numerical_grad(f, x, h=1e-5):
    grad = torch.zeros_like(x)
    for i in range(x.numel()):
        x_plus  = x.clone(); x_plus.view(-1)[i]  += h
        x_minus = x.clone(); x_minus.view(-1)[i] -= h
        grad.view(-1)[i] = (f(x_plus) - f(x_minus)) / (2 * h)
    return grad

# Analytical gradient via autograd
x = torch.tensor([1.0, 2.0, 3.0], requires_grad=True)
loss = (x ** 2).sum()   # f(x) = x1^2 + x2^2 + x3^2
loss.backward()
print("Analytical:", x.grad)         # tensor([2., 4., 6.])
print("Numerical: ", numerical_grad(lambda v: (v**2).sum(), x.detach()))
Section 3

Gradients & the Gradient Vector

For $f : \mathbb{R}^n \to \mathbb{R}$, the gradient is the vector of all partial derivatives:

$$\nabla f(\mathbf{x}) = \left[\frac{\partial f}{\partial x_1},\; \frac{\partial f}{\partial x_2},\; \ldots,\; \frac{\partial f}{\partial x_n}\right]^T \in \mathbb{R}^n$$

The gradient $\nabla f(\mathbf{x})$ points in the direction of steepest ascent of $f$ at $\mathbf{x}$. Its magnitude $\|\nabla f\|$ tells you how steeply $f$ rises in that direction.

Gradient as Steepest Ascent

The directional derivative in direction $\mathbf{u}$ (unit vector) is $D_\mathbf{u} f = \nabla f \cdot \mathbf{u}$. This is maximized when $\mathbf{u} = \frac{\nabla f}{\|\nabla f\|}$. Therefore, moving in the direction $-\nabla f$ (negative gradient) decreases $f$ most rapidly — this is gradient descent.

Gradient Direction on a Loss Contour

Gradient of the Loss w.r.t. Weights

In a neural network, the weight matrix $\mathbf{W} \in \mathbb{R}^{m \times n}$ contributes a gradient matrix of the same shape:

$$\nabla_{\mathbf{W}}\mathcal{L} = \begin{bmatrix} \frac{\partial \mathcal{L}}{\partial W_{11}} & \cdots & \frac{\partial \mathcal{L}}{\partial W_{1n}} \\ \vdots & \ddots & \vdots \\ \frac{\partial \mathcal{L}}{\partial W_{m1}} & \cdots & \frac{\partial \mathcal{L}}{\partial W_{mn}} \end{bmatrix}$$

This matrix has the same shape as $\mathbf{W}$ — a fundamental fact that makes parameter updates simple: $\mathbf{W} \leftarrow \mathbf{W} - \eta \nabla_\mathbf{W}\mathcal{L}$.

import torch
import torch.nn as nn

# Simple linear layer gradient
W = torch.randn(4, 3, requires_grad=True)  # weight matrix
b = torch.randn(4, requires_grad=True)
x = torch.randn(3)                          # input

# Forward pass
y_hat = W @ x + b
loss  = y_hat.pow(2).sum()                  # toy loss

# Backward pass — gradient of loss w.r.t. W
loss.backward()
print("grad W shape:", W.grad.shape)         # torch.Size([4, 3])
print("grad b shape:", b.grad.shape)         # torch.Size([4])
# Update rule: W <- W - lr * W.grad
lr = 0.01
with torch.no_grad():
    W -= lr * W.grad
    b -= lr * b.grad
Section 4

Jacobians & Hessians

The Jacobian Matrix

When a function maps vectors to vectors, $\mathbf{f} : \mathbb{R}^n \to \mathbb{R}^m$, the Jacobian generalizes the derivative to a matrix of all partial derivatives:

$$\mathbf{J} = \frac{\partial \mathbf{f}}{\partial \mathbf{x}} = \begin{bmatrix} \frac{\partial f_1}{\partial x_1} & \cdots & \frac{\partial f_1}{\partial x_n} \\ \vdots & \ddots & \vdots \\ \frac{\partial f_m}{\partial x_1} & \cdots & \frac{\partial f_m}{\partial x_n} \end{bmatrix} \in \mathbb{R}^{m \times n}$$

So $J_{ij} = \frac{\partial f_i}{\partial x_j}$. The chain rule in matrix form becomes: $\frac{d\mathbf{z}}{d\mathbf{x}} = \frac{d\mathbf{z}}{d\mathbf{y}} \cdot \frac{d\mathbf{y}}{d\mathbf{x}}$ (Jacobian product).

In reverse-mode autodiff (backprop), we never materialize the full Jacobian — instead we compute Jacobian-vector products $\mathbf{v}^T \mathbf{J}$ efficiently.

The Hessian Matrix

The Hessian of a scalar function $f : \mathbb{R}^n \to \mathbb{R}$ is the matrix of second-order partial derivatives, capturing curvature:

$$\mathbf{H} = \nabla^2 f = \begin{bmatrix} \frac{\partial^2 f}{\partial x_1^2} & \frac{\partial^2 f}{\partial x_1 \partial x_2} & \cdots \\ \frac{\partial^2 f}{\partial x_2 \partial x_1} & \frac{\partial^2 f}{\partial x_2^2} & \cdots \\ \vdots & \vdots & \ddots \end{bmatrix}$$

Curvature interpretation: If $\mathbf{H} \succ 0$ (positive definite) at a critical point, it is a local minimum. If $\mathbf{H}$ has both positive and negative eigenvalues, it is a saddle point — extremely common in deep network loss landscapes.

Why the Hessian is Infeasible for LLMs

Computational Cost: A model with $n$ parameters requires an $n \times n$ Hessian matrix. For GPT-3 with $n = 175 \times 10^9$, this would require storing $175B \times 175B \approx 3 \times 10^{22}$ floating point numbers — roughly $10^{11}$ petabytes. Even approximating it is expensive. This is why virtually all LLM training uses first-order methods (gradient-only) like Adam.

Critical Points: Minimum, Maximum, Saddle

import torch

# Computing the Hessian (only feasible for tiny models)
def hessian(y, x):
    """Compute full Hessian of scalar y w.r.t. vector x."""
    grad = torch.autograd.grad(y, x, create_graph=True)[0]
    n = x.numel()
    H = torch.zeros(n, n)
    for i in range(n):
        H[i] = torch.autograd.grad(grad[i], x, retain_graph=True)[0]
    return H

x = torch.tensor([1.0, 2.0], requires_grad=True)
f = x[0]**2 + 2*x[0]*x[1] + 3*x[1]**2   # f = x1^2 + 2x1x2 + 3x2^2
H = hessian(f, x)
print(H)  # tensor([[2., 2.], [2., 6.]])  -- positive definite (minimum)
Section 5

Computational Graphs & Automatic Differentiation

When PyTorch evaluates an expression, it silently builds a computational graph — a directed acyclic graph (DAG) where nodes are operations and edges carry tensors. The forward pass produces the output; the backward pass traverses the same graph in reverse, applying the chain rule at each node.

Example: $L = (xw + b - y)^2$

Consider a single linear neuron with input $x$, weight $w$, bias $b$, target $y$, and mean-squared-error loss $L$. The forward computation decomposes as:

$$u = xw \qquad v = u + b \qquad r = v - y \qquad L = r^2$$

Forward & Backward Computation Graph

The backward pass computes, in reverse order: $$\frac{\partial L}{\partial r} = 2r, \quad \frac{\partial L}{\partial v} = 2r, \quad \frac{\partial L}{\partial u} = 2r, \quad \frac{\partial L}{\partial w} = 2r \cdot x, \quad \frac{\partial L}{\partial b} = 2r$$

Reverse-Mode Autodiff

Reverse-mode autodiff (what PyTorch uses) is efficient when the output is a scalar — you compute all $n$ partial derivatives in a single backward pass. Forward-mode autodiff computes one directional derivative per pass and is efficient when $n$ is small (e.g., sensitivity of a single output with respect to many inputs). For LLM training — one scalar loss, billions of parameters — reverse mode wins decisively. 

import torch

# PyTorch autograd: requires_grad, .backward(), .grad
x = torch.tensor(2.0,  requires_grad=False)  # input (not a parameter)
w = torch.tensor(3.0,  requires_grad=True)   # weight
b = torch.tensor(-1.0, requires_grad=True)   # bias
y = torch.tensor(5.0,  requires_grad=False)  # target

# Forward pass — graph is built automatically
u = x * w           # u = 6.0
v = u + b           # v = 5.0
r = v - y           # r = 0.0
L = r ** 2          # L = 0.0

# Backward pass
L.backward()

print(f"dL/dw = {w.grad.item()}")  # 2 * r * x = 0.0
print(f"dL/db = {b.grad.item()}")  # 2 * r     = 0.0

# Try with non-zero residual
w2 = torch.tensor(1.0, requires_grad=True)
b2 = torch.tensor(0.0, requires_grad=True)
L2 = (x * w2 + b2 - y) ** 2      # (2 - 5)^2 = 9
L2.backward()
print(f"dL/dw2 = {w2.grad.item()}")  # 2*(2-5)*2 = -12
print(f"dL/db2 = {b2.grad.item()}")  # 2*(2-5)   = -6

Backpropagation in Detail

Backpropagation is the algorithm that efficiently computes $\nabla_\theta \mathcal{L}$ by applying the chain rule layer by layer, working backwards from the loss. We derive it step by step for a 2-layer MLP.

2-Layer MLP Forward Pass

Let $\mathbf{x} \in \mathbb{R}^{d_0}$, layer weights $\mathbf{W}^{(1)} \in \mathbb{R}^{d_1 \times d_0}$, $\mathbf{W}^{(2)} \in \mathbb{R}^{d_2 \times d_1}$, activation $\sigma$ (e.g., ReLU):

$$\mathbf{z}^{(1)} = \mathbf{W}^{(1)}\mathbf{x} + \mathbf{b}^{(1)}$$ $$\mathbf{a}^{(1)} = \sigma(\mathbf{z}^{(1)})$$ $$\mathbf{z}^{(2)} = \mathbf{W}^{(2)}\mathbf{a}^{(1)} + \mathbf{b}^{(2)}$$ $$\mathbf{a}^{(2)} = \text{softmax}(\mathbf{z}^{(2)})$$ $$\mathcal{L} = -\sum_k y_k \log a_k^{(2)} \quad\text{(cross-entropy)}$$

Backward Pass: Deriving Each Gradient

Step 1: Loss → output layer pre-activation

For cross-entropy + softmax, the combined gradient is remarkably clean:

$$\boldsymbol{\delta}^{(2)} = \frac{\partial \mathcal{L}}{\partial \mathbf{z}^{(2)}} = \mathbf{a}^{(2)} - \mathbf{y}$$

Step 2: Output weight gradient

$$\frac{\partial \mathcal{L}}{\partial \mathbf{W}^{(2)}} = \boldsymbol{\delta}^{(2)} \left(\mathbf{a}^{(1)}\right)^T$$ $$\frac{\partial \mathcal{L}}{\partial \mathbf{b}^{(2)}} = \boldsymbol{\delta}^{(2)}$$

Step 3: Propagate error to hidden layer

$$\boldsymbol{\delta}^{(1)} = \frac{\partial \mathcal{L}}{\partial \mathbf{z}^{(1)}} = \left(\mathbf{W}^{(2)}\right)^T \boldsymbol{\delta}^{(2)} \odot \sigma'\!\left(\mathbf{z}^{(1)}\right)$$

where $\odot$ is elementwise multiplication and $\sigma'$ is the derivative of the activation.

Step 4: Hidden weight gradient

$$\frac{\partial \mathcal{L}}{\partial \mathbf{W}^{(1)}} = \boldsymbol{\delta}^{(1)} \mathbf{x}^T$$ $$\frac{\partial \mathcal{L}}{\partial \mathbf{b}^{(1)}} = \boldsymbol{\delta}^{(1)}$$
General Backprop Pattern: At each layer $l$, the error signal $\boldsymbol{\delta}^{(l)}$ is: (upstream gradient) $\times$ (transpose weight matrix) $\times$ (activation derivative). Weight gradient = $\boldsymbol{\delta}^{(l)} \otimes \mathbf{a}^{(l-1)}$. This pattern repeats for any depth.

Full derivation using the chain rule notation:

$$\frac{\partial \mathcal{L}}{\partial \mathbf{W}^{(1)}} = \underbrace{\frac{\partial \mathcal{L}}{\partial \mathbf{a}^{(2)}}}_{\text{loss grad}} \cdot \underbrace{\frac{\partial \mathbf{a}^{(2)}}{\partial \mathbf{z}^{(2)}}}_{\text{softmax Jac}} \cdot \underbrace{\frac{\partial \mathbf{z}^{(2)}}{\partial \mathbf{a}^{(1)}}}_{\mathbf{W}^{(2)}} \cdot \underbrace{\frac{\partial \mathbf{a}^{(1)}}{\partial \mathbf{z}^{(1)}}}_{\sigma'} \cdot \underbrace{\frac{\partial \mathbf{z}^{(1)}}{\partial \mathbf{W}^{(1)}}}_{\mathbf{x}^T}$$ 
import torch
import torch.nn.functional as F

# Manual backprop for a 2-layer MLP (illustrative, without autograd)
torch.manual_seed(42)
d0, d1, d2 = 4, 8, 3   # input, hidden, output dims

W1 = torch.randn(d1, d0) * 0.1
b1 = torch.zeros(d1)
W2 = torch.randn(d2, d1) * 0.1
b2 = torch.zeros(d2)

x = torch.randn(d0)          # single input
y = torch.tensor([0, 1, 0], dtype=torch.float)   # one-hot target

# --- FORWARD PASS ---
z1 = W1 @ x + b1
a1 = torch.relu(z1)          # ReLU hidden activation
z2 = W2 @ a1 + b2
a2 = F.softmax(z2, dim=0)    # output probabilities
L  = -torch.dot(y, torch.log(a2 + 1e-9))

# --- BACKWARD PASS (manual) ---
# delta2: gradient of L w.r.t. z2 (softmax + cross-entropy combined)
delta2 = a2 - y                          # shape: [d2]

dW2 = torch.outer(delta2, a1)            # shape: [d2, d1]
db2 = delta2                             # shape: [d2]

# Propagate through W2 and ReLU
delta1 = (W2.T @ delta2) * (z1 > 0).float()   # ReLU derivative

dW1 = torch.outer(delta1, x)            # shape: [d1, d0]
db1 = delta1                            # shape: [d1]

# Verify with autograd
W1_t = W1.clone().requires_grad_(True)
W2_t = W2.clone().requires_grad_(True)
b1_t = b1.clone().requires_grad_(True)
b2_t = b2.clone().requires_grad_(True)
a2_t = F.softmax(W2_t @ torch.relu(W1_t @ x + b1_t) + b2_t, dim=0)
L_t  = -torch.dot(y, torch.log(a2_t + 1e-9))
L_t.backward()

print("Max dW1 error:", (W1_t.grad - dW1).abs().max().item())  # ~0
print("Max dW2 error:", (W2_t.grad - dW2).abs().max().item())  # ~0
Section 7

Gradient Descent Variants

Vanilla Gradient Descent

$$\mathbf{w} \leftarrow \mathbf{w} - \eta \nabla_\mathbf{w}\mathcal{L}(\mathbf{w})$$

Batch GD: uses the full dataset. Exact gradient but very slow per step for large datasets. Stochastic GD (SGD): one random sample per step. Fast but noisy. Mini-batch GD: best of both — computes gradient on a small batch (32–2048 samples), balancing noise and computation.

Momentum

Momentum accumulates a velocity vector in directions of persistent gradient, dampening oscillations:

$$\mathbf{v}_t = \beta \mathbf{v}_{t-1} + \nabla_\mathbf{w}\mathcal{L}_t$$ $$\mathbf{w}_t = \mathbf{w}_{t-1} - \eta \mathbf{v}_t$$

Typical $\beta = 0.9$. The velocity exponentially averages past gradients, accelerating descent along consistent directions and cancelling oscillations in others.

Nesterov Accelerated Gradient (NAG)

$$\mathbf{v}_t = \beta \mathbf{v}_{t-1} + \nabla_\mathbf{w}\mathcal{L}(\mathbf{w}_{t-1} - \beta\mathbf{v}_{t-1})$$ $$\mathbf{w}_t = \mathbf{w}_{t-1} - \eta \mathbf{v}_t$$

NAG "looks ahead" by computing the gradient at the anticipated next position $\mathbf{w} - \beta\mathbf{v}$, giving better convergence than standard momentum.

SGD vs Momentum: Path on Loss Landscape

import torch
import torch.nn as nn

model = nn.Linear(10, 1)

# Plain SGD
opt_sgd = torch.optim.SGD(model.parameters(), lr=0.01)

# SGD with momentum
opt_mom = torch.optim.SGD(model.parameters(), lr=0.01, momentum=0.9)

# Nesterov momentum
opt_nes = torch.optim.SGD(model.parameters(), lr=0.01,
                           momentum=0.9, nesterov=True)

# Training step template
x = torch.randn(32, 10)
y = torch.randn(32, 1)

for opt in [opt_sgd, opt_mom, opt_nes]:
    opt.zero_grad()                        # clear accumulated gradients
    loss = nn.MSELoss()(model(x), y)
    loss.backward()                        # compute gradients
    opt.step()                             # update weights
Section 8

Adam Optimizer

Adam (Adaptive Moment Estimation, Kingma & Ba 2015) is the dominant optimizer for LLM training. It maintains per-parameter learning rates by tracking two exponential moving averages of the gradient: the first moment (mean) and the second moment (uncentered variance).

Full Adam Algorithm

Hyperparameters: $\eta$ (learning rate), $\beta_1 = 0.9$, $\beta_2 = 0.999$, $\epsilon = 10^{-8}$

At each step $t$, with gradient $\mathbf{g}_t = \nabla_\theta \mathcal{L}_t$:

$$\mathbf{m}_t = \beta_1 \mathbf{m}_{t-1} + (1 - \beta_1)\mathbf{g}_t \quad \text{(1st moment: mean)}$$ $$\mathbf{v}_t = \beta_2 \mathbf{v}_{t-1} + (1 - \beta_2)\mathbf{g}_t^2 \quad \text{(2nd moment: variance)}$$

Bias correction (critical in early steps when $\mathbf{m}, \mathbf{v}$ are initialized to 0):

$$\hat{\mathbf{m}}_t = \frac{\mathbf{m}_t}{1 - \beta_1^t} \qquad \hat{\mathbf{v}}_t = \frac{\mathbf{v}_t}{1 - \beta_2^t}$$

Parameter update:

$$\mathbf{w}_t = \mathbf{w}_{t-1} - \frac{\eta \hat{\mathbf{m}}_t}{\sqrt{\hat{\mathbf{v}}_t} + \epsilon}$$

Why Adam Works

Adaptive LR

$\sqrt{\hat{v}_t}$ normalizes updates: large, noisy gradients get shrunk; small, consistent gradients get amplified. Each parameter has its own effective learning rate.

Momentum

$\hat{m}_t$ provides momentum — smoother updates, less oscillation in ravines. It accumulates signal across many noisy mini-batch gradients.

Bias Correction

Without correction, $m_1 = (1-0.9)g_1 = 0.1g_1$ — only 10% of the gradient is used at step 1. Bias correction restores the true estimate.

AdamW: Decoupled Weight Decay

Standard Adam applies weight decay by adding $\lambda\mathbf{w}$ to the gradient before computing moments — this couples the decay with the adaptive learning rate. AdamW (Loshchilov & Hutter 2019) decouples them:

$$\mathbf{w}_t = (1 - \eta\lambda)\mathbf{w}_{t-1} - \frac{\eta \hat{\mathbf{m}}_t}{\sqrt{\hat{\mathbf{v}}_t} + \epsilon}$$

Weight decay is applied directly to the weights, not through the gradient moments. This is the correct L2 regularization for adaptive methods and is why AdamW is preferred for LLM pretraining (GPT, LLaMA, Gemma all use AdamW).

import torch
import torch.nn as nn

model = nn.TransformerEncoderLayer(d_model=512, nhead=8)

# Standard Adam
opt_adam = torch.optim.Adam(
    model.parameters(),
    lr=3e-4,
    betas=(0.9, 0.999),
    eps=1e-8
)

# AdamW — preferred for LLM training
opt_adamw = torch.optim.AdamW(
    model.parameters(),
    lr=3e-4,
    betas=(0.9, 0.95),        # LLaMA uses beta2=0.95
    eps=1e-8,
    weight_decay=0.1          # L2 penalty decoupled
)

# Manual Adam implementation (instructional)
def adam_step(params, grads, m, v, t, lr=1e-3, b1=0.9, b2=0.999, eps=1e-8):
    for i, (p, g) in enumerate(zip(params, grads)):
        m[i] = b1 * m[i] + (1 - b1) * g
        v[i] = b2 * v[i] + (1 - b2) * g ** 2
        m_hat = m[i] / (1 - b1 ** t)
        v_hat = v[i] / (1 - b2 ** t)
        p -= lr * m_hat / (v_hat.sqrt() + eps)
    return params, m, v
Section 9

Learning Rate Scheduling

The learning rate $\eta$ is the single most important hyperparameter. Too large: training diverges. Too small: training is slow and may get stuck. Modern LLM training uses dynamic schedules that vary $\eta$ throughout training.

Common Schedules

Constant

$$\eta_t = \eta_0$$

Simplest. Works for short runs but rarely optimal.

Step Decay

$$\eta_t = \eta_0 \cdot \gamma^{\lfloor t / s \rfloor}$$

Drop by factor $\gamma$ every $s$ steps. Requires manual tuning of milestones.

Cosine Annealing

$$\eta_t = \eta_{\min} + \frac{1}{2}(\eta_{\max} - \eta_{\min})\left(1 + \cos\!\left(\frac{t\,\pi}{T}\right)\right)$$

Smoothly decays from $\eta_{\max}$ to $\eta_{\min}$ over $T$ steps. Standard for LLM pretraining.

Linear Warmup + Cosine Decay (LLaMA schedule)

$$\eta_t = \begin{cases} \eta_{\max} \cdot \frac{t}{t_\text{warm}} & t \le t_\text{warm} \\ \eta_{\min} + \frac{1}{2}(\eta_{\max} - \eta_{\min})\!\left(1 + \cos\!\left(\frac{(t - t_\text{warm})\pi}{T - t_\text{warm}}\right)\right) & t > t_\text{warm} \end{cases}$$

Why LLMs Need Warmup

Warmup Rationale: At initialization, weights are random and gradients are noisy and large. Starting with a high learning rate causes large, destructive updates. Warmup ramps $\eta$ from near-zero to the peak, letting the optimizer first accumulate reliable gradient estimates in $\mathbf{m}$ and $\mathbf{v}$ before taking large steps. Adam's bias correction partially addresses this, but warmup provides additional stability. LLaMA-2 uses 2000 warmup steps; GPT-3 uses 375M warmup tokens.

Learning Rate Schedules Compared

import torch
import torch.nn as nn
from torch.optim.lr_scheduler import (
    CosineAnnealingLR, StepLR, LinearLR, SequentialLR
)

model = nn.Linear(128, 64)
optimizer = torch.optim.AdamW(model.parameters(), lr=3e-4, weight_decay=0.1)

T_max   = 100_000   # total training steps
warmup  = 2_000     # warmup steps

# Warmup scheduler (linear ramp from 0 to lr)
warmup_sched = LinearLR(optimizer, start_factor=1e-8, end_factor=1.0,
                         total_iters=warmup)

# Cosine decay after warmup
cosine_sched = CosineAnnealingLR(optimizer, T_max=T_max - warmup, eta_min=1e-5)

# Chain them together
scheduler = SequentialLR(optimizer,
                          schedulers=[warmup_sched, cosine_sched],
                          milestones=[warmup])

# Training loop
for step in range(T_max):
    optimizer.zero_grad()
    loss = model(torch.randn(32, 128)).sum()   # dummy loss
    loss.backward()
    optimizer.step()
    scheduler.step()

    if step % 10_000 == 0:
        print(f"step {step:6d}  lr={optimizer.param_groups[0]['lr']:.2e}")
Section 10

Gradient Clipping

Deep networks — especially Transformers — are prone to exploding gradients: the gradient norm $\|\mathbf{g}\|$ grows exponentially through many layers or sharp loss curvatures, causing catastrophically large parameter updates that destabilize training. Gradient clipping bounds the norm before the update.

Global Norm Clipping

Compute the global gradient norm across all parameters:

$$\|\mathbf{g}\|_{\text{global}} = \sqrt{\sum_i \|\nabla_{\theta_i} \mathcal{L}\|^2}$$

If it exceeds threshold $\tau$, rescale all gradients uniformly:

$$\mathbf{g} \leftarrow \mathbf{g} \cdot \frac{\tau}{\max(\tau,\; \|\mathbf{g}\|_{\text{global}})}$$

This preserves the direction of the gradient while capping its magnitude. Typical $\tau = 1.0$ for Transformers.

Why It Is Essential for Transformers

Transformer-specific reasons:
  • Attention scores can grow large early in training, producing large softmax outputs and huge gradients through the attention backward pass.
  • Layer normalization's learnable scale $\gamma$ can grow, amplifying gradients.
  • Long sequences amplify gradient products through time (similar to RNNs).
  • Without clipping, a single bad batch can push weights into a catastrophically bad region from which recovery takes thousands of steps or is impossible.
import torch
import torch.nn as nn

model = nn.TransformerEncoder(
    nn.TransformerEncoderLayer(d_model=512, nhead=8, batch_first=True),
    num_layers=6
)
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-4)

x    = torch.randn(4, 32, 512)     # (batch, seq_len, d_model)
loss = model(x).sum()
loss.backward()

# Inspect gradient norm before clipping
total_norm = 0.0
for p in model.parameters():
    if p.grad is not None:
        total_norm += p.grad.data.norm(2).item() ** 2
total_norm = total_norm ** 0.5
print(f"Gradient norm before clipping: {total_norm:.4f}")

# Clip gradients — ALWAYS call before optimizer.step()
max_norm = 1.0
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=max_norm)

total_norm_after = 0.0
for p in model.parameters():
    if p.grad is not None:
        total_norm_after += p.grad.data.norm(2).item() ** 2
total_norm_after = total_norm_after ** 0.5
print(f"Gradient norm after  clipping: {total_norm_after:.4f}")

optimizer.step()
optimizer.zero_grad()
Section 11

Backpropagation Through Attention

The scaled dot-product attention mechanism has a non-trivial gradient. Understanding it explains why FlashAttention's recomputation trick is both valid and necessary.

Attention Forward Pass

$$\mathbf{S} = \frac{\mathbf{Q}\mathbf{K}^T}{\sqrt{d_k}}, \quad \mathbf{P} = \text{softmax}(\mathbf{S}), \quad \mathbf{O} = \mathbf{P}\mathbf{V}$$

where $\mathbf{Q}, \mathbf{K}, \mathbf{V} \in \mathbb{R}^{N \times d_k}$ and $\mathbf{O} \in \mathbb{R}^{N \times d_k}$.

Attention Backward Pass

Given upstream gradient $\mathbf{d}\mathbf{O} = \frac{\partial \mathcal{L}}{\partial \mathbf{O}}$, we apply the chain rule:

Gradient w.r.t. V:

$$\frac{\partial \mathcal{L}}{\partial \mathbf{V}} = \mathbf{P}^T \cdot \mathbf{d}\mathbf{O}$$

Gradient w.r.t. attention weights P:

$$\frac{\partial \mathcal{L}}{\partial \mathbf{P}} = \mathbf{d}\mathbf{O} \cdot \mathbf{V}^T$$

Gradient through softmax (using the softmax Jacobian):

$$\frac{\partial \mathcal{L}}{\partial \mathbf{S}} = \mathbf{P} \odot \left(\frac{\partial \mathcal{L}}{\partial \mathbf{P}} - \left(\frac{\partial \mathcal{L}}{\partial \mathbf{P}} \odot \mathbf{P}\right)\mathbf{1}^T\right)$$

This is the row-wise softmax backward. Define $D_i = \sum_j \frac{\partial \mathcal{L}}{\partial P_{ij}} P_{ij}$, then $\frac{\partial \mathcal{L}}{\partial S_{ij}} = P_{ij}\left(\frac{\partial \mathcal{L}}{\partial P_{ij}} - D_i\right)$.

Gradients w.r.t. Q and K:

$$\frac{\partial \mathcal{L}}{\partial \mathbf{Q}} = \frac{1}{\sqrt{d_k}}\frac{\partial \mathcal{L}}{\partial \mathbf{S}} \cdot \mathbf{K}, \qquad \frac{\partial \mathcal{L}}{\partial \mathbf{K}} = \frac{1}{\sqrt{d_k}}\left(\frac{\partial \mathcal{L}}{\partial \mathbf{S}}\right)^T \cdot \mathbf{Q}$$

Why FlashAttention's Recomputation is Valid

The Key Insight: Standard attention saves the $N \times N$ attention matrix $\mathbf{P}$ in HBM for the backward pass (needed to compute $\frac{\partial \mathcal{L}}{\partial \mathbf{V}} = \mathbf{P}^T \mathbf{dO}$ and the softmax backward). FlashAttention instead saves only the softmax normalization statistics (the row-wise log-sum-exp values, $O(N)$ not $O(N^2)$) and recomputes $\mathbf{P}$ on-the-fly during the backward pass from $\mathbf{Q}$, $\mathbf{K}$ in SRAM. This is mathematically valid because $\mathbf{P}$ is a deterministic function of $\mathbf{Q}$, $\mathbf{K}$, and the saved statistics — the result is identical, just recomputed rather than stored. 
import torch
import torch.nn.functional as F
import math

def attention_with_grad(Q, K, V):
    """Standard attention — for illustration of gradient flow."""
    d_k = Q.size(-1)
    # Forward
    scores = torch.matmul(Q, K.transpose(-2, -1)) / math.sqrt(d_k)
    P = F.softmax(scores, dim=-1)     # N x N — stored for backward
    O = torch.matmul(P, V)
    return O, P

# PyTorch 2.0+ uses FlashAttention automatically via SDPA
# (recomputation handled internally)
Q = torch.randn(2, 8, 64, 64, requires_grad=True)   # (B, H, N, d_k)
K = torch.randn(2, 8, 64, 64, requires_grad=True)
V = torch.randn(2, 8, 64, 64, requires_grad=True)

# Flash-backed attention (PyTorch >= 2.0, CUDA)
with torch.backends.cuda.sdp_kernel(enable_flash=True) if torch.cuda.is_available() else torch.no_grad():
    # On CPU, falls back to math kernel
    O = F.scaled_dot_product_attention(Q, K, V)

loss = O.sum()
loss.backward()   # Gradients flow back to Q, K, V
print("dQ norm:", Q.grad.norm().item())
print("dK norm:", K.grad.norm().item())
print("dV norm:", V.grad.norm().item())
Section 12

Second-Order Methods & Approximations

First-order methods (Adam, SGD) use only $\nabla \mathcal{L}$. Second-order methods additionally use curvature information from the Hessian $\mathbf{H}$ to take more informed steps. In theory they converge faster; in practice they are rarely used for LLMs.

Newton's Method

$$\mathbf{w}_{t+1} = \mathbf{w}_t - \mathbf{H}_t^{-1} \nabla \mathcal{L}(\mathbf{w}_t)$$

The Hessian inverse $\mathbf{H}^{-1}$ acts as a natural per-parameter learning rate that accounts for curvature. A steep direction (high curvature) gets a small step; a flat direction (low curvature) gets a large step. In practice: $O(n^2)$ memory, $O(n^3)$ inversion — completely infeasible for LLMs.

Practical Approximations

L-BFGS

Limited-memory BFGS approximates $\mathbf{H}^{-1}$ using the last $m$ gradient differences (typically $m = 10$–$20$). $O(mn)$ memory instead of $O(n^2)$. Used for small models and fine-tuning but not large-scale pretraining due to poor mini-batch behavior.

K-FAC

Kronecker-Factored Approximate Curvature approximates the Fisher information matrix as a Kronecker product of smaller matrices per layer: $\mathbf{F} \approx \mathbf{A} \otimes \mathbf{G}$. Reduces cost to $O(d_\text{in}^2 + d_\text{out}^2)$ per layer. Used in some research settings but still $5$–$10\times$ overhead vs Adam.

Shampoo

Maintains per-layer preconditioner matrices (one per dimension of the weight tensor), updated as running outer products of gradients. Google uses distributed Shampoo for some large-scale training. Shown to reach the same loss as Adam in fewer steps — but each step is more expensive.

Sophia

A recent (2023) second-order optimizer using a diagonal Hessian estimate via Hutchinson's estimator: $\hat{H} = \mathbf{g} \odot \mathbf{g}$ on random perturbation vectors. Claimed $2\times$ sample efficiency over Adam on LLM pretraining. Still experimental.

Why Second-Order Methods Aren't Used for LLMs

Method Memory Compute Mini-batch
Adam $2n$ (m + v) $O(n)$ / step Excellent
Newton $n^2$ $O(n^3)$ / step Requires full batch
L-BFGS $mn$ $O(mn)$ / step Poor mini-batch
K-FAC $O(d^2)$ / layer $5$–$10\times$ Adam Approximate
Shampoo $O(d^2)$ / layer $2$–$5\times$ Adam Reasonable 
import torch
import torch.nn as nn

# L-BFGS example (only practical for small models / full-batch)
model   = nn.Linear(10, 1)
X_train = torch.randn(100, 10)
y_train = torch.randn(100, 1)

# L-BFGS requires a closure that recomputes loss
optimizer = torch.optim.LBFGS(model.parameters(), lr=1.0,
                               max_iter=20, history_size=10)

def closure():
    optimizer.zero_grad()
    loss = nn.MSELoss()(model(X_train), y_train)
    loss.backward()
    return loss

for _ in range(5):
    loss = optimizer.step(closure)
    print(f"Loss: {loss.item():.6f}")

# For large-scale LLM training: always use AdamW
# torch.optim.AdamW(model.parameters(), lr=3e-4, weight_decay=0.1)
Bottom Line: Despite their theoretical advantages, second-order methods face a fundamental tension with LLM-scale training: (1) noisy stochastic gradients make curvature estimates unreliable; (2) memory overhead is prohibitive; (3) Adam with warmup + cosine decay is already close to optimal for overparameterized models where most loss landscape curvature is benign. The field continues to develop better approximations, but AdamW remains the default for the foreseeable future.
