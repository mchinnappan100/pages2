Introduction

Why Linear Algebra?

Every large language model is, at its core, a deep stack of linear maps interspersed with cheap nonlinearities. When a token is fed into a transformer, its integer ID is converted to a dense vector via an embedding lookup — a row selection from a learned matrix. From there, Q, K, V projections are matrix multiplications that reinterpret each token vector in three different subspaces for attention. Finally, the feed-forward network (FFN) layers apply two more matrix multiplications with a nonlinearity in between, expanding and contracting the representation. Understanding these operations through the lens of linear algebra is not optional — it is the language in which LLM architecture, training dynamics, and optimisation are written.

LLM Operation → Linear Algebra Concept

Section 2

Vectors, Norms & Cosine Similarity

Token embeddings live in a high-dimensional vector space $\mathbb{R}^d$ (typically $d = 768$–$8192$). The $\ell_2$ norm measures a vector's magnitude; cosine similarity measures the angle between two vectors and is the standard metric for semantic relatedness — direction matters more than magnitude once embeddings are normalised.

$$\|\mathbf{x}\|_2 = \sqrt{\sum_i x_i^2}, \qquad \cos\theta = \frac{\mathbf{u}\cdot\mathbf{v}}{\|\mathbf{u}\|\,\|\mathbf{v}\|}$$ 
import torch
import torch.nn.functional as F

# Two token embeddings (d=4 for illustration)
u = torch.tensor([1.0, 0.5, -0.3, 0.8])
v = torch.tensor([0.9, 0.4,  0.1, 0.7])

# L2 norm
norm_u = torch.norm(u, p=2)          # tensor(1.3565)
norm_v = torch.norm(v, p=2)          # tensor(1.2530)

# Dot product
dot = torch.dot(u, v)                 # tensor(1.4100)

# Cosine similarity (manual)
cos_manual = dot / (norm_u * norm_v)  # tensor(0.8302)

# Cosine similarity via F.cosine_similarity (batched)
cos_fn = F.cosine_similarity(u.unsqueeze(0), v.unsqueeze(0))
print(f"norm u={norm_u:.4f}, norm v={norm_v:.4f}")
print(f"cosine similarity = {cos_fn.item():.4f}")
Section 3

Matrix Multiplication

Matrix multiplication is the single most executed operation in a transformer. The shape rule $(m\times k)(k\times n)\to(m\times n)$ dictates how sequence length, hidden dimension, and head dimension interact throughout the architecture.

$$(\mathbf{A}\mathbf{B})_{ij} = \sum_k A_{ik}B_{kj}, \qquad (m\times k)\;(k\times n)\;\to\;(m\times n)$$ 
import torch

A = torch.randn(32, 64)   # m=32, k=64
B = torch.randn(64, 128)  # k=64, n=128

# Standard matmul
C = torch.matmul(A, B)    # shape: (32, 128)
C2 = A @ B                # identical via @ operator

# Batched matmul — (batch, seq, d_model) @ (batch, d_model, d_head)
X  = torch.randn(8, 512, 768)   # batch=8, seq=512, d=768
W  = torch.randn(8, 768,  64)   # per-head projection
out = torch.bmm(X, W)           # (8, 512, 64)
print(C.shape, out.shape)        # torch.Size([32, 128]) torch.Size([8, 512, 64])
Section 4

Tensors in PyTorch

LLM activations are rank-3 tensors shaped $(B, T, d)$ where $B$ is batch size, $T$ is sequence length, and $d$ is the hidden dimension. Operations like reshape, permute, and einsum rearrange these axes without copying data, enabling efficient multi-head attention and batch processing.

$$\mathbf{X} \in \mathbb{R}^{B \times T \times d}, \quad \text{linear projection:} \quad Y_{btd'} = \sum_d X_{btd}\,W_{dd'}$$ 
import torch

B, T, d, d_out = 4, 128, 768, 64

# Create a batch of token embeddings
X = torch.randn(B, T, d)           # (4, 128, 768)

# reshape: merge batch and time axes
X_flat = X.reshape(B * T, d)       # (512, 768)

# permute: (B, T, d) -> (T, B, d) as some layers expect
X_perm = X.permute(1, 0, 2)        # (128, 4, 768)

# Projection weight matrix
W = torch.randn(d, d_out)          # (768, 64)

# einsum for batched linear projection — explicit and readable
Y = torch.einsum('btd,de->bte', X, W)   # (4, 128, 64)

# Equivalent with matmul broadcast
Y2 = X @ W                              # (4, 128, 64)

assert Y.shape == Y2.shape == (B, T, d_out)
print("Y shape:", Y.shape)   # torch.Size([4, 128, 64])
Section 5

Eigenvalues & Eigenvectors

An eigenvector $\mathbf{v}$ of $\mathbf{A}$ is a direction that the matrix merely scales — it does not rotate. The scale factor $\lambda$ is the eigenvalue. PCA of an embedding matrix finds the axes of maximum variance via eigenvectors of the covariance matrix, providing interpretable low-dimensional projections of token representations.

$$\mathbf{A}\mathbf{v} = \lambda\mathbf{v}, \qquad \det(\mathbf{A} - \lambda\mathbf{I}) = 0$$ 
import torch

A = torch.tensor([[4.0, 1.0, 0.0],
                  [2.0, 3.0, 0.0],
                  [0.0, 0.0, 2.0]])

eigenvalues, eigenvectors = torch.linalg.eig(A)

print("Eigenvalues:", eigenvalues.real)
# tensor([5., 2., 2.])

print("Eigenvectors (columns):\n", eigenvectors.real)
# PCA: eigenvectors of cov(X) give principal directions in embedding space
Section 6

SVD & Low-Rank Approximation

SVD decomposes any matrix into an orthogonal basis, a diagonal of singular values, and another orthogonal basis. Truncating to the top $r$ singular values gives the best rank-$r$ approximation (Eckart–Young theorem). LoRA exploits this directly: instead of fine-tuning a full weight matrix $\mathbf{W}\in\mathbb{R}^{m\times n}$, it learns a correction $\Delta\mathbf{W} = \mathbf{B}\mathbf{A}$ where $\mathbf{B}\in\mathbb{R}^{m\times r}$ and $\mathbf{A}\in\mathbb{R}^{r\times n}$ with $r \ll d$, reducing trainable parameters by orders of magnitude.

$$\mathbf{A} = \mathbf{U}\boldsymbol{\Sigma}\mathbf{V}^T, \qquad \mathbf{A}_r = \sum_{i=1}^{r} \sigma_i\,\mathbf{u}_i\mathbf{v}_i^T$$ 
import torch

# Simulate a weight matrix (e.g., FFN layer)
A = torch.randn(256, 128)

# Full SVD
U, S, Vh = torch.linalg.svd(A, full_matrices=False)
# U: (256,128), S: (128,), Vh: (128,128)

# Rank-k approximation
k = 16
A_k = U[:, :k] @ torch.diag(S[:k]) @ Vh[:k, :]  # (256, 128)

# Reconstruction error
err = torch.norm(A - A_k) / torch.norm(A)
print(f"Rank-{k} relative error: {err:.4f}")
# LoRA: DeltaW = B @ A  with r << d, no SVD needed at runtime
Section 7

Embeddings as Matrix Lookups

The embedding table $\mathbf{E}\in\mathbb{R}^{V\times d}$ maps each integer token ID to a dense row vector. Mathematically this is equivalent to multiplying the one-hot vector $\mathbf{e}_{id}\in\mathbb{R}^V$ by $\mathbf{E}$, but in practice it is implemented as a fast index operation. Because addition and subtraction in embedding space correspond to semantic composition, classic analogies like king − man + woman ≈ queen emerge naturally.

$$\mathbf{E}\in\mathbb{R}^{V\times d},\quad \text{lookup}(\text{id}) = \mathbf{e}_{\text{id}}^T\,\mathbf{E} = \mathbf{E}[\text{id},\,:]$$ 
import torch
import torch.nn as nn

V, d = 50_000, 512   # vocab size, embedding dim
emb = nn.Embedding(V, d)
print("Weight matrix shape:", emb.weight.shape)  # (50000, 512)

# Lookup a batch of token IDs
ids = torch.tensor([42, 1337, 9999])
vecs = emb(ids)               # (3, 512)

# Vector arithmetic (analogy demo with toy embeddings)
king   = emb(torch.tensor([0])).squeeze()
man    = emb(torch.tensor([1])).squeeze()
woman  = emb(torch.tensor([2])).squeeze()
queen_approx = king - man + woman   # direction ≈ queen embedding
print("Analogy vector shape:", queen_approx.shape)  # (512,)
Section 8

Attention as Linear Algebra

Scaled dot-product attention is entirely composed of matrix multiplications and a softmax. The division by $\sqrt{d_k}$ is a variance-stabilising trick: since the dot product of two random $d_k$-dimensional unit vectors has variance $d_k$, dividing by $\sqrt{d_k}$ restores O(1) variance and prevents softmax from saturating into near-zero gradients for large $d_k$.

$$\mathbf{Q}=\mathbf{X}\mathbf{W}^Q,\quad \mathbf{K}=\mathbf{X}\mathbf{W}^K,\quad \mathbf{V}=\mathbf{X}\mathbf{W}^V$$ $$\text{Attention}(\mathbf{Q},\mathbf{K},\mathbf{V})=\text{softmax}\!\left(\frac{\mathbf{Q}\mathbf{K}^T}{\sqrt{d_k}}\right)\mathbf{V}$$ 
import torch
import torch.nn.functional as F
import math

def scaled_dot_product_attention(X, W_Q, W_K, W_V):
    """
    X   : (B, T, d_model)
    W_* : (d_model, d_k)
    returns: (B, T, d_k)
    """
    Q = X @ W_Q          # (B, T, d_k)
    K = X @ W_K          # (B, T, d_k)
    V = X @ W_V          # (B, T, d_v)

    d_k = Q.shape[-1]
    # Scores: (B, T, T) — every query attends to every key
    scores = Q @ K.transpose(-2, -1) / math.sqrt(d_k)

    # Causal mask (optional) — set future positions to -inf
    T = scores.shape[-1]
    mask = torch.triu(torch.ones(T, T, dtype=torch.bool), diagonal=1)
    scores = scores.masked_fill(mask, float('-inf'))

    attn_weights = F.softmax(scores, dim=-1)   # (B, T, T)
    return attn_weights @ V                     # (B, T, d_v)

# Demo
B, T, d_model, d_k = 2, 16, 64, 32
X   = torch.randn(B, T, d_model)
W_Q = torch.randn(d_model, d_k)
W_K = torch.randn(d_model, d_k)
W_V = torch.randn(d_model, d_k)
out = scaled_dot_product_attention(X, W_Q, W_K, W_V)
print("Attention output shape:", out.shape)   # (2, 16, 32)
