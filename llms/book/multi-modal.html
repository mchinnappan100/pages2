Section 1

The Big Picture

A traditional LLM works with text tokens. A multimodal LLM works with multiple modalities — Text, Images, Audio, Video — by converting each into representations that a Transformer can process and relate to each other.

Section 2

From Pixels to Vision Tokens

CNN — Hierarchical Features

Pixels → Edges → Textures
→ Shapes → Parts → Objects
e.g. pixels → edges → curves → wheels → car

Strong local-image inductive bias from convolution.

ViT — Patch Projection

Pixels → Patch (16×16)
→ Linear projection
→ Embedding / vector
→ Vision token

Analogous to text tokens — each patch becomes a position in the sequence.

Section 4

Why Do Images Need Embeddings?

"Numbers are not the same thing as semantic representations."

Raw pixels

[0.21, 0.73, 0.12, ...]

Do not inherently mean "aircraft wing"

Learned embedding

Training transforms pixel patterns into representations where wing, cockpit, engine, aircraft become computationally related — just like word embeddings.

Section 5

Connection to Word2Vec

King − Man + Woman ≈ Queen

Relationships between concepts emerge as geometric relationships in high-dimensional space.

Multimodal systems extend this idea: the text token "cat" and an image of a cat can be represented in related regions of the same learned representation space — enabling the system to connect language and vision.

Section 7

OCR vs Multimodal Vision Understanding

📄 OCR

"What text is present in this image?"

Image → OCR → "WARNING: HIGH VOLTAGE"

Excellent for:

  • Scanned docs / forms
  • Labels & serial numbers
  • Tables with text

🧠 Vision LLM

"What does this image mean?"

Diagram → "Shows relationship between power supply, controller and sensor"

Can reason about:

  • Charts & diagrams
  • Visual anomalies
  • Pictures without text
Don't replace OCR with multimodal understanding. Combine them.

Sections 15–17

Interpretability

The Problem

We can explain the architecture, input, output, and training — but not a complete human-readable account of every internal computation.

Not Traditionally Programmed

There is no if verified: change_booking() equivalent written by hand. Behaviour emerges from billions of trained parameters.

Mechanistic Interpretability

Researchers use sparse autoencoders and circuit analysis to investigate neurons, attention heads, and layers — like using a microscope on a biological system.

Sections 18–20

Trusted System Architecture

"Don't ask the LLM to perform tasks that must be deterministic."

The LLM can reason, but deterministic controls decide whether it is allowed to act.

Verified context example: verified = false is set by the system. The LLM can never declare verified = true. Only the deterministic verification service can set it — making the control variable and authorization check fully deterministic.
Section 21

Toxicity / Output Safety — Graduated Scoring

0.00–0.20

Allow

0.20–0.50

Review / rewrite

0.50–0.80

Strong filter

0.80–1.00

Block / escalate

The principle is Score → Policy → Action, not simply Score → Block. Exact thresholds must be empirically determined for your application.

Sections 27–30

RAG vs Fine-Tuning vs Domain Training

📚

Level 1 — RAG

"Teach the system where to find the knowledge."

  • No model retraining
  • Info can be updated
  • Sources can be cited
  • Easier to audit

First choice for enterprise knowledge.

⚙️

Level 2 — Fine-Tuning

"Teach the model how to behave."

  • Style & terminology
  • Response format
  • Domain patterns
  • Tool-use behavior

Not ideal for constantly changing facts.

🏭

Level 3 — Domain Training

"Change the model's learned representations."

  • Large domain corpus
  • Significant compute
  • Careful evaluation
  • Strong data quality

For orgs with large proprietary datasets.

Section 33

Re-ranking

Initial retrieval finds candidates. The re-ranker determines which are actually most relevant — significantly improving RAG quality.

Section 34

Security-Aware RAG

The model should never retrieve information the user isn't authorized to see. Do not rely on the LLM to decide whether confidential information should be shown.
User → Identity → Permissions
→ Retriever (filter by authorization)
→ Only authorized documents → LLM
Section 35

The Enterprise AI Philosophy

Section 36

Key Takeaways

Multimodal

Different modalities → representations → Transformer → shared reasoning.

Vision

Pixels → patches → embeddings → visual tokens → attention.

OCR vs Vision

OCR extracts text. Vision LLMs interpret visual meaning. Combine both.

RAG

Supplies current/domain-specific knowledge without retraining.

Safety

Put deterministic controls around probabilistic models.

Trust

Don't promise deterministic LLM behavior. Promise deterministic system controls around the LLM.
