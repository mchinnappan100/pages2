Mixture of Experts (MoE)

MoE replaces the dense FFN in each Transformer layer with $N$ expert sub-networks and a learned router. Only $k=2$ experts process each token, so the active parameter count stays small while the total parameter count scales to hundreds of billions — giving GPT-4 / Mixtral class capacity at a fraction of the compute cost per token.

MoE Layer — Top-2 Routing

Router gate and MoE output:

$$\mathbf{g}(\mathbf{x})=\text{TopK}(\text{softmax}(\mathbf{x}\mathbf{W}_g),\, k), \qquad \text{output}=\sum_{i\in\text{TopK}}\mathbf{g}_i(\mathbf{x})\cdot E_i(\mathbf{x})$$

Load-balancing auxiliary loss to prevent router collapse:

$$\mathcal{L}_{aux}=\alpha\cdot N\sum_{i=1}^{N} f_i\cdot P_i$$

$f_i$ = fraction of tokens routed to expert $i$; $P_i$ = mean gate probability for expert $i$.

import torch, torch.nn as nn, torch.nn.functional as F

class MoELayer(nn.Module):
    def __init__(self, d, n_experts=8, k=2, d_ff=256):
        super().__init__()
        self.k = k; self.n = n_experts
        self.gate = nn.Linear(d, n_experts, bias=False)
        self.experts = nn.ModuleList([
            nn.Sequential(nn.Linear(d, d_ff), nn.ReLU(), nn.Linear(d_ff, d))
            for _ in range(n_experts)])

    def forward(self, x):                        # x: (B, T, d)
        B, T, d = x.shape; flat = x.view(-1, d)  # (BT, d)
        logits = self.gate(flat)                  # (BT, N)
        topk_w, topk_idx = torch.topk(F.softmax(logits, -1), self.k, dim=-1)
        out = torch.zeros_like(flat)
        for i, expert in enumerate(self.experts):
            mask = (topk_idx == i).any(-1)        # tokens routed here
            if mask.any():
                w = topk_w[mask][topk_idx[mask] == i].unsqueeze(-1)
                out[mask] += w * expert(flat[mask])
        return out.view(B, T, d)

Grouped Query Attention (GQA) & Multi-Query Attention

Standard MHA has $H$ heads each with independent K, V projections — the KV cache grows as $O(H)$ per token, dominating memory at long context. MQA shares a single K, V pair; GQA uses $G$ groups ($1 \le G \le H$), each sharing one K, V. LLaMA-3 70B uses $H=64$ query heads with $G=8$ KV heads, yielding an $8\times$ KV cache reduction with negligible quality loss.

KV cache memory per token per layer:

$$\text{MHA} \propto H, \quad \text{GQA} \propto G, \quad \text{MQA} \propto 1$$

LLaMA-3 70B: $H=64,\; G=8 \;\Rightarrow\; 8\times$ reduction. Each query head $h$ in group $g$ uses $K_g, V_g$ where $g = \lfloor h \cdot G / H \rfloor$.

import torch, torch.nn as nn, math

class GQAttention(nn.Module):
    def __init__(self, d=512, H=8, G=2):
        super().__init__()
        self.H, self.G, self.dh = H, G, d // H
        self.q = nn.Linear(d, d)
        self.k = nn.Linear(d, G * self.dh)
        self.v = nn.Linear(d, G * self.dh)
        self.out = nn.Linear(d, d)

    def forward(self, x):
        B, T, _ = x.shape
        Q = self.q(x).view(B, T, self.H, self.dh).transpose(1,2)
        K = self.k(x).view(B, T, self.G, self.dh).transpose(1,2)
        V = self.v(x).view(B, T, self.G, self.dh).transpose(1,2)
        rep = self.H // self.G
        K = torch.repeat_interleave(K, rep, dim=1)  # (B,H,T,dh)
        V = torch.repeat_interleave(V, rep, dim=1)
        attn = (Q @ K.transpose(-2,-1)) / math.sqrt(self.dh)
        return self.out((attn.softmax(-1) @ V).transpose(1,2).reshape(B,T,-1))

Post-Training Quantization (PTQ)

PTQ compresses weights after training, reducing memory by 2–4× without retraining. Per-channel symmetric INT8 quantization assigns one scale $s$ per output channel so large outliers don't corrupt small weights. GPTQ extends this with a second-order update that minimizes layer-wise reconstruction error, enabling accurate 3–4 bit quantization of 70B+ models.

Per-channel symmetric INT8:

$$s = \frac{\max(|\mathbf{W}|)}{127}, \quad \mathbf{W}_q = \text{round}\!\left(\frac{\mathbf{W}}{s}\right), \quad \hat{\mathbf{W}} = s\cdot\mathbf{W}_q$$

Frobenius error bound: $\|\mathbf{W}-\hat{\mathbf{W}}\|_F \leq \tfrac{s}{2}\sqrt{mn}$. GPTQ layer-wise objective:

$$\min_{\hat{\mathbf{W}}}\;\|\mathbf{W}\mathbf{X}-\hat{\mathbf{W}}\mathbf{X}\|^2 \quad\text{using Hessian diagonal }\mathbf{H}=\mathbf{X}\mathbf{X}^\top$$ 
import torch, torch.nn as nn

def fake_int8_linear(linear: nn.Linear, x: torch.Tensor):
    W = linear.weight.data.float()           # (out, in)
    # per-channel scale (one scale per output neuron)
    s = W.abs().max(dim=1, keepdim=True).values / 127.0
    W_q = W.div(s).round().clamp(-128, 127)  # INT8 range
    W_hat = W_q * s                          # dequantized
    err = (W - W_hat).norm() / W.norm()
    print(f"Relative Frobenius error: {err:.4f}")
    # Run inference with fake-quantized weights
    with torch.no_grad():
        linear.weight.data = W_hat.to(linear.weight.dtype)
    return linear(x), err

Speculative Decoding

Autoregressive decode is memory-bound: the large target model $M_p$ processes one token at a time, underutilizing compute. Speculative decoding uses a tiny draft model $M_q$ to propose $\gamma$ tokens in a single forward pass, then scores all of them with $M_p$ in parallel. Accepted tokens are kept via rejection sampling — losslessly preserving the exact distribution of $M_p$ while amortizing its cost over multiple tokens.

Acceptance probability for draft token $x_t$:

$$\Pr[\text{accept}\; x_t] = \min\!\left(1,\;\frac{p(x_t)}{q(x_t)}\right)$$

Expected accepted tokens per speculative step (acceptance rate $\alpha$):

$$\mathbb{E}[\text{tokens}] = \frac{1 - \alpha^{\gamma+1}}{1-\alpha}$$ 
import torch, torch.nn.functional as F

def speculative_decode(prompt, draft_model, target_model, gamma=4, max_new=50):
    tokens = prompt.clone()
    while tokens.shape[-1] < prompt.shape[-1] + max_new:
        # Draft: generate gamma tokens autoregressively
        draft_ids, draft_probs = [], []
        draft_input = tokens
        for _ in range(gamma):
            logits = draft_model(draft_input).logits[:, -1]
            probs = F.softmax(logits, dim=-1)
            t = torch.multinomial(probs, 1)
            draft_ids.append(t); draft_probs.append(probs.gather(1, t))
            draft_input = torch.cat([draft_input, t], dim=-1)
        draft_seq = torch.cat([tokens] + draft_ids, dim=-1)
        # Target: score all drafted tokens in one pass
        target_logits = target_model(draft_seq).logits[:, tokens.shape[-1]-1:-1]
        target_probs = F.softmax(target_logits, dim=-1)
        # Rejection sampling
        accepted = 0
        for i in range(gamma):
            tp = target_probs[:, i].gather(1, draft_ids[i])
            if torch.rand(1) < (tp / draft_probs[i]).clamp(max=1.0):
                tokens = torch.cat([tokens, draft_ids[i]], dim=-1); accepted += 1
            else:
                break
        if accepted < gamma:  # sample correction token from target
            adj = (target_probs[:, accepted] - F.softmax(
                   draft_model(tokens).logits[:, -1], dim=-1)).clamp(min=0)
            tokens = torch.cat([tokens, torch.multinomial(adj/adj.sum(-1,keepdim=True),1)],dim=-1)
    return tokens

PagedAttention & KV Cache

Each decode step appends one K, V vector per layer to the KV cache. For $L$ layers, $H$ heads, head dimension $d_k$, and sequence length $T$, total cache bytes = $2 \cdot L \cdot H \cdot d_k \cdot T \times \text{sizeof(dtype)}$. Traditional contiguous allocation reserves space up front, wasting memory when sequences are shorter than the reserved maximum. PagedAttention (vLLM) stores KV in fixed-size pages (e.g., 16 tokens) allocated on demand — eliminating fragmentation.

KV Cache: Contiguous vs Paged

$$\text{KV cache bytes} = 2 \cdot L \cdot H \cdot d_k \cdot T \cdot \text{sizeof(dtype)}$$

Example: LLaMA-3 8B, FP16 — $L=32$, $H=32$, $d_k=128$, $T=4096$: $2\times32\times32\times128\times4096\times2 = 2\text{ GB}$.

import torch

class PagedKVCache:
    def __init__(self, n_layers, n_heads, d_k, page_size=16, max_pages=512, dtype=torch.float16):
        self.ps = page_size; self.L = n_layers; self.H = n_heads; self.dk = d_k
        # Physical page pool: (max_pages, page_size, 2, n_heads, d_k)
        self.pool = torch.zeros(max_pages, page_size, 2, n_heads, d_k, dtype=dtype)
        self.free = list(range(max_pages))
        self.tables: dict = {}  # seq_id -> list of page indices

    def append(self, seq_id, layer, k, v):   # k,v: (H, d_k)
        if seq_id not in self.tables: self.tables[seq_id] = []
        tbl = self.tables[seq_id]
        total = sum(self.ps for _ in tbl)    # tokens already stored
        if total % self.ps == 0:             # need a new page
            pg = self.free.pop(0); tbl.append(pg)
        pg, slot = tbl[-1], total % self.ps
        self.pool[pg, slot, 0, :, :] = k
        self.pool[pg, slot, 1, :, :] = v

Knowledge Distillation

Distillation trains a small student model to mimic a large teacher's output distribution, not just its hard labels. The temperature $T$ softens the teacher's logits, revealing relative similarities between classes that carry more information than the argmax. Sequence-level distillation additionally aligns intermediate hidden states, enabling student models (e.g. DistilBERT at 40% the size) to recover 97%+ of teacher performance.

$$\mathcal{L}_{KD}=(1-\alpha)\,\mathcal{L}_{CE}(\mathbf{y},\mathbf{p}_s)+\alpha T^2\,\mathcal{L}_{CE}\!\left(\text{softmax}\!\left(\tfrac{\mathbf{z}_t}{T}\right),\text{softmax}\!\left(\tfrac{\mathbf{z}_s}{T}\right)\right)$$

The $T^2$ factor compensates for gradient scaling introduced by temperature. Hidden-state alignment: $\mathcal{L}_{hs}=\|\mathbf{h}_t^{\text{teacher}}-\mathbf{W}\mathbf{h}_s^{\text{student}}\|^2$.

import torch, torch.nn as nn, torch.nn.functional as F

def distillation_loss(student_logits, teacher_logits, labels, T=4.0, alpha=0.5):
    # Hard-label cross-entropy
    ce_hard = F.cross_entropy(student_logits, labels)
    # Soft targets: teacher distribution at temperature T
    s_soft = F.log_softmax(student_logits / T, dim=-1)
    t_soft = F.softmax(teacher_logits / T, dim=-1)
    ce_soft = -(t_soft * s_soft).sum(dim=-1).mean()
    return (1 - alpha) * ce_hard + alpha * (T ** 2) * ce_soft

def train_step(student, teacher, batch, optimizer, T=4.0, alpha=0.5):
    x, y = batch
    with torch.no_grad(): t_logits = teacher(x)
    s_logits = student(x)
    loss = distillation_loss(s_logits, t_logits, y, T, alpha)
    optimizer.zero_grad(); loss.backward(); optimizer.step()
    return loss.item()

Flash Attention Math Revisited

FlashAttention tiles Q, K, V into blocks sized $B_r \times d$ and $B_c \times d$ that fit in SRAM of size $M$. The SRAM requirement per block is $4B_r d + B_r B_c$ floats; setting $B_c = \lfloor M/(4d) \rfloor$ saturates bandwidth while keeping the tile in SRAM. The online softmax recurrence accumulates output exactly in a single pass — no N×N matrix is ever written to HBM.

Optimal tile sizes and IO complexity:

$$B_c=\left\lfloor\frac{M}{4d}\right\rfloor,\quad B_r=\min\!\left(\left\lfloor\frac{M}{4d}\right\rfloor,\,d\right)$$ $$\text{IO complexity: } O\!\left(\frac{T^2 d}{M}\right) \text{ vs standard } O(T^2)$$

Online softmax row-block update (running max $m$, sum $\ell$, output $O$):

$$m_{\text{new}}=\max(m,\,m_{\text{block}}),\quad O_{\text{new}}=\frac{\ell\cdot O\cdot e^{m-m_{\text{new}}}+\tilde{O}_{\text{block}}\cdot e^{m_{\text{block}}-m_{\text{new}}}}{\ell_{\text{new}}}$$ 
import torch, torch.nn.functional as F

def flash_attention_sdpa(q, k, v, is_causal=True):
    """Uses PyTorch's built-in FlashAttention kernel via SDPA."""
    # q, k, v: (B, H, T, d_k)  — float16 or bfloat16 recommended
    with torch.backends.cuda.sdp_kernel(
        enable_flash=True, enable_math=False, enable_mem_efficient=True
    ):
        out = F.scaled_dot_product_attention(q, k, v, is_causal=is_causal)
    return out   # (B, H, T, d_k) — exact, O(N) memory

Continuous Batching & Throughput

Static batching idles the GPU when different sequences finish at different times. Continuous batching inserts new requests as slots free up, keeping GPU utilization near 100%. Prefill is compute-bound ($\sim 2\times12Ld^2 T_{\text{prompt}}$ FLOPs for all tokens at once), while decode is memory-bound ($\sim2\times12Ld^2$ FLOPs per single new token — far below roofline arithmetic intensity).

$$\text{Throughput}=\frac{B\cdot T_{\text{gen}}}{\text{wall time}}, \quad \text{Prefill FLOPs}\approx 2\cdot 12Ld^2\cdot T_{\text{prompt}}$$ $$\text{Arithmetic intensity}=\frac{\text{FLOPs}}{\text{memory bytes accessed}}\;\;\begin{cases}>I_{\text{ridge}} & \text{compute-bound}\\ 
import torch, time

def throughput_benchmark(model, batch_size=8, seq_len=128, n_steps=20, device="cuda"):
    model.eval().to(device)
    ids = torch.randint(0, model.config.vocab_size, (batch_size, seq_len), device=device)
    past = None
    # Warm-up
    with torch.no_grad():
        for _ in range(3):
            out = model(ids[:, -1:], past_key_values=past, use_cache=True)
            past = out.past_key_values
    torch.cuda.synchronize()
    t0 = time.perf_counter()
    with torch.no_grad():
        for _ in range(n_steps):
            out = model(ids[:, -1:], past_key_values=past, use_cache=True)
            past = out.past_key_values
    torch.cuda.synchronize()
    elapsed = time.perf_counter() - t0
    tok_per_sec = batch_size * n_steps / elapsed
    print(f"Throughput: {tok_per_sec:.1f} tokens/s  ({elapsed*1000/n_steps:.1f} ms/step)")

Pruning & Sparse Models

Magnitude pruning zeroes weights with $|w_{ij}| < \tau$, achieving sparsity $s = \text{zeros}/N$ with no retraining. Structured pruning removes entire attention heads or MLP neurons for hardware-friendly speedups. SparseGPT achieves 50–60% sparsity on LLMs with one-shot second-order updates, minimizing $\|\mathbf{W}\mathbf{X}-\hat{\mathbf{W}}\mathbf{X}\|^2$ without gradient steps.

$$\text{Magnitude pruning: }\hat{w}_{ij}=w_{ij}\cdot\mathbf{1}[|w_{ij}|\geq\tau], \quad s=\frac{\#\{w_{ij}=0\}}{N}$$

Lottery Ticket: the sparse subnetwork trained from the original init $\theta_0 \odot m$ matches dense accuracy. SparseGPT second-order update removes one weight at a time using the Hessian inverse without full retraining.

import torch, torch.nn as nn
import torch.nn.utils.prune as prune

def magnitude_prune(model, sparsity=0.5):
    for name, module in model.named_modules():
        if isinstance(module, nn.Linear):
            prune.l1_unstructured(module, name='weight', amount=sparsity)
    return model

def check_sparsity(model):
    total, zeros = 0, 0
    for name, module in model.named_modules():
        if isinstance(module, nn.Linear):
            w = module.weight
            zeros += (w == 0).sum().item()
            total += w.numel()
    print(f"Global sparsity: {zeros/total:.2%}  ({zeros}/{total} zero weights)")

Putting It All Together: Efficient LLM Stack

Modern production LLM inference stacks layer each technique to attack a different bottleneck. The table below summarizes the most impactful components, what each saves, and where it applies.

Technique What it saves Math key Where applied
FlashAttention Memory bandwidth IO: $O(T^2 d/M)$ Attention (train + infer)
GQA / MQA KV cache memory KV $\propto G \ll H$ Attention heads (infer)
Quantization (INT4/8) Weight memory 2–4× $\hat{W}=s\cdot\text{round}(W/s)$ All linear weights
Speculative Decoding Latency 2–3× $\mathbb{E}[\text{toks}]=\tfrac{1-\alpha^{\gamma+1}}{1-\alpha}$ Decode loop
Continuous Batching GPU utilization Throughput = $BT/\text{wall}$ Serving scheduler
LoRA Training params 100× $\Delta W = BA$, rank $r$ Fine-tuning
ZeRO (DeepSpeed) Training memory 8× Partition params/grad/opt Distributed training 
import torch, torch.nn.functional as F

def efficient_inference_step(model, input_ids, kv_cache, device="cuda"):
    """Minimal efficient inference: BF16 + FlashAttention SDPA + KV cache."""
    model = model.to(device=device, dtype=torch.bfloat16)
    model.eval()
    with torch.inference_mode():
        out = model(
            input_ids.to(device),
            past_key_values=kv_cache,
            use_cache=True,
            # PyTorch 2.x SDPA dispatches to FlashAttention kernel automatically
            attn_implementation="sdpa",
        )
    next_token = out.logits[:, -1].argmax(-1, keepdim=True)
    return next_token, out.past_key_values

def generate(model, prompt_ids, max_new=128, device="cuda"):
    ids, cache = prompt_ids.to(device), None
    for _ in range(max_new):
        ids_in = ids if cache is None else ids[:, -1:]
        next_tok, cache = efficient_inference_step(model, ids_in, cache, device)
        ids = torch.cat([ids, next_tok], dim=-1)
        if next_tok.item() == model.config.eos_token_id: break
    return ids
