Core Principles

The principles that run through every chapter

1

Memory movement can be as important as computation. A powerful GPU can still be bottlenecked waiting for data — not just arithmetic. FlashAttention, KV cache design, and quantization all target this.

2

Total parameters ≠ active parameters. MoE models can have trillions of total parameters while activating only a small fraction per token — delivering high quality at low inference cost.

3

Profile before optimising. Nsight Systems shows where time goes; Nsight Compute explains why. Measure first. Never optimise what you assume is the bottleneck.

4

Don't try to make the LLM deterministic. Build a deterministic system around the LLM. Identity, authorization, state machines, safety filters, and audit logs are engineering controls — not prompts.

5

RAG teaches the system where to find knowledge. Fine-tuning teaches it how to behave. Domain training changes its learned representations. Use the right tool for the knowledge problem you have.

6

The LLM is the reasoning engine, not the entire application. The strongest systems combine LLM + multimodal understanding + RAG + deterministic controls + security + observability + evaluation + human escalation.
